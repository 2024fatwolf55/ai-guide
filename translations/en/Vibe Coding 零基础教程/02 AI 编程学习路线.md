## 1. Getting Started with AI Programming

At this stage, the core idea is just one sentence: **build something first**.

Don’t get stuck on theory. Don’t worry about understanding the code. If you make something usable, that’s already a win.

First, you need to understand the basic concepts of AI programming. For example: What is Vibe Coding? What is a large language model? What is a Token? What’s the difference in mindset between traditional programming and AI programming? These concepts aren’t hard. You can read *Introduction to Vibe Coding* and *Vibe Coding Concepts Encyclopedia* in this tutorial. They explain everything in the simplest way possible, and 10 minutes is enough to get the basic idea.

![](https://pic.yupi.icu/1/image-20260520171913541.png)

Then jump in and start building. Open an AI no-code platform like Lovable, Meituan NoCode, or Baidu Miaoda, type in a requirement, watch AI generate the code, render the page, and publish it online with one click. The sense of accomplishment from that process is the best motivation to keep learning.

![](https://pic.yupi.icu/1/image-20260520172103766.png)

Once you finish your first project, you’ll realize that AI programming is basically this loop: describe requirements to AI → improve through multiple rounds of conversation → verify the results and fix issues, over and over again.

I recommend doing 3 to 5 simple projects first to build confidence, such as a personal profile page, a countdown tool, or a simple calculator. If you’re a complete beginner, **I don’t recommend starting with professional tools like Cursor right away**. Build a few small projects first, get a feel for the workflow, and then move on to more advanced tools.



## 2. Master Mainstream AI Programming Tools

No-code platforms have their limits. If you want to build more complex projects, you’ll need to learn more professional AI programming tools.

### Tool Categories

At the moment, AI programming tools on the market can roughly be divided into four categories: AI code editors (such as Cursor, Codex, Trae), AI command-line tools (such as Claude Code), AI coding assistant plugins (such as GitHub Copilot), and AI no-code platforms (which you already used in the beginner stage).

![](https://pic.yupi.icu/1/02_AI%E7%BC%96%E7%A8%8B%E5%B7%A5%E5%85%B7%E5%9B%9B%E5%A4%A7%E5%88%86%E7%B1%BB_compressed_v1.png)



### The Three Mainstream Tools

Right now, the three most mainstream AI programming tools are Cursor, Codex, and Claude Code. Let me briefly introduce them one by one.

Cursor is an AI code editor based on VS Code. It has a friendly interface, a full feature set, and supports one-click switching between mainstream models. It’s my main tool for day-to-day AI programming.

![](https://pic.yupi.icu/1/1_cursor.png)

Codex is OpenAI’s AI programming tool. It comes in both desktop and CLI versions, uses GPT-family models by default, and offers great cost performance.

![](https://pic.yupi.icu/1/image-20260520170343111.png)

Claude Code is a terminal-based programming Agent. It has the strongest ability to handle complex tasks and achieved the highest industry score on the SWE-bench benchmark. That said, because it runs in the command line, the learning curve is a bit steeper.

![](https://pic.yupi.icu/1/14_claudecode.png)

If you’re a beginner, **I recommend starting with Cursor**, because it has a complete visual interface and offers the best code editing and review experience.

If Cursor feels too expensive, Codex is also a great option. The Plus plan costs $20 per month and gives you access to GPT-5.5, which is pretty good value. You can pair it with VS Code for reading and editing code.

Once you’re familiar with the AI programming workflow, then try Claude Code’s command-line style and experience the power of the strongest Agent.



### What to Learn in AI Programming Tools

No matter which tool you choose, what you need to learn is mostly the same. I summarize it into five parts.

1. Basic usage: Chat conversations, Agent autonomous coding, Tab intelligent completion, and `@` references for context  
2. Core features: Plan Mode, Background Agent execution, and Browser Use testing  
3. Extensions and enhancements: MCP for connecting external services, and Agent Skills  
4. Practical techniques: multi-Agent parallelism and using sub-Agents to split tasks  
5. Custom configuration: rules files that define AI behavior and project-level constraints

![](https://pic.yupi.icu/1/03_AI%E7%BC%96%E7%A8%8B%E5%B7%A5%E5%85%B7%E4%BA%94%E5%A4%A7%E5%AD%A6%E4%B9%A0%E6%96%B9%E9%9D%A2_compressed_v3.png)

You don’t need to learn every tool. It’s enough to deeply master 1 or 2 of them, because their core logic is very similar.



### AI Programming Extensions

MCP is like giving your AI programming tool a **universal plug**, allowing it to connect to external services. For example, it can read design files through Figma MCP to generate code, query business data through a database MCP, or fetch the latest information through web search MCP.

![](https://pic.yupi.icu/1/1746710765234-c974bda8-666e-45b3-adc4-ace97cbb8c0a.png)

Agent Skills are like **skill packs** for AI. Install a document-processing skill, and AI knows how to generate PPTs or handle Excel files. Install a coding standards skill, and it knows how to write code according to your company’s conventions.

![](https://pic.yupi.icu/1/1769306811193-2ee3acbc-5e36-46c2-8d08-b2682494fb56.png)

CLI tools are also becoming more and more important. Large models are naturally good at reading commands and executing actions, so big companies are now open-sourcing CLI tools for their own products. At the core, they’re providing AI with an operational interface.

## 3. Core AI Programming Skills

Once you know how to use the tools, the next step is learning how to make projects better. The skills at this stage do not require a programming background. Even complete beginners can learn them.

### Requirement Analysis

The first step in building a project is not asking AI to write code. It’s thinking clearly about what you want to build. You need to define the project goal and core features, break large requirements into smaller tasks, and decide on the tech stack and project architecture.

When I first started building projects, I wanted to throw the entire page at AI in a single prompt and let it do everything in one go. The result was a mess of bad code. Later I learned the “small-step fast-iteration” approach: ask AI to complete one small feature at a time, verify it, and then move on. It turned out to be much more efficient.

![](https://pic.yupi.icu/1/05_%E9%9C%80%E6%B1%82%E5%88%86%E6%9E%90%E5%B0%8F%E6%AD%A5%E5%BF%AB%E8%B7%91_compressed_v3.png)



### Prompt Engineering

Prompt engineering is the core skill of AI programming. A good prompt can improve the quality of the generated code by several levels.

A good prompt usually includes role definition, background information, specific requirements, constraints, and the desired output format.

Here are a few universal tips:

1. Be specific in requirement descriptions. Don’t be vague. For example, instead of “make it look nicer,” say “change the background to a blue gradient and add rounded corners to the buttons.”  
2. Break down complex tasks  
3. Give AI examples—it understands much better that way  
4. Learn to follow up and iterate continuously

![](https://pic.yupi.icu/1/06_%E6%8F%90%E7%A4%BA%E8%AF%8D%E5%B7%A5%E7%A8%8B%E6%A0%B8%E5%BF%83%E8%A6%81%E7%B4%A0_compressed_v1.png)



### Context Management

Prompting alone isn’t enough. You also need to learn how to provide AI with enough reference information.

The most important thing is learning to use project rules files. I recommend starting with the general `AGENTS.md` format, which is supported by almost all mainstream AI programming tools. In this rules file, you can write down the project’s tech stack, coding conventions, and directory structure, and AI will automatically follow those rules when generating code.

![](https://pic.yupi.icu/1/image-20260201145003244.png)

Then learn to use `@` references to include files, functions, and documentation as context, so AI can generate new code based on existing code.

You also need to be aware of context window limits. Keep one conversation focused on one problem. Once that problem is solved, start a new conversation.



### Bug Troubleshooting

Both humans and AI run into bugs, so you need to learn how to troubleshoot and fix them.

When describing a bug to AI, tell it the expected behavior and the actual behavior, provide complete error messages, and explain what solutions you’ve already tried.

If a problem can’t be solved, roll back to the last stable version in time. Don’t let AI keep charging down a dead end. If AI gets stuck repeatedly trying and failing to fix the same problem, try describing it from a different angle.



### Git Version Control

Git is the **undo pill** of the AI programming era. AI can absolutely wreck your code, and Git lets you roll it back with one click.

In the AI era, you don’t need to understand every Git command. The essentials are learning `git add`, `git commit`, and `git push`, learning to use `git diff` to see what AI changed, and using `git checkout` to roll back to earlier versions.

![](https://pic.yupi.icu/1/07_Git%E7%89%88%E6%9C%AC%E7%AE%A1%E7%90%86%E5%90%8E%E6%82%94%E8%8D%AF_compressed_v3.png)



### Project Development Workflow

The things we’ve discussed so far—requirement analysis, prompts, context, bug troubleshooting, and Git—are all point skills. Once you start building real complete projects, you need to connect them into a proper development workflow.

Move forward step by step with a process like: requirement breakdown → solution confirmation → task-by-task implementation → code review → refactoring and optimization. Each conversation should focus on only one thing. Verify before moving on. After completing each feature, commit the code with Git—that’s like creating a save point. If AI breaks something later, you can roll back anytime.

Also note: if you’re working on projects in a company environment, AI-generated code should never be used directly. **It must be reviewed.** Pay special attention to whether the business logic is correct, whether error handling is missing, whether there are security risks, and whether the change affects other features.

![](https://pic.yupi.icu/1/1773743259446-0023e562-efb7-48e0-8930-3de6e475ed4a.png)

You also need basic security awareness. Don’t hardcode API Keys into source code, verify that third-party packages recommended by AI actually exist, and validate user input.



### Project Deployment

Once the development workflow is running smoothly, the next step is deploying your project online so the whole world can access it.

For quick deployment, I recommend Vercel. It can deploy frontend and full-stack projects with one click, and the free tier is enough for most people. As you advance, you can learn Docker-based container deployment and cloud server deployment.

![](https://pic.yupi.icu/1/image-20260109111323983.png)



### AI Programming Modes

After building a few projects, you may notice that casually chatting with AI in a pure Vibe Coding style works well for small projects, but once a project gets bigger, it can easily go off the rails. That’s when you need to understand several more mature AI programming modes. Choosing the right method for the right scenario will help you build projects faster and more reliably.

1) **Agentic Engineering**  

This is suitable for medium to large projects, and was further defined by Karpathy after he introduced Vibe Coding. The core idea is that you no longer write code yourself. Instead, you act as the **chief commander**, orchestrating AI agents, designing the system architecture and constraints, letting AI handle implementation while you focus on review and acceptance. It’s a shift from casual chatting to deliberately directing AI work.

![](https://pic.yupi.icu/1/08_Agentic_Engineering%25E6%2599%25BA%25E8%2583%25BD%25E4%25BD%2593%25E5%25B7%25A5%25E7%25A8%258B_compressed_v3.png)

2) **Harness Engineering**  

This is an extremely popular concept in the AI world right now and is better suited for enterprise projects.

Harness originally means horse tack. If you think of AI as a horse, this mode is about building a complete working environment and process around it so it can run both fast and steadily.

![](https://pic.yupi.icu/1/7_harness_layers-20260520185712885.png)

3) **SDD, Specification-Driven Development**  

This is a new development methodology for the AI era. It emphasizes creating clear specification documents that AI can directly understand and execute before coding begins.

The traditional workflow is: think of something, write it, revise while writing, and only document it later. That often leads to unclear requirements and mismatches between code and docs.

SDD flips that around: **write the requirements as specifications first, and treat those specifications as the single source of truth for the code**.

![](https://pic.yupi.icu/1/09_SDD%25E8%25A7%2584%25E8%258C%2583%25E9%25A9%25B1%25E5%258A%25A8%25E5%25BC%2580%25E5%258F%2591_compressed_v1.png)

In real development, you can combine these modes flexibly. Use Vibe Coding for quickly building small tools. Switch into an Agentic Engineering mindset for serious projects. The bigger and more complex the project, the more you need the engineering approach of Harness. If you want to go deeper, check out my [Harness Engineering practical tutorial](https://mp.weixin.qq.com/s/qdTXCvMA4yI9mTuQv8Zq6A).



## 4. AI Programming Project Practice

## 5. Advanced Improvement

After building a few complete projects, you’re already an AI programming developer with practical experience. Next, you can go deeper based on your own goals. You don’t need to learn everything.

1) **AI programming tips and techniques**

These are the practical skills distilled from lots of real-world work. They can double your efficiency, covering things like conversation techniques, code quality assurance, refactoring, performance optimization, security protection, and website beautification.

What you especially need to watch out for are **systematic failure patterns** that show up after doing AI programming for a while—for example, context drift, feature regression, architecture degradation, and dependency bloat. Recognizing these patterns helps you prevent problems early instead of waiting until they become severe.

![](https://pic.yupi.icu/1/10_AI%E7%BC%96%E7%A8%8B%E7%B3%BB%E7%BB%9F%E6%80%A7%E5%A4%B1%E8%B4%A5%E6%A8%A1%E5%BC%8F_compressed_v1.png)

2) **Context Engineering**

This is the advanced version of context management. It includes context budget design (what should stay loaded vs. what should load on demand), decision logs (recording pitfalls to avoid repeating mistakes), and window management strategies (when to start a new conversation and when to turn knowledge into documentation).

![](https://pic.yupi.icu/1/11_%E4%B8%8A%E4%B8%8B%E6%96%87%E5%B7%A5%E7%A8%8B%E6%A0%B8%E5%BF%83%E6%96%B9%E9%9D%A2_compressed_v1.png)

3) **Cost Management**

For the same task, some people spend 1 yuan and others spend 10. That’s real money.

For example: choosing models based on the task, simplifying rules files, and using tools efficiently.

![](https://pic.yupi.icu/1/12_AI%E7%BC%96%E7%A8%8B%E6%88%90%E6%9C%AC%E7%AE%A1%E7%90%86%E7%AD%96%E7%95%A5_compressed_v2.png)

4) **Basic Programming Knowledge**

Having some programming basics helps you collaborate with AI better. You don’t need to fully master a language, but you should understand common tech stacks at a basic level—what they are and what they’re used for—so you can express your requirements more accurately when talking to AI.

![](https://pic.yupi.icu/1/13_%25E7%25BC%2596%25E7%25A8%258B%25E6%258A%2580%25E6%259C%25AF%25E5%259F%25BA%25E7%25A1%2580%25E8%25AE%25A4%25E7%259F%25A5%25E5%259B%25BE_compressed_v2.png)

5) **Introduction to Large-Model Principles**

Understanding the basic principles behind large models helps you use AI better and understand what it’s good at and where it struggles.

For example: understanding Tokens and tokenization, context windows, temperature parameters, a plain-language grasp of Transformers and attention mechanisms, why hallucinations happen, and why there are context length limits.

![](https://pic.yupi.icu/1/14_AI%25E5%25A4%25A7%25E6%25A8%25A1%25E5%259E%258B%25E5%258E%259F%25E7%2590%2586%25E5%2585%25A5%25E9%2597%25A8%25E6%A6%2582%25E5%25BF%25B5_compressed_v2.png)

6) **AI Application Development Tech Stack**

If you want to build professional AI applications or work in AI application development roles, you can learn AI development frameworks like LangChain, RAG (Retrieval-Augmented Generation), AI Agent development, and MCP service development.

## 6. Keep Learning

AI programming is evolving extremely fast. Best practices from a few months ago may already be outdated now, so this really is a field where you need to keep learning for life.
