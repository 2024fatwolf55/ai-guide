## 1. MCP Server Category

MCP stands for Model Context Protocol. Simply put, it's an open standard that allows AI models to connect with external tools and data sources.

Think of MCP as a USB-C port for AI. Originally, AI could only answer questions or generate code based on its training data. But with this universal interface, it can now connect to various external tools - like opening browsers to view websites, searching and scraping web content, deploying projects to the cloud, accessing databases, etc. Its capabilities instantly become much richer.

![](https://pic.yupi.icu/1/%E6%BC%AB%E7%94%BB%E5%9B%BE1%E5%A4%A7.jpeg)

### ⭐️ Firecrawl MCP for Web Content Scraping

First is [Firecrawl MCP](https://www.firecrawl.dev/), which enables AI to automatically scrape and understand web content.

When developing projects, I often need to gather reference materials from the web, read official documentation and tech blogs, or analyze competitors' feature implementations. Doing this manually requires opening websites, copying and pasting content, or writing custom scraping scripts - a huge hassle.

With Firecrawl MCP, it becomes much simpler. I just tell my AI programming tool:
- Get me the content from this website
- Read this document for me
- Search online for information about XX

It automatically retrieves the webpage's content, structure, even dynamically loaded data.

![](https://pic.yupi.icu/1/image-20260116105912027.png)

**How to use?**

First register on [Firecrawl's website](https://www.firecrawl.dev/app/api-keys) and create an API Key for service calls.

![](https://pic.yupi.icu/1/image-20260116105955795.png)

Then configure the MCP server in your AI programming tool. Using Cursor as an example (other tools have similar MCP integration methods - check their official docs like [Claude Code MCP integration](https://docs.anthropic.com/en/docs/claude-code/mcp)).

Open Cursor settings, find Tools & MCP, click `+ New MCP Server`.

![](https://pic.yupi.icu/1/image-20260116110425690.png)

Essentially you're modifying the MCP config file to add:

```json
{
  "mcpServers": {
    "firecrawl-mcp": {
      "command": "npx",
      "args": ["-y", "firecrawl-mcp"],
      "env": {
        "FIRECRAWL_API_KEY": "Your_API_Key"
      }
    }
  }
}
```

![](https://pic.yupi.icu/1/image-20260116110454499.png)

This configuration means: Run the firecrawl-mcp tool via npx command and pass your API key to it. If you don't have npx installed, first [install Node.js](https://nodejs.org/zh-cn) - npx comes bundled with it.

After configuration, green success dots indicate it's ready to use.

![](https://pic.yupi.icu/1/image-20260116110558199.png)

Beyond basic web scraping, Firecrawl MCP also supports batch site scraping, recursive multi-layer link scraping, automatic retries on failure, and other advanced features.

### Brave Search MCP for Private Searching

Next is [Brave Search MCP](https://github.com/brave/brave-search-mcp-server), enabling AI to perform privacy-focused web searches.

During development, I often need AI to search for the latest technical materials, find library usage examples, or troubleshoot technical issues. The traditional approach requires manually searching and copying results to AI - quite tedious.

With Brave Search MCP, I simply tell AI:
- Search for React 19's new features
- Look up how to fix this error

It uses Brave Search to find answers. Brave doesn't track search history, offering excellent privacy protection.

![](https://pic.yupi.icu/1/image-20260116111803869.png)

**How to use?**

First register at [Brave Search API](https://brave.com/search/api/), then go to API Key management. You must select the free plan! 2000 monthly queries are enough for personal development.

![](https://pic.yupi.icu/1/image-20260116110947801.png)

One catch: Even the free plan requires payment method setup. Those without overseas bank cards may need to skip.

After subscription, create an API Key:

![](https://pic.yupi.icu/1/image-20260116111311536.png)

With the API Key, add to Cursor's MCP config:

```json
{
  "mcpServers": {
    "brave-search": {
      "command": "npx",
      "args": ["-y", "brave-search-mcp"],
      "env": {
        "BRAVE_API_KEY": "Your_API_Key"
      }
    }
  }
}
```

Once configured, AI can search for latest information anytime.

Supports web, image, video, news searches, even local business info (like nearby coffee shops).

![](https://pic.yupi.icu/1/image-20260116111954334.png)

It also features AI summarization, automatically condensing search results into concise answers.

### ⭐️ Context7 for Latest Documentation

[Context7](https://context7.com/) helps AI access the latest technical documentation.

We know AI training data has cutoff dates - GPT-4's knowledge might only be current until 2023. This creates problems when asking about latest framework versions - answers may be outdated.

Context7 solves this by automatically scraping latest version-specific docs from official sites for AI.

![](https://pic.yupi.icu/1/image-20260116112229490.png)

Thus, AI's code examples and suggestions are based on current docs, avoiding deprecated practices, significantly improving project success rates.

**How to use?**

Visit [Context7 Dashboard](https://context7.com/dashboard) to register and get an API Key (free for personal use).

![](https://pic.yupi.icu/1/image-20260116112322940.png)

Add to MCP config:

```json
{
  "mcpServers": {
    "context7": {
      "url": "https://mcp.context7.com/mcp",
      "headers": {
        "CONTEXT7_API_KEY": "Your_API_Key"
      }
    }
  }
}
```

When discussing technical docs with AI or mentioning "use context7", it automatically fetches latest documentation.

![](https://pic.yupi.icu/1/image-20260116112656483.png)

### Web to MCP for UI Component Replication

[Web to MCP](https://web-to-mcp.com/) is a Chrome extension that works with MCP to send any webpage UI component directly to AI for code generation - the fastest way to "copy homework"!

![](https://pic.yupi.icu/1/image-20260116113052973.png)

Often when browsing sites, I see nice UI components and want AI to recreate similar effects. Previously, I'd screenshot and describe: "Make a button like this - rounded corners, gradient, with shadow..." Time-consuming and imprecise.

With Web to MCP, I just click the element I want to replicate:

![](https://pic.yupi.icu/1/image-20260116113725321.png)

It automatically captures the component's DOM structure, CSS styles, even interactions, providing a prompt for AI replication.

Just send the prompt to AI, which uses MCP to get complete component info and generates replication code.

![](https://pic.yupi.icu/1/image-20260116114142631.png)

Compared to vague screenshots, the generated code is much more accurate.

![](https://pic.yupi.icu/1/image-20260116114426822.png)

**How to use?**

1) Install extension via website or Chrome Web Store search

![](https://pic.yupi.icu/1/image-20260116113138693.png)

2) Log in with Google account to get your MCP config:

![](https://pic.yupi.icu/1/image-20260116113241575.png)

3) Add to AI tool's MCP config:

```json
{
  "mcpServers": {
    "web-to-mcp": {
      "url": "https://web-to-mcp.com/mcp/your_unique_ID"
    }
  }
}
```

When browsing, click the extension icon, select desired components, and directly reference them in your AI tool to quickly generate style-consistent code.

### Chrome DevTools MCP for Browser Debugging

[Chrome DevTools MCP](https://github.com/ChromeDevTools/chrome-devtools-mcp) by Chrome's team lets AI directly control Chrome for operations and debugging.

For frontend development, I often need to debug pages, inspect network requests, analyze performance. Previously manual in browser DevTools, now AI can do it.

For example: "Why is this site loading slowly?" AI opens DevTools, analyzes network requests, checks resource load times, then identifies issues.

![](https://pic.yupi.icu/1/image-20260116115138719.png)

Or: "Test this form submission" - it auto-fills forms, clicks submit, checks responses.

**How to use?**

Add to MCP config:

```json
{
  "mcpServers": {
    "chrome-devtools": {
      "command": "npx",
      "args": ["-y", "chrome-devtools-mcp@latest"]
    }
  }
}
```

After configuration, AI can automate testing and debugging. The tool auto-connects to your running Chrome browser without extra setup.

Also supports element locating, network monitoring, performance analysis, screenshots - ideal for frontend development and testing.

### COS MCP for Object Storage

[COS MCP](https://github.com/Tencent/cos-mcp) lets AI directly operate Tencent Cloud Object Storage.

Object storage is cloud file storage - think cloud drives.

![](https://pic.yupi.icu/1/image-20260116120009365.png)

For team collaboration, we often need AI to reference project specs or images. Previously storing files locally and manually uploading to AI was inconvenient and hard to maintain/share/modify across teams.

With COS MCP, I can store shared files in the cloud and have AI directly access them.

![](https://pic.yupi.icu/1/image-20260116122211103.png)

For example: "Write this feature according to our team's COS-shared project specs" - AI reads specs from COS and codes accordingly.

![](https://pic.yupi.icu/1/image-20260116122453843.png)

**How to use?**

1) First enable Tencent Cloud COS service at [COS Console](https://console.cloud.tencent.com/cos), create a Bucket:

![](https://pic.yupi.icu/1/image-20260116120711822.png)

2) Get SecretId and SecretKey at "Access Management" > "API Key Management" - keep these secure!

![](https://pic.yupi.icu/1/image-20260116121022222.png)

3) Add to MCP config:

```json
{
  "mcpServers": {
    "cos-mcp": {
      "command": "npx",
      "args": [
        "cos-mcp",
        "--Region=your_region",
        "--Bucket=your_bucket",
        "--SecretId=your_SecretId",
        "--SecretKey=your_SecretKey"
      ]
    }
  }
}
```

![](https://pic.yupi.icu/1/image-20260116121243549.png)

After configuration, AI can read/manage your cloud files - essentially giving AI a cloud drive.

Also supports image search, processing, document conversion, video thumbnail generation.

![](https://pic.yupi.icu/1/image-20260116121658701.png)

## 3. Agent Skills Category

Agent Skills are skill packs equipped for AI, allowing AI to behave more professionally on specific tasks. Just like MCP, Agent Skills are now an indispensable part of the AI programming ecosystem, and they are an open standard shared across tools rather than tied to a specific editor.

For a detailed beginner tutorial on Agent Skills, you can read *Agent Skills: A General AI Skill Library* in the Tool Practice section.

### Agent Skills: A General AI Skill Library

[Agent Skills](https://claude.com/blog/skills) is a newly launched AI skill system from Anthropic.

It defines a standard for **packaging AI workflows**: developers can bundle complex task instructions, scripts, and resources into a **Skill**; as a user, you only need to install these skills, and AI can immediately learn that capability without reinventing the wheel every time.

![](https://pic.yupi.icu/1/%E6%BC%AB%E7%94%BB%E5%9B%BE7%E5%A4%A7.jpeg)

Let’s try it in practice by using the [frontend-design](https://www.claudeskill.site/en/skills/anthropic-agent-skills:frontend-design) Agent Skill to improve the UI of a generated website.

⭐️ I recommend watching the animated video version too—it’s even easier to understand: [https://bilibili.com/video/BV1T7zzBQEaA](https://www.bilibili.com/video/BV1T7zzBQEaA/)

1) Install Agent Skills

First, open Claude Code and enter one command to register the official Skills repository as a plugin marketplace:

```markdown
/plugin marketplace add anthropics/skills
```

![](https://pic.yupi.icu/1/image-20260116145357194.png)

Then enter `/plugin`, switch to the Marketplaces panel with the Tab key, and bulk-install the official Skills provided there, including:

- `document-skills`: A document skill pack for handling Excel, Word, PPT, PDF, and other documents.
- `example-skills`: An example skill pack covering skill creation, MCP building, visual design, algorithmic art, webpage testing, animated image generation, theme styling, and more.

![](https://pic.yupi.icu/1/claudecode%E6%8F%92%E4%BB%B6%E5%AE%89%E8%A3%85.png)

After installation, enter the `/skills` command and you’ll see all installed skills, including the `frontend-design` one we need.

![](https://pic.yupi.icu/1/image-20260116145938235.png)

You can also find the local installation location of Skills. Once you look inside, you’ll realize that Skills are essentially just a packaged set of prompt documents, script files, and the like:

![](https://pic.yupi.icu/1/image-20260116151949110.png)

There’s another installation method as well: in Claude Code, you can directly install the [frontend-design](https://www.claudeskill.site/en/skills/anthropic-agent-skills:frontend-design) skill with one command:

```markdown
skill install anthropic-agent-skills:frontend-design
```

2) After installing the Skills, you can just keep chatting with AI as usual, and the program will automatically decide which Skills to use based on your task.

For example, when I asked AI to build a polished Werewolf web game, it asked me whether I wanted to use the `frontend-design` skill.

![](https://pic.yupi.icu/1/image-20260116152325220.png)

After using this skill, AI selected a more distinctive design style. The generated UI became both more unique and more professional, instead of the same old generic blue-purple gradient. And the best part is that you don’t need to repeat a big pile of design requirements every single time.

![](https://pic.yupi.icu/1/image-20260116153402176.png)

Without the skill, it looks like this by comparison:

![](https://pic.yupi.icu/1/image-20260116155623890.png)

The [official Anthropic Skills repository](https://github.com/anthropics/skills) already provides a rich collection of skills covering programming-related areas such as database optimization, API security, testing strategies, code review, and documentation generation, as well as office-related tasks like PPT creation, Excel processing, Word documents, PDF generation, and more.

If the official skills aren’t enough, you can upload your own custom skills, or download community-contributed skills from these platforms:

- ⭐️ [Yupi AI Navigation - Skills Collection](https://ai.codefather.cn/skills): continuously updated high-quality skills that unlock more of AI’s execution potential
- [Claude Skills Hub](https://www.claudeskill.site/): a community skill marketplace

### Skills Installation and Management Tools

**skills CLI**: an official command-line tool from Vercel. With one command, you can install any Skill. Simple and practical.

Usage is `npx skills add <owner/repo>`. For example, `npx skills add vercel-labs/agent-skills` installs all the official Vercel Skills.

> Link: https://www.npmjs.com/package/skills

![](https://pic.yupi.icu/1/image-20260204114830800.png)

**find-skills**: a Skills discovery tool from Vercel that helps you quickly find and install the Skills you need. It supports interactive search and keyword search. Run `npx skills find` to launch it.

> Link: install it via `npx skills add vercel-labs/skills`

![](https://pic.yupi.icu/1/image-20260204144654011.png)

**skill-creator**: Anthropic’s official Skill creation tool that teaches you how to create custom Skills. It guides you through writing a `SKILL.md` file following best practices, including skill descriptions, trigger conditions, execution steps, and more.

> Link: install it via `npx skills add anthropics/skills`

![](https://pic.yupi.icu/1/1769307998192-27ac24c2-c732-401d-a19e-ebe07086d73b-20260204144825800.png)

### Spec-kit for Specification-Driven Development

[Spec-kit](https://speckit.org/) is a Specification-Driven Development (SDD) framework launched by GitHub.

What is SDD?

The traditional development workflow is: write whatever comes to mind, modify while building, and patch the documentation later. This easily leads to unclear requirements and documentation that no longer matches the code.

Specification-driven development does the opposite: you first write requirements into specification documents and treat those documents as the **single source of truth** for the code. You can think of the spec document as **legal text** containing detailed requirement descriptions, system design, and interface definitions. AI must strictly follow those rules when generating code, ensuring that the output matches expectations exactly.

![](https://pic.yupi.icu/1/%E6%BC%AB%E7%94%BB%E5%9B%BE4%E5%A4%A7.jpeg)

This may sound a bit abstract, so let’s follow the official documentation in the [Spec-kit GitHub repository](https://github.com/github/spec-kit) and try it out in practice.

First open your terminal and use the `uvx` command to directly install and run the Specify tool, then initialize a project:

```bash
uvx --from git+https://github.com/github/spec-kit.git specify init my-project
```

![](https://pic.yupi.icu/1/image-20260116141308958.png)

Choose the AI programming tool you use. Spec-kit supports almost all mainstream tools, including Claude Code and GitHub Copilot. Here I chose Claude Code:

![](https://pic.yupi.icu/1/image-20260116141507190.png)

Choose the script type according to your operating system: Windows should choose the lower option, others the upper one:

![](https://pic.yupi.icu/1/image-20260116141537030.png)

After running this command, a `my-project` folder will be created in the current directory:

![](https://pic.yupi.icu/1/image-20260116141613246.png)

Inside the folder are these core files:

- `.specify/memory/constitution.md`: the project’s basic principles and conventions
- `.specify/scripts/`: some executable scripts
- `.specify/templates/`: template files
- `.claude/commands/`: a built-in set of slash commands that you can directly call from an AI programming tool

![](https://pic.yupi.icu/1/image-20260116142528820.png)

The initialization program also gives us some guidance on how to use these commands to develop the project next.

![](https://pic.yupi.icu/1/image-20260116141715310.png)

Open this project folder with Claude Code, and you can then use the predefined commands in the conversation.

![](https://pic.yupi.icu/1/image-20260116142740271.png)

What follows is a standardized development process. According to the [official documentation](https://github.com/github/spec-kit), it mainly consists of 7 steps:

1) Constitution: define project principles

Run the `/speckit.constitution` command to define the project’s basic principles, coding standards, performance standards, and so on. This is the project’s “constitution,” and all later development must follow it.

For example:

```markdown
/speckit.constitution Do not use blue-purple gradient style UI
```

💡 If you’re building a Chinese-language project, it’s best to explicitly tell AI in the project principles: “Use Chinese throughout the website.”

![](https://pic.yupi.icu/1/image-20260116160508054.png)

AI updated the project constitution document:

![](https://pic.yupi.icu/1/image-20260116160610169.png)

I recommend committing a Git version after every step. That way, if something goes wrong, you can roll back quickly, and it also makes it easier to see which files changed at each step.

![](https://pic.yupi.icu/1/image-20260116160745548.png)

2) Specify: write the feature specification

Run the `/speckit.specify` command to describe what feature you want to build, why you’re building it, and what the user needs are. For example:

```markdown
/speckit.specify I want to build a [website that automatically reminds me to drink water]
```

![](https://pic.yupi.icu/1/image-20260116161231223.png)

AI created a new Git branch for this requirement to avoid contaminating the existing project. On that branch, it created a requirements specification document (`spec.md`) and a requirements checklist document (`requirements.md`).

![](https://pic.yupi.icu/1/image-20260116161307642.png)

The requirements specification document is very detailed and even includes edge-case test cases to handle the many possible user actions.

![](https://pic.yupi.icu/1/image-20260116161926017.png)

The requirements checklist document records AI’s understanding of the requirements, and checked items mean the AI has understood and confirmed them:

![](https://pic.yupi.icu/1/image-20260116161500358.png)

3) Clarify: clarify ambiguous points (optional)

If you find that some items in the requirements checklist are not checked, you need to use the Clarify command to let AI guide you in refining the requirements until everything is checked off.

Run the `/speckit.clarify` command, and AI will ask you structured questions for you to answer, helping fill in requirement gaps such as edge cases and error handling.

![](https://pic.yupi.icu/1/image-20260116162702812.png)

I got lucky—AI had already understood all the items, so I didn’t need this step. Next, we could move directly into the stage of formulating the technical plan.

![](https://pic.yupi.icu/1/image-20260116162201772.png)

4) Plan: formulate the technical solution

Run the `/speckit.plan` command to let AI decide the tech stack, system architecture, data models, API interfaces, and so on.

![](https://pic.yupi.icu/1/image-20260116163506902.png)

Once the technical plan is finished, a whole batch of documents gets generated. Here’s a quick look:

- `CLAUDE.md`: the project development guide, recording the tech stack and project structure to guide Claude Code’s later development
- `quickstart.md`: a quick start guide containing 6 implementation phases and the deployment plan
- `plan.md`: the implementation plan defining the pure client-side architecture, storage strategy, constitution compliance checks, and more
- `data-model.md`: the data model design defining 4 core entities (reminder settings, water logs, daily progress, history) and the storage structure
- `research.md`: the technical research document recording 8 key technical decisions
- `contracts/api-contract.md`: the API interface document

![](https://pic.yupi.icu/1/image-20260116164021646.png)

After that, we’re ready to start implementation.

![](https://pic.yupi.icu/1/image-20260116163553725.png)

5) Tasks: break the plan into tasks

Run the `/speckit.tasks` command to decompose the plan into an executable task list, with dependency relationships and priorities marked.

![](https://pic.yupi.icu/1/image-20260116164537006.png)

A task list document is generated, making every implementation step crystal clear:

![](https://pic.yupi.icu/1/image-20260116164612533.png)

6) Analyze: analysis and checking (optional)

Run the `/speckit.analyze` command to check whether the specifications, plans, and tasks are complete and consistent, so you can find design defects in advance.

![](https://pic.yupi.icu/1/image-20260116164936733.png)

As you can see, AI didn’t find any issues and confidently told me to continue to the next step. It felt great!

7) Implement: carry out implementation

Finally, run the `/speckit.implement` command to let AI generate code according to the task list.

![](https://pic.yupi.icu/1/image-20260116170006815.png)

Mission accomplished. Let’s look at the result~

![](https://pic.yupi.icu/1/image-20260116170146827.png)

Since I never mentioned that the output should use Chinese, the website content is all in English, but honestly the result still looks pretty good.

At this point, we’ve learned how to use Spec-kit to develop a complete project. Let’s review the full process:

![](https://pic.yupi.icu/1/%25E6%25BC%25AB%25E7%2594%25BB%25E5%259B%25BE5%25E5%25A4%25A7.jpeg)

Even if you don’t use Spec-kit, you can still manually follow these same steps when developing a complete project.

The biggest advantage of this model is **alignment**. Everyone works from the same clear specification documents, keeping their understanding of the requirements highly consistent, reducing misunderstandings in communication, and ensuring code quality.

The downside is also obvious: for small projects, you could have just written the code directly in a few minutes, while going through this whole process can easily take half an hour!

So this workflow is more suitable for teams starting a brand-new project from scratch. Although the process is slower than writing code directly, it greatly reduces the risk of rework, so in the long run it’s actually more efficient.

### OpenSpec: A Lightweight Specification Framework

[OpenSpec](https://openspec.dev/) is a lightweight specification-driven development framework that is simpler and easier to use than Spec-kit.

Its core idea is to treat specification documents as part of the repository. Every time you change a feature, you **write a change proposal first** => implement it after confirmation => archive the change back into the specification documents after implementation, so the docs and code always stay in sync.

![](https://pic.yupi.icu/1/%E6%BC%AB%E7%94%BB%E5%9B%BE6%E5%A4%A7.jpeg)

Visit the [official OpenSpec repository](https://github.com/Fission-AI/OpenSpec/) to read the documentation.

First make sure your computer has a compatible Node.js version installed (for example, mine requires Node.js >= 20.19.0), then install the OpenSpec CLI globally:

```bash
npm install -g @fission-ai/openspec@latest
```

Enter your project directory and run the initialization command:

```bash
openspec init
```

During initialization, you’ll be asked to choose the AI tool you want to integrate with (such as Claude Code or Cursor). Here I selected Cursor.

![](https://pic.yupi.icu/1/image-20260116163202471.png)

After the command runs, OpenSpec automatically generates an `openspec/` directory in your project containing:

- `openspec/specs/`: stores the main spec documents that record the project’s full current state
- `openspec/changes/`: stores change proposals and the plan for each modification
- ⭐️ `openspec/AGENTS.md`: an operation guide for AI programming assistants using OpenSpec for specification-driven development, including the complete workflow for creating change proposals, writing requirement specs, validating changes, and archiving them
- `openspec/project.md`: current project context information

![](https://pic.yupi.icu/1/image-20260116164308965.png)

In addition, depending on the AI programming tool you selected, corresponding command files are generated—for example, Cursor’s:

![](https://pic.yupi.icu/1/image-20260116173814973.png)

With these files in place, we can begin the standardized development process. According to the [official documentation](https://github.com/Fission-AI/OpenSpec/), it mainly consists of 5 steps:

1) Draft: create a change proposal

Just tell AI directly in the programming tool to create a change proposal. For example, suppose I want to add a user search feature:

```markdown
Create an OpenSpec change to add a feature: search users by name and email
```

You can also use slash commands in AI programming tools such as Claude Code or Cursor:

```markdown
/openspec:proposal Add a feature: search users by name and email
```

![](https://pic.yupi.icu/1/image-20260116171714070.png)

AI creates an independent directory for this feature at `openspec/changes/add-user-search/`, and inside it creates a series of documents:

- `proposal.md`: describes what is changing and why
- `tasks.md`: task breakdown for implementation
- `specs/.../spec.md`: the concrete contents of the requirement change

![](https://pic.yupi.icu/1/image-20260116171953809.png)

2) Verify & Review: validation and review

You can run the following commands to check whether AI created the change proposal correctly:

```bash
openspec list                        # View all changes
openspec validate add-user-search    # Validate whether the format is correct
openspec show add-user-search        # View detailed contents
```

![](https://pic.yupi.icu/1/image-20260116172259055.png)

3) Review the proposal together with the team

If it needs improvement, you can continue chatting with AI. For example:

```markdown
Can you help me add more search conditions and constraints?
```

AI will update the spec and task list until everyone reaches agreement.

4) Implement: implement the change

After the spec is confirmed, tell AI to start implementation:

```markdown
The specification is already perfect. Start generating the code.
```

You can also use the slash command:

```markdown
/openspec:apply add-user-search
```

AI will implement the tasks one by one according to the task list in `tasks.md` and mark completion status.

![](https://pic.yupi.icu/1/image-20260116172654371.png)

The generation finishes quickly, and AI’s output is very neat—every change is clear at a glance:

![](https://pic.yupi.icu/1/image-20260116172905921.png)

5) Archive: archive the change

After all tasks are completed, ask AI to archive this change:

```markdown
Please archive this change
```

You can also use the slash command:

```markdown
/openspec:archive add-user-search
```

Or run it in the terminal:

```bash
openspec archive add-user-search --yes
```

![](https://pic.yupi.icu/1/image-20260116172957759.png)

This command will:

- move the change folder into the `openspec/changes/archive/` archive area
- automatically merge the requirement change into the main specs in `openspec/specs/`
- keep the documentation and the code synchronized

![](https://pic.yupi.icu/1/image-20260116174247313.png)

This way, through the history in `openspec/changes/`, you can trace the full story of every change at any time.

In addition, throughout the development process, I recommend running the `openspec validate` validation command regularly to ensure the integrity of the specification.

---

By this point, I believe you can already feel the difference between OpenSpec and Spec-kit:

- Spec-kit requires a complete 7-step process: define principles → write requirements → clarify questions → create the plan → split tasks → check → write code. It’s suitable for building large new projects from scratch.
- OpenSpec has a more streamlined workflow: draft proposal → review → implement → archive → validate. It’s quicker to get started with and suitable for iterating on existing projects.

### AIChat: A Command-Line Enhancement Tool

After using AIChat, you only need to speak plain language in the terminal, and its **Shell Assistant** capability automatically converts your natural language into accurate executable commands.

## 5. AI’s Productivity Toolbox

The MCPs, plugins, and Skills introduced above all run inside AI programming tools as extensions. The open-source projects I’m introducing next, however, are standalone productivity tools in their own right—they were designed for AI from the start, enabling AI to read files, listen to audio, edit video, and connect to external services, turning it from a chat-only mouth warrior into a true all-around worker.

### AI’s Reader - File Processing Tools

In daily work, lots of materials come in PDF, Word, Excel, or PPT format. But by default, AI can only read plain text. If you directly throw it a PDF, chances are it won’t extract anything useful.

The solution is simple: AI loves Markdown most, so why not convert the file to Markdown first, then hand it over for processing?

**MarkItDown**

[MarkItDown](https://github.com/microsoft/markitdown) is an all-purpose format converter open-sourced by Microsoft. PDF, Word, Excel, PPT, images, audio, HTML, even YouTube videos—it can convert them all into Markdown in one go.

> Open-source link: https://github.com/microsoft/markitdown

![](https://pic.yupi.icu/1/image-20260403142348396.png)

Installation and usage are both very simple. One pip command gets it done:

```bash
pip install markitdown
```

After installation, you can convert files with a single terminal command. It also provides an MCP Server that can be directly connected to AI programming tools. After that, when you drop a PDF or Word document into a project and ask AI to analyze it, it can automatically call MarkItDown to convert it to Markdown before processing—very smooth.

![](https://pic.yupi.icu/1/image-20260403142531441.png)

The advantage of MarkItDown is its broad format coverage—it can convert almost anything. But if it encounters very complex PDF layouts, such as multi-column papers, mathematical formulas, or complicated tables, it can start to struggle.

In that case, check out the following two more specialized tools.

**MinerU**

[MinerU](https://github.com/opendatalab/MinerU) specializes in deep PDF parsing. It can turn formulas into LaTeX, tables into HTML, automatically extract images, and ultimately output multimodal Markdown containing both text and images. If you often deal with papers, technical reports, and other complex documents, MinerU is more reliable than MarkItDown.

> Open-source link: https://github.com/opendatalab/MinerU

![](https://pic.yupi.icu/1/image-20260403143732593.png)

**Docling**

[Docling](https://github.com/docling-project/docling) is a document parsing tool open-sourced by IBM. In addition to PDFs, it also supports Word, PPT, Excel, and images, and it’s stronger than MarkItDown at understanding complex layouts and restoring structure. If you install its speech-recognition extension, it can even process audio and video by extracting audio tracks and converting them into text.

> Open-source link: https://github.com/docling-project/docling

![](https://pic.yupi.icu/1/image-20260403143816972.png)

To put it simply: use MarkItDown for daily conversions, MinerU for papers and formulas, and Docling for complex layouts. Just mix and match as needed.

### AI’s Ears and Video Editor - Audio/Video Tools

Besides documents, audio and video are also common materials in daily work. Meeting recordings need sorting, video materials need downloading, formats need converting... if AI handles these tasks, efficiency goes through the roof.

**whisper.cpp**

[whisper.cpp](https://github.com/ggml-org/whisper.cpp) is the C/C++ port of OpenAI’s Whisper model, a fully local speech-to-text tool. Its biggest advantage is that it requires neither a GPU nor an internet connection—you can run it on the CPU alone, so you never need to worry about private data leaking out.

It can handle transcribing meeting recordings, podcasts, and video subtitles with ease, supports speech recognition in multiple languages, and can even automatically detect the language. Just drop in an audio clip and out comes text.

> Open-source link: https://github.com/ggml-org/whisper.cpp

![](https://pic.yupi.icu/1/image-20260403144636577.png)

**yt-dlp**

[yt-dlp](https://github.com/yt-dlp/yt-dlp) is an amazingly useful video downloading tool that supports more than a thousand websites, including YouTube, Bilibili, TikTok, Twitter, and pretty much anything else you can think of.

It’s a pure command-line tool, which makes it very smooth for AI to call. Just specify a URL and output format, and you’re done. It also supports choosing resolution, extracting audio only, downloading subtitles, and much more.

> Open-source link: https://github.com/yt-dlp/yt-dlp

![](https://pic.yupi.icu/1/image-20260403151136014.png)

**FFmpeg**

[FFmpeg](https://github.com/FFmpeg/FFmpeg) may be one of the most important open-source projects in computing history. Nearly all software involving audio or video relies on it under the hood. Whether you want transcoding, clipping, concatenation, subtitles, audio extraction, or format conversion, one command can do it.

Humans get a headache trying to memorize FFmpeg parameters—but AI is amazing at remembering parameters! For example, if you tell AI, “Trim the first 30 seconds of this video and turn it into a GIF,” it can immediately generate and execute the correct FFmpeg command. If a human does it manually, they might have to search for the parameters for half an hour first...

> Open-source link: https://github.com/FFmpeg/FFmpeg

![](https://pic.yupi.icu/1/image-20260403152202764.png)

Used together, `yt-dlp` downloads the source material, `whisper.cpp` transcribes speech to text, and `FFmpeg` handles audio/video processing. With this three-hit combo, AI can complete a full workflow from download to transcription to editing.

### AI’s Hands and Feet - Browser Automation

I already mentioned [Browser Use](https://github.com/browser-use/browser-use) in the Skills section earlier; now let’s expand on it a bit more.

Browser Use is not only a Skill, but also a powerful standalone framework itself—a Python-based browser automation tool that lets AI control a browser like a real human.

For example, you can tell AI: “Open a certain website, find the Java learning roadmap, and take a screenshot.”

It can carry this out step by step, supporting clicks, typing, scrolling, multi-tab operations, and even automatic planning of execution steps, so it can handle complex multi-step tasks as well.

> Open-source link: https://github.com/browser-use/browser-use

![](https://pic.yupi.icu/1/image-20260403141700375.png)

It’s suitable for automated testing, bulk data scraping, repetitive operations in backend systems, and similar scenarios. Under the hood, it’s built on Microsoft’s open-source Playwright browser automation framework, so its stability and compatibility are both solid.

### AI’s Treasure Chest - External Service Integration

Want AI to send emails, create GitHub Issues, update Notion documents, or send messages to chat tools? Each of these requires connecting to a different platform and API, with different authentication methods, so integrating them one by one is a pain.

[Composio](https://github.com/ComposioHQ/composio) handles this dirty and exhausting work for AI. It has already integrated 1000+ external services and handles OAuth authentication, API calls, retry logic, and other details for you. AI only needs to call one function to operate GitHub, Gmail, Slack, Notion, and many other platforms, saving you the pain of integrating each one yourself.

> Open-source link: https://github.com/ComposioHQ/composio

![](https://pic.yupi.icu/1/image-20260403152926005.png)

Whether you’re developing AI applications with Python or TypeScript, you can use it directly. The official side also provides many ready-to-use application templates.

### AI’s Memo Pad - Memory Management

Anyone who has used AI programming has probably had this experience: you spend several rounds discussing requirements and technical details with AI, but as soon as you start a new conversation, it forgets everything and you have to explain the background all over again.

Although many AI programming tools now come with memory management built in, if you want to build your own AI application, you’ll need to solve the memory problem yourself.

[Mem0](https://github.com/mem0ai/mem0) adds a persistent memory layer to AI. It automatically extracts key information from conversations and stores it in a database, then automatically retrieves it in future conversations. This lets AI remember things like which programming language you prefer, what tech stack your project uses, and where the previous conversation left off, so next time it can continue directly without needing the background repeated.

> Open-source link: https://github.com/mem0ai/mem0

![](https://pic.yupi.icu/1/image-20260403150058803.png)

It supports user-level, session-level, and agent-level three-layer memory management, ensuring that different users’ context doesn’t get mixed up. If you’re learning AI application development, I recommend studying how Mem0 implements memory—it’s very insightful.
