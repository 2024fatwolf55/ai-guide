# AI 程式設計學習路線：我們學 AI 程式設計時，到底在學什麼？

最近因為身體原因，沒辦法直播帶大家做專案了，唉。。。

不過我也沒閒著，除了高強度編寫免費教程之外，我還在打造一套付費的、體系化的 AI 程式設計影片課程。

正好借這個機會，我係統梳理了一下 AI 程式設計的完整學習路線，今天分享給大家。

![](https://pic.yupi.icu/1/image-20260520191637710.png)

經常聽到有同學說：AI 程式設計不就是對話麼？有手就行吧？

我不否認這個說法。確實，如果你只是做個簡單的小工具，開啟一個 AI 零程式碼平臺，用人話描述一下需求，幾分鐘就能做出來。

但問題是，一旦專案複雜起來，各種問題就冒出來了。AI 不理解你的需求、程式碼質量不穩定、改了一個地方另一個地方又出 Bug、專案越做越難維護…… 這時候你就會發現，光靠聊天根本撐不住。

那 AI 程式設計到底要學什麼？

我把它分成了六個階段，從零基礎入門到進階提升，每個階段要掌握的內容都不一樣，下面一個個來講。

## 一、AI 程式設計入門

這個階段的核心就是一句話，**先把東西做出來**。

不用糾結原理，不用理解程式碼，做出能用的東西就是勝利。

首先你需要理解 AI 程式設計的基本概念。比如什麼是 Vibe Coding、什麼是大語言模型、什麼是 Token、傳統程式設計和 AI 程式設計的思維區別是什麼。這些概念不復雜，可以閱讀本教程的《Vibe Coding 簡介》和《Vibe Coding 概念大全》，用最通俗的方式講解了這些內容，花 10 分鐘讀一遍就能理解。

![](https://pic.yupi.icu/1/image-20260520171913541.png)

然後直接動手開幹。開啟一個 AI 零程式碼平臺，比如 Lovable、美團 NoCode 或者百度秒噠，輸入一段需求描述，看著 AI 幫你生成程式碼、頁面展示出來、一鍵釋出到網上。這個過程帶來的成就感，就是最好的學習動力。

![](https://pic.yupi.icu/1/image-20260520172103766.png)

跑通了第一個專案之後，你會發現 AI 程式設計的過程其實就是：向 AI 描述需求 → 多輪對話不斷最佳化 → 驗證效果並修復問題，迴圈往復。

建議先做 3 ~ 5 個簡單專案來鞏固練習，比如個人名片網頁、倒計時工具、簡單計算器這類。完全零基礎的話，**不建議一開始就用 Cursor 這類專業工具**，等你做了幾個小專案有了感覺，再去學更專業的工具。



## 二、掌握主流 AI 程式設計工具

零程式碼平臺的能力終究有限，想做更復雜的專案，就需要學習更專業的 AI 程式設計工具了。

### 工具分類

目前市面上的 AI 程式設計工具大致分四類：AI 程式碼編輯器（如 Cursor、Codex、Trae）、AI 命令列工具（如 Claude Code）、AI 程式設計輔助外掛（如 GitHub Copilot）、AI 零程式碼平臺（入門階段已經用過了）。

![](https://pic.yupi.icu/1/02_AI%E7%BC%96%E7%A8%8B%E5%B7%A5%E5%85%B7%E5%9B%9B%E5%A4%A7%E5%88%86%E7%B1%BB_compressed_v1.png)



### 三大主流工具

目前最主流的 AI 程式設計工具是 Cursor、Codex 和 Claude Code，下面我分別簡單介紹一下。

Cursor 是基於 VS Code 的 AI 程式碼編輯器，介面友好、功能齊全，能夠一鍵切換各種主流模型，是我日常 AI 程式設計的主力工具。

![](https://pic.yupi.icu/1/1_cursor.png)

Codex 是 OpenAI 推出的 AI 程式設計工具，有桌面端和 CLI 版本，預設使用 GPT 系列模型，價效比很高。

![](https://pic.yupi.icu/1/image-20260520170343111.png)

Claude Code 是終端程式設計 Agent，處理複雜任務的能力最強，在 SWE-bench 基準測試中拿到了行業最高分。不過它執行在命令列裡，上手門檻略高。

![](https://pic.yupi.icu/1/14_claudecode.png)

如果你是新手，**建議從 Cursor 開始入門**，因為它有完整的視覺化介面，程式碼編輯和審查體驗是最好的。

如果 Cursor 的成本負擔不起，Codex 也是很好的選擇，Plus 版每月 20 美元就能用上 GPT-5.5 模型，價效比不錯。可以搭配 VS Code 來檢視和編輯程式碼。

等你熟悉了 AI 程式設計的工作方式，再去嘗試 Claude Code 的命令列操作，感受一下最強 Agent 的威力。



### AI 程式設計工具要學什麼

無論你選哪個工具，要學的東西是相通的，我總結為 5 個部分。

1. 基本使用：Chat 對話、Agent 自主程式設計、Tab 智慧補全、@ 符號引用上下文
2. 核心特性：Plan Mode 計劃模式、Background Agent 後臺執行、Browser Use 瀏覽器測試
3. 擴充套件增強：MCP 連線外部服務、Agent Skills 技能包
4. 使用技巧：多 Agent 並行、子 Agent 拆分任務
5. 自定義配置：規則檔案定義 AI 行為規範、專案級約束

![](https://pic.yupi.icu/1/03_AI%E7%BC%96%E7%A8%8B%E5%B7%A5%E5%85%B7%E4%BA%94%E5%A4%A7%E5%AD%A6%E4%B9%A0%E6%96%B9%E9%9D%A2_compressed_v3.png)

工具不用全學，選 1 ~ 2 個深入掌握就夠了，操作邏輯都是相通的。



### AI 程式設計擴充套件

MCP 相當於給 AI 程式設計工具裝上了「萬能插頭」，讓 AI 能夠連線外部服務。比如透過 Figma MCP 讀取設計稿生成程式碼，透過資料庫 MCP 查詢業務資料，透過聯網搜尋 MCP 獲取最新資訊。

![](https://pic.yupi.icu/1/1746710765234-c974bda8-666e-45b3-adc4-ace97cbb8c0a.png)

Agent Skills 是給 AI 準備的「技能包」。裝上文件處理技能，AI 就知道怎麼生成 PPT、處理 Excel；裝上程式碼規範技能，它就知道怎麼按公司標準寫程式碼。

![](https://pic.yupi.icu/1/1769306811193-2ee3acbc-5e36-46c2-8d08-b2682494fb56.png)

還有 CLI 命令列工具也越來越值得關注。AI 大模型天生擅長讀命令、執行操作，現在大廠紛紛開源了自家產品的 CLI 工具，本質上就是在給 AI 提供操作介面。

![](https://pic.yupi.icu/1/image-20260407131112596.png)



## 三、AI 程式設計核心技能

會用工具之後，下一步就是把專案做得更好。這個階段要學的技能不需要程式設計基礎，零基礎也能學。

### 需求分析

做專案的第一步不是讓 AI 寫程式碼，而是要先想清楚做什麼。明確專案目標和核心功能，將大需求拆解為小任務，確定技術棧和專案架構。

我早期做專案的時候，恨不得一條提示詞把整個頁面全交給 AI 一把梭，結果生成出來的程式碼問題一大堆。後來我學會了「小步快跑」，一次只讓 AI 完成一個小功能，做完驗證沒問題再繼續下一個，效率反而高了很多。

![](https://pic.yupi.icu/1/05_%E9%9C%80%E6%B1%82%E5%88%86%E6%9E%90%E5%B0%8F%E6%AD%A5%E5%BF%AB%E8%B7%91_compressed_v3.png)



### 提示詞工程

提示詞工程是 AI 程式設計的核心技能，寫好提示詞能讓 AI 生成的程式碼質量提高好幾個檔次。

一個好的提示詞通常包含角色設定、背景資訊、具體需求、約束條件和輸出格式。

有幾個萬用的技巧：

1. 需求描述要具體，不要模稜兩可，比如「做得好看」應該改成「背景改成藍色漸變，按鈕加圓角」
2. 遇到複雜任務時，要進行拆解
3. 給 AI 舉例子，它會更容易理解
4. 學會不斷追問和迭代

![](https://pic.yupi.icu/1/06_%E6%8F%90%E7%A4%BA%E8%AF%8D%E5%B7%A5%E7%A8%8B%E6%A0%B8%E5%BF%83%E8%A6%81%E7%B4%A0_compressed_v1.png)



### 上下文管理

光靠提示詞還不夠，你還要學會給 AI 提供充足的參考資訊。

最重要的是學會使用專案規則檔案。建議優先學習通用的 `AGENTS.md` 格式，幾乎所有主流 AI 程式設計工具都支援。在規則檔案裡寫入專案技術棧、編碼規範、目錄結構說明，AI 生成程式碼時就會自動遵守這些約定。

![](https://pic.yupi.icu/1/image-20260201145003244.png)

然後是學會用 @ 引用來引用檔案、函式、文件作為上下文，讓 AI 基於已有程式碼生成新程式碼。

還要注意上下文視窗的限制，一個對話專注於解決一個問題，解決完了就開新的對話。



### Bug 排查

無論是人還是 AI，都會遇到 Bug，所以要學會排查和解決 Bug。

向 AI 描述 Bug 時，要告訴它期望的效果和實際的效果，提供完整的錯誤資訊，說明已嘗試的解決方案。

遇到解決不了的問題，要及時回退到上一個穩定版本，不要讓 AI 一條路走到黑。如果發現 AI 卡在同一個問題上反覆修不好，試試換個角度描述問題。



### Git 版本管理

Git 就是 AI 程式設計時代的「後悔藥」。AI 可能改崩你的程式碼，有了 Git 你可以一鍵回退。

AI 時代，不用把 Git 的每個命令都搞懂，核心是學會 `git add` / `git commit` / `git push` 這三個命令，學會用 `git diff` 檢視 AI 改了什麼，用 `git checkout` 回退到之前的版本。

![](https://pic.yupi.icu/1/07_Git%E7%89%88%E6%9C%AC%E7%AE%A1%E7%90%86%E5%90%8E%E6%82%94%E8%8D%AF_compressed_v3.png)



### 專案開發流程

前面講的需求分析、提示詞、上下文、Bug 排查、Git 都是單點技能，當你開始做真正的完整專案，就需要把這些技能串成一套規範的開發流程了。

按照需求拆解 → 方案確認 → 逐任務實現 → 程式碼審查 → 重構最佳化的流程來推進，單次對話只做一件事，做完驗證再繼續。每完成一個功能，用 Git 提交一次程式碼，相當於打了一個存檔點。萬一後面 AI 改出了問題，可以隨時回退。

注意，如果是在企業中做專案，AI 生成的程式碼不能直接用，**一定要經過審查**。重點關注業務邏輯是否正確、有沒有遺漏錯誤處理、有沒有安全隱患、改動是否影響了其他功能。

![](https://pic.yupi.icu/1/1773743259446-0023e562-efb7-48e0-8930-3de6e475ed4a.png)

還要有基本的安全意識。不要把 API Key 直接寫在程式碼裡，AI 推薦的第三方包要驗證是否真實存在，使用者輸入要做校驗。



### 專案部署上線

開發流程跑通了，下一步就是把專案部署上線，讓全世界都能訪問你的作品。

快速部署推薦 Vercel 平臺，能夠一鍵部署前端和全棧專案，免費額度就夠用了。進階可以學 Docker 容器化部署、雲伺服器部署。

![](https://pic.yupi.icu/1/image-20260109111323983.png)



### AI 程式設計模式

做了幾個專案之後，你可能會發現，光靠 Vibe Coding 的方式跟 AI 隨意對話，小專案做得挺順的，但專案一旦大起來就容易翻車。這時候你需要了解幾種更成熟的 AI 程式設計模式，不同場景選擇不同的方法，能讓你做專案更穩更快。

1）Agentic Engineering 智慧體工程

適合中大型專案，由 Karpathy 在提出 Vibe Coding 後進一步定義。核心思路是你不再自己寫程式碼，而是作為「總指揮」來編排 AI 智慧體，設計好系統架構和約束條件，讓 AI 去執行實現，你負責審查和驗收質量。從隨性聊天變成有規劃地指揮 AI 幹活。

![](https://pic.yupi.icu/1/08_Agentic_Engineering%25E6%2599%25BA%25E8%2583%25BD%25E4%25BD%2593%25E5%25B7%25A5%25E7%25A8%258B_compressed_v3.png)

2）Harness Engineering 駕馭工程

這是目前 AI 圈非常火的概念，適合企業級專案。

Harness 本意是馬具，你可以把 AI 想象成一匹馬，這個模式就是圍繞它搭一整套工作環境和流程，讓它跑得又快又穩。

![](https://pic.yupi.icu/1/7_harness_layers-20260520185712885.png)

3）SDD 規範驅動開發

這是 AI 時代的一種新型開發方法論，強調在編碼之前先建立明確的、AI 能直接理解和執行的規範文件。

傳統開發流程是：想到什麼寫什麼，邊寫邊改，最後再補文件。這樣容易導致需求不清晰、程式碼和文件對不上。

而 SDD 的思路正好相反：**先把需求寫成規範文件，並且把規範文件當作程式碼的唯一真相來源**。

![](https://pic.yupi.icu/1/09_SDD%25E8%25A7%2584%25E8%258C%2583%25E9%25A9%25B1%25E5%258A%25A8%25E5%25BC%2580%25E5%258F%2591_compressed_v1.png)

實際開發中可以靈活組合多種模式。做小工具時用 Vibe Coding 快速出活，做正經專案就切到 Agentic Engineering 的思維，專案越大越複雜就越需要 Harness 的工程化方法。想詳細瞭解可以看我的 [Harness Engineering 實戰教程](https://mp.weixin.qq.com/s/qdTXCvMA4yI9mTuQv8Zq6A)。



## 四、AI 程式設計專案實戰

學完上面的技能後，最重要的事情就是做專案。實戰是最好的老師，只有真正動手，才能把之前學的知識融會貫通。

建議分三個階段來做。

剛開始可以做一些純前端的小工具和小應用，不需要後端和資料庫，難度最低，重點是跑通 AI 程式設計的完整流程。比如個人作品集網站、線上簡歷生成器、記賬工具、番茄鍾、Markdown 編輯器這類。

有了幾個小專案的基礎後，可以挑戰包含前端頁面、後端介面、資料庫、使用者認證的完整全棧應用了。比如部落格系統、線上商城、社群論壇這類。

當你全棧專案做得比較熟練了，就可以挑戰更復雜的專案了。比如在專案中接入 AI 大模型 API，做 AI 對話、AI 內容生成、AI 知識庫、AI 資料分析等功能。還可以對接各種第三方服務，比如 Stripe 國際支付、物件儲存、簡訊服務、內容稽核等。

![](https://pic.yupi.icu/1/1778558955839-01e86b7c-4a9e-4438-9c93-1157a53a59f4.png)

如果你想體系化地學習，可以跟著我的專案教程做。我在 [程式設計導航](https://www.codefather.cn/post/1797431216467001345) 上有近 30 套保姆級專案教程，含簡歷寫法和麵試題解，覆蓋了從 AI 程式設計專案到傳統程式設計專案的各種型別。

## 五、進階提升

做了幾個完整專案後，你已經是一個有實戰經驗的 AI 程式設計開發者了。接下來可以根據自己的目標，選擇性地深入學習，不用全學完。

1）AI 程式設計經驗技巧

這些技巧都是在大量實戰中沉澱下來的，能讓你的效率翻倍，包括對話技巧、程式碼質量保障、程式碼重構、效能最佳化、安全防護、網站美化等方面。

特別要注意，用 AI 程式設計時間長了後，你會遇到一些 **系統性的失敗模式**。比如上下文漂移、功能倒退、架構退化、依賴膨脹等。識別這些模式能幫你提前防範，而不是等問題嚴重了才去補救。

![](https://pic.yupi.icu/1/10_AI%E7%BC%96%E7%A8%8B%E7%B3%BB%E7%BB%9F%E6%80%A7%E5%A4%B1%E8%B4%A5%E6%A8%A1%E5%BC%8F_compressed_v1.png)

2）上下文工程

這是進階版的上下文管理。包括上下文預算設計（哪些資訊常駐、哪些按需載入）、決策日誌（把踩過的坑記錄下來防止重複犯錯）、視窗管理策略（什麼時候該開新對話、什麼時候該沉澱文件）等。

![](https://pic.yupi.icu/1/11_%E4%B8%8A%E4%B8%8B%E6%96%87%E5%B7%A5%E7%A8%8B%E6%A0%B8%E5%BF%83%E6%96%B9%E9%9D%A2_compressed_v1.png)

3）成本管理

同樣一個任務，有人花 1 元，有人花 10 元，這就是真金白銀的區別。

比如根據任務選擇模型、精簡規則檔案、合理使用工具等等。

![](https://pic.yupi.icu/1/12_AI%E7%BC%96%E7%A8%8B%E6%88%90%E6%9C%AC%E7%AE%A1%E7%90%86%E7%AD%96%E7%95%A5_compressed_v2.png)

4）程式設計技術基礎

有了程式設計基礎能更好地和 AI 協作。不需要系統學完一門語言，但需要對常見技術棧有基本認知，知道這些技術分別是什麼、能幹什麼，這樣在和 AI 對話時能更準確地表達需求。

![](https://pic.yupi.icu/1/13_%25E7%25BC%2596%25E7%25A8%258B%25E6%258A%2580%25E6%259C%25AF%25E5%259F%25BA%25E7%25A1%2580%25E8%25AE%25A4%25E7%259F%25A5%25E5%259B%25BE_compressed_v2.png)

5）AI 大模型原理入門

搞懂大模型的基本原理，能幫你更好地駕馭 AI，知道它擅長什麼、不擅長什麼。

比如瞭解 Token 和分詞、上下文視窗、溫度引數，通俗理解 Transformer 和注意力機制，知道為什麼會出現幻覺、為什麼有上下文長度限制。

![](https://pic.yupi.icu/1/14_AI%25E5%25A4%25A7%25E6%25A8%25A1%25E5%259E%258B%25E5%258E%259F%25E7%2590%2586%25E5%2585%25A5%25E9%2597%25A8%25E6%25A6%2582%25E5%25BF%25B5_compressed_v2.png)

想做專業 AI 應用或從事 AI 應用開發崗位的話，可以學 LangChain 等 AI 開發框架、RAG 檢索增強生成、AI Agent 智慧體開發、MCP 服務開發。

## 六、持續學習
