# AI 命令列程式設計工具

> 更高效、更極客的 Vibe Coding 方式



你好，我是魚皮。

在前面的文章中，我們學習了 AI 零程式碼平臺和 AI 程式碼編輯器。隨著你使用 Vibe Coding 越來越多，可能會遇到一些特殊場景：

- 我想在伺服器上直接開發，但伺服器沒有圖形介面......
- 我想寫個指令碼自動化處理任務，怎麼讓指令碼操作 Cursor 呢？
- 我想讓 AI 批次處理幾十個檔案，但在 Cursor 裡操作太麻煩......

如果你有這些需求，那麼 **命令列 AI 程式設計工具** 可能就是你要找的答案。

命令列工具沒有花哨的介面，只有簡潔的文字互動。但正是這種極簡，讓它們擁有了極致的效率和靈活性。

![](https://pic.yupi.icu/1/image-20260429110454017-20260430230948435.png)

這篇文章，我會重點介紹 Claude Code 這個最火的命令列 AI 程式設計工具，並分享更多值得關注的命令列 AI 程式設計工具。



## 一、什麼是命令列 AI 程式設計工具？

在學習具體工具之前，我們先來搞清楚：命令列工具和程式碼編輯器有什麼區別？

AI 程式碼編輯器是有圖形介面的軟體，你可以看到檔案列表、程式碼高亮、按鈕等等。而命令列工具完全在終端裡執行，只有文字輸入和輸出，幾乎沒有任何圖形介面。

打個比方，AI 程式碼編輯器像開自動擋汽車，有方向盤、儀表盤、各種按鈕；命令列工具像開手動擋賽車，只有最核心的控制，但速度更快、更靈活。



### 命令列工具的優勢

為什麼有些開發者更喜歡命令列工具？

首先是速度快，不需要載入圖形介面，啟動速度極快，而且全鍵盤操作效率更高。資源佔用也很少，因為沒有圖形介面，記憶體和 CPU 佔用都很低，在配置一般的電腦上也能流暢執行。

命令列工具特別適合自動化。可以寫指令碼批次處理任務，或者整合到自動化流程中，這是圖形介面工具很難做到的。

此外，如果需要遠端開發，透過 SSH 連線到伺服器，可以直接在伺服器上用命令列工具開發。

說實話，在黑色終端裡敲命令，看著程式碼自動生成，確實很酷。



### CLI 在 AI 時代的新角色

你可能會好奇，都什麼年代了，命令列這種最古老的互動方式，怎麼突然又火了？

事實上，最近網際網路大廠的風向變了。Google 率先開源了 Workspace CLI，緊接著短短一週之內，飛書、釘釘、企業微信不約而同地在 GitHub 上開源了自己的 CLI 工具。

![](https://pic.yupi.icu/1/image-20260407142441568.png)

為什麼這些大廠不去卷更漂亮的介面，反而集體開起了倒車？

答案就 2 個字：**AI**。

大廠們不是在給人類做 CLI，而是在給 AI 做 CLI。

**CLI 就是 AI 的母語。** AI 大模型從誕生那天起就在學習海量的程式碼、命令列操作、終端輸出。讓它讀一行命令、執行一個操作，跟喝水一樣自然。反過來，你讓 AI 去操作一個圖形介面那可就難了 —— 要開啟瀏覽器、等頁面載入、找到按鈕、處理一堆網頁元素，中間有大量和內容無關的干擾資訊。

有人做過測試，讓 AI 透過瀏覽器完成真實任務，成功率只有 35.8%；換成 CLI 來完成同樣的任務，成功率接近 100%！

所以你會看到一個很有意思的現象。以前大廠做產品，想方設法把 UI 做得好看好用，給人類使用。現在是返璞歸真，**面向 AI 做產品，給 AI 使用，越簡單直接越好**。誰先把自己的產品 CLI 化，誰就能先被 AI Agent 接入，誰就能在 AI 時代繼續保持競爭力。

國外科技博主甚至寫了一篇文章叫《CLI is the new API》，引起了很大反響。意思是以前產品之間的互通靠 API，現在 AI 時代產品和 AI 之間的互通靠 CLI。

說到這裡，你可能會問：之前很火的 MCP 不也是連線 AI 和工具的協議嗎？為什麼還需要 CLI？

MCP 協議要求把所有工具的名稱和引數格式全部注入到 AI 的上下文裡，工具一多 Token 消耗就很誇張。有機構做過基準測試，同樣的任務，MCP 的 Token 消耗可能是 CLI 的幾十倍！

![](https://pic.yupi.icu/1/image-20260407123223554.png)

而且 MCP 的執行過程對人類來說就像個黑盒，出了問題很難排查；CLI 就不一樣了，如果出錯了，直接把命令複製到終端裡跑一遍，報錯資訊一目瞭然。

當然這不是說 MCP 就過時了，在需要統一許可權管控的企業場景下，MCP 的標準化鑑權規範依然很有價值。而且 Cursor 最近就上線了按需載入 MCP 的功能，不再一股腦把所有工具定義塞進上下文，而是等 AI 需要用到某個工具時再載入，大大減少了 Token 消耗。



### 適合哪些人？

如果你熟悉終端操作、追求極致效率、需要遠端開發、或者喜歡極簡風格，那命令列工具就很適合你。

如果你對終端還不太熟悉，建議先用 Cursor 這種 AI 程式碼編輯器練習一段時間，等對 Vibe Coding 有了足夠的理解，再來嘗試命令列工具。



## 二、Claude Code 最強大的命令列工具

[Claude Code](https://claude.com/product/claude-code) 是 Anthropic 公司推出的官方命令列 AI 程式設計工具，直接整合了 Claude 模型。它是目前功能最強大的命令列程式設計工具之一。

![](https://pic.yupi.icu/1/image-20260107153527087.png)

Claude Code 最厲害的是它的自主執行能力 —— AI 不僅能生成程式碼，還能自動執行命令、修改檔案、安裝依賴，真正做到 “說一句話，專案就搭好了”。

Claude Code 內建了安全審查功能，在執行危險操作前會先詢問你，防止誤操作。它還能理解整個專案的結構和上下文，修改程式碼時會考慮到專案的整體一致性。

特別值得一提的是，Claude Code 支援 **Claude Skills**。這是一種給 AI 準備的能力擴充套件包。你可以把它理解成給新同事準備的工作交接文件，裡面包含任務執行方法、工具使用說明、模板素材等。

比如你可以建立一個 `公司程式碼規範 Skill`，把程式碼風格、命名規則、註釋要求等寫進去。之後 Claude Code 生成的程式碼就會自動遵循這些規範，不用每次都重複說明。

Skills 的核心價值在於：人提供專業知識和方法論，AI 提供智慧。這對於快速驗證想法、打造內部工具來說，是極大的效率提升。



### 怎麼使用 Claude Code？

讓我用一個實際例子來演示 Claude Code 的使用流程。

0）首先確保你的電腦有 Node.js 環境和 npm 軟體依賴安裝工具，沒有的話，直接到 [Node 官網](https://nodejs.org/en/download) 下載傻瓜式安裝包就好：

![](https://pic.yupi.icu/1/1777341714221-67b76f0e-c816-410b-adc0-e445074efc46-20260430231040061.png)

1）開啟終端，輸入一行命令安裝 Claude Code：

```bash
npm install -g @anthropic-ai/claude-code
```

2）然後執行 `claude` 命令開啟程式，預設是需要登入 Claude 賬號的，而且 Claude Code 對中國地區有訪問限制，直接訪問 Anthropic 官網或使用 Claude 的 API 可能會被遮蔽，真狗！

![](https://pic.yupi.icu/1/1764145940075-ace6fd24-a09c-41c0-b400-1cffc394fc8a.png)

除了訪問限制之外，Claude Code 還有大規模封號的歷史，而且它在客戶端裡藏了一套隱蔽的使用者標記系統來識別中國使用者，想搞清楚原理和風險的同學可以閱讀本板塊「Claude Code」目錄中的《Claude Code 封號機制和應對方案》。

不過沒關係，可以把 Claude Code 背後的 AI 大模型 API 配置改成國產大模型的 API，比如智譜的 GLM。

3）進入 `{使用者目錄}/.claude` 目錄，建立一個 `settings.json` 配置檔案：

![](https://pic.yupi.icu/1/1764146110361-06e13de5-7de4-4fc5-9533-3651447d5e19.png)

4）修改配置檔案中的內容如下，記得替換成你自己的 API Key。

可以在 [智譜 AI 開放平臺](https://open.bigmodel.cn) 獲取到 API Key，注意不要洩露！

![](https://pic.yupi.icu/1/1764146125955-3029843c-26b8-4628-b2b7-a9d8abb2aef1.png)

```json
{
    "env": {
        "ANTHROPIC_AUTH_TOKEN": "your_zhipu_api_key",
        "ANTHROPIC_BASE_URL": "https://open.bigmodel.cn/api/anthropic",
        "API_TIMEOUT_MS": "3000000",
        "CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC": 1
    }
}
```

5）接下來就可以愉快地使用了。在專案目錄下執行 `claude`，就可以開始對話：

![](https://pic.yupi.icu/1/1764146174167-3018c8f3-0ad9-4a4f-9764-246f33b33203.png)

6）就讓 AI 做個實用的圖片壓縮小工具吧，提示詞如下：

```markdown
請生成一個《圖片壓縮工具》網站，實現圖片壓縮處理功能。需要包含完整的前端和後端程式碼，要求專案可以正常執行。

需要實現的功能：
1. 支援常見圖片格式（JPG、PNG、WebP 等）的上傳與壓縮
2. 可設定壓縮質量（如高 / 中 / 低或自定義百分比）
3. 顯示原始圖片與壓縮後圖片的對比（尺寸、大小、預覽圖）
4. 壓縮完成後提供下載按鈕，支援批次處理

設計要求：
1. 現代簡約風格，主色調使用綠色
2. 響應式佈局，在手機和桌面裝置上均有良好體驗
3. 上傳區域有明顯的拖放提示，操作流程直觀清晰
```

7）點選執行後，大模型很快給出了任務規劃 —— 先搭建後端、再實現前端、前後端聯調、最後測試執行：

![](https://pic.yupi.icu/1/1759250070544-7ede700d-37f2-4e4a-bfdb-01631f10df34.png)

不到 5 分鐘，AI 就完成了任務，而且還自動幫我安裝好了依賴，貼心~

![](https://pic.yupi.icu/1/1759250293957-36299a39-fff9-4e5d-a23a-299efd854938.png)

我們開啟瀏覽器訪問 `localhost:3000` 就能看到效果了：

![](https://pic.yupi.icu/1/1759291145587-14fb0214-53c7-45a8-8ad1-949368363e19.png)

整個過程中，Claude Code 會自動執行命令、建立檔案、修改程式碼，你只需要用自然語言描述需求就行。爽的一批！



### Claude Code 的優缺點

除了前面提到的自主執行能力和 Skills 支援，Claude Code 還有很多其他優勢。

比如它支援多種程式語言，不僅是 JavaScript / TypeScript，Python、Go、Rust 等都支援。專案理解能力也很強，能自動分析專案結構，理解各個檔案之間的關係。在修改程式碼時，會考慮到整個專案的一致性。

缺點大家也知道了，Claude Code 使用 Anthropic 的 API，按 Token 計費，詳細的價格資訊建議檢視 [Anthropic 官方定價文件](https://www.anthropic.com/pricing)。不過如果你經常需要開發複雜的新專案、寫大量程式碼，Claude Code 的效率也值得這個成本。

💡 想要系統學習 Claude Code 的使用方法，可以看看 [官方的實戰教程](https://anthropic.skilljar.com/claude-code-in-action)。



### 切換第三方模型

Claude Code 雖然預設使用 Anthropic 的 Claude 模型，但它是支援切換第三方模型的。很多國產大模型（如 DeepSeek）都提供了相容 OpenAI 格式的 API，可以直接對接 Claude Code 使用。

推薦使用開源工具 **CC Switch** 來視覺化管理 Claude Code 的模型配置。它內建了 50 多個供應商預設，一鍵切換不同的模型供應商，不用自己手動改配置檔案。

> 開源指路：https://github.com/farion1231/cc-switch

![](https://pic.yupi.icu/1/1777343334412-73a61961-5d7e-4fbb-a0e0-691f5d867b48-20260430231155296.png)

以切換 DeepSeek V4 為例，操作步驟如下：

1. 安裝 CC Switch（Mac 使用者可透過 Homebrew 安裝）
2. 執行軟體，新增 DeepSeek 供應商
3. 填寫從 DeepSeek 開放平臺獲取的 API Key
4. 設定主模型為 DeepSeek-V4-Pro（Agent 能力和複雜推理更強）
5. 儲存並啟用，重新進入 Claude Code 即可使用

![](https://pic.yupi.icu/1/1777343299981-c370c8ff-b24a-460a-891e-e08bc1efcf54-20260430231211935.png)

透過 CC Switch，你還可以在 DeepSeek、小米 MiMo 等多個國產模型之間自由切換，按需選擇最合適的模型。關於用 Claude Code + DeepSeek V4 開發完整專案的實戰經驗，可以閱讀本教程專案實戰板塊「AI 創意應用」分類中的《Claude Code - AI 提肛助手專案實戰》。



## 三、其他值得關注的命令列工具

除了 Claude Code，還有一些其他的命令列工具也值得了解。



### Gemini CLI

[Gemini CLI](https://geminicli.com/) 是 Google 推出的開源命令列工具，整合了 Gemini 模型。最大的優勢是有免費額度，而且支援超長上下文（100 萬 Token），可以一次性分析整個大型專案。適合想嘗試命令列工具，但預算有限、需要分析大型專案的開發者。

它採用 ReAct（推理和行動）迴圈，AI 會先思考再行動，處理複雜任務的能力比較強。而且支援 MCP（Model Context Protocol），可以連線各種外部工具和服務。

用法跟 Claude Code 類似，也是一行命令就能安裝：

```bash
npm install -g @google/gemini-cli
```

然後輸入 `gemini` 就能執行了：

![](https://pic.yupi.icu/1/image-20260107154410787.png)



### Warp

[Warp](https://www.warp.dev) 是一個現代化的終端工具，它不僅是終端，還整合了程式碼編輯器和 AI 助手，三位一體。

個人體驗下來，Warp 的介面比 Claude Code 更易用，支援 AI 命令建議和團隊協作功能。

如果你經常在終端裡工作，又想要更好的互動體驗，Warp 是個不錯的選擇。它能讓你在享受命令列效率的同時，不用完全放棄圖形介面的便利。

![](https://pic.yupi.icu/1/image-20260107154658863.png)



### GitHub Copilot CLI

GitHub Copilot 是微軟推出的 AI 程式設計助手，已經被數百萬開發者使用。[GitHub Copilot CLI](https://github.com/features/copilot/cli) 是它的命令列版本，可以在終端裡使用 AI 輔助。

它與 GitHub 深度整合、支援 MCP 協議、可以生成和解釋命令。

![](https://pic.yupi.icu/1/image-20260107154809001.png)

如果你已經在用 GitHub Copilot 做程式碼補全，那麼 Copilot CLI 能讓你在終端裡也享受到類似的 AI 輔助，特別適合需要頻繁執行命令的場景。



### OpenCode

[OpenCode](https://opencode.ai) 是最近非常火的開源命令列 AI 程式設計工具，被稱為 “Claude Code 的開源版”。

OpenCode 最大的優勢是 **完全免費開源**，相比 Claude Code，OpenCode 不需要付費訂閱，也沒有地區限制，對國內使用者特別友好。

它提供直觀的終端介面、會話管理、自定義命令等功能。而且支援多模型自由切換，包括 Claude、GPT、Gemini、DeepSeek 等。你可以根據不同任務選擇最合適的模型，不用被單一模型限制。

如果你想嘗試命令列 AI 程式設計，但不想付費，OpenCode 是最佳選擇。

用法很簡單，直接一行命令安裝：

```bash
curl -fsSL https://opencode.ai/install | bash
```

然後執行 `opencode` 命令就可以愉快使用了：

![](https://pic.yupi.icu/1/image-20260107155212400.png)

這個互動比 Claude Code 舒服很多~

![](https://pic.yupi.icu/1/image-20260107155206368.png)



### 怎麼選擇命令列 AI 工具？

選擇命令列 AI 工具主要看你的需求和預算。

- 如果追求最強功能和最好的體驗，選 Claude Code。它的自主執行能力、Skills 支援、專案理解能力都是最強的，適合專業開發者和複雜專案。不過需要付費，而且國內需要配置國產大模型 API。
- 如果想完全免費使用，選 OpenCode。它是開源的，支援多模型切換，功能接近 Claude Code，而且沒有地區限制。對於預算有限的學生和個人開發者來說，OpenCode 是最佳選擇。
- 如果需要超長上下文分析大型專案，選 Gemini CLI，它支援 100 萬 Token 上下文，可以一次性分析整個大型專案，而且有免費額度。
- 如果需要更好的終端體驗，選 Warp。它把終端、編輯器和 AI 三合一，介面現代化，適合不想完全放棄圖形介面的開發者。
- 如果已經在用 GitHub Copilot，就選 Copilot CLI，可以無縫銜接你現有的工作流程。

根據不同任務選擇最合適的工具，效率最高。

我自己主要用 Claude Code + 配置國產模型來快速搭建中小型專案、或者進行檔案批處理操作。當然，作為一名 AI 程式設計博主，也會嘗試各種不同的命令列工具，反覆橫跳。



### CLI 開源生態

除了上面這些 AI 程式設計工具，CLI 的開源生態也在快速發展。目前飛書、釘釘、企業微信、Google 等大廠的 CLI 基本都覆蓋了訊息、日曆、文件、通訊錄等核心業務，而且都內建了 AI Agent Skills，可以直接被 Claude Code、Cursor 等 AI 工具呼叫。

![](https://pic.yupi.icu/1/image-20260407141854598.png)

除了大廠官方出品，社群裡也湧現了很多有意思的專案。

比如 [OpenCLI](https://github.com/jackwener/opencli) 能把任意網站、Electron 應用、甚至本地工具統統變成命令列介面。如果你想讓 AI 幫你查 B 站熱門、知乎熱榜，裝上 OpenCLI 後輸入一行命令就搞定了。它內建了幾十個介面卡，覆蓋了 B 站、知乎、Twitter、Reddit 等一大堆平臺，就像給 AI 裝了一個萬能遙控器。

![](https://pic.yupi.icu/1/image-20260403143000224.png)

還有 [CLI-Anything](https://github.com/HKUDS/CLI-Anything)，它能自動分析一個開源軟體的原始碼，找出每個功能背後的 API 邏輯，然後自動生成對應的 CLI 命令。有了它，幾乎任何軟體都能被快速 CLI 化，非常適合給 AI 呼叫。

## 四、命令列工具實戰技巧

無論你選擇哪個命令列工具，下面這些技巧都能幫你提升效率。



### 1、善用別名

在 `.bashrc` 或 `.zshrc` 中設定別名，快速啟動工具。

比如：

```bash
alias cc="claude"
alias gc="gemini"
alias oc="opencode"
```

這樣只需要輸入 `cc` 就能啟動 Claude Code，輸入 `gc` 就能啟動 Gemini CLI，輸入 `oc` 就能啟動 OpenCode。雖然只是少打幾個字母，但對於頻繁使用的開發者來說，也能節省時間。



### 2、建立專案配置檔案

在專案根目錄建立配置檔案，告訴 AI 專案的規範。

Claude Code 會自動讀取專案根目錄的 `CLAUDE.md` 檔案，這是官方推薦的配置檔名。你可以在裡面寫上專案的規範、常用命令、核心檔案說明等：

```markdown
# 專案規範

- 使用 TypeScript
- 遵循 Airbnb 程式碼規範
- 所有函式必須有型別註解
- 使用 ESLint 和 Prettier

# 常用命令

- npm run dev：啟動開發伺服器
- npm run build：構建生產版本
- npm test：執行測試
```

這樣 AI 生成的程式碼就會自動遵循這些規範。而且可以把 `CLAUDE.md` 檔案提交到 Git，團隊成員共同維護，讓 AI 越來越懂你的專案。



### 3、分步驟執行

不要一次性提出太複雜的需求，而是分步驟來：

- 先建立基本的專案結構
- 然後新增功能
- 再最佳化細節

這樣更容易控制進度，也更容易發現和修復問題。



### 4、結合其他命令

命令列工具可以和其他命令結合使用。比如可以把一個命令的輸出結果儲存到檔案，然後讓 AI 讀取：

```bash
# 把 git diff 輸出儲存到檔案
git diff > changes.txt

# 然後在 Claude Code 中引用這個檔案
# 在對話中說：根據 @changes.txt 的改動生成提交資訊
```

或者寫指令碼批次處理任務，實現完全自動化的開發流程。

舉個例子，可以寫一個指令碼來自動遍歷所有檔案，並且讓 AI 新增註釋、最佳化程式碼等等。



### 5、Claude Code 創始人的神級技巧

Claude Code 的創始人曾多次分享使用技巧，這裡挑幾個最值得學習的：

1）並行多開提高效率：在終端中同時執行多個 Claude，將標籤頁編號，透過系統通知了解哪個需要人工輸入。還可以在網頁端 Claude Code 上執行多個例項，和本地 Claude 同時進行，充分利用等待時間。

更進階的方式是同時開 3 ~ 5 個 git worktree，每個跑一個 Claude 會話，互不干擾，還可以設定快捷鍵一鍵切換，或者專門留一個 worktree 只用來看日誌跑查詢。

2）善用計劃模式：複雜任務一定要先讓 Claude 進入計劃模式，把心思花在打磨計劃上，計劃到位了 Claude 基本能一次性搞定。一旦感覺方向不對，別硬推，立刻切回計劃模式重新來。優先使用帶思考功能的模型，雖然比較慢，但在工具使用方面更出色，長遠來看效率更高。

3）團隊維護 CLAUDE.md 檔案：把檔案用 Git 管理，團隊成員共同維護。每次糾正 Claude 的錯誤，順手讓它把這條經驗更新到 CLAUDE.md 中，這樣 Claude 下次就知道不要這樣做了，時間久了出錯率會明顯下降。

4）封裝技能和斜槓命令：重複的事情就封裝成技能或斜槓命令，用 Git 管理，跨專案複用。比如搞個 `/techdebt` 命令每次會話結束跑一下清理重複程式碼，或者建立 `/commit-push-pr` 命令一次性完成提交、推送和建立 PR。

5）使用 MCP 工具擴充套件功能：比如 Slack 搜尋和釋出內容、執行 BigQuery 查詢、從 Sentry 獲取錯誤日誌等。創始人說他半年沒手寫過一行 SQL 了，全靠 AI 用命令列直接查資料庫做分析。

6）完善反饋驗證機制：別光讓 Claude 幹活，還要讓它知道怎麼驗證自己的工作。比如讓它開啟瀏覽器測試 UI，發現問題後自動迭代，直到功能正常執行。

7）提示詞要更有創意：比如讓 Claude 當考官 "先考考我這些改動理解對不對，我過了再提 PR"，或者說 "根據你現在掌握的所有資訊，推翻重來，給我個更優雅的方案"，還可以讓它對比 main 和功能分支的差異，往往能得到更好的結果。

8）使用子代理（Subagents）：想讓 Claude 更快完成任務的時候，在請求後面加一句 "use subagents"，把獨立的小任務丟給子代理處理，主代理的上下文就能保持乾淨。還可以用鉤子（Hooks）把許可權請求轉給高階模型，讓它判斷安不安全、自動批准。

9）選擇合適的終端環境：推薦試試語音輸入（macOS 按兩下 fn 就能用），因為說話比打字快 3 倍，描述需求時會寫得更詳細，AI 理解也更準確。還可以用 `/statusline` 定製狀態列顯示上下文用量和當前分支。

10）靠 Claude 學習新東西：在配置中開啟 "解釋型" 輸出風格，讓它講清楚每個改動背後的原因。還可以讓它生成 HTML 幻燈片講解陌生程式碼，或者畫 ASCII 圖解釋協議和架構，把 AI 當成你的 1 對 1 導師。



### 6、動手開發 CLI 工具

前面我們介紹了很多現成的 CLI 工具，其實你完全可以自己動手做一個。如果你有自己的產品或工具，做個 CLI 能讓使用者透過 AI 更方便地使用。

這裡重點介紹一個開發 CLI 的寶藏技術 —— **React Ink**。

前段時間 Claude Code 的原始碼意外洩露，我扒了一下發現，它就是用 React Ink 開發的。簡單來說，我們平時用 React 寫網頁，React 會把元件渲染成瀏覽器裡的頁面。而 React Ink 做的事情是把同樣的 React 元件渲染成終端介面。這個庫在 GitHub 上已經有幾萬 Star，Gatsby CLI、Prisma CLI 等知名專案都在用，非常成熟。

> 開源指路：https://github.com/vadimdemedes/ink

![](https://pic.yupi.icu/1/image-20260401124426974.png)

舉個例子，比如編寫下面這段程式碼，就能渲染出一個簡易的終端介面，會顯示一個每秒自動加 1 的計數器：

![](https://pic.yupi.icu/1/image-20260407144127215.png)

瞭解了 React Ink 之後，我們用它來做一個 CLI 試試。以我的程式設計導航為例，這是一個程式設計師學習交流社群。做成 CLI 工具之後，使用者就可以直接在終端裡搜尋程式設計教程、檢視熱門內容，也方便 AI Agent 呼叫。

整個開發過程其實就跟寫網頁差不多，簡單的 CLI 工具直接讓 AI 一把梭就行。

先編寫給 AI 的提示詞：

```markdown
幫我用 React Ink 開發一個名為 codefather-cli 的命令列工具，實現以下功能：

1）codefather search <關鍵詞>
獲取程式設計導航搜尋結果 https://www.codefather.cn/search/all?searchText=<關鍵詞>
在終端中展示搜尋結果列表，包括標題、作者、點贊數

2）codefather hot
獲取程式設計導航熱榜 https://www.codefather.cn/hot/all_hot
在終端中展示熱榜 TOP20，包括排名、標題、作者、熱度

要求：支援 --help 檢視幫助資訊
```

把這段提示詞丟給 Claude Code 或者 Cursor 等 AI 程式設計工具，AI 就能幫你生成完整的專案程式碼。

![](https://pic.yupi.icu/1/image-20260407144535296.png)

最終執行效果大概長這樣，還不錯吧~

![](https://pic.yupi.icu/1/image-20260407150349886.png)

可以試試讓 AI 使用這個工具，AI 透過 `--help` 就能快速瞭解這個工具怎麼用，準確地給出了回答，嘎嘎快！

![](https://pic.yupi.icu/1/image-20260407150632856.png)

這就是 CLI 的魅力，對人類來說是一個好用的效率工具，對 AI 來說更是一個天然的操作介面。



### 7、上手試試飛書 CLI

如果你想直觀感受一下現代 CLI 的使用體驗，可以試試最近飛書開源的 [Lark CLI](https://www.feishu.cn/feishu-cli)，這個工具可以讓你在終端裡直接操作飛書的訊息、日曆、文件等功能。

![](https://pic.yupi.icu/1/image-20260407141759722.png)

首先輸入一行命令安裝：

```bash
npm install -g @larksuite/cli
```

![](https://pic.yupi.icu/1/image-20260407113800957.png)

裝好之後，先配置一下應用資訊：

```bash
lark-cli config init --new
```

![](https://pic.yupi.icu/1/image-20260407125520107.png)

開啟連結配置飛書 CLI 應用：

![](https://pic.yupi.icu/1/image-20260407125551163.png)

建立應用成功後，需要登入授權，按需選擇你允許透過 CLI 操作的業務：

```bash
lark-cli auth login
```

![](https://pic.yupi.icu/1/image-20260407125833469.png)

跟著 CLI 的引導一步步操作就好：

![](https://pic.yupi.icu/1/image-20260407130308162.png)

授權過程中，記得要在飛書管理後臺稽核應用：

![](https://pic.yupi.icu/1/image-20260407130344599.png)

稽核應用透過後，可以再重新執行登入命令，直到你看到"授權成功"：

![](https://pic.yupi.icu/1/image-20260407130807612.png)

之後，你就可以用命令列來操作飛書了。

比如檢視今天的日程安排：

```bash
lark-cli calendar +agenda
```

![](https://pic.yupi.icu/1/image-20260407131112596.png)

檢視我的待辦任務：

```bash
lark-cli task +get-my-tasks
```

![](https://pic.yupi.icu/1/image-20260407141253773.png)

甚至直接建立一篇文件：

```bash
lark-cli docs +create --title "週報" --markdown "# 本週進展"
```

![](https://pic.yupi.icu/1/image-20260407131334934.png)

以前這些操作你要開啟飛書 App，點好幾下才能完成，現在一行命令就搞定了。

CLI 有這麼多命令和引數，使用過程中，如果忘了某個命令怎麼用，怎麼辦呢？只需要記住一個萬能口訣：**不會就加 `--help`**。

```bash
lark-cli --help
lark-cli calendar --help
```

![](https://pic.yupi.icu/1/image-20260407131533712.png)

你可以透過這個例子直觀感受 CLI 的高效和便捷，體會一下為什麼大廠都在卷 CLI。



## 寫在最後

看到這裡，相信你已經對命令列 AI 程式設計工具有了全面的瞭解。

如果你覺得 Cursor 已經夠用了，完全可以繼續用 Cursor。命令列工具更適合追求極致效率、喜歡極簡風格的開發者，或者有遠端開發、自動化處理等特殊需求的場景。
