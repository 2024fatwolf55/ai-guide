## 一、MCP 伺服器類

MCP 的全稱是 Model Context Protocol 模型上下文協議。簡單來說，就是讓 AI 大模型能夠連線外部工具和資料來源的一個開放標準。

打個比方，MCP 就像是 AI 的 USB-C 介面，原本 AI 只能根據訓練資料來回答問題、生成程式碼，但有了這個統一介面，它就能連線各種外部工具，比如開啟瀏覽器看網站、搜尋並抓取網頁內容、部署專案到雲端、訪問資料庫等等，能力一下子就豐富起來了。

![](https://pic.yupi.icu/1/%E6%BC%AB%E7%94%BB%E5%9B%BE1%E5%A4%A7.jpeg)



### ⭐️ Firecrawl MCP 網頁內容抓取

首先要介紹的是 [Firecrawl MCP](https://www.firecrawl.dev/)，讓 AI 能夠自動抓取和理解網頁內容。

我在開發專案時經常需要從網上獲取參考資料、閱讀官方文件和技術部落格，或者分析競品的功能實現。如果人工來做這件事，需要先開啟網站、再手動複製貼上內容，或者自己寫個爬蟲指令碼，麻煩得一批。

有了 Firecrawl MCP，這事兒就簡單多了。我直接在 AI 程式設計工具中跟 AI 說：

- 幫我獲取這個網站的內容
- 幫我讀一下這個文件
- 幫我從網上搜尋 XX 相關的資訊

它就能自動把網頁的內容、結構、甚至是動態載入的資料都給我抓下來。

![](https://pic.yupi.icu/1/image-20260116105912027.png)



**如何使用？**

首先你需要在 [Firecrawl 官網](https://www.firecrawl.dev/app/api-keys) 註冊賬號，並建立一個呼叫服務的 API Key。

![](https://pic.yupi.icu/1/image-20260116105955795.png)

然後進入到 AI 程式設計工具中配置一下 MCP 伺服器。這裡我以 Cursor 為例，其他 AI 程式設計工具對接 MCP 的方法可以看各自的官方文件，比如 [Claude Code 接入 MCP 文件](https://docs.anthropic.com/en/docs/claude-code/mcp)。

開啟 Cursor 設定，找到 Tools & MCP，點選 `+ New MCP Server`。

![](https://pic.yupi.icu/1/image-20260116110425690.png)

本質上就是修改 MCP 配置檔案，新增這樣的配置：

```json
{
  "mcpServers": {
    "firecrawl-mcp": {
      "command": "npx",
      "args": ["-y", "firecrawl-mcp"],
      "env": {
        "FIRECRAWL_API_KEY": "你的API金鑰"
      }
    }
  }
}
```

![](https://pic.yupi.icu/1/image-20260116110454499.png)

這段配置的意思是：透過 npx 命令來執行 firecrawl-mcp 這個工具，並且把你的 API 金鑰傳給它。如果你電腦上還沒有安裝 npx，需要先 [到官網安裝 Node.js](https://nodejs.org/zh-cn)，npx 會隨著 Node.js 一起安裝。

配置好之後，看到綠色的成功點點，表示能夠正常使用了。

![](https://pic.yupi.icu/1/image-20260116110558199.png)

除了基礎的網頁抓取，Firecrawl MCP 還支援批次抓取整站內容、遞迴抓取網站的多層連結、失敗自動重試等高階功能。

類似的開源專案還有 [Crawl4AI](https://github.com/unclecode/crawl4ai)，定位是對大模型友好的爬蟲工具，同樣內建了 MCP Server 和 Agent Skills 技能包，可以作為 Firecrawl 的替代方案。



### Brave Search MCP 隱私搜尋

接下來是 [Brave Search MCP](https://github.com/brave/brave-search-mcp-server)，讓 AI 能夠進行注重隱私保護的網路搜尋。

在開發過程中，我經常需要讓 AI 幫我搜尋最新的技術資料、查詢某個庫的使用示例、或者瞭解某個技術問題的解決方案。傳統的做法是自己去搜尋引擎查，然後把結果複製給 AI，比較麻煩。

有了 Brave Search MCP，我直接跟 AI 說：

- 幫我搜尋一下 React 19 的新特性
- 查一下這個錯誤怎麼解決

它就能透過 Brave 搜尋引擎去找答案。而且 Brave 搜尋不會追蹤你的搜尋記錄，隱私保護做得很好。

![](https://pic.yupi.icu/1/image-20260116111803869.png)



**如何使用？**

首先去 [Brave Search API](https://brave.com/search/api/) 註冊賬號，然後進入 API Key 管理頁面，首先要選擇一個訂閱計劃。必須選擇免費版啊！每月有 2000 次查詢額度，對於個人開發來說夠用了。

![](https://pic.yupi.icu/1/image-20260116110947801.png)

但這裡比較坑的一點是，即使訂閱免費版，也要填寫付款方式，沒有海外銀行卡的朋友可以撤了。

訂閱成功後，建立 API Key：

![](https://pic.yupi.icu/1/image-20260116111311536.png)

拿到 API Key 後，在 Cursor 的 MCP 配置中新增：

```json
{
  "mcpServers": {
    "brave-search": {
      "command": "npx",
      "args": ["-y", "brave-search-mcp"],
      "env": {
        "BRAVE_API_KEY": "你的API金鑰"
      }
    }
  }
}
```

配置好後，AI 就能隨時幫你搜尋最新資訊了。

支援網頁、圖片、影片、新聞等多種型別的內容搜尋，甚至能搜尋本地商家資訊（比如附近的咖啡店）。

![](https://pic.yupi.icu/1/image-20260116111954334.png)

它還帶有 AI 摘要功能，能把搜尋結果自動總結成簡潔的答案。



### ⭐️ Context7 獲取最新文件

[Context7](https://context7.com/) 能幫 AI 獲取到最新的技術文件。

我們都知道，AI 的訓練資料是有截止時間的，比如 GPT-4 的知識可能只更新到 2023 年。這就導致一個問題，當你問 AI 關於某個框架最新版本的用法時，它給出的答案可能是過時的。

Context7 就是來解決這個問題的。它會自動從官方文件網站抓取最新的、特定版本的文件內容，然後提供給 AI。

![](https://pic.yupi.icu/1/image-20260116112229490.png)

這樣一來，AI 給出的程式碼示例和建議就是基於最新文件的，不會去用已經廢棄的寫法，大大提高了專案能正常執行的機率。



**如何使用？**

訪問 [Context7 Dashboard](https://context7.com/dashboard) 註冊賬號並獲取 API Key，個人使用是免費的。

![](https://pic.yupi.icu/1/image-20260116112322940.png)

然後在 MCP 配置中新增：

```json
{
  "mcpServers": {
    "context7": {
      "url": "https://mcp.context7.com/mcp",
      "headers": {
        "CONTEXT7_API_KEY": "你的API金鑰"
      }
    }
  }
}
```

之後你在 AI 程式設計工具中跟 AI 對話時，只要跟技術文件相關，或者主動提一嘴 "use context7"，它就會自動去獲取最新文件來回復你。

![](https://pic.yupi.icu/1/image-20260116112656483.png)



### Web to MCP 復刻網頁元件

[Web to MCP](https://web-to-mcp.com/) 是一個 Chrome 擴充套件，搭配 MCP 使用，能把網頁上的任何 UI 元件直接傳送給 AI，讓 AI 生成對應的程式碼，用最快的速度抄作業！

![](https://pic.yupi.icu/1/image-20260116113052973.png)

很多時候，我在瀏覽網站時看到一個不錯的 UI 元件，想讓 AI 幫我實現類似的效果。以前的做法是截圖，然後跟 AI 描述：“幫我做一個類似這樣的按鈕，圓角、漸變色、帶陰影……” 既費時又不準確。

有了 Web to MCP，我只需要在網頁上點選某個想復刻的元素：

![](https://pic.yupi.icu/1/image-20260116113725321.png)

它就會自動捕獲元件的 DOM 結構、CSS 樣式、甚至是互動效果，並且給你一個讓 AI 復刻元件的提示詞。

你只需要把提示詞傳送給 AI，AI 會呼叫 MCP 拿到完整的元件資訊，並生成程式碼來複刻元件。

![](https://pic.yupi.icu/1/image-20260116114142631.png)

相比於直接給 AI 模糊的截圖，生成的程式碼更準確了。

![](https://pic.yupi.icu/1/image-20260116114426822.png)



**如何使用？**

1）透過官網或者在 Chrome 應用商店搜尋 Web to MCP 來安裝擴充套件

![](https://pic.yupi.icu/1/image-20260116113138693.png)

2）用 Google 賬號登入，獲取你的 MCP 配置：

![](https://pic.yupi.icu/1/image-20260116113241575.png)

3）在 AI 程式設計工具的 MCP 配置中新增：

```json
{
  "mcpServers": {
    "web-to-mcp": {
      "url": "https://web-to-mcp.com/mcp/你的唯一ID"
    }
  }
}
```

之後瀏覽網頁時，點選擴充套件圖示，選中你想要的元件，就能直接在 AI 程式設計工具裡引用它，並且快速生成風格一致的程式碼了。



### Chrome DevTools MCP 瀏覽器除錯

[Chrome DevTools MCP](https://github.com/ChromeDevTools/chrome-devtools-mcp) 是 Chrome 官方團隊開發的 MCP 伺服器，讓 AI 能夠直接控制 Chrome 瀏覽器進行操作和除錯。

在做前端開發時，我經常需要除錯頁面、檢視網路請求、分析效能問題。以前這些都得手動在瀏覽器的開發者工具裡操作，現在有了這個工具，我可以直接讓 AI 幫我做這些事。

比如我跟 AI 說：“幫我分析當前這個網站載入慢的原因”，它就能開啟 Chrome DevTools，分析網路請求、檢視資源載入時間，然後告訴我哪裡有問題。

![](https://pic.yupi.icu/1/image-20260116115138719.png)

或者我說：“幫我測試一下這個表單提交功能”，它就能自動填寫表單、點選提交按鈕、檢視請求響應。

**如何使用？**

在 MCP 配置中新增：

```json
{
  "mcpServers": {
    "chrome-devtools": {
      "command": "npx",
      "args": ["-y", "chrome-devtools-mcp@latest"]
    }
  }
}
```

配置好後，AI 就能幫你自動化測試、除錯頁面了。工具會自動連線到你正在執行的 Chrome 瀏覽器，無需額外設定。

這個工具還支援元素定位、網路請求監控、效能分析、頁面截圖等功能，非常適合前端開發和測試。



### EdgeOne Pages MCP 一鍵部署

[EdgeOne Pages MCP](https://github.com/TencentEdgeOne/edgeone-pages-mcp) 是騰訊雲團隊開發的部署工具，能把你的專案一鍵部署到騰訊雲的加速網路，讓別人能訪問你的網站，並且給你的網站提速。

開發完專案後，你一定會想讓別人訪問你的網站。傳統的部署流程很繁瑣，需要人工打包程式碼、上傳程式碼到伺服器、配置域名、設定 HTTPS 安全證書，一套流程下來得花不少時間。

![](https://pic.yupi.icu/1/%E6%BC%AB%E7%94%BB%E5%9B%BE2%E5%A4%A7.jpeg)

有了 EdgeOne Pages MCP，我直接在 AI 程式設計工具裡跟 AI 說：“幫我部署這個專案”，它就能自動完成打包、上傳、部署的全過程，最後給我一個可以直接訪問的 URL。而且部署到全球加速網路，各地訪問速度都很快。

![](https://pic.yupi.icu/1/1752212029384-16cfba8f-babb-49c0-9d41-3b76ee78eecf.png)



**如何使用？**

首先到 [EdgeOne 控制檯](https://console.cloud.tencent.com/edgeone/pages) 開通 Pages 服務：

![](https://pic.yupi.icu/1/1752209404627-3a3193d9-4c94-4f80-ad02-435ff22f16ed.png)

然後獲取 API Token，作為呼叫服務的憑證：

![](https://pic.yupi.icu/1/1752209504079-6741bbd0-438e-48a4-86be-6eddfc3efa83.png)

在 MCP 配置中新增：

```json
{
  "mcpServers": {
    "edgeone-pages-mcp-server": {
      "command": "npx",
      "args": ["edgeone-pages-mcp"],
      "env": {
        "EDGEONE_PAGES_API_TOKEN": "你的API Token"
      }
    }
  }
}
```

配置好後，就能讓 AI 幫你一鍵部署專案了。部署是免費的，支援靜態網站、全棧專案、自動配置 HTTPS 和 CDN 加速等功能，非常適合個人專案和小型應用。

![](https://pic.yupi.icu/1/1752211869664-b74dc4d9-57b1-4bb7-9f02-703112b613eb.png)



### COS MCP 物件儲存

[COS MCP](https://github.com/Tencent/cos-mcp) 能讓 AI 直接操作騰訊雲物件儲存。

物件儲存就是雲端的檔案儲存服務，可以理解為雲盤。

![](https://pic.yupi.icu/1/image-20260116120009365.png)

在團隊協作開發中，我們經常需要讓 AI 參考一些專案規範文件、或者引用一些圖片。以前的做法是把這些檔案放在本地，然後手動上傳給 AI，既不方便，也不利於團隊維護、修改和共享。

有了 COS MCP，我可以說一句話把這些需要共享的檔案存到雲端，然後讓 AI 直接去讀取。

![](https://pic.yupi.icu/1/image-20260116122211103.png)

比如我跟 AI 說：“按照我們團隊 COS 共享的專案規範文件來寫這個功能”，它就能自動從 COS 裡讀取規範文件，然後按照規範來寫程式碼。

![](https://pic.yupi.icu/1/image-20260116122453843.png)



**如何使用？**

1）首先需要開通騰訊雲 COS 物件儲存服務。訪問 [騰訊雲 COS 控制檯](https://console.cloud.tencent.com/cos)，建立一個儲存桶（Bucket）：

![](https://pic.yupi.icu/1/image-20260116120711822.png)

2）然後在 "訪問管理" > "API 金鑰管理" 中獲取 SecretId 和 SecretKey，注意一定不要洩露這些資訊！

![](https://pic.yupi.icu/1/image-20260116121022222.png)

3）在 MCP 配置中新增：

```json
{
  "mcpServers": {
    "cos-mcp": {
      "command": "npx",
      "args": [
        "cos-mcp",
        "--Region=你的地域",
        "--Bucket=你的儲存桶",
        "--SecretId=你的SecretId",
        "--SecretKey=你的SecretKey"
      ]
    }
  }
}
```

![](https://pic.yupi.icu/1/image-20260116121243549.png)

配置好後，AI 就能讀取和管理你雲端的檔案了，相當於給了 AI 一個網盤。

此外，這個工具還支援圖片搜尋、圖片處理、文件轉換、影片封面生成等功能。

![](https://pic.yupi.icu/1/image-20260116121658701.png)




### GitHub MCP 程式碼倉庫管理

[GitHub MCP](https://github.com/github/github-mcp-server) 是 GitHub 官方開發的 MCP 伺服器，讓 AI 能夠直接操作 GitHub 程式碼倉庫。

程式設計師朋友們對 GitHub 肯定不陌生，這是全球最大的程式碼託管平臺，可以用它來儲存程式碼、團隊協作開發。

![](https://pic.yupi.icu/1/image-20260116122621938.png)

在日常開發中，我可能需要搜尋 GitHub 程式碼倉庫、建立 Issue 問題反饋、提交 PR 程式碼合併請求、檢視程式碼變更、分析提交歷史等等。以前這些操作都得在 GitHub 網站上手動完成，現在我可以直接讓 AI 幫我做。

比如我跟 AI 說：“我最近在 GitHub 上開源了哪些專案？star 數如何？”

![](https://pic.yupi.icu/1/image-20260116123701822.png)

它就能快速給我在 GitHub 上的專案生成一份資料包告：

![](https://pic.yupi.icu/1/image-20260116123734660.png)

或者我說：“幫我看看最近一週的程式碼變更”，它就能分析 Git 提交記錄，告訴我都改了什麼。

![](https://pic.yupi.icu/1/image-20260116124022290.png)



**如何使用？**

首先需要在 GitHub 獲取到你的 [Access Token](https://github.com/settings/tokens)，作為訪問你 GitHub 資源的憑證：

![](https://pic.yupi.icu/1/image-20260116122846165.png)

然後在 MCP 配置中新增：

```json
{
  "mcpServers": {
    "github": {
      "url": "https://api.githubcopilot.com/mcp/",
      "headers": {
        "Authorization": "Bearer 你的GitHub憑證"
      }
    }
  }
}
```

這個工具還支援程式碼分析、CI/CD 監控、安全掃描等功能，基本上你在 GitHub 中能做的事，AI 都能幫你做。

![](https://pic.yupi.icu/1/image-20260116123148068.png)



## 二、IDE 擴充套件外掛類

MCP 伺服器講完了，接下來聊聊 IDE 擴充套件外掛。

IDE 就是整合開發環境，簡單理解就是寫程式碼的軟體，比如 VS Code、JetBrains IDEA 這些，可以透過安裝外掛來增強編輯器的能力，讓你的開發體驗更上一層樓。

值得一提的是，現在很多有圖形介面的 AI 程式設計工具（比如 Cursor）都是基於 VS Code 開發的，自然也支援 VS Code 的外掛，所以下面我也主要分享 VS Code 外掛，裝上就能用。

![](https://pic.yupi.icu/1/image-20260116124127539.png)



### Claude Code 官方擴充套件

Claude Code 是 Anthropic 推出的 AI 程式設計助手，原本是獨立的命令列工具。而 [Claude Code VS Code 擴充套件](https://www.anthropic.com/news/enabling-claude-code-to-work-more-autonomously) 能讓你在程式碼編輯器中直接使用 Claude Code，不用額外開啟終端。

在 VS Code 或 Cursor 的擴充套件商店搜尋 "Claude Code" 即可安裝：

![](https://pic.yupi.icu/1/image-20260116124255886.png)

這個擴充套件的優點是提供了圖形介面，你可以透過側邊欄面板和 Claude 對話，能夠靈活輸入文字。

![](https://pic.yupi.icu/1/image-20260116124614180.png)

當 AI 修改程式碼時，你能在編輯器裡實時看到變化，並且自動顯示 diff 對比，讓你清楚地知道 AI 改了哪些地方。

![](https://pic.yupi.icu/1/image-20260116124700221.png)

我經常用它來重構程式碼、修復 Bug、新增新功能。它還支援多會話並行，也就是說你可以同時讓多個 Claude 代理處理不同的任務，比如一個負責前端，一個負責後端，大大提高開發效率。

![](https://pic.yupi.icu/1/image-20260116124928547.png)

## 三、Agent Skills 技能類

Agent Skills 是給 AI 裝備的技能包，讓 AI 在特定任務上表現得更專業。和 MCP 一樣，Agent Skills 現在也是 AI 程式設計生態中不可或缺的一部分，而且它是跨工具通用的開放標準，不繫結特定的編輯器。

詳細的 Agent Skills 入門教程可以閱讀工具實戰目錄下的《Agent Skills：通用 AI 技能庫》。



### Agent Skills 通用 AI 技能庫

[Agent Skills](https://claude.com/blog/skills) 是 Anthropic 新推出的 AI 技能系統。

它定義了一種 **封裝 AI 工作流** 的標準：開發者可以把複雜的任務指令、指令碼和資源打包成一個 **技能（Skill）**；作為使用者，你只需要安裝這些技能，AI 就能立刻學會這項本事，不用重複造輪子。

![](https://pic.yupi.icu/1/%E6%BC%AB%E7%94%BB%E5%9B%BE7%E5%A4%A7.jpeg)

讓我們來實戰一下，利用 [frontend-design](https://www.claudeskill.site/en/skills/anthropic-agent-skills:frontend-design)  這個 Agent Skills 來最佳化生成網站的介面。

⭐️ 推薦觀看影片動畫版，更通俗易懂：[https://bilibili.com/video/BV1T7zzBQEaA](https://www.bilibili.com/video/BV1T7zzBQEaA/)

1）安裝 Agent Skills

首先開啟 Claude Code，輸入一行命令，把官方提供的 Skills 註冊為外掛市場：

```markdown
/plugin marketplace add anthropics/skills
```

![](https://pic.yupi.icu/1/image-20260116145357194.png)

然後輸入 `/plugin`，透過 Tab 鍵切換到 Marketplaces 介面，批次安裝官方提供的 Skills。包括：

- document-skills：文件技能包，可以處理 Excel、Word、PPT、PDF 等文件。
- example-skills：示例技能包 ，可以處理技能建立、構建 MCP、視覺設計、演算法藝術、網頁測試、動圖製作、主題樣式等。

![](https://pic.yupi.icu/1/claudecode%E6%8F%92%E4%BB%B6%E5%AE%89%E8%A3%85.png)

安裝好之後，輸入 `/skills` 命令，就能看到所有已經安裝完成的技能了，我們要的 `frontend-design` 也在其中。

![](https://pic.yupi.icu/1/image-20260116145938235.png)

可以在本地找到 Skills 的安裝位置，你會發現，SKills 的本質就是一組封裝好的提示詞文件 + 指令碼檔案等：

![](https://pic.yupi.icu/1/image-20260116151949110.png)

還有另外一種安裝方式，也可以在 Claude Code 中輸入一行命令來安裝 [frontend-design](https://www.claudeskill.site/en/skills/anthropic-agent-skills:frontend-design) 技能。

```markdown
skill install anthropic-agent-skills:frontend-design
```



2）安裝完 SKills 後，你只需要和之前一樣跟 AI 對話，程式會自動根據你的任務選擇使用什麼 Skills。

比如我讓 AI 開發一個精美的狼人殺網頁遊戲，它會詢問我是否要使用 `frontend-design`  技能。

![](https://pic.yupi.icu/1/image-20260116152325220.png)

使用這個技能後，AI 會選擇獨特的設計風格，生成的介面既有個性又專業，告別千篇一律的藍紫漸變色。而且不需要你每次都重複輸入一堆設計要求，非常方便！

![](https://pic.yupi.icu/1/image-20260116153402176.png)

不用技能是這樣的，對比一下：

![](https://pic.yupi.icu/1/image-20260116155623890.png)

目前 [Anthropic 官方技能倉庫](https://github.com/anthropics/skills) 已經提供了豐富的技能集合，涵蓋程式設計相關的資料庫最佳化、API 安全、測試策略、程式碼審查、文件生成，還有辦公相關的 PPT 製作、Excel 處理、Word 文件、PDF 生成等各個方面。

如果官方提供的技能不夠用，你還可以上傳自定義技能，或者訪問以下平臺下載社群貢獻的技能：

- ⭐️ [魚皮 AI 導航 - Skills 大全](https://ai.codefather.cn/skills)：持續更新優質技能，釋放 AI 執行潛力
- [Claude Skills Hub](https://www.claudeskill.site/)：社群技能市場

![](https://pic.yupi.icu/1/image-20260201150711260.png)

值得一提的是，Agent Skills 現已成為 [通用標準](https://agentskills.io)。除了 Claude，[Cursor](https://cursor.com/docs/context/skills) 等主流 AI 程式設計工具也會陸續提供支援。也就是說，你在一個工具裡用的技能，在另一個工具裡也能複用。

### Spec-kit 規範驅動開發

[Spec-kit](https://speckit.org/) 是 GitHub 推出的規範驅動開發（SDD）框架。

什麼是 SDD 呢？

傳統開發流程是：想到什麼寫什麼，邊寫邊改，最後再補文件。這樣容易導致需求不清晰、程式碼和文件對不上。

而規範驅動開發的思路正好相反：先把需求寫成規範文件，並且把規範文件當作程式碼的 **唯一真相來源**。你可以把規範文件理解為 **法律條文**，它包含了詳細的需求描述、系統設計和介面定義。AI 必須嚴格遵守這些條文來生成程式碼，確保產出完全符合預期。

![](https://pic.yupi.icu/1/%E6%BC%AB%E7%94%BB%E5%9B%BE4%E5%A4%A7.jpeg)

聽起來有些抽象，我們可以跟著 [Spec-kit GitHub 倉庫](https://github.com/github/spec-kit) 的官方文件來實戰一下。

首先開啟終端，利用 uvx 命令直接安裝執行 Specify 工具，並初始化一個專案：

```bash
uvx --from git+https://github.com/github/spec-kit.git specify init my-project
```

### OpenSpec 輕量規範框架

[OpenSpec](https://openspec.dev/) 是一個輕量的規範驅動開發框架，比 Spec-kit 更簡單易用。

它的核心理念是把規範文件作為程式碼庫的一部分，每次改功能都 **先寫變更提案** => 確認後再實現 => 實現完再把變更歸檔到規範文件中，讓文件和程式碼始終保持同步。

![](https://pic.yupi.icu/1/%E6%BC%AB%E7%94%BB%E5%9B%BE6%E5%A4%A7.jpeg)

訪問 [OpenSpec 官方倉庫](https://github.com/Fission-AI/OpenSpec/) 檢視文件。

首先確保你的電腦安裝了符合要求的 Node.js 版本（比如我這裡要求 Node.js >= 20.19.0），然後全域性安裝 OpenSpec CLI：

```bash
npm install -g @fission-ai/openspec@latest
```

進入你的專案目錄，執行初始化命令：

```bash
openspec init
```

初始化過程中會讓你選擇要整合的 AI 工具（比如 Claude Code、Cursor 等），我這裡選擇 Cursor。

![](https://pic.yupi.icu/1/image-20260116163202471.png)

執行命令後，OpenSpec 會自動在你的專案中生成一個 `openspec/` 目錄，裡面包含：

- `openspec/specs/`：存放主規範文件，記錄了專案的完整現狀
- `openspec/changes/`：存放變更提案，記錄了每次修改的計劃
- ⭐️ `openspec/AGENTS.md`：讓 AI 程式設計助手使用 OpenSpec 進行規範驅動開發的操作指南，包含了如何建立變更提案、編寫需求規範、驗證和歸檔變更的完整工作流程。
- `openspec/project.md`：當前專案的上下文說明（用來記錄專案的資訊）

![](https://pic.yupi.icu/1/image-20260116164308965.png)

此外，還會根據你選擇的 AI 程式設計工具，生成對應的命令檔案，比如 Cursor 的：

![](https://pic.yupi.icu/1/image-20260116173814973.png)

有了這些檔案，我們就可以開始規範化的開發流程了。參考 [官方文件](https://github.com/Fission-AI/OpenSpec/)，主要分為 5 個步驟：

1）Draft 起草變更提案

直接在 AI 程式設計工具中跟 AI 說，讓它建立變更提案。比如我想新增使用者搜尋功能：

```markdown
建立一個 OpenSpec 的 change，新增功能：根據名稱和郵箱搜尋使用者
```

也可以用 AI 程式設計工具（比如 Claude Code、Cursor）的斜槓命令：

```markdown
/openspec:proposal 新增功能：根據名稱和郵箱搜尋使用者
```

![](https://pic.yupi.icu/1/image-20260116171714070.png)

AI 會給這個功能建立一個獨立的目錄 `openspec/changes/add-user-search/`，目錄下建立一系列文件：

- `proposal.md`：描述要改什麼、為什麼改
- `tasks.md`：實施步驟的任務分解
- `specs/…/spec.md`：需求變更的具體內容

![](https://pic.yupi.icu/1/image-20260116171953809.png)



2）Verify & Review 驗證和審查

可以執行下列命令，檢視 AI 建立的變更提案是否正確：

```bash
openspec list                        # 檢視所有變更
openspec validate add-user-search    # 驗證格式是否正確
openspec show add-user-search        # 檢視詳細內容
```

![](https://pic.yupi.icu/1/image-20260116172259055.png)



3）和團隊一起審查提案

如果需要完善，可以繼續跟 AI 對話，比如：

```markdown
你能幫我新增更多搜尋條件和限制麼？
```

AI 會更新規範和任務列表，直到大家達成一致。



4）Implement 實現變更

規範確認後，讓 AI 開始實現：

```markdown
規範已經很完美了，開始生成程式碼吧
```

也可以用斜槓命令：

```markdown
/openspec:apply add-user-search
```

AI 會按照 `tasks.md` 中的任務列表逐一實現，並標記完成狀態。

![](https://pic.yupi.icu/1/image-20260116172654371.png)

很快生成完成，AI 的輸出非常整齊，所有改動一目瞭然：

![](https://pic.yupi.icu/1/image-20260116172905921.png)



5）Archive 歸檔變更

所有任務完成後，讓 AI 歸檔這次變更：

```markdown
請歸檔這次變更
```

也可以用斜槓命令：

```markdown
/openspec:archive add-user-search
```

或者在終端執行：

```bash
openspec archive add-user-search --yes
```

![](https://pic.yupi.icu/1/image-20260116172957759.png)

這個命令會：

- 將變更資料夾移動到 `openspec/changes/archive/` 歸檔區
- 將需求變更自動合併到 `openspec/specs/` 主規範中
- 保持文件和程式碼的同步

![](https://pic.yupi.icu/1/image-20260116174247313.png)

這樣一來，透過 `openspec/changes/` 的歷史記錄，你可以隨時追溯每次變更的來龍去脈。

此外，整個開發過程中，建議大家定期執行 `openspec validate` 驗證命令， 確保規範的完整性。



---



到這裡，相信大家也能感受到 OpenSpec 和 Spec-kit 的區別了。

- Spec-kit 需要完整的 7 步流程：制定準則 → 寫需求 → 澄清疑問 → 定方案 → 拆任務 → 檢查 → 寫程式碼），適合從 0 開始做大型新專案
- OpenSpec 的流程更簡化：起草提案 → 審查 → 實現 → 歸檔 → 驗證，上手更快，適合在現有專案上迭代功能。






### AIChat 命令列增強工具

[AIChat](https://github.com/sigoden/aichat) 是一個功能完善的 AI 命令列助手，整合了 20+ 主流大模型。

現在主流的 AI 程式設計工具（Cursor、VS Code 等）都內建了終端，有時我們需要敲命令來執行任務，但是命令記不住怎麼辦？

用了 AIChat 後，你只需要在終端中說人話，它的 **Shell 助手** 能力就會把你的自然語言自動轉換成準確可執行的命令。

使用方法非常簡單。開啟終端，透過包管理器一行命令就能安裝：

```bash
# macOS/Linux
brew install aichat

# Windows
scoop install aichat
```

安裝完成後，執行 `aichat` 命令，首次執行會引導你建立配置，選擇你要用的大模型並填寫 API Key：

![](https://pic.yupi.icu/1/image-20260116143602756.png)

然後就可以愉快地跟 AI 對話了：

![](https://pic.yupi.icu/1/image-20260116143719965.png)

但是我個人主要用它的 Shell 助手能力（給命令新增 `-e` 選項），而不是 AI 對話能力。

![](https://pic.yupi.icu/1/ai-chat-e.gif)

比如我想批次重新命名檔案，但不記得命令怎麼寫，在終端裡執行下列命令：

```markdown
aichat -e 幫我把當前目錄下所有 .txt 檔案改成 .md
```

它就會生成對應的 shell 命令，我確認後它就自動執行了。

![](https://pic.yupi.icu/1/image-20260116144218847.png)

還可以透過快捷鍵來智慧補全命令：

![](https://pic.yupi.icu/1/ai-chat-completion.gif)

除了 Shell 助手，AIChat 還有一些進階功能。比如支援 RAG 檢索增強生成，可以讓 AI 基於你的本地文件回答問題；支援建立 AI 代理，把指令、工具和文件組合成自動化工作流。

![](https://pic.yupi.icu/1/ai-chat-agents.png)

此外，如果你想對比不同模型的效果，執行 `aichat --serve` 可以啟動本地網頁介面，同時對比多個模型的回答。

![](https://pic.yupi.icu/1/ai-chat-compare-model.png)



## 五、AI 的效率工具箱

前面介紹的 MCP、外掛、Skills 都是跑在 AI 程式設計工具裡的擴充套件。而接下來要介紹的這些開源專案，本身就是獨立的效率工具 —— 它們天生就是為 AI 設計的，讓 AI 能讀檔案、聽語音、剪影片、連線外部服務，從一個只會聊天的嘴強王者，變成真正能幹活的六邊形戰士。



### AI 的閱讀器 - 檔案處理工具

日常工作中，很多資料都是 PDF、Word、Excel、PPT 格式的。但 AI 預設只能讀純文字，你直接把一個 PDF 丟給它，大機率讀不出什麼有用的東西。

解決方法很簡單：AI 最喜歡 Markdown 了，那不妨把檔案先轉成 Markdown，再交給它處理就好了。



**MarkItDown**

[MarkItDown](https://github.com/microsoft/markitdown) 是微軟開源的萬能格式轉換器。PDF、Word、Excel、PPT、圖片、音訊、HTML，甚至 YouTube 影片，它都能一把梭轉成 Markdown。

> 開源指路：https://github.com/microsoft/markitdown

![](https://pic.yupi.icu/1/image-20260403142348396.png)

安裝和使用非常簡單，一行 pip 命令搞定：

```bash
pip install markitdown
```

裝好之後，在終端輸入一行命令就能轉換檔案。而且它還提供了 MCP Server，可以直接接入到 AI 程式設計工具中。之後你在專案裡丟一個 PDF 或 Word 檔案讓 AI 分析，它就會自動呼叫 MarkItDown 先轉成 Markdown 再處理，非常絲滑。

![](https://pic.yupi.icu/1/image-20260403142531441.png)

MarkItDown 的優點在於格式覆蓋廣，幾乎啥格式都能轉。但遇到排版很複雜的 PDF，比如論文裡的多欄排版、數學公式、複雜表格，就有點力不從心了。

這時候可以看看下面兩個更專業的工具。



**MinerU**

[MinerU](https://github.com/opendatalab/MinerU) 專攻 PDF 深度解析，能把公式轉成 LaTeX、表格轉成 HTML，還能自動提取圖片，最終輸出的是包含圖文的多模態 Markdown。如果你經常需要處理論文、技術報告這類排版複雜的文件，MinerU 比 MarkItDown 更靠譜。

> 開源指路：https://github.com/opendatalab/MinerU

![](https://pic.yupi.icu/1/image-20260403143732593.png)



**Docling**

[Docling](https://github.com/docling-project/docling) 是 IBM 開源的文件解析工具。除了 PDF 之外還支援 Word、PPT、Excel、圖片，在複雜文件的版面理解和結構還原上比 MarkItDown 更強。甚至裝上語音識別擴充套件後還能處理音影片，提取音軌轉成文字。

> 開源指路：https://github.com/docling-project/docling

![](https://pic.yupi.icu/1/image-20260403143816972.png)

簡單來說：日常轉換選 MarkItDown，論文公式選 MinerU，複雜版面選 Docling，按需搭配就好。



### AI 的耳朵和剪輯師 - 音影片工具

除了文件，音影片也是我們日常工作中經常打交道的內容。會議錄音要整理、影片素材要下載、格式要轉換……這些活兒交給 AI 來做，效率高到飛起。



**whisper.cpp**

[whisper.cpp](https://github.com/ggml-org/whisper.cpp) 是 OpenAI Whisper 模型的 C/C++ 移植版，純本地執行的語音轉文字工具。最大的優勢就是不需要 GPU 也不需要聯網，CPU 就能跑，完全不用擔心隱私資料外洩。

轉錄會議錄音、播客、影片字幕都不在話下，支援多種語言的語音識別，還能自動檢測語種，丟進去一段音訊就能出文字。

> 開源指路：https://github.com/ggml-org/whisper.cpp

![](https://pic.yupi.icu/1/image-20260403144636577.png)



**yt-dlp**

[yt-dlp](https://github.com/yt-dlp/yt-dlp) 是一個影片下載神器，支援上千個網站，包括 YouTube、B 站、TikTok、Twitter 等等，你能想到的基本都有。

它是純命令列工具，AI 呼叫起來非常絲滑，指定一個 URL 和輸出格式就完事了。還能選擇解析度、提取純音訊、下載字幕，功能非常全面。

> 開源指路：https://github.com/yt-dlp/yt-dlp

![](https://pic.yupi.icu/1/image-20260403151136014.png)



**FFmpeg**

[FFmpeg](https://github.com/FFmpeg/FFmpeg) 可能是整個計算機歷史上最重要的開源專案之一，幾乎所有涉及音影片的軟體底層都在用它。不管是轉碼、裁剪、拼接、加字幕、提取音訊還是轉換格式，一條命令就能搞定。

人類記 FFmpeg 引數頭皮發麻，但 AI 記引數可太擅長了！比如你跟 AI 說 "把這個影片裁剪前 30 秒並轉成 GIF"，它立刻就能生成對應的 FFmpeg 命令並執行。換成人工操作，可能還得先去搜半天引數……

> 開源指路：https://github.com/FFmpeg/FFmpeg

![](https://pic.yupi.icu/1/image-20260403152202764.png)

組合使用的話，yt-dlp 負責下載素材，whisper.cpp 負責語音轉文字，FFmpeg 負責音影片處理，三板斧一套下來，AI 就能完成從下載、轉錄到剪輯的完整工作流了。



### AI 的手腳 - 瀏覽器自動化

前面在 Skills 板塊已經提到了 [Browser Use](https://github.com/browser-use/browser-use)，這裡再展開聊聊。

Browser Use 不僅是一個 Skill，它本身也是一個功能強大的獨立框架 —— 基於 Python 的瀏覽器自動化工具，讓 AI 能像真人一樣操控瀏覽器。

比如你跟 AI 說：“幫我開啟某個網站，找到 Java 學習路線並截圖。”

它就能一步步完成，支援點選、輸入、滾動等各種操作，甚至支援多標籤頁操作和自動規劃執行步驟，複雜的多步任務也能搞定。

> 開源指路：https://github.com/browser-use/browser-use

![](https://pic.yupi.icu/1/image-20260403141700375.png)

適合用來做自動化測試、批次資料抓取、後臺系統的重複性操作等場景。它的底層基於微軟開源的 Playwright 瀏覽器自動化框架，穩定性和相容性都不錯。



### AI 的百寶箱 - 外部服務整合

想讓 AI 幫你發郵件、建立 GitHub Issue、更新 Notion 文件、給聊天軟體發訊息？這些事情每個都要對接不同的平臺和 API，認證方式也各不相同，一個個對接起來很麻煩。

[Composio](https://github.com/ComposioHQ/composio) 就是幫 AI 搞定這些髒活累活的。它預先整合了 1000+ 外部服務，幫你處理好 OAuth 認證、API 呼叫、錯誤重試這些細節。AI 只需要調一個函式就能操作 GitHub、Gmail、Slack、Notion 等各種平臺，省去了逐個對接的痛苦。

> 開源指路：https://github.com/ComposioHQ/composio

![](https://pic.yupi.icu/1/image-20260403152926005.png)

不管你用 Python 還是 TypeScript 開發 AI 應用，都能直接用上。官方還提供了不少現成的應用模板，拿來就能用。



### AI 的備忘錄 - 記憶管理

用過 AI 程式設計的同學應該都有過這種體驗：跟 AI 聊了好幾輪的需求和技術細節，結果一開新對話，它全忘了，又得從頭介紹一遍。

雖然現在不少 AI 程式設計工具已經自帶了記憶管理功能，但如果你想自己開發 AI 應用，記憶這塊兒就得自己解決。

[Mem0](https://github.com/mem0ai/mem0) 能給 AI 裝上一個持久記憶層。它會自動從對話中提取關鍵資訊存到資料庫裡，下次對話時自動檢索出來。這樣一來，AI 能記住你喜歡用什麼程式語言、你的專案用了什麼技術棧、上次聊到哪了，下次對話直接接著來，不用重複交代背景了。

> 開源指路：https://github.com/mem0ai/mem0

![](https://pic.yupi.icu/1/image-20260403150058803.png)

它支援使用者級、會話級、Agent 級三層記憶管理，不同使用者的上下文不會互相混淆。如果你在學 AI 應用開發，建議研究一下 Mem0 的記憶系統實現，很有參考價值。
