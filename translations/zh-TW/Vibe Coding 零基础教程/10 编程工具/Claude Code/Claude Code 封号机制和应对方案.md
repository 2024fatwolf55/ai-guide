# Claude Code 封號機制和應對方案

> 搞懂 Anthropic 是怎麼識別使用者的，以及號沒了該怎麼辦

你好，我是程式設計師魚皮。

學 AI 程式設計的同學，多半都聽說過 Claude Code 封號這件事。很多人穩定用了一年的號突然翻車，甚至有百人規模的公司被整個團滅。

眾所周知，Anthropic 一直在封禁中國區使用者，但之前沒有人搞清楚，自己明明都跑到美國了，它到底是怎麼把人揪出來的？

直到國外開發者對 Claude Code 做了逆向工程，才發現它在客戶端裡藏了一套隱蔽的使用者標記系統。

![](https://pic.yupi.icu/1/image-20260701120931639.png)

這篇文章我會用傻子都能懂的方式講清楚三件事：Claude Code 到底是怎麼識別使用者的、之前那波大規模封號是怎麼發生的、以及如果你也想穩定地用上強模型，有哪些現實的應對方案。

這些內容不只是吃瓜，理解了背後的機制，你在選工具、選模型的時候心裡會更有數。



## 一、Claude Code 是怎麼識別你的

先簡單概括一下思路：Claude Code 會讀取你電腦上的本地資訊，然後用一種肉眼完全看不到的方式，給你傳送給伺服器的每一個請求打上「這個人是中國使用者」的隱形標記，傳回 Anthropic 的伺服器。

![](https://pic.yupi.icu/1/02_%E6%95%B4%E4%BD%93%E6%A3%80%E6%B5%8B%E6%9C%BA%E5%88%B6%E6%A6%82%E8%A7%88%EF%BC%9AClaude_Code%E5%A6%82%E4%BD%95%E6%A0%87%E8%AE%B0%E4%B8%AD%E5%9B%BD%E7%94%A8%E6%88%B7_compressed_v3.png)

根據多位獨立研究者的驗證，這套檢測機制有一個觸發條件，就是你必須設定了一個叫 `ANTHROPIC_BASE_URL` 的環境變數，把 Claude Code 的請求指向了非官方的 API 地址。換句話說，如果你直接連的是官方的 `api.anthropic.com`，這套標記機制不會啟用。

![](https://pic.yupi.icu/1/03_%E8%A7%A6%E5%8F%91%E6%9D%A1%E4%BB%B6%EF%BC%9AANTHROPIC_BASE_URL%E7%8E%AF%E5%A2%83%E5%8F%98%E9%87%8F_compressed_v3.png)

但問題是，國內大多數使用者都需要透過中轉站來用 Claude Code，所以很多中國開發者都設定了這個變數，也都會被這套機制檢查到。



### 兩條識別路徑

在這個前提下，Claude Code 透過 2 條路徑來判斷你是不是中國使用者。

**第一條路徑，讀取你電腦的系統時區。**

只要你的系統時區是 `Asia/Shanghai` 或者 `Asia/Urumqi`，Claude Code 就會把你標記為中國使用者。

而絕大多數中國開發者雖然切換了網路，但一般不會去改電腦時區，畢竟還要正常看時間和日曆，所以這條路徑幾乎能命中所有人。

![](https://pic.yupi.icu/1/04_%E8%AF%86%E5%88%AB%E8%B7%AF%E5%BE%84%E4%B8%80%EF%BC%9A%E7%B3%BB%E7%BB%9F%E6%97%B6%E5%8C%BA%E6%A3%80%E6%B5%8B_compressed_v2.png)

**第二條路徑，把你的中轉地址跟一份域名黑名單做比對。**

因為國內訪問不了 Claude 的官方 API，很多開發者和公司都是透過中轉站來呼叫的。Claude Code 會把你在 `ANTHROPIC_BASE_URL` 裡填的地址提取出來，跟一份內建的域名名單做匹配。

![](https://pic.yupi.icu/1/05_%E8%AF%86%E5%88%AB%E8%B7%AF%E5%BE%84%E4%BA%8C%EF%BC%9A%E5%9F%9F%E5%90%8D%E9%BB%91%E5%90%8D%E5%8D%95%E5%8C%B9%E9%85%8D%E6%9C%BA%E5%88%B6_compressed_v3.png)

這份名單本身也是被混淆加密儲存的，被逆向之後發現一共有 **147 個域名**。

我看了一下這份名單，真的蚌埠住了。

上來就是中國頂級域名 `cn`，直接腰斬。緊接著是百度、阿里、位元組等國內大廠的域名，而且連阿里和百度的內網域名都沒放過。此外 DeepSeek、智譜等幾乎所有國內 AI 公司的域名和關鍵詞也在名單裡，剩下的大頭就是各種 API 中轉服務的域名了。

![](https://pic.yupi.icu/1/image-20260701122013567.png)



### 用隱寫術回傳標記

前面講了 Claude Code 怎麼識別中國使用者，接下來才是真正讓我大開眼界的部分：它識別出結果之後，是怎麼把這個資訊傳回伺服器的呢？

每次你在 Claude Code 裡輸入提示詞，它在把請求發給伺服器之前，都會在最前面拼一段系統提示詞。這段提示詞裡有一行平平無奇的日期資訊，長這樣：

```plain
Today's date is 2026-06-30.
```

就是這行看起來人畜無害的文字，Claude Code 會在傳送請求之前，對它動兩處手腳。

第一處，改日期分隔符。如果檢測到你的時區是中國時區，日期格式會從 `2026-06-30` 變成 `2026/06/30`，連字元變斜槓。

第二處，改單引號的 Unicode 編碼。根據你中轉地址的匹配結果不同，`Today's` 裡面那個單引號會被替換成不同的 Unicode 字元，分別代表不同的含義：

- `'`（U+0027，正常 ASCII 單引號）表示沒命中任何名單
- `’`（U+2019，右單引號）表示命中了域名列表
- `ʼ`（U+02BC，修飾字母撇號）表示命中了 AI 實驗室關鍵詞
- `ʹ`（U+02B9，修飾字母角分符）表示兩個都命中了

這四個字元長得一模一樣，你在編輯器和終端里根本看不出區別。但在機器層面，它們是完全不同的編碼值。

![](https://pic.yupi.icu/1/09_%E9%9A%90%E5%86%99%E6%9C%AF%E6%89%8B%E6%B3%95%E4%BA%8C%EF%BC%9A%E5%9B%9B%E7%A7%8DUnicode%E5%8D%95%E5%BC%95%E5%8F%B7%E7%9A%84%E5%8C%BA%E5%88%AB_compressed_v2.png)

這種手法叫做 **隱寫術**，就是把秘密資訊藏在看起來完全正常的內容裡。就像你寫了一封普通的信，但其中某些字母用了不同品牌的墨水，收件人用特殊儀器一掃就能讀出暗號，而你拿著信怎麼看都覺得一切正常。

伺服器收到請求後，只需要檢查一下那個單引號是哪個 Unicode 字元、日期用的是連字元還是斜槓，立刻就能判定這條請求來自中國使用者、是否透過中轉站、是否和國內 AI 公司有關。

而且整個過程不需要額外的網路請求，不會留下任何可疑的流量痕跡，因為這些修改後的字元在顯示層面和正常字元一模一樣。這也是為什麼這事一直沒人發現，直到有人對程式檔案做了逆向工程。

可能有人會問：直接封掉所有用中轉站的使用者不就完了，為什麼要搞這麼複雜？

因為很多海外的企業和開發者也會因為安全合規等原因使用自定義 API 閘道器，如果一刀切全封就會誤傷大量正常使用者。所以官方選擇了一種更「聰明」的方式：先靜默標記、持續收集情報，等積累了足夠多的資料之後，再在服務端做針對性的封禁決策。

另外提醒一下，如果你真的收到了封號郵件想申訴解封，開啟郵件的時候也要小心。因為有人發現 Anthropic 的郵件裡埋了追蹤畫素，你一開啟郵件它就能獲取到你的真實 IP 地址，相當於二次確認你在中國。



## 二、大規模封號事件始末

搞清楚了識別機制，我們再來看一下之前那波鬧得沸沸揚揚的封號事件，因為它是理解「為什麼會有人無辜被封」的關鍵。

事情是這樣的。有一天社群裡突然傳出一套操作方法，聲稱可以零元白票 Claude Max 20x 的訂閱，這是官方最貴的套餐，月費 200 刀。

訊息迅速傳遍了推特、微信群和各種技術社群，甚至連閒魚上都有人在賣教程。

![](https://pic.yupi.icu/1/image-20260729100925685.png)

到底是怎麼回事呢？

簡單來說，Claude 官網的支付頁面存在一個安全缺陷。有人寫了一段瀏覽器外掛指令碼，執行之後能篡改網頁的結賬頁面，強行調出一個原本不對外開放的歐洲銀行轉賬支付通道。然後使用者只需要在網上隨便生成一組虛假的銀行卡號和地址資訊，填進去點選訂閱，系統就會判定支付成功，直接給你開通最高檔的會員許可權。

之所以出現這個漏洞，本質上是因為後端伺服器太相信前端提交過來的資訊了。

正常來說，使用者在網頁上選了什麼套餐、用什麼方式付款，伺服器應該自己再校驗一遍。但 Claude 的系統沒有做這一步，前端說付了就是付了。再加上那個歐洲銀行轉賬通道本身是非同步扣款的模式，系統在確認到賬之前就已經把會員許可權發放出去了。

兩個漏洞疊在一起，就成了零元購。

![](https://pic.yupi.icu/1/01_%E4%B8%A4%E4%B8%AA%E6%BC%8F%E6%B4%9E%E5%8F%A0%E5%8A%A0%E5%AF%BC%E8%87%B4%E9%9B%B6%E5%85%83%E8%B4%AD%E7%9A%84%E5%8E%9F%E7%90%86%E5%9B%BE_compressed_v1.png)

就好比一家自助餐廳的收銀系統出了 Bug，門口的閘機不需要付款就能開啟，這不得有一堆人湧進去吃霸王餐？據說當天好幾家 API 中轉站直接打出了跳樓價折扣，畢竟人人都能零元購了，誰還花錢找中間商。

可惜好景不長，漏洞曝光後的第二天，Anthropic 的工程師就緊急上線修復，那個指令碼徹底失效了。

**但修完漏洞只是第一步，緊接著就是大規模封號。**

這次封號力度非常狠，不只是封利用漏洞的賬號，而是把關聯的所有東西一起封。只要你的裝置曾經登入過參與漏洞操作的賬號，哪怕你另一個正常付費的老賬號也在同一臺電腦上用過，也會被連帶封禁。而且裝置的硬體資訊會被平臺永久標記，之後再想註冊新號都很困難。

更離譜的是，有些人根本沒去薅這個漏洞，只是恰好跟薅漏洞的人用了同一個代理節點，結果也被封了。

漏洞本身確實是官方自己的技術問題，但在修復之後，他們選擇了最激進的方式來止損，不僅封掉了利用漏洞的賬號，還把能關聯到的裝置、IP 一起拉黑。至於這個過程中誤傷了多少正常使用者，從之前 3.3% 的申訴成功率來看，他們似乎並不太在意。



## 三、這件事該怎麼看

逆向了 Claude Code 的那位國外開發者，直接怒斥 Anthropic 在客戶端裡嵌入了「間諜軟體」。

有人認為這不算間諜軟體，只是一種反濫用的合規措施；但更多人認為，在使用者完全不知情的情況下搞隱蔽標記，就是不對。

![](https://pic.yupi.icu/1/image-20260701121820094.png)

我的看法是這樣的：Claude Code 不是一個普通的聊天軟體，它執行在你的終端裡，擁有檔案系統許可權，能讀寫你的程式碼和配置，甚至能執行各種 Shell 命令。開發者把這麼大的信任給了它，結果它揹著你在每一條請求裡偷偷夾帶私貨，這種事情一旦被發現，大家以後用它的時候心裡都會有根刺，總想著它是不是還在背後搞別的小動作。

**今天它能上報你的時區，明天就能偷偷上報你所有的資料。**

而且還有一個很現實的問題，這套機制對真正搞大規模轉售和模型蒸餾的人來說，想繞過並不難，改個時區、換個域名就完事了。最終被精準打擊的，反而是那些正常付費使用的普通開發者。

這也提醒我們一件事：不管你用哪家的 AI，你的賬號、你積累的對話歷史、你的工作流，可能就在一封郵件之後全部歸零。

順便說一下，封號和漲價不只是 Claude 的問題。OpenAI 的 Codex 也搞過幾波封禁，200 刀的賬號沒有任何預警直接封停；Cursor 一直存在地區限制；國內這邊也有峰谷定價、限量發售、付費專業版等各種變化。

**AI 的能力的確越來越強了，但能穩定用上的門檻也越來越高了。**



## 四、現實的應對方案

聊了這麼多，最實際的問題還是：接下來該怎麼辦，用什麼模型？

**方案一：換模型，不換工具。**

如果你就是喜歡 Claude Code 這個工具的互動方式和自主性，其實完全可以保留工具、只換底層模型。把它接到 DeepSeek、Kimi、智譜 GLM 這些國內模型上，量大管飽、不用魔法、也不怕封號。具體怎麼操作，可以閱讀本目錄中的《Claude Code 和 Codex 對接國內模型教程》，幾分鐘就能跑通。

需要注意的是，用中轉站配合官方賬號是風險最高的組合，而直接換成國內模型的官方 API 就沒有這個問題了，因為你壓根不需要 Anthropic 的賬號。

**方案二：換成 Codex + GPT 系列。**

如果你預算有限，Codex + GPT 系列模型是目前價效比和智慧都比較均衡的選擇。OpenAI 經常贈送重置額度，很多辦公自動化、網站開發任務的完成度都不錯。

![](https://pic.yupi.icu/1/image-20260729102157381.png)

**方案三：用國產模型，別有偏見。**

國產模型這一年進步飛快，很多場景已經不比國外的差了。比如 Kimi K3 做前端開發和視覺效果很強，DeepSeek V4 價效比極高、很適合做 AI 應用開發專案的底層模型，GLM-5 系列的全棧開發能力也很能打。具體怎麼選，可以閱讀本教程程式設計工具板塊中的《AI 模型選擇指南》。

![Kimi K3 開發的前端網站](https://pic.yupi.icu/1/1784181917700-09e53717-bbf1-42c1-9f4e-c17413ace9f1-20260717144616347.png)

**方案四：預算充足就走官方合作方。**

如果你預算充足，還是想用 Claude 系列模型，建議走 Cursor 這種官方合作方，比直接訂閱 Claude 更穩定。畢竟 Claude Opus 5 的編碼能力確實很強，這一點我在本教程模型動態板塊的《Claude Opus 5 程式設計能力實測 - 7 個專案案例》裡已經詳細驗證過了。何必整天跟 Anthropic 鬥智鬥勇呢？



## 寫在最後

這篇文章帶你看清了 Claude Code 的封號機制：以 `ANTHROPIC_BASE_URL` 環境變數為觸發條件，透過系統時區和域名黑名單兩條路徑識別使用者，再用 Unicode 隱寫術把標記悄悄回傳伺服器。也覆盤了那次因為支付漏洞引發的大規模連坐封禁。

對我們來說，最有價值的結論其實是這一條：**關鍵的工作流一定要有備用方案。**

不要把自己的生產力完全繫結在一家公司的一個賬號上。能跑在本地的儘量跑在本地，模型和工具儘量做到可替換。這樣哪天某家公司抽風了，你也能第一時間切換過去，不影響幹活。

說到底，工具和模型都只是手段。真正屬於你的是需求拆解能力、工程方法和產品思維，這些東西不會因為一封封號郵件而歸零。
