# Claude Code 常用斜槓命令大全，用好了效率翻倍！

如今用 Claude Code 的人越來越多了，但我發現很多人的使用方式還是純聊天，有什麼需求就直接打字跟它說。

這當然沒問題，AI 模型的能力已經很強了，一般能夠理解你的意思。

但其實 Claude Code 內建了很多斜槓命令，輸入 `/` 就能看到完整的命令列表。這些命令覆蓋了會話管理、上下文控制、並行協作等方方面面，用好了能省很多事。

![](https://pic.yupi.icu/1/image-20260519171514784.png)

雖然現在 Claude Code 已經有 50 多個命令了，但是你不用死記這些命令。日常使用時，直接用中文跟 Claude 說你的需求，比如幫我壓縮一下上下文、切換到規劃模式、把這個任務放到後臺跑，它會自動幫你執行對應的命令。

但瞭解這些命令有什麼用、什麼場景該用，才能讓你知道 Claude Code 的能力邊界在哪裡，開啟使用思路，提高效率。

下面我會按照分類把常用的命令講一遍，告訴你每個命令是什麼？怎麼用？什麼時候該用？

需要演示的地方我會提供 Demo 提示詞，你可以直接在 Claude Code 裡執行試試。

點個收藏，咱們開始~

💡 如果你還沒用過 Claude Code，可以看看我的 [這篇實戰教程](https://mp.weixin.qq.com/s/PHPtZcS2sX62O3Szj-mWsw)，手把手帶你配置好 Claude Code 並做出一個完整專案。



## Claude Code 斜槓命令大全

### 一、會話管理

#### /clear

清空當前對話，開始一個全新的會話。

當你做完一個任務，**要切到下一個任務時**，用 `/clear` 可以把之前的上下文全部清掉，避免舊資訊干擾新任務。

清空的對話不會丟失，後續還能透過 `/resume` 找回來。

![](https://pic.yupi.icu/1/image-20260519172239175.png)

注意，如果你只是覺得上下文太長了、但還在做同一個任務，不要用 `/clear`，用接下來要講的 `/compact` 更合適。



#### /compact

壓縮當前對話，釋放上下文空間。

Claude Code 的上下文視窗是有限的，聊著聊著就滿了。一旦上下文接近上限，AI 的注意力會開始渙散，容易遺漏之前討論過的細節，回答質量明顯下降。

`/compact` 會把之前的對話濃縮成一份摘要，騰出空間繼續工作，同時保留關鍵資訊不丟失。壓縮後的對話輪次更少了，後續每次請求傳送的 token 也會減少，相當於間接幫你省錢。

![](https://pic.yupi.icu/1/image-20260519192717120.png)

雖然 Claude Code 在上下文達到大約 95% 時會自動觸發壓縮，但我建議不要等到那時候才處理。自動壓縮的時機不可控，可能正好在你實現關鍵邏輯的時候觸發，導致一些重要細節被壓縮掉。

更好的做法是在每完成一個階段性任務後（比如除錯完一個 Bug、開發完一個功能），主動執行一次 `/compact`，這樣你可以控制保留哪些資訊。

你還可以在後面加一段指令，告訴它壓縮時重點保留什麼。

比如你正在做 API 設計，可以這樣：

```bash
/compact 重點保留 API 介面的設計決策和引數定義
```

![](https://pic.yupi.icu/1/image-20260519172504841.png)

我的習慣是，當 `/context` 顯示上下文用量超過 80% 時就執行一次 compact。



#### /resume

恢復之前的會話。

假如你昨天做到一半的任務今天想接著做，或者剛才 `/clear` 掉的對話需要回去看看，都可以用 `/resume` 來恢復。

直接輸入後，會彈出一個會話選擇器，列出你最近的所有會話，選一個就能恢復。

![](https://pic.yupi.icu/1/image-20260519172815216.png)

預設只顯示當前工作空間（專案目錄）下的會話，如果想檢視所有專案的歷史會話，可以按 `Ctrl+A` 切換到全部列表。

![](https://pic.yupi.icu/1/image-20260519172945037.png)

如果你記得會話的名字或 ID，也可以直接指定：

```bash
/resume 昨天的重構任務
```



#### /branch 和 /fork

這兩個命令的作用完全相同，從當前對話分支出一個新會話。

當你想基於當前的討論內容去探索一個不同方向，但又不想影響當前的對話進度時，就可以用它。

執行後你會切到一個新分支上，原來的對話保持不動，隨時可以 `/resume` 回去。

比如你在討論一個架構方案，想試試另一種實現思路，又怕改著改著原來的思路找不回來了，就可以先 `/branch` 出去探索，不滿意再回來。

```bash
/branch 試試用 Redis 替代記憶體快取的方案
```

![](https://pic.yupi.icu/1/image-20260519173209261.png)



#### /rewind

把對話和程式碼回退到之前的某個節點。

Claude 在工作過程中會自動儲存檢查點，也就是每一次你按回車讓它執行操作之前的狀態，都會被記錄下來。

如果 Claude 改了一堆程式碼，但你覺得改歪了，用 `/rewind` 可以回到之前的任意一個節點，對話記錄和檔案改動都會一起回退。

執行後會彈出一個節點選擇器，你選擇回退到哪一步就行。

![](https://pic.yupi.icu/1/image-20260519173628854.png)

你可以把它理解成編輯 Word 文件時的撤銷，或者 Git 裡的版本回滾，它同時回退對話記錄和檔案改動。



#### /recap

生成當前會話的一句話摘要。

如果你離開了一會兒回來，忘了剛才做到哪了，`/recap` 可以快速幫你回憶。

其實 Claude Code 本身在你長時間離開後回來也會自動顯示一個 recap，這個命令是讓你隨時主動觸發。

![](https://pic.yupi.icu/1/image-20260519174322674.png)



#### /btw

btw 就是 by the way 的縮寫，作用是快速插入一個問題，不會汙染當前對話上下文。

有時候你正在做一個任務，突然想問一個不太相關的小問題，比如：Python 的 dataclass 怎麼設預設值來著？

如果直接問，這段對話會被加到上下文裡，不僅佔用空間，還可能干擾後續任務。

用 `/btw` 就不會有這個問題，它相當於開了一個臨時小窗，問完就關：

![](https://pic.yupi.icu/1/image-20260519174229758.png)



#### /copy

把 Claude 最近一條回覆內容複製到剪貼簿。

直接輸入 `/copy` 就是複製最新的回覆。

![](https://pic.yupi.icu/1/image-20260519174511609.png)

如果回覆裡有程式碼塊，會彈出一個選擇器讓你選複製哪一段。

![](https://pic.yupi.icu/1/image-20260519174550215.png)

加數字可以複製第 N 條回覆，比如 `/copy 2` 就是複製倒數第二條。

![](https://pic.yupi.icu/1/image-20260519174717159.png)

這個功能雖然簡單，但我覺得特別有用，因為終端裡直接選中複製經常會出問題。



#### /export

把當前整個對話匯出為純文字檔案。

如果你想儲存一段對話記錄，或者分享給同事看，可以用這個命令。預設會讓你選擇複製到剪貼簿還是儲存到檔案。

![](https://pic.yupi.icu/1/image-20260519174853832.png)

在命令後面加檔名的話，就會直接儲存：

```bash
/export 開發記錄.txt
```

![](https://pic.yupi.icu/1/image-20260519174946874.png)



#### /exit

這個沒啥好說的，作用是退出 Claude Code 會話，連按兩次 `Ctrl+C` 也能退出。

![](https://pic.yupi.icu/1/image-20260519175031641.png)

但是要注意一個細節，如果當前有子代理（subagent）或者後臺任務（background）在執行，退出時 Claude Code 會詢問你是否要一併關閉它們。



### 二、資訊與診斷

#### /usage

檢視當前會話的 token 用量和費用。

用 Claude Code 最怕的就是不知不覺燒了很多錢。`/usage` 會告訴你這次會話花了多少 token、換算成多少美元、離你的計劃用量上限還有多遠。建議在長時間工作後定期看一眼。

![](https://pic.yupi.icu/1/1777359631006-6a630d28-fda7-426d-9b7d-e188b8fdf9b5.png)

不過要提一句，如果你透過 API Key 接入了第三方模型（比如國內的 DeepSeek），`/usage` 顯示的費用可能不準確，因為它是按 Claude 官方的定價來估算的。實際花了多少錢，還是以模型供應商後臺的賬單為準。



#### /context

視覺化當前上下文視窗的使用情況。

執行後會顯示一個彩色網格，直觀地告訴你上下文空間被什麼東西佔滿了，是對話記錄太長、還是載入的檔案太多、還是系統提示詞太大。如果快滿了還會給出最佳化建議。

![](https://pic.yupi.icu/1/1777358465249-dbc18a92-6c77-471d-a15e-4f79a7837a67-20260429113526400.png)

後面加 `all` 可以展開每一項的詳細資訊：

```bash
/context all
```

![](https://pic.yupi.icu/1/image-20260519175443232.png)

我一般會跟 `/compact` 配合著用，先看 `/context` 確認上下文壓力，再決定要不要 compact。



#### /diff

開啟互動式 diff 檢視器，看 Claude 到底改了什麼。

這個命令會展示當前所有未提交的程式碼變更。你可以用左右鍵切換檢視整體 git diff 和 Claude 每一輪的單獨改動，用上下鍵瀏覽不同檔案。

![](https://pic.yupi.icu/1/image-20260519175542291.png)

在 Claude 改了很多檔案之後，提交程式碼前用 `/diff` 過一遍是個好習慣。不過在終端的小黑框裡看程式碼 diff 還是挺痛苦的，如果改動比較多，建議還是配合 VS Code 的 Git 外掛或其他支援視覺化程式碼對比的 IDE 來看，體驗會好很多。



#### /status

開啟設定介面的狀態標籤頁，顯示當前的版本號、使用的模型、賬戶資訊和連線狀態。

![](https://pic.yupi.icu/1/image-20260519175729482.png)

這個命令有個優點，它不需要等 Claude 當前的回覆結束就能用。如果 Claude 正在跑一個很長的任務，你隨時可以輸入 `/status` 看看當前狀態。



#### /help

顯示所有可用命令的列表和簡短說明。記不住命令的時候隨時 `/help` 查一下。

![](https://pic.yupi.icu/1/image-20260519175817191.png)

這其實是命令列工具的一個通用慣例，幾乎所有命令列工具都支援 `--help` 或類似的幫助命令。養成習慣，之後遇到不熟悉的命令列工具，先敲個 help 看看有什麼功能。



#### /insights

生成一份你使用 Claude Code 的分析報告，包括你經常在哪些專案目錄工作、互動模式是怎樣的、哪些地方產生了問題。

如果你想回顧自己的 AI 程式設計習慣、找找最佳化空間，可以定期跑一次看看。

![](https://pic.yupi.icu/1/image-20260519180603438.png)

生成出來的報告預設是英文的，你可以把這個報告檔案扔給 AI，讓它再幫你分析總結。

![](https://pic.yupi.icu/1/image-20260519180701112.png)



#### /doctor

給你的專案配置做一次體檢，也可以用 `/checkup` 這個別名。

它會自動掃描你的 Skills、CLAUDE.md 等配置檔案，檢查裡面有沒有寫目錄結構、依賴列表這些模型自己就能從程式碼庫讀到的冗餘資訊，找出沒用到的 Skills 和 MCP 服務，檢測本地和倉庫裡的 CLAUDE.md 有沒有重複或矛盾，並建議把不需要每次都載入的內容遷移到可以按需載入的 Skills 裡。

![](https://pic.yupi.icu/1/1785830100705-ba0f3f43-ba78-43e0-bf59-5dabcf2f2c61.png)

所有變更都會先給你看報告，等你確認後才會執行，不用擔心它亂改配置。

這個命令是配合新模型時代的「提示詞減法」思路推出的，因為官方發現規則寫太多反而會搶佔模型幹活的注意力。想了解背後的原理，可以閱讀本教程經驗技巧板塊中的《Anthropic 官方 - 提示詞精簡方法》。



### 三、模型和模式控制

#### /plan

在開發全棧專案、或者做大改動之前，不建議直接讓 AI 直接開始寫程式碼。

使用 `/plan` 可以進入規劃模式，會讓 AI 先制定一個執行計劃給你看，確認方案沒問題後，再動手實現。

你可以在命令後面直接描述任務：

```bash
/plan 重構整個專案，增加使用者系統和 JWT 認證
```

![](https://pic.yupi.icu/1/image-20260519180528043.png)

AI 可能會透過互動式提問，來確認更多的資訊：

![](https://pic.yupi.icu/1/image-20260519180823098.png)

然後輸出一份詳細的實施方案，等你確認了再開始執行。適合那些改動範圍大、不確定最佳方案的任務。

![](https://pic.yupi.icu/1/image-20260519181940794.png)



#### /goal

這是我認為 Claude Code 目前最強大的命令之一。

一般情況下，Claude Code 每完成一輪操作，就會停下來等你確認或者下一步指示。

但有些任務你其實不需要盯著它一步步做，只需要告訴它「最終達到什麼狀態就算完成」，讓它自己悶頭幹到底。特別適合睡覺前丟一個任務給它，第二天早上起來直接驗收成果。

`/goal` 命令就是幹這個的。你設定一個完成條件，Claude Code 會自動持續工作，不需要你每一輪都按回車確認。設定了 goal 之後，每輪結束會有一個輕量評估模型檢查條件是否滿足，沒滿足就自動開始下一輪，滿足了才停下來。

先演示一下基本用法。比如我想讓 Claude Code 修復整個專案的程式碼：

```bash
/goal 修復整個專案的程式碼，直到全部測試透過且沒有報錯
```

執行後 Claude 會立刻開始工作，直到所有測試透過且沒有報錯為止，整個過程你完全不用幹預。

![](https://pic.yupi.icu/1/image-20260519191842661.png)

不過這個命令能不能用好，關鍵在於你怎麼編寫完成條件。因為評估模型只會讀對話記錄裡的內容，它不會自己去跑命令檢查，所以條件必須是 Claude Code 執行過程中能自證的，比如「跑某個命令的結果是什麼」。

下面是幾個例子：

- ✅ 執行 npm test 退出碼為 0，且 git status 沒有未提交的更改（Claude 跑完測試，結果就在對話記錄裡，評估模型能看得到）
- ✅ src/ 目錄下不再有任何 TODO 註釋（Claude 可以 grep 檢查並展示結果）
- ❌ 程式碼質量要好（太主觀了，評估模型沒法判斷）

如果條件寫得不夠好，或者任務本身就很難收斂，Claude 可能會無限迴圈下去，一直燒 token。所以我建議在條件後面加上一個熔斷限制，比如：

```bash
/goal 把所有 API 呼叫遷移到 v2 格式，直到測試透過，如果 20 輪還沒搞定就停下來
```

這樣即使任務沒完成，20 輪之後也會自動停下來。

goal 命令雖然強大，但因為它會自動跑很多輪，token 消耗是比較大的。所以不是什麼任務都適合用它，建議在這些有明確終止條件、且手動盯著比較費時的場景下使用。比如：

- 模組遷移：把舊 API 呼叫全部遷移到新版本，直到編譯透過
- 批次重構：拆分大檔案，直到每個檔案都在指定行數以內
- Bug 修復：修復某個測試用例，直到它綠了
- 清理積壓：處理標了特定 label 的 issue，直到清空

如果你想中途看看進度，直接輸入 `/goal` 就行，不用帶任何引數，能看到當前任務跑了多久、花了多少 token。

![](https://pic.yupi.icu/1/image-20260519192117090.png)

想提前喊停的話，用 `/goal clear` 即可。

![](https://pic.yupi.icu/1/image-20260519192203259.png)



#### /model、/effort、/fast

這三個命令都是控制模型行為的，我放在一起簡單聊聊。

- `/model` 切換 AI 模型，輸入後會彈出一個選擇器讓你挑
- `/effort` 調整模型的思考力度，從 low 到 max 共五檔。任務簡單的時候調低點兒省 token，複雜任務調高點兒，我一般都是 high 或者 xhigh。
- `/fast` 用來開關快速模式。開啟後響應速度大約快 2.5 倍，質量不變。但 token 單價更貴，適合需要快速迭代的簡單改動，長時間跑的複雜任務就沒必要開了。反正我是開不起（

![image-20260519181459065](https://pic.yupi.icu/1/image-20260519181459065.png)

一般來說，大家是用不到這些命令的，反正我是很少手動調整這些。不妨試試開源的 CC Switch 工具，提供了一個視覺化介面來切換模型和調整引數，方便多了。

![](https://pic.yupi.icu/1/image-20260519181417445.png)



### 四、配置與擴充套件

#### /config

開啟 Claude Code 的設定介面，可以調整主題、模型、輸出風格等各種偏好。

相當於一個總控面板，記不住具體命令的時候可以直接 `/config` 進去找，還支援搜尋配置項。

![](https://pic.yupi.icu/1/image-20260519181629699.png)



#### /mcp、/skills、/plugin

這三個命令分別用來管理 MCP 伺服器連線、Skills 技能列表和外掛。

MCP 是讓 AI 連線外部工具和服務的協議，比如連線資料庫、操作瀏覽器。

Skills 是可複用的自定義命令，你可以把常用的工作流封裝成一個 skill，下次更快速規範地完成任務。

Plugin 可以理解為技能的打包集合，一個外掛裡可以包含多個 skill、自定義主題、hook 等，方便分享和安裝。

這三個命令我用得不算多，一般配置好一次就不用再動了。如果你覺得命令列管理這些東西不夠直觀，用 CC Switch 等第三方工具也能視覺化管理 MCP、技能和外掛配置。

![](https://pic.yupi.icu/1/image-20260519181902887.png)



### 五、程式碼審查

#### /review

讓 Claude 審查當前分支對應的 Pull Request。

輸入 `/review` 命令後，AI 會自動檢測當前分支關聯的 PR 並開始審查：

![](https://pic.yupi.icu/1/image-20260519182317653.png)

也可以指定 PR 號來審查特定的 PR：

```bash
/review 42
```

審查過程中，Claude 會啟動多個子代理並行檢查程式碼，重點找 Bug 和邏輯錯誤。適合在讓同事 review 之前或合併之前，自己先用 AI 過一遍，提前發現明顯問題。

![](https://pic.yupi.icu/1/image-20260519182358586.png)

如果你想要更深度的雲端多代理審查，可以試試 `/ultrareview` 命令，不過那個會額外消耗 usage credits，也就是在你的訂閱套餐額度之外單獨計費的補充額度，Pro/Max 使用者有 3 次免費機會。



#### /simplify

雖然這個命令的名字叫 simplify，但它乾的事不只是簡化程式碼。

它的核心作用是審查你最近修改的檔案，從三個維度找問題並直接修復：程式碼複用（有沒有重複邏輯可以抽取）、程式碼質量（有沒有 hack 寫法和冗餘狀態）、執行效率（有沒有不必要的計算、可以併發的地方）。

之所以叫 simplify，大概是因為這三個方向做下來，程式碼確實會變得更簡潔。

跟 `/review` 不同的是，`/simplify` 不只是給意見，它會直接動手改程式碼。它會並行啟動三個審查代理，分別從上面說的三個角度檢查，然後彙總問題並應用修復。

![](https://pic.yupi.icu/1/image-20260519183027485.png)

你也可以在後面加一段描述，讓它聚焦在特定方向：

```bash
/simplify 重點關注記憶體效率
```

![](https://pic.yupi.icu/1/image-20260519183241226.png)



### 六、子代理和並行

#### /agents

Claude Code 可以把一些子任務委派給子代理來並行處理，`/agents` 命令用來檢視和配置這些子代理。

不過對大多數人來說，不需要手動去配置子代理，Claude Code 在需要的時候會自動啟用。這個命令更多是讓你看看當前有哪些代理在跑、狀態如何。

![](https://pic.yupi.icu/1/image-20260519183337674.png)



#### /tasks

檢視和管理當前會話里正在執行的後臺任務。

Claude 在執行復雜操作時，可能會同時啟動多個子代理並行處理不同的子任務。`/tasks` 讓你看到這些子代理各自在幹什麼、進度如何。

![](https://pic.yupi.icu/1/image-20260519183357190.png)

選中某個任務按回車，還能進入檢視這個子代理的完整執行過程和輸出詳情：

![](https://pic.yupi.icu/1/image-20260519183444151.png)



#### /background

把當前整個會話放到後臺去跑，釋放你的終端。

我覺得這個挺實用的，比如我讓 Claude 跑一個比較耗時的任務（重構一個大模組），不想一直開著終端等它，就可以用 `/background` 把它扔到後臺。

執行後，當前會話會從終端分離出來，在後臺繼續執行，你的終端就空閒了，可以去做別的事情。後面想接回來看看進度，再附加 attach 上去就行。

你還可以在後面加一句話作為分離前的最後指令：

```bash
/background 編寫單元測試並執行，執行失敗則自動修復
```

![](https://pic.yupi.icu/1/image-20260519183834248.png)

之後想看進度，用 `claude agents` 命令就能監控所有後臺會話的狀態。

![](https://pic.yupi.icu/1/image-20260519183917357.png)

選中某個後臺會話，然後按右方向鍵，就能進入這個任務的對話介面了：

![](https://pic.yupi.icu/1/image-20260519184129719.png)



#### /loop

透過 `/loop` 命令，你可以設定一個時間間隔，讓 Claude 每隔一段時間執行一次某個操作，也就是定時任務。

比如每 5 分鐘檢查一下部署是否完成：

```bash
/loop 5m 檢查專案前後端的部署狀態
```

![](https://pic.yupi.icu/1/image-20260519184353594.png)

如果不指定間隔，Claude 會根據任務性質自己決定執行節奏。如果連提示詞都不指定，它會去讀專案裡 `.claude/loop.md` 檔案的內容來執行（如果有的話），沒有這個檔案就做一次自主維護檢查。

這玩意適合用在需要持續監控的場景，比如等部署完成、等 CI 跑完、定期檢查日誌有沒有異常之類的。

但是我個人不太喜歡用 `/loop` 來跑長時間的定時任務。如果設了之後忘了關，它會一直在後臺迴圈執行，不知不覺消耗資源。
