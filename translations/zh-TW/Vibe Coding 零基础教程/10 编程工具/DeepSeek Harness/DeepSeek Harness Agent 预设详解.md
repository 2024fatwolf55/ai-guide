# DeepSeek Harness Agent 預設詳解

> 四種內建模式怎麼選？如何自定義專屬 Agent 預設？一文講透。

大家好，我是程式設計師魚皮。

DeepSeek Harness 是 DeepSeek 官方最新開源的 AI Agent 執行環境，你可以把它理解成一個高度可定製的 AI 程式設計工具，對標 Claude Code 和 Codex，核心理念是「一切皆外掛」。

![](https://pic.yupi.icu/1/image-20260814133452050.png)

在可以閱讀本教程程式設計工具板塊 DeepSeek Harness 目錄中的《DeepSeek Harness 保姆級入門教程》中，我已經帶大家從零上手了 DeepSeek Harness，覆蓋了安裝、實戰、社群外掛和自己寫外掛的基礎用法。

接下來開始進階教程，我會把 DeepSeek Harness 裡那些更深入的玩法一個個拆開來講。

本篇先從 Agent 預設開始。



## Agent 預設是什麼？

很多 AI 程式設計工具都有模式切換功能，比如用過 Cursor 的同學應該對 Agent、Ask、Plan 這幾種模式不陌生：

![](https://pic.yupi.icu/1/image-20260819094426555.png)

DeepSeek Harness 同樣有模式切換功能，官方把它叫做 Agent 預設。

所謂 Agent 預設，就是 AI 在一次會話中能用哪些工具、遵守什麼系統提示詞、以什麼方式工作的一整套配置。不同的預設組合出來的 AI，幹起活來風格完全不同。

DeepSeek Harness 內建了四種預設，對應四種執行模式，你可以在對話方塊上方的模式選擇器裡直接切換。

![](https://pic.yupi.icu/1/image-20260814145323400.png)

選對預設很重要，寫程式碼、做測試、修 Bug，不同型別的任務適合不同的模式，選錯了可能事倍功半。

下面我先帶大家瞭解一下這四種內建模式，然後再教你怎麼自己定製。



## 四種內建模式



### 標準模式

標準模式是開啟 DeepSeek Harness 之後的預設選項。

它載入了一個 AI 程式設計工具應有的全部能力，包括檔案讀寫、終端命令、聯網搜尋、任務規劃、Skills 技能、子 Agent、待辦管理等等，加起來有 20 多個工具。

![](https://pic.yupi.icu/1/image-20260818210034485.png)

絕大多數場景下用標準模式就夠了，它的覆蓋面足夠廣，遇到什麼任務都能應對。

你看，標準模式下的 DeepSeek Harness 是不是跟 Codex 這種 AI 程式設計工具很像？

![](https://pic.yupi.icu/1/image-20260814143812878.png)

沒錯，你就把標準模式當成國產版的 Codex 來用就好了，AI 程式設計、自動化辦公等任務，都能搞定。

不過工具多也有代價，模型每走一步都要先從這 20 多個工具裡挑一個來用，光是做這個選擇就要佔用一部分推理能力。而且所有工具的說明書都會塞進上下文裡，模型能分給你真正那道題的注意力就被攤薄了。

標準模式下，光是跟 AI 說個「你好」，就要佔用 1 萬多 tokens 上下文！

![](https://pic.yupi.icu/1/image-20260818210415241.png)



### 極簡模式

極簡模式就樸素多了，官方只保留了兩個工具，一個能持續執行的終端和一個檔案編輯器，其他能力全部關掉。

![](https://pic.yupi.icu/1/image-20260818210623289.png)

不只是工具少了，極簡模式的系統提示詞也被鎖成了一句「You are a helpful software engineer assistant」，上下文壓縮、任務規劃、Skills 技能、子 Agent 這些統統沒有。

同樣跟 AI 說一句「你好」，極簡模式只佔用 1000 多 tokens 上下文，比標準模式少了 10 倍！

工具說明書少了，模型能分給任務本身的注意力自然就多了。

![](https://pic.yupi.icu/1/image-20260818210911159.png)

在這個模式下，AI 就像個悶頭幹活的老師傅，不跟你彙報進度、不做花哨的規劃，拿到活兒直接動手嘎嘎寫。

![](https://pic.yupi.icu/1/image-20260815122619221.png)

官方對它的定位很明確，是專門拿來跑模型基準測試的。把環境削到最乾淨，讓不同模型在同一個標準下公平比較。

DeepSeek V4 Pro 的跑分成績用的就是極簡模式，你仔細看跑分圖最下方的小字：V4-Pro 使用 DeepSeek Harness 極簡模式作為框架進行測試。

![](https://pic.yupi.icu/1/HPmOJZlbUAAOgVt-20260818211001128.jpeg)

那把「考試」模式拿來幹活，效果會怎麼樣呢？想了解極簡模式的詳細實測對比，可以閱讀本教程程式設計工具板塊 DeepSeek Harness 目錄中的《DeepSeek Harness 極簡模式實測》。



### PTC 模式

PTC 是 Programmatic Tool Call 的縮寫，翻譯過來就是「程式化工具呼叫」。

在標準模式下，AI 是一步一步呼叫工具的，執行完一個再決定下一個做什麼。每一步都要等模型思考、選工具、返回結果，來來回回要經歷非常多輪。

PTC 模式換了一種思路。模型不再一步步呼叫工具，而是直接生成一段 TypeScript 程式碼，把多步工具呼叫串聯起來一次性執行完。

舉個例子，假設你要把 128 張照片批次重新命名，重新命名工具每次只能處理一張圖片。標準模式下 AI 要一張一張呼叫重新命名工具，每張都要等一個來回。但在 PTC 模式下，AI 直接寫了 5 行 TypeScript 指令碼，用一個迴圈把 128 個檔案全部重新命名了，只需要跟模型互動 1 次。

> 注意，實際情況標準模式應該也不會這麼幹，這裡只是舉個例子便於大家理解區別

![](https://pic.yupi.icu/1/image-20260818211153120.png)

PTC 模式適合那種步驟很多但邏輯清晰的任務，比如批次重新命名檔案、跑一整套自動化流程，效率比一步步確認要高得多。

有意思的是，PTC 模式和標準模式在配置上其實只差一行，就是把工具呈現模式從預設的 `native` 切換成了 `code`。本質上它擁有標準模式的全部工具能力，只是模型呼叫工具的方式不同。

![](https://pic.yupi.icu/1/image-20260818214210342.png)



### 創造模式

創造模式是四個預設裡最特殊的一個。

它繼承了標準模式的全部能力，在此基礎上還額外提供了一組用於操作 Cordis 外掛系統的專屬工具，讓 AI 可以檢查當前執行時有哪些外掛在跑、在記憶體裡試驗新的外掛組合、甚至自己創作出一個全新的模式預設。

![](https://pic.yupi.icu/1/image-20260819102346095.png)

簡單來說，這個模式就是用來改造 DeepSeek Harness 自身的。

在入門教程中，我就是使用創造模式來開發了一個 Harness 桌寵外掛。

![](https://pic.yupi.icu/1/image-20260814135037195.png)

不過創造模式的許可權非常高，按官方的話來說，你要像對待 Shell 訪問一樣對待它的許可權範圍。

所以日常幹活不建議長期開著這個模式，需要開發外掛或者定製預設的時候再切換過來就好。



## 選哪個模式好？

介紹完了四種模式，總結一下它們的核心區別。

這四種模式本質上就是「當前會話載入了哪些工具和配置」的不同組合。

極簡模式只留兩個工具，標準模式配齊全套能力，PTC 模式換了一種工具呼叫方式，創造模式還能讓 AI 自己檢視和改裝當前的外掛配置。

![](https://pic.yupi.icu/1/image-20260814150646065.png)

之前有社群的大佬發現，切換到極簡模式之後，模型在純編碼任務上的速度和表現反而更好了。於是我專門做了一期實測，用同一個 3D 射擊遊戲的任務在標準模式和極簡模式下各跑了一遍。

先看看標準模式的成品效果：

![](https://pic.yupi.icu/1/image-20260815123745988.png)

再看看極簡模式下的成品效果，差別不大。

![](https://pic.yupi.icu/1/image-202608151243407956.png)

但是，標準模式跑了 33 分鐘，極簡模式只用了 23 分鐘，快了將近 10 分鐘！

不過極簡模式的短板也很明顯，沒辦法聯網搜尋、沒有上下文壓縮、沒有任務規劃，你對成品質量的要求越高，極簡模式越容易掉鏈子。

完整的對比測評可以閱讀本教程程式設計工具板塊 DeepSeek Harness 目錄中的《DeepSeek Harness 極簡模式實測》，這裡就不展開了。

我還用 PTC 模式跑了同樣的任務。比標準模式快了 7 分鐘，而且整個任務只用了 1 輪 18 步，比標準模式精簡了很多。Tokens 消耗也低了不少，輸入只用了 150 萬，不到標準模式 520 萬的三分之一。

PTC 模式的成品效果也是我覺得三種模式裡最好的：

![](https://pic.yupi.icu/1/image-20260818215427583.png)

總結就一句話，圖快就用極簡模式，圖穩就用標準模式，步驟多的自動化任務試試 PTC 模式。



## 自定義 Agent 預設

除了使用四種內建模式外，如果你有特定的工作習慣或者經常做某一類任務，可以給自己量身定製一個專屬的 Agent 預設。

舉個例子，Cursor 有一個很受歡迎的 Debug 模式，它會讓 AI 先生成假設、插入日誌、讓你復現 Bug、再根據執行時資料來定位根因，整個排查過程非常有章法。

![](https://pic.yupi.icu/1/image-20260707183325681.png)

這套思路完全可以搬到 DeepSeek Harness 上來。

DeepSeek Harness 支援自定義預設，可以切換到 **創造模式**，讓 AI 幫你建立想要的預設。

比如我要讓 AI 建立一個「Debug 模式」，只需要給 AI 提供 Cursor Debug 模式的官方文件作為參考，讓它據此來編寫預設就行了。

提示詞可以這樣寫：

```markdown
基於標準模式建立一個自定義 Agent 預設，名稱為「Debug 模式」。
要求復刻 Cursor IDE 的 Debug 模式工作方式。
必須參考 Cursor 官方文件來設計：https://cursor.com/docs/agent/debug-mode
```

提交任務後，可以看到 AI 自動載入了編輯預設的技能，然後透過終端抓取了 Cursor Debug 模式的官方文件頁面，提取出了 Debug 模式的核心工作流程。

![](https://pic.yupi.icu/1/image-20260819105013846.png)

幾分鐘後，AI 完成了任務。它從標準模式複製了一份預設，然後修改了兩個檔案，一個是存放預設名稱和描述的 `preset.yml`，另一個是定義 Agent 工具和角色人設的 `agent.cordis.yml`，把 Debug 模式的六步工作流和硬性規則都寫了進去。

![](https://pic.yupi.icu/1/image-20260819105116895.png)

建立完成後，你在模式選擇器裡就能看到這個自定義的「Debug 模式」了。

![](https://pic.yupi.icu/1/image-20260819114556459.png)

以後遇到那種能復現但是找不到原因的疑難 Bug，切換到這個模式修復就行，AI 會按照「假設 → 插樁 → 復現 → 分析 → 修復 → 清理」的流程來幫你排查，比直接讓 AI 憑著經驗來改要靠譜得多。

![](https://pic.yupi.icu/1/image-20260819114746666.png)



## 更多玩法

同樣的套路，你可以復刻各種專用模式。

比如建立一個「程式碼審查模式」，讓 AI 只做程式碼審查不做修改，從安全性、效能、可讀性等維度逐一檢查，最後輸出一份審查報告。

或者建立一個「文件模式」，讓 AI 專注於給程式碼寫註釋、生成 API 文件、更新 README 專案介紹文件。

又比如搞一個「重構模式」，讓 AI 先分析專案中的冗餘程式碼和重複邏輯，再製定重構計劃，最後逐步執行，每一步都跑通測試才往下走。

本質上，自定義預設就是給 AI 設定一套固定的工作 SOP，你把自己做某類任務時的最佳實踐寫進系統提示詞裡，AI 就會每次都按這個流程來執行。如果你之前接觸過 AGENTS.md 或者 CLAUDE.md，應該會覺得很熟悉，它們的思路是一樣的，都是透過配置檔案來約束 AI 的行為方式。



## 寫在最後

Agent 預設是 DeepSeek Harness 裡一個非常實用的功能，選對模式能讓你的工作效率翻倍。

日常開發用標準模式就夠了，追求速度的純編碼任務可以切換到極簡模式，批次自動化任務試試 PTC 模式，需要開發外掛或者定製預設的時候再用創造模式。

如果你經常做某一類重複性任務，強烈建議花幾分鐘定製一個專屬預設，一次配置、長期受益。

想了解 DeepSeek Harness 的更多進階玩法，可以繼續閱讀本教程程式設計工具板塊 DeepSeek Harness 目錄中的其他文章。
