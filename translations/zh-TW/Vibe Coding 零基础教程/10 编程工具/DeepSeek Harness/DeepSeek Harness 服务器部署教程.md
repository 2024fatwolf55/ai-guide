## DSH 伺服器部署教程

首先，我們需要準備一臺雲伺服器。這篇教程所用的伺服器配置為 2C 2G，也就是 2 個 CPU 核心加 2 GB 記憶體，作業系統為 Debian 12.15，實測剛好能穩定執行 DSH。

建議大家使用不低於這個配置的伺服器，配置太低可能會導致 DSH 執行不穩定。



### 1、連線到伺服器

如果你用的是騰訊雲、阿里雲、華為雲等主流大廠的雲伺服器，可以直接透過網頁控制檯登入伺服器。

比如阿里雲伺服器，支援透過 Workbench 遠端連線：

![](https://pic.yupi.icu/hackdeacon/62199223013191388358370042eb5134.png?imageSlim)

除了網頁登入，你也可以透過 SSH 連線到伺服器，大家可以查閱對應雲服務商的官方文件瞭解具體操作。

成功連線伺服器後，我們接下來需要安裝一個伺服器管理面板，省的在小黑框裡操作。常見的有寶塔面板、1Panel 面板等。



### 2、安裝 1Panel

這裡我們以 1Panel 為例。1Panel 是一款現代化的開源 Linux 伺服器運維管理面板，介面簡潔好用，而且內建了應用商店，可以一鍵安裝各種服務。

![](https://pic.yupi.icu/hackdeacon/20260819093905184.png?imageSlim)

在伺服器的終端中，執行 1 行命令就能安裝 1Panel：

```
bash -c "$(curl -sSL https://resource.fit2cloud.com/1panel/package/v2/quick_start.sh)"
```

安裝的第一步需要選擇語言，我們輸入 `2` 並按回車鍵來選擇中文。

![](https://pic.yupi.icu/hackdeacon/install.png?imageSlim)

接下來要選擇安裝目錄，直接回車，使用預設路徑 `/opt` 就行。

然後系統會問你是否安裝 Docker，輸入 `y` 確認。這一步可能會因為網路環境稍慢一些，耐心等待幾分鐘就好。

![](https://pic.yupi.icu/hackdeacon/opt.png?imageSlim)

Docker 安裝完成之後，來到安裝面板的最後一個環節，配置面板資訊。

![](https://pic.yupi.icu/hackdeacon/b4db65d99ef2a93454da26d7dd84af97.png?imageSlim)

先是 **配置映象加速**。國內網路訪問 GitHub、Docker 等資源會比較慢，所以有必要開啟映象加速，輸入 `y` 並回車即可。

接著 **設定 1Panel 的訪問埠**。這個埠會拼接在你的伺服器 IP 地址後面，用來訪問管理面板。舉個例子，假設伺服器 IP 是 `114.51.41.xx`，你把埠設定成 `9810`，那麼訪問面板的地址就是 `114.51.41.xx:9810`。

你可以直接回車使用 1Panel 隨機生成的埠號，也可以自己設定一個好記的數字。不過要注意避開一些常用服務已經佔用的埠號，我給大家整理成了一張圖片方便參考：

![](https://pic.yupi.icu/hackdeacon/20260817171536312.png?imageSlim)

接下來是 **設定 1Panel 安全入口**，相當於訪問管理面板時額外需要的一個口令，也是拼接在地址後面的。比如你設定成 `ikun`，那根據上面的例子，訪問管理面板的完整地址就是 `114.51.41.91:9810/ikun`。這樣一來，就算別人知道了你伺服器的 IP 和埠，沒有安全入口也進不去。

這一步同樣可以直接敲回車使用隨機入口，但我強烈建議你設定一個自己記得住的。

最後是 **設定面板的使用者名稱和密碼**，這一步就不用多說了，設定完之後就算有人知道了安全入口，也會被使用者名稱和密碼擋在外面。三重防護，安全拉滿。

![](https://pic.yupi.icu/hackdeacon/20260818094731552.png?imageSlim)



### 3、開放防火牆埠

這一步也至關重要，只有開放了防火牆埠，你才能從外部正常訪問伺服器上的服務。

以阿里云為例，我們進入雲伺服器 ECS 的管理後臺，找到「安全組」，在「入方向」裡點選「增加規則」。如果你用的是其他廠商的伺服器，也是找到類似「防火牆」或「安全組」的設定頁面。

![](https://pic.yupi.icu/hackdeacon/f3f0b07035f44fb2cd0c9e7efcdd81ce.png?imageSlim)

訪問來源選擇 `0.0.0.0/0（任何位置）`，然後在訪問目的埠中填入剛才為 1Panel 設定的埠號。

這裡可以順便把後面 DSH 要用到的埠也一起加上，比如 `10443`。你也可以自定義，只要不和上面的避讓清單衝突就行。

全部填好之後點選提交。

恭喜你，看到這裡你已經打敗了 66.66% 的同學！

![](https://pic.yupi.icu/1/image-20260820122944494.png)

前置工作全部完成，接下來我們正式安裝 DeepSeek Harness。



### 4、安裝 DSH

在瀏覽器中輸入 `IP 地址:埠號/安全口令` 來訪問 1Panel 管理後臺。

進入首頁後，你可以看到伺服器當前的執行狀態和記憶體佔用。

![](https://pic.yupi.icu/hackdeacon/6516be4bd4254146759ac9538ffbeef3.png?imageSlim)

點選左側選單進入應用商店，搜尋 DeepSeek Harness，能看到 1Panel 已經內建了這個應用，直接點選安裝。

![](https://pic.yupi.icu/hackdeacon/9f10e076076ef37cb62b3bcbe74c0629.png?imageSlim)

安裝介面中有幾個需要注意的配置項。

- HTTPS 埠：填剛才在防火牆安全組裡為 DSH 分配的埠號，比如 `10443`
- 訪問地址：填你伺服器的公網 IP 地址
- Web 使用者名稱和密碼：就是之後訪問 DSH 時需要的登入憑證

![](https://pic.yupi.icu/hackdeacon/ad4e2451202feae6ad4b7b9e685ab400.png?imageSlim)

這裡科普一下，DSH 本身其實是沒有內建登入認證的，它的 Web 伺服器甚至故意拒絕繫結到 `0.0.0.0`（也就是公網可訪問的地址），就是為了防止被未經授權的人訪問。而 1Panel 應用商店裡的這個版本整合了 Caddy 反向代理來提供 HTTPS 加密和使用者名稱密碼認證，所有外部訪問都必須先透過 Caddy 鑑權才會轉發給 DSH，安全性有了保障。

最後，勾選高階設定，開啟埠外部訪問，然後點選右下角的確認按鈕開始安裝。

![](https://pic.yupi.icu/hackdeacon/20260817183203204.png?imageSlim)

耐心等待安裝完成後，我們就可以透過 `IP:10443` 來訪問 DeepSeek Harness 了。

由於我們還沒有配置自己的域名和正式的 HTTPS 證書（1Panel 用的是自簽名證書），瀏覽器會提示安全性問題，這是正常現象，無視風險繼續訪問就行。

![](https://pic.yupi.icu/hackdeacon/20260817184102752.png?imageSlim)

輸入剛才設定好的 Web 使用者名稱和密碼就可以登入了：

![](https://pic.yupi.icu/hackdeacon/20260817182501027.png?imageSlim)

進入 DSH 之後，第一件事就是配置模型。你可以直接填入 DeepSeek 的 API Key，也可以在設定裡切換到其他模型提供商。DSH 相容 OpenAI 介面格式，所以市面上大多數相容 OpenAI API 的模型服務都能直接接入。

> 到 DeepSeek 開放平臺獲取 API Key：https://platform.deepseek.com/api_keys

![](https://pic.yupi.icu/1/image-20260814130304526.png)

還有一點需要注意。因為 DSH 是執行在雲端伺服器上的，所以無法像在本地一樣直接開啟你電腦上的專案資料夾。你需要在工作區裡手動建立專案目錄，也可以讓 DSH 用 `git clone` 把 GitHub 上的專案拉取到伺服器上。

首次體驗的話，建議大家先用一個測試專案，不要直接指向生產環境的程式碼倉庫，畢竟 Agent 是有檔案讀寫和命令執行許可權的。

![](https://pic.yupi.icu/hackdeacon/20260817185045890.png?imageSlim)

到這裡，所有準備工作就完成了，可以開始體驗多裝置訪問了。



### 5、體驗演示

理論上，只要伺服器配置扛得住，同時訪問的裝置數量是不受限制的。我自己用三四臺裝置同時訪問也沒有任何壓力，而且專案會話、聊天記錄、外掛環境全部都是實時同步的。

這裡我裝了坤坤的主題皮膚，可以看到不管是手機還是電腦，開啟 DSH 之後皮膚都是同步的。

![](https://pic.yupi.icu/hackdeacon/20260817192624023.png?imageSlim)

文字的流式輸出也是完全同步的，一臺裝置上正在生成的內容，另一臺裝置同步就能看到。

手機端體驗的話，推薦裝一個移動端 UI 適配外掛 `mexiaosqwq/dsh-web-mobile`，它會在窄屏下自動把側邊欄收成抽屜、會話區鋪滿全寬，互動體驗會好很多。

![](https://pic.yupi.icu/hackdeacon/20260819173700357.jpg?imageSlim)

一行命令就能安裝：

```bash
dsh plugin --profile web add github:mexiaosqwq/dsh-web-mobile
```

如果你想快速上手 DeepSeek Harness，學習基礎用法，可以閱讀本教程程式設計工具板塊 DeepSeek Harness 目錄中的《DeepSeek Harness 保姆級入門教程》。



### 6、域名繫結

用 IP + 埠號的方式雖然能夠訪問 DSH，但不夠方便也不夠安全。如果你手頭有域名的話，推薦給 DSH 繫結一個域名，這樣不僅好記，還能配上正式的 HTTPS 證書。

操作起來並不難，首先進入 1Panel 左側選單的「網站」頁面，1Panel 會提示你安裝 OpenResty，點選去商店安裝即可。

![](https://pic.yupi.icu/hackdeacon/20260818104728584.png?imageSlim)

所有設定保持預設即可，直接點選安裝。

![](https://pic.yupi.icu/hackdeacon/20260818105003532.png?imageSlim)

安裝完成後，再次回到左側選單的「網站」頁面，點選建立。

![](https://pic.yupi.icu/hackdeacon/20260819155642959.png?imageSlim)

這裡可以選擇「一鍵部署」或「反向代理」來完成域名繫結。

![](https://pic.yupi.icu/hackdeacon/20260818105639844.png?imageSlim)

![](https://pic.yupi.icu/hackdeacon/20260818105710699.png?imageSlim)

光在 1Panel 裡配置還不夠，你還需要到雲服務商的域名控制檯，給伺服器 IP 配置 DNS 域名解析。

在域名解析設定裡新增一條記錄，記錄型別選擇 `A`，主機記錄（名稱）填 `dsh`，記錄值填你的伺服器公網 IP。

![](https://pic.yupi.icu/hackdeacon/20260818170549641.png?imageSlim)

儲存之後等待解析生效，再用完整的域名地址訪問就能看到 DeepSeek Harness 了。

需要注意的是，如果 DSH 是部署在國內的伺服器上，需要先完成 ICP 備案，才能正常進行域名訪問。沒有備案的話，運營商會攔截請求，頁面是打不開的。

![](https://pic.yupi.icu/hackdeacon/20260818110235684.png?imageSlim)



## 為什麼選擇伺服器部署？

看到這裡，有同學可能要問了：Vercel、Cloudflare、Netlify 這些平臺這麼方便，還不用自己準備伺服器，為什麼不把 DSH 部署在上面呢？

因為 DSH 不是一個單純的前端網頁，它是一個需要長期存活、持續讀寫檔案、不斷執行指令碼命令的「AI 員工」，需要一個穩定的執行環境作為它的家。

而 Vercel、Cloudflare、Netlify 這些平臺主打的是 Serverless 無伺服器架構。

![](https://pic.yupi.icu/1/image-20260526190516543.png)

注意，Serverless 並不是真的沒有伺服器，而是你只有伺服器的臨時使用權，伺服器由平臺統一管理和排程，讓你用起來幾乎不需要自己透過命令列來操作伺服器，更方便。

為什麼說是臨時使用權呢？

程式碼部署到 Serverless 平臺後，只有收到請求的時候才會啟動一個執行例項，請求處理完就銷燬。這就是它的核心設計理念「用完即焚」。

這個理念本身很適合 API 介面、靜態網站這類「來一個請求處理一個」的場景，但對 DSH 來說完全不適用。

DSH 需要持久的檔案系統來儲存專案程式碼和會話記錄，需要真正的終端來執行 shell 命令，還需要長時間執行來處理複雜的多步任務。而 Serverless 平臺的檔案系統是隻讀或臨時的，沒有持久化終端，還有嚴格的執行超時限制，函式跑完就銷燬，根本沒法滿足這些需求。

所以，最好還是把 DSH 老老實實部署在一臺有完整作業系統的伺服器上。



## 區域網部署

如果你還沒有云伺服器，或者想讓所有 AI 生成的產物都保留在本地，區域網部署也是一個不錯的選擇。

使用區域網部署 DSH 後，可以在家裡的裝置之間共享，一臺主力機跑著 DSH，躺床上用平板也能連過去檢視 AI 的工作進度，全家裝置共用一套環境。

如果你在辦公室搭了一套共享的 DSH，同事們在同一個 Wi-Fi 下就能訪問，不需要每個人都裝一遍。

聽上去還是很實用的吧，具體怎麼操作呢？

由於 DSH 的外掛生態太豐富了，已經有不少外掛能很好地解決區域網訪問這個需求。

社群裡有一個很火的全家桶外掛 [dsh-web-ui](https://github.com/zhu1090093659/dsh-web-ui)，不僅內建了區域網遠端訪問功能，還提供了任務看板、Git 圖譜、移動端遠端控制、皮膚中心等一整套功能增強。這個專案在 GitHub 上已經有幾千 Stars，大家有興趣可以去體驗一下。想了解更多 DSH 外掛，可以閱讀本教程程式設計工具板塊 DeepSeek Harness 目錄中的《DeepSeek Harness 精選外掛推薦》。

![](https://pic.yupi.icu/1/13-hero-main.png?imageSlim)

如果你不想裝全家桶，只需要區域網訪問功能的話，也可以單獨安裝對應的外掛。

我根據不同的使用場景，把相關的外掛整理成了一張圖片，大家按需選擇就好：

![](https://pic.yupi.icu/hackdeacon/20260818150215666.png?imageSlim)

這裡補充一個技術細節。DSH 預設只監聽 `127.0.0.1` 本機迴環地址，官方在 CLI 層面故意拒絕了 `--host 0.0.0.0` 的繫結請求，就是為了防止把 Agent 的命令執行能力直接暴露到網路上。

上面這些區域網外掛的工作原理，就是透過 bundle patch 在外掛層面把 webserver 繫結到 `0.0.0.0`，同時注入 `crypto.randomUUID` 的 polyfill 來解決非 HTTPS 環境下瀏覽器 API 缺失的問題。雖然方便，但區域網訪問意味著同網路下的任何裝置都能連上你的 DSH，所以只建議在家庭、公司這種可信的內網環境中使用。



## 寫在最後

看到這裡，你應該能感受到 DeepSeek Harness 有多開放。

除了「一切皆外掛」之外，DSH 本身選擇 Web 形態而不是桌面客戶端，意味著它天然支援遠端訪問、多裝置同步、團隊協作，這種開放性是那些只能在本地跑的 Agent 工具不具備的。

如果你想隨時隨地使用 DSH、跟團隊共享，又或者是擔心 AI 破壞了你自己電腦的檔案，都可以跟著這篇教程來試試雲端 DSH。

如果你想快速上手 DeepSeek Harness，學習基礎用法，可以閱讀本教程程式設計工具板塊 DeepSeek Harness 目錄中的《DeepSeek Harness 保姆級入門教程》。
