> 全球最貴 AI 模型實測對比：Fable 5 vs Opus 4.8 vs GPT-5.5

大家好，我是程式設計師魚皮。

就在剛剛，Anthropic 釋出了新一代模型 **Claude Fable 5**，同時還放出了一個面向專業安全人員的「解限版」叫 Claude Mythos 5。

![](https://pic.yupi.icu/1/1781053123369-84164e0d-6682-48a1-bf69-98300e8ade11.png)

官方把它稱為「神話級」模型，能力凌駕於之前的 Opus 系列之上。據說 Stripe 公司在自己 5000 萬行的 Ruby 程式碼庫裡測了一圈，一天就搞定了團隊原本要兩個月才能完成的遷移工作。

這篇文章我會先帶大家看看 Fable 5 到底更新了什麼，然後上兩輪硬核實測，分別讓 Fable 5、Opus 4.8 和 GPT-5.5 同場競技，看看新模型的 AI 程式設計能力到底怎麼樣。

友情提示，這次的測試成本有點高，希望大家心疼一下我的錢包，把這篇文章看到最後哦。



## Claude Fable 5 更新了什麼？

### 1、一個模型，兩個名字

這次 Anthropic 同時放出了 Fable 5 和 Mythos 5，但它倆其實是 **同一個底層模型**，能力完全一樣。區別只在「安全護欄」的鬆緊程度上。

Fable 5 面向所有人，今天就能用。但加了一層安全分類器，遇到涉及網路安全、生物化學或模型蒸餾（防止別人偷學能力去訓練競品）的請求時，會降級到 Opus 4.8 來回答你，並且給你一條提示。

Mythos 5 是把護欄拆掉的「完全體」，只發給 Anthropic 稽核過的網路安全機構和少數生物研究人員，普通人接觸不到。

關於 Fable 5 的降級機制，官方說平均不到 5% 的會話會觸發。但我測試使用 Fable 5 來寫文章的能力時，就觸發了安全過濾，直接被切換到了 Opus 4.8。

不是哥們，寫個文章哪裡不安全了？！

![](https://pic.yupi.icu/1/1781053278660-299797cf-fc94-41d3-8418-c2d5b0c19a89-20260610123536602.png)

肯定有朋友好奇，為什麼這次更新不延續 Opus 系列，來個 Opus 4.9，而是直接跳到第 5 代？

因為它根本不是 Opus 這個級別的模型了，而是 Anthropic 內部一個更高的等級，叫 **Mythos 級**，能力直接碾壓 Opus。

> 有趣的是，Fable（寓言）這個詞本身就源自拉丁語 fabula，和希臘語的 Mythos（神話）是近親。

簡單來說，就是同一把刀，一把開了刃給專業人士，一把套了刀鞘發給大眾。



### 2、定價全球最貴

Claude Fable 5 和 Mythos 5 的定價是每百萬輸入 token 10 美元、輸出 50 美元。

聽起來你可能沒什麼感覺，但是對比一下目前主流模型的價格，你就知道有多離譜了：

| 模型               | 輸入 / 輸出（每百萬 token） | 總成本  |
| ------------------ | --------------------------- | ------- |
| DeepSeek V4        | $0.4 / $0.8                 | $1.2    |
| Claude Opus 4.8    | $5 / $25                    | $30     |
| GPT-5.5            | $5 / $30                    | $35     |
| **Claude Fable 5** | **$10 / $50**               | **$60** |

Fable 5 的總成本直接是 Opus 4.8 的兩倍、DeepSeek V4 的 50 倍，穩坐目前主流模型裡最貴的位置。官方還特意強調了，這已經比之前的 Mythos Preview 便宜了一半多。

好傢伙，便宜一半還是最貴的，以後的模型怕是普通人真的用不起了……

注意，官方說從今天到 6 月 22 號，Pro、Max、Team 這些套餐可以免費使用 Fable 5。但 **6 月 23 號之後就要單獨花「用量積分」了**，等產能上來再恢復。所以想白嫖體驗的，一定要利用好這兩週的視窗期。



### 3、跑分炸裂

每次新模型出來都得看看跑分。官方說 Fable 5 幾乎在所有測試過的基準上都是 SOTA，尤其在程式設計、知識工作、視覺、科學研究這幾個方向。而且 **任務越長、越複雜，它領先得越多**。

說實話我已經有點麻了，因為各家基本都說自己是 SOTA 最佳水平……

但這次 Fable 5 的成績，確實配得上「炸裂」兩個字。

![](https://pic.yupi.icu/1/1781053155639-63c73b4b-f732-44e8-bf48-7efaeb314e11.png)

挑幾個亮眼的資料說說：

- SWE-bench Pro（Agent 程式設計能力）是 80.3%，遠超 GPT-5.5 的 58.6% 和 Opus 4.8 的 69.2%
- FrontierCode（高質量編碼）是 29.3%，Opus 4.8 只有 13.4%，GPT-5.5 是 5.7%
- 視覺能力（GDPpdf 文件推理）是 29.8%，GPT-5.5 是 24.9%，Opus 4.8 是 22.5%。官方讓 Fable 5 去玩寶可夢火紅版，純視覺就通關了。

好傢伙，這是斷層式的提升啊！

不過跑分是一方面，好不好用還是得拿到真實專案裡檢驗才知道。所以老規矩，我帶大家動手測一測，拿 Fable 5、Opus 4.8 和 GPT-5.5 同場競技。

## 實戰測評一、全棧專案一把梭

第一個測評，我選了一個有代表性的全棧專案來測模型的綜合編碼能力。

專案叫「TaskFlow 任務管理看板」，類似簡化版飛書看板，包含 7 個功能需求：使用者註冊登入、三列看板拖拽、任務增刪改查、資料圖表面板、搜尋篩選、暗色 / 亮色主題切換、響應式設計。技術棧是 React + TypeScript 前端 + Python FastAPI 後端 + SQLite 資料庫。

選這個專案的原因是它前後端都有、互動複雜度適中，能同時考察模型的 UI 審美、工程能力和功能完整度。

這次參賽的選手是 **Claude Fable 5**、**Claude Opus 4.8** 和 **GPT-5.5**。3 個模型使用完全相同的提示詞，全部開到 High thinking 檔位，全程零人工干預。

## 實戰測評二、重構 Claude Code 原始碼

第二輪測評才是這次的重頭戲。

官方反覆強調，**任務越長、越複雜，Fable 5 領先得越多**。短平快的 demo 根本測不出代際差距，要測就得上真正的長程任務。

對了，前段時間 Claude Code 不是把自己 50 多萬行的原始碼給洩露了嗎？

這份程式碼是真正的工業級 Agent 架構，拿來做測試再合適不過了。

說幹就幹。具體做法是把洩露的 Claude Code 原始碼包提供給模型，讓它自主分析裡面的架構設計，然後從零重構一個能在終端實際執行的命令列 AI 程式設計助手「Yupi Code」。全程不需要人工干預，看它能不能一次搞定。

提示詞如下：

```markdown
你是一個資深的 TypeScript 全棧工程師，精通 AI Agent 架構和命令列工具開發。

claude-code-origin 目錄下是 Claude Code 洩露的部分原始碼，包含完整的實現邏輯，但無法執行。

你要先閱讀並理解這份原始碼的核心設計，在此基礎上重構一個命令列 AI 程式設計助手「Yupi Code」，放到新目錄下。

要求必須能實際執行，各項功能正常可用。
```

### 開發過程對比

看完了最終效果，我又新開了一個對話，讓 AI 幫我分析幾個模型各自完成任務的對話記錄，看看開發過程到底有什麼不同。

最關鍵的發現是，**Claude Fable 5 是唯一做了 PTY 終端互動式測試的模型**。

![](https://pic.yupi.icu/1/1781058521904-b1f23509-52e4-4407-afaf-1105e49ed3e4.png)

Opus 4.8 雖然寫了最多的測試，但所有驗證都在非互動環境下進行，從來沒有在真實終端裡驗證過互動效果。結果到使用者手裡，輸出顯示就出了問題。

Fable 5 雖然沒有寫 mock 測試套件，但它做了 Opus 沒做的事情，**用 PTY 在真實終端裡反覆除錯互動**（用 script 命令模擬 PTY，驗證 /help、/cost、許可權對話方塊、寫檔案全流程）。它花了大量輪次調通了 PTY 下回車鍵 `\r` → `\n` 的問題，修復了 API 協議 Bug，這些投入最終換來了最好的使用者體驗。

這給了我一個很重要的啟發。**「AI 自己測試透過」和「使用者實際能用」之間，隔著一個巨大的鴻溝**。在 CLI 這種場景下，在真實環境中調通互動，遠比在隔離環境中跑測試更能保障最終質量。

透過功能覆蓋矩陣，可以更直觀地看到差距。Fable 5 做了完整的 Ink TUI、上下文壓縮、自動複用本地配置這些其他模型都沒做的功能，而 GPT-5.5 連最基本的 Read 工具都報錯，功能嚴重缺失：

![](https://pic.yupi.icu/1/1781059044766-2644ca30-1003-4c6d-a559-c9453a649b34.png)

從架構理解、工程執行、驗證與可用性、開箱即用和價效比這五個維度來打分。Opus 4.8 在架構理解上最強，但 Fable 5 在驗證和開箱即用兩個維度上直接拉滿，形成了明顯的差異化優勢：

![](https://pic.yupi.icu/1/1781059103060-40d41546-5c2f-4158-b0b6-2507246b7735.png)

最終綜合評分，Claude Fable 5 以 8.3 分排名第一。它不是每項都最強，但光是「唯一能交付可用產品」這一條就壓過了其他模型。畢竟我們用 AI 程式設計，最終目的就是想省心地直接拿到能用的成果，而不是拿到一堆還需要自己修的半成品。

![](https://pic.yupi.icu/1/1781059149037-63336958-f848-42f7-a1fb-853d830f5c21.png)

回頭看這三個模型的策略，其實很像一個經典的不可能三角。

**速度、成本、質量，不可能三角。**

GPT-5.5 選了速度和成本，結果不能用；Opus 4.8 選了程式碼質量和成本，但驗證有盲區；Fable 5 選了質量和使用者體驗，代價就是貴。

當然，這只是我的一次測試，不代表普遍規律。但可見一斑，Fable 5 在「長程任務最終交付可用產品」這件事上，確實比上一代有質的飛躍。

結合這次測評，我可以給到大家一些模型選擇的建議。

如果你要做大規模重構、遷移這種又長又複雜的專案，選擇 Fable 5 最好，貴有貴的道理。但日常一把梭中小專案，Opus 4.8 的程式碼質量高、架構完整，價效比明顯更高。GPT-5.5 雖然這次表現拉了，但它在終端自動化和命令列相關任務上的跑分還是領先的，適合追求速度的自動化任務。預算比較緊的話，用國產模型也完全可以應付大多數場景。

總之，**別盲目追新，按你的真實需求來選**。最貴的不一定最適合你。



## 最後嗶嗶

OK，測試就到這裡。我覺得 Fable 5 這次的表現符合我對新一代模型的預期，AI 程式設計的能力在快速逼近「能獨立交付完整專案」的水平了，但這個價格，大多數人是真的用不起。到底值不值，得看你的時間和錢哪個更貴。

但其實這次測評給我印象最深的，不是 Fable 5 本身的實力，而是它背後的釋出方式。

同一個模型，套上不同鬆緊的護欄，然後拆成通用版和解限版發給不同的人。遇到敏感問題時，不直接拒絕，而是降級到上一代模型來回答你。雖然之前也有模型限流時降級的例子，但像這樣從產品設計層面就把「分級釋放」做成核心機制，Anthropic 算是第一個這麼幹的。

我的判斷是，隨著模型能力越來越強，這種模式很可能會被越來越多的廠商抄作業。以後你用的那個「最新最強模型」，用著用著說不定就換成別的模型了。

**作為使用者，至少我們得知道這件事。**
