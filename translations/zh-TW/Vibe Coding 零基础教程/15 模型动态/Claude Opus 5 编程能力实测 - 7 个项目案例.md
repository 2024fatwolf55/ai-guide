# Claude Opus 5 程式設計能力實測 - 7 個專案案例

> 號稱半價追平旗艦，用 7 個真實專案驗證一下 Opus 5 到底幾斤幾兩

大家好，我是程式設計師魚皮。

前幾天 Anthropic 釋出了 Claude Opus 5，官方宣稱它只用一半的價格，就能把能力追平自家最貴的 Claude Fable 5 旗艦模型。

這個模型的跑分確實很能打。比如 Frontier-Bench 這個測試，專門考察模型能不能在命令列裡獨立做完一整套程式設計任務，Opus 5 拿了 43.3%，上一代 Opus 4.8 只有 18.7%，頂配的 Fable 5 是 33.7%，OpenAI 的 GPT-5.6 Sol 是 37.5%。

![](https://pic.yupi.icu/1/HOAffmCWsAA1D_X-20260728104640570.png)

但是跑分不能完全相信，模型好不好用，還得拿真實專案來檢驗。

所以這篇文章我會用 **7 個不同型別的專案** 來實測 Opus 5 的程式設計能力。為了能和其他模型公平對比，我用的提示詞跟之前測 Kimi K3 時一模一樣（可以閱讀本教程模型動態板塊中的《Kimi K3 程式設計能力實測 - 7 個專案案例》瞭解那次測試）。

測試方法很簡單，我在 Cursor 裡同時開了多個子 Agent，每個 Agent 分配一個獨立的專案目錄和獨立的埠，全程不需要人工干預，等跑完了我再一個一個驗收。

![](https://pic.yupi.icu/1/image-20260728101254851.png)

激動的心，顫抖的手，咱們開始~



## 7 個測試專案

這次準備的 7 個專案，從簡單的前端動畫到複雜的全棧產品，由淺入深：

1. 互動式動畫講解網站
2. 3D 版動畫知識講解
3. 文案拆解為網頁 PPT
4. 網頁 PPT 生成工具（內建 AI 大模型）
5. 足球對戰網頁遊戲（橫評對比）
6. 以撒的結合肉鴿遊戲
7. 全棧 AI 程式設計工具（復刻 Cursor）

大家可以猜猜看，跑完這些任務要花多少錢？答案在結尾揭曉。



### 1、互動式動畫講解網站

第一個專案，讓模型做一個用互動式動畫講解知識的網站，講的知識點是「注意力殘差」。

提示詞裡我要求它先用 Firecrawl 聯網搜尋技術細節，做完之後自己開啟截圖驗證效果，不滿意就自主調整，改到滿意再交付。

![](https://pic.yupi.icu/1/image-20260717111349321-20260717144613538-20260728104640628.png)

來看成品，介面科技感滿滿，背景還有漂浮的光點特效。

而且整個網站很清晰、很結構化，讀者可以像看教程一樣連貫地學會這個知識，也可以透過左側的章節導航快速跳轉、查漏補缺。

![](https://pic.yupi.icu/1/1785144666553-66077ab6-a75d-4730-84d7-963dc05f8a50.png)

第一部分它用「一張越寫越花的便利貼」來引出問題，這個比喻很生動。你可以拖動滑塊來增加堆疊的層數，能親眼看到第 1 句話在最終畫面裡的份量越來越少，最後基本讀不清了。

![](https://pic.yupi.icu/1/1785144739223-15eb9fb7-2cd2-440e-824c-3e44e9e10b37.png)

不過頁面上存在一些瑕疵，比如出現了文字被遮擋的情況，這點比 Kimi K3 的前端效果差了一些。

![](https://pic.yupi.icu/1/1785144789542-88677a5c-d92a-4a8d-8be9-cc13e3bce750.png)

但大多數動畫效果和元素位置都是準確的，比 Opus 4.8 做動畫網站的體驗好太多了。

![](https://pic.yupi.icu/1/1785144946281-9a41c9f8-f0ab-4b60-864e-28c26c6b65fb.png)

它甚至還給出了幾道題目來檢測學習效果，選錯了會告訴你為什麼錯，細節很到位。

![](https://pic.yupi.icu/1/1785144892860-fed3bc03-d72a-4b79-aa9d-f904fec855d3.png)



### 2、3D 版動畫知識講解

還是同一個知識點，這次換成 3D 場景來呈現。

提示詞裡除了聯網搜尋，我還要求它用 Context7 查一下所用 3D 庫的最新文件，別拿過時的 API 來寫。

![](https://pic.yupi.icu/1/image-20260717111408539-20260717144615047-20260728104641704.png)

來看成品，我剛開啟頁面就被驚豔到了，科技感爆棚，而且動畫非常流暢生動。

![](https://pic.yupi.icu/1/1785145006075-8be31bfa-8f84-466c-ae7d-b58366524c51.png)

可以自由切換視角、放大縮小，還能並排對比多種不同的殘差模式。

![](https://pic.yupi.icu/1/1785145067089-c8c05cfb-e1a3-4f3c-abe8-e3c30aa1390e.png)

從事教育行業的朋友有福了，可以讓 AI 把枯燥的知識點透過動畫栩栩如生地展示清楚，讓學生更快理解。

單從前端的角度，我真的挑不出缺點。



### 3、文案拆解為網頁 PPT

我做影片教程的時候，偶爾需要把文章內容做成演示畫面，但手動做 PPT 太慢了。

這次我乾脆把一篇技術文章丟給它，讓它按照文章的講解順序，拆成一個能全屏演示的網頁 PPT，後續可以當做影片錄製的畫面素材。

![](https://pic.yupi.icu/1/image-20260717111421384-20260717144616722-20260728104642024.png)

先看封面，這個大標題…… 現在怎麼 Claude 也一股子 GPT 味兒了。

![](https://pic.yupi.icu/1/1785145163594-b863aa42-a51d-4440-988e-585ce57ef50e.png)

整個 PPT 的效果跟其他模型差不多，畢竟我沒給 AI 提供圖片等素材，無非就那麼幾種佈局。

![](https://pic.yupi.icu/1/1785145204715-e3eaf964-6677-426f-976c-7e3fb229e831.png)

不過科技感還是很足的，對於很多場合下的 PPT 講演都夠用了。比如做畢業設計的同學，直接把自己的專案甩給 AI，畢設答辯 PPT 就搞定了。

![](https://pic.yupi.icu/1/1785145242391-0e506acc-4b23-4167-9d5c-e52a400cb7e8.png)



### 4、網頁 PPT 生成工具

前面 3 個都是開胃小菜，接下來該測測它的全棧工程能力了。

上一個案例是給定一篇文章生成 PPT，那能不能把這個能力做成一個通用工具呢？

使用者貼上任意文案，後端呼叫大模型拆解內容，前端渲染成可演示的網頁 PPT，還要支援切換配色主題和匯出成獨立的 HTML 檔案。

需求明確之後，提示詞就很簡單了。由於涉及到 AI 能力，這裡我用新出的 Kimi K3 模型作為給後端呼叫的模型，注意，專案本身的程式碼還是 Opus 5 生成的。

![](https://pic.yupi.icu/1/image-20260717111459584-20260717144618089-20260728104642413.png)

之前用 Kimi K3 生成 PPT 工具的時候，成品非常精簡，主頁基本上就只有文案輸入框和按鈕。

![](https://pic.yupi.icu/1/1784182758933-6b75a1c9-f922-437b-8c85-0115cdea665e-20260717144619030-20260728104642459.png)

但 Claude Opus 5 做的更像一個成熟的工具產品。你看左下角那一排配色主題就知道了，極光、象牙、暮色、青薄，名字起得還挺文藝，而且每個主題下面還配了一句定位說明。

而且它還支援填寫生成 PPT 的額外要求。注意，我並沒有在提示詞中提到這一點，是 AI 自己錦上添花的。

![](https://pic.yupi.icu/1/1785145527106-4c6d9e30-ba47-47c2-a8a6-d1c9e4cd0d48.png)

隨便拿我之前的一篇文章來製作 PPT，可以實時看到生成進度，質量很高。

![](https://pic.yupi.icu/1/1785146087244-153c15ee-6ffe-4f7b-8c8d-8224fe272074.png)

切換個主題試試，效果不錯吧，還能直接全屏演示或者匯出為 HTML：

![](https://pic.yupi.icu/1/1785146169709-34ce614b-115b-4713-8a42-e165e9c1205e.png)

整體來說，無論是前端細節還是後端生成邏輯都做得很好，一段提示詞直接梭出來一個能用的產品。



### 5、足球對戰網頁遊戲

經常看我文章的朋友應該知道，這個專案是老熟人了。

之前 GPT-5.6 釋出的時候，我用同一段提示詞讓 GPT-5.6 Sol、Claude Fable 5、Grok 4.5 三個模型同時開發了一個叫「2066 決戰世界盃」的足球遊戲（可以閱讀本教程模型動態板塊中的《GPT-5.6 三模型橫評 - 全棧專案實測》）。這次的提示詞跟那時候完全一致，正好拿來做個對比。

先看賽前設定介面，淺綠主題色跟足球場很搭。

![](https://pic.yupi.icu/1/1785145627018-69826233-8f03-4610-8ab7-ae4a152bfa05.png)

踢球、換人功能都是正常的，非常流暢。而且注意到細節了沒？9 號球員下方有個紅色的蓄力槽，給了玩家更多的操作空間。

![](https://pic.yupi.icu/1/1785145802068-9d828079-9355-4afd-95d9-65d3d4e38cba.png)

遊戲的人機也非常智慧，不像其他模型開發出來的人機只會防守，這次的人機甚至還能踢出配合。而且作為玩家，也不是完全沒有機會贏過人機，遊戲體驗非常好。

對比一下之前幾個模型的表現。GPT-5.6 Sol 開發的那版，人機不會主動進攻，我打滿一整場中等難度，只能以 0 比 0 收場。

![](https://pic.yupi.icu/1/1783647330206-bb64786d-95d9-41e5-9d53-4fb42ffdd9da-20260717144623818-20260728104642909.png)

Grok 4.5 開發的那版，球場渲染有硬傷，換人邏輯也很不順暢，經常切換到離球最遠的那個隊友身上。

![](https://pic.yupi.icu/1/1783648020795-d1809bda-6c3c-4e36-babf-a3f6e9e494e1-20260717144623018-20260728104642942.png)

Claude Fable 5 開發的那版，球的物理引擎翻車了，球經常會瞬移，根本沒法正常玩。

![](https://pic.yupi.icu/1/1783648857986-4d1edca9-1496-494c-80b1-096690b34bc4-20260717144622560-20260728104642988.png)

而 Opus 5 不僅在人機智慧上突破了，左側還會實時展示賽況，這也是之前的模型都沒有做到的。

![](https://pic.yupi.icu/1/1785145881584-df6c0f0a-5868-4ebd-9d3a-fec99e57ba88.png)

美中不足的是，足球場的白線有點兒問題，禁區前面那道罰球弧兩端拐進了禁區裡面。



### 6、以撒的結合肉鴿遊戲

之前我讓 Kimi K3 開發過這個遊戲，提示詞中要求先用 Firecrawl 搜尋以撒的結合的遊戲機制和美術風格資料，用 Context7 查詢所用遊戲框架的文件：

### 7、全棧 AI 程式設計工具

最後一個專案，直接把難度拉滿。

我讓 AI 基於 VS Code 的開原始碼，開發一個類似 Cursor 的 Web AI 程式設計工具，要支援 Editor Window 程式碼編輯器和 Agents Window 對話工作臺兩種模式，兩個視窗之間可以自由切換。

看看成品，幾乎完整地保留了 VS Code 的精髓，比如程式碼高亮、程式碼小地圖、管理面板、程式碼搜尋等等。

![](https://pic.yupi.icu/1/1785147124049-912c793e-0915-4843-853b-9848a4611536.png)

讓 AI 執行個任務試試，你能清晰地看到 AI 的思考資訊、工具呼叫等等。

![](https://pic.yupi.icu/1/1785147250942-846cdd2b-a6be-4848-b412-dc1d9e31e0b0.png)

AI 甚至能夠呼叫終端、自主測試開發出的程式碼，還能清晰地看到本次改動的檔案。

## 寫在最後

7 個專案全部跑完了，聊聊我的真實感受。

讓我印象最深刻的一點是，Claude 沒有完全機械地、用最簡單直接不繞彎子的方式完成任務，你讓它做什麼它就只做什麼，而是會在你需求的基礎上加一點自己的想法，儘量達到理想的效果。

它不僅後端邏輯強、前端視覺效果也強，還非常注重細節，真的是六邊形戰士了。**至少對我來說，我暫時想不到什麼開發任務是 AI 完不成的。** 如果有，那大概是我沒有駕馭好 AI，或者 tokens 不夠。

另一個讓我印象深刻的點是，Opus 5 確實像官方說的那樣，特別愛自己檢查作業。Anthropic 甚至專門提醒開發者把提示詞裡那句「最後記得驗證一遍」刪掉，你越叮囑它反而越容易檢查上癮。他們後來乾脆把 Claude Code 的系統提示詞刪掉了 80% 以上，程式設計跑分一點沒掉。關於這套提示詞減法的具體做法，可以閱讀本教程經驗技巧板塊中的《Anthropic 官方的提示詞精簡方法》。

當然，這個特性是一把雙刃劍，Opus 5 很容易把簡單的任務搞複雜，這是 Claude 一貫的通病，也就更廢 tokens。

所以如果你想更好地利用 Opus 5 這種級別的模型，還是要在提示詞上下點功夫，不是說要寫得又臭又長，**而是把需求描述清楚、把 AI 的邊界限制好**，否則它搞不好就跑偏了。

最後揭曉謎底，這 7 個任務打包加起來，一共花了我 900 多塊。

這就是效果好相應的代價。之前我用 Kimi K3 等國產模型做同樣的專案，加起來套餐額度才動了百分之幾。

所以還是要根據你的實際需求來選擇模型：

- 追求 90 分效果的任務，可以交給 Opus 5
- 只需要 80 分的任務，可以交給 GPT 或者 Kimi K3、GLM-5 這類模型，快、穩、便宜
- 只要及格就好的任務，那就用價效比極高的 DeepSeek

模型沒有絕對的好壞，只有合適與不合適。多動手試試不同的模型和工具，用實際專案來感受它們的能力差異，你一定能找到最適合自己的程式設計搭檔。
