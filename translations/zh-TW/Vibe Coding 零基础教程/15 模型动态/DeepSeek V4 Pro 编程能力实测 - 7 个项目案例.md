## 先給 DeepSeek V4 Pro 搭一套 Harness

這次測試我統一使用 Codex 這個主流的 AI 程式設計工具來跑所有任務。

把 DeepSeek V4 Pro 接進 Codex CLI 沒什麼難度，官方這次專門適配了 Responses API 和 Codex，改改配置檔案就能跑。具體步驟可以閱讀本教程程式設計工具板塊「Codex」目錄中的《Codex 對接國產模型教程》，照著做就行。

![](https://pic.yupi.icu/1/image-20260803114842807.png)

真正麻煩的是另外兩件事。

DeepSeek V4 Pro 是純文字模型，看不了圖。這意味著它沒辦法像 Kimi K3 或 Claude Opus 5 那樣寫完頁面自己截圖看一眼效果對不對，也沒辦法跟之前有視覺理解能力的模型放在完全公平的條件下橫向對比。

另外，官方那些跑分數字本身就不是隻靠裸模型跑出來的。公開基準裡的 Code Agent 任務，用的是 **DeepSeek Harness 極簡模式**，而且開的是 max 檔位。

Harness 指的是把模型能力落到真實環境裡的那層工程，負責呼叫工具、讀寫檔案、管理上下文、處理報錯，讓模型能把一件事從頭幹到尾。

問題是，官方那套 Harness 到現在都還沒放出來。

那我就自己給它搭一套唄~

這套 Harness 並不複雜，主要做 4 件事：

1. 統一執行環境：所有任務走同一個啟動指令碼，推理檔位保持一致，每個任務獨立目錄和埠，不會互相影響
2. Playwright 驗證器：模型看不了圖，就讓指令碼替它抓 console 報錯、網路請求和 DOM 斷言，再存截圖便於人工驗證
3. Token 計費對賬：把任務執行過程中的事件流儲存為 JSON 檔案，按官方定價算錢，測試前後各查一次餘額做交叉驗證
4. 90 分鐘看門狗機制：超時就強行關掉任務，失敗也不會重跑，保證資料乾淨

準備工作做完，我在 Cursor 裡把 8 次執行一次性並行丟了出去，全程不需要人工干預，跑完我再一個一個驗收。

![Cursor 並行排程 8 個子任務](https://pic.yupi.icu/1/image-20260813150439721.png)

### 3、竹知了模擬網頁遊戲

竹知了是中國傳統的竹製玩具，一根竹籤上串著一片薄竹片，用手搓動竹籤讓竹片高速旋轉，竹片切割空氣產生振動，發出類似夏天蟬鳴的「哇嗚哇嗚」聲。

![](https://pic.yupi.icu/1/1786602860735-55ee064d-1521-4501-847d-c12a0cfe9fc4.png)

這道題同時考察了前端效果、物理引擎和實時聲音合成，而且效果好不好只能靠耳朵聽、憑自己的手感來玩，程式碼寫得再漂亮也沒用。

先看 DeepSeek V4 Pro 做的效果。介面中規中矩，象徵性地畫了幾顆小竹子，但沒什麼氛圍感。

![](https://pic.yupi.icu/1/1786599373401-a561d583-aeca-46c3-9895-d55c9356e731.png)

遊戲的操作方式很簡單，用滑鼠拖拽讓竹知了旋轉起來。頁面上還支援開啟體感模式，搖一搖手機或轉動手腕就能驅動竹片旋轉。

![](https://pic.yupi.icu/1/1786599484181-ade4c638-69c4-443a-8f04-d579cbf4562d.png)

不過發出的聲音竟然是《嗡嗡嗡》的，跟我想要的那種《哇哇哇》的蟬鳴聲完全不搭，配不上 1000 萬以內最好的玩具！

這道題我還額外用 DeepSeek V4 Flash 拿同樣的提示詞跑了一遍，結果還挺意外的。竹知了的結構變了，聲音也更接近我想要的那種哇哇聲。

### 4、網頁 PPT 生成工具（內建 AI）

前面三個都是開胃小菜，接下來該測測它的全棧工程能力了。

使用者在網頁上貼上一段長文案，後端呼叫大模型把文案拆解成多頁 PPT 結構，前端渲染成可以全屏演示、鍵盤翻頁的網頁 PPT，還要支援切換配色主題和匯出 HTML 檔案，後端用流式輸出，前端實時顯示生成進度。

![](https://pic.yupi.icu/1/1786602871186-1801d617-e049-4a66-93d9-a37a3b25367f.png)

這道題相當於對 DeepSeek V4 Pro 的雙重驗證。專案程式碼是它寫的，專案裡內建的那個大模型介面填的也是它自己，一舉兩得，同時測試了它的編碼能力和內容生成能力。

來看看效果，整體介面佈局和風格還算中規中矩，左側輸入生成 PPT 的長文案，右側預覽 PPT 成品效果。

### 5、線上抽獎系統

接下來讓 AI 開發一個人人可用的線上抽獎系統，使用場景是公司年會、社群活動、直播間抽獎等等。

管理員可以建立一場抽獎活動，配置好每檔獎品的名額，生成參與連結和二維碼；參與者開啟連結填暱稱報名；到點管理員點選開獎，大屏上滾動出中獎名單。

![](https://pic.yupi.icu/1/1786602887504-679a0212-cd94-43e3-983c-6d1503d5b705.png)

前面幾道題拼的是審美和創意，這道題拼的是工程嚴謹度。

- 名額絕對不能超發，一等獎 1 名就只能出 1 個人，哪怕同一瞬間有海量請求湧進來也一樣。
- 同一個參與者在同一場活動裡最多隻能中一次獎。
- 開獎操作必須冪等，管理員手抖連點五下開獎按鈕，結果也只能產生一輪。

來看下效果。

光看到這個介面，我已經沒什麼期待了，這也太醜了叭！我以為高低得整個轉盤呢。

![](https://pic.yupi.icu/1/1786600763380-af0f9dd5-7cb5-4046-9669-8b356f720298.png)

試試功能，能夠在管理後臺正常新建活動、配置獎品名額。

![](https://pic.yupi.icu/1/1786600802250-6f303738-7f6f-4b0c-8520-6e4279033d1c.png)

參與者可以透過掃描二維碼報名參與抽獎，這個流程還挺方便的。

![](https://pic.yupi.icu/1/1786600853785-67afb787-6fb6-4554-8122-96b87d8d4029.png)

管理員開獎後，參與者可以實時看到中獎結果：

![](https://pic.yupi.icu/1/1786600931033-5aae5f42-04bd-4311-b977-7efc6ce97fa9.png)

我讓其他 AI 幫忙驗證了後端邏輯，1000 人搶 100 個名額，中獎總人數正好 100，沒有超發，也沒有重複中獎。後端的冪等和併發控制是做到位了的。

作為一個小工具使用，是足夠的了。唯一的硬傷就是太醜了，太一板一眼了，讓我感覺像是 2024 年的模型搞出來的前端。但後端邏輯沒毛病，綜合來看給到「人上人（低配版）」。



### 6、以撒的結合肉鴿遊戲

接下來是一個更有挑戰性的遊戲專案。

以撒的結合是我小孩兒時代很愛玩的一款肉鴿遊戲，玩家在隨機生成的房間裡探索，用射擊消滅敵人，清完一個房間開門進下一個，每層有若干房間和一個 Boss 房。

![](https://pic.yupi.icu/1/image-20260730215626570.png)

我讓 AI 復刻核心玩法，包括隨機地牢生成、射擊戰鬥、道具系統、屬性系統，至少 3 種普通敵人和 1 個 Boss，圖形素材全部用程式碼繪製。

![](https://pic.yupi.icu/1/1786602896622-3e913641-85d9-4515-8ae9-cb36a6077af9.png)

這道題的圖形素材全部靠程式碼一筆一筆畫出來，畫成什麼樣模型自己心裡其實是沒數的，所以這道題最能看出不同模型之間的水平差距。

來看看 DeepSeek V4 Pro 的版本。遊戲名叫「地下室：淚之迴廊」，好傢伙，遊戲名稱都一股 AI 味兒。

![](https://pic.yupi.icu/1/1786601275633-79bedc9a-a388-4038-b489-12cf0c8f3656.png)

進入遊戲，開屏暴擊。來看看這個人物形象，帶著個面罩，我是小偷啊我是？不過小人的眼淚標誌還是致敬了原版。

我的評價是「人上人」。



### 7、全棧 AI 程式設計工具

最後一個專案，直接把難度拉滿。

我讓它克隆 VS Code 的開原始碼，在這個基礎上開發一個復刻 Cursor 核心體驗的 Web AI 程式設計工具，要支援 Editor Window 程式碼編輯器和 Agents Window 對話工作臺兩種模式，兩個視窗之間能自由切換，Agent 還得能自主讀檔案、改程式碼、執行終端命令。

![](https://pic.yupi.icu/1/1786602907526-9df019bc-5fc8-480b-a26f-abfdcdb50f0c.png)

這是 7 道題裡唯一的長程任務，考察模型能不能在一個幾十萬行的程式碼庫面前穩定執行、不跑偏。

來看看成品，雖然跟真實的 Cursor 差距甚大，但整體佈局還是合理的。在 Editor Window 編輯器模式中，能夠順利開啟和編輯檔案，還有程式碼提示和高亮。

![](https://pic.yupi.icu/1/1786602228169-31beaebe-3162-4d6a-a34f-7e2aef9399c9.png)

切換到 Agents Window，建立一個新的 AI 對話，讓它幫我開發一個推箱子游戲。

![](https://pic.yupi.icu/1/1786602275433-113cbb01-223b-4e62-bfa2-da1448889741.png)

可以看到 AI 能夠執行命令、呼叫工具來檢視檔案，然後自己編寫程式碼。等了一會兒，AI 完成了開發。

![](https://pic.yupi.icu/1/1786602317068-9b7a7666-1f0e-4465-a4b4-a1b3ed8391ad.png)

開發完成後，直接讓 AI 把網站跑起來。

![](https://pic.yupi.icu/1/1786602366637-0640c8f9-d1b1-4c4b-916b-ba5fdae4d289.png)

來看下我用 AI 做的 AI 程式設計工具開發出的推箱子游戲，效果還不錯，能夠正常玩耍：

![](https://pic.yupi.icu/1/1786602398632-5f0f7f2d-3722-4732-b1cd-75b7e082af65.png)

從工程角度來說這個選擇是合理的，畢竟直接改造 VS Code 原始碼是要消耗大量成本的，但 AI 也沒跟我打聲招呼。

跟之前的模型對比一下。

## 我的感受

7 個專案全部跑完了，聊聊我的真實感受。

先說 AI 程式設計能力，DeepSeek V4 Pro 的前端能力可以說是遠遠低於我的預期。互動動畫的文字溢位、PPT 的排版失衡、抽獎系統的刻板介面審美，跟 Claude Opus 5 和 Kimi K3 做出來的效果差距很明顯。

但是後端能力還不錯。PPT 生成工具跑通了完整的 AI 生成流程，抽獎系統的併發控制和冪等邏輯做得很到位，全棧 AI 程式設計工具的 Agent 模式也能正常工作。

而且關鍵是 7 個專案全部能跑起來，沒有出現依賴裝不上、服務啟動報錯這種需要人工救場的情況。

整體來看，DeepSeek V4 Pro 在 AI 程式設計能力上，跟國外頂尖模型的差距還是很明顯的。後端邏輯可以放心交給它，但如果你對前端效果有要求，還是得上 Claude 這個級別的模型。

DeepSeek V4 Pro 還有一個對 AI 程式設計影響極大的短板，就是沒有視覺理解能力。它寫完頁面之後沒辦法自己截圖看一眼效果對不對，前端佈局有沒有錯位、配色好不好看，這些它全都判斷不了。我這次專門搭了一套 Playwright Harness 來替它做驗證，但 Harness 只能抓報錯和 DOM 斷言，涉及到「好不好看」的判斷還是得靠人工。

比如開發《以撒的結合》遊戲時，地板的配色程式碼邏輯是對的，顏色確實畫了，但是選了一個跟純黑幾乎分不出來的暗色，人眼看上去就是一片漆黑。模型自己完全發現不了這個問題。

![](https://pic.yupi.icu/1/1786601311551-f9bc962b-ab7c-45cf-be16-c325ab7295b2-20260813162827387.png)

然後揭曉本次測試花費的總金額。

你敢相信麼，這麼多專案跑下來，竟然只花了 **5 塊錢左右**？？？

該說不說，DeepSeek 的價效比是真的高。

![DeepSeek 消費面板](https://pic.yupi.icu/1/1786602606582-f5c74b1b-aeaa-4a42-a491-a3d624856ec6.png)

這麼便宜主要是因為 DeepSeek 的快取命中率實在太高了，平均達到 99%，絕大部分輸入 Token 的計費幾乎可以忽略不計。

而之前用 Claude Opus 5 跑同樣的 7 個專案，花了 900 多塊（具體測評可以閱讀本教程模型動態板塊中的《Claude Opus 5 程式設計能力實測 - 7 個專案案例》）。DeepSeek V4 Pro 只花了 5 塊錢，**差了 180 倍！**

不過 DeepSeek 官方說近期會整體上調 API 的價格，而且漲幅較大，所以珍惜現在這個價格吧，先多蹬 AI 一會兒。

![](https://pic.yupi.icu/1/image-20260813154806089.png)

另外簡單對比一下 DeepSeek V4 Pro 和 V4 Flash。開發竹知了遊戲時，Flash 跑了 15 分鐘、花了 7 毛，Pro 跑了 11 分鐘、花了 4 毛，兩個版本的完成度和效果差別不大。

說實話，我現在沒有明顯感受到 DeepSeek V4 Pro 和 V4 Flash 之間的差距，在我的使用體感而言，它們算是同一檔的模型，都可以獨立完成全棧開發的任務。

**但無論是前端效果還是交付成果的質量，都跟國外頂級的大模型有差距。**

不過由於時間有限，這塊的測試還不夠充足，感興趣的同學也可以自己試試。

我的建議是，在學習 AI 程式設計階段，或者對於一些日常小工具、內部系統、快速驗證想法這類不太在意前端精細度的任務，用 DeepSeek 完全沒問題，節省成本。如果你要做面向使用者的產品，可以先用 DeepSeek 跑一遍 Demo，調通提示詞、明確功能和業務流程，再切換到 Claude 這個級別的模型去系統開發，這樣既省錢又高效。

![](https://pic.yupi.icu/1/woquandouyao.jpeg)



## 寫在最後

至少 DeepSeek V4 Pro 是不及我的預期的，畢竟等了這麼久，結果正式版在 AI 程式設計上的體驗並沒有給我驚喜。

![](https://pic.yupi.icu/1/620cb309a8d1aaeda1364a6f34c90f25.jpg)

不過 DeepSeek 應該還有大招沒有發。

按照官方那個公式，**Model + Harness = Agent**，模型這一半算是交付了，他們自研的 Harness 框架應該也快了。

等 Harness 正式釋出，DeepSeek V4 Pro 的 Agent 能力可能還會再上一個臺階。

總的來說，DeepSeek V4 Pro 的優勢在於後端邏輯靠譜、價效比超高，但前端效果跟海外頂尖模型還有明顯差距。如果你想深入瞭解不同 AI 模型的程式設計能力對比，可以閱讀本教程模型動態板塊中的其他實測文章，找到最適合自己場景的模型。
