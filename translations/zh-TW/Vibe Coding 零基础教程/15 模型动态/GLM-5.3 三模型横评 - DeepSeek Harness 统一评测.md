![DeepSeek Harness 工具](https://pic.yupi.icu/1/image-20260814133452050.png)



## 模型接入 DeepSeek Harness

首先要把 GLM-5.3 和 Kimi K3 模型接入 DeepSeek Harness，這裡我就以 GLM-5.3 為例。

如果你還沒有安裝和使用過 DeepSeek Harness，可以閱讀本教程程式設計工具板塊「DeepSeek Harness」目錄中的《DeepSeek Harness 保姆級入門教程》，從安裝到上手只要幾分鐘。

> 影片教程：https://www.bilibili.com/video/BV1VkgK6NEZS

這裡我只講怎麼在已有的 DeepSeek Harness 裡接入第三方模型。

1）開啟 DSH 的 Web 介面，點選左下角的「設定」按鈕。

![](https://pic.yupi.icu/1/1786932507970-41599bc0-493b-43be-b23a-06167310714e.png)

2）進入「模型」標籤頁，點選「新增提供方」。

![](https://pic.yupi.icu/1/1786932573401-dc4b2cba-6e89-490e-986e-45b62c49258a.png)

3）選擇模型提供方為 `zai-coding-cn`，然後到 [智譜開放平臺](https://bigmodel.cn/coding-plan/personal/overview) 獲取你的 API Key 填進去就行。

![](https://pic.yupi.icu/1/1786932690701-74c2d894-8922-40f3-ac8d-43b0cb3d3b07.png)

4）展開自定義設定，點選「獲取可用模型」。不過因為 GLM-5.3 太新了，預設不會被自動拉取到。

所以需要手動點選「新增模型」，填入 `glm-5.3`，然後儲存。

![](https://pic.yupi.icu/1/1786933645912-f2d165ea-cef1-41d1-b34f-9e244e85c6cb.png)

搞定！現在就可以在對話方塊中選擇並使用 GLM-5.3 模型了~

![](https://pic.yupi.icu/1/1786933520324-c3de8492-bfb7-4b9e-bd5a-47af4ac36add.png)

用同樣的方法把 Kimi K3 也新增進來。DeepSeek V4 Pro 是 DSH 安裝成功後預設接入的，不需要額外配置。

三個模型都就位了，下面開始正式比拼。



## 測試說明

為了公平對比，三個模型全部在 DeepSeek Harness 的標準模式下執行，統一使用各模型的預設推理檔位，工具鏈完全一致，提示詞完全相同。而且全程不做人工干預，給完提示詞就讓 AI 自己跑到底。

DSH 會自動掃描我本地安裝的技能目錄，比如我這裡裝了 Firecrawl 聯網搜尋技能、Context7 文件查詢技能等，三個模型跑任務時都可以使用這些技能來搜尋資料。

## 實戰 1、致敬《牛來》的 3D 跑酷遊戲

最近有一部國產動畫電影叫《牛來》，因為建模極度粗糙、劇情抽象離譜，在社交媒體上反向爆火了。

上映第一天票房才 3420 元，結果因為獵奇打卡，短短十幾天就衝到了 900 多萬。

用半佛老師的話來說：

- 如果你花一個多小時去了解這個電影，你就浪費了人生的一個小時。
- 但如果你花了 30 塊去看了《牛來》，那說明你真的有 30 塊錢。

![](https://pic.yupi.icu/1/%25E7%2589%259B%25E6%259D%25A5%25E5%259B%25BE%25E7%2589%2587.jpg)

我決定讓 3 個模型致敬這部電影，做一個《3D 網頁跑酷遊戲》。

提示詞裡我故意不做太多功能約束和技術限制，就是想看看模型自己能發揮到什麼程度，能不能把電影裡的元素還原出來。值得一提的是，我讓 AI 用 Loop Engineering 的方式推進，做完一步就自己驗證一步，出了問題自己修復。

![](https://pic.yupi.icu/1/1786934842850-22be3935-b9b6-43ad-8a7f-16c163795b57-20260817183037814.png)

OK，開跑！

### 實戰 1 對比

三個版本都跑完了，勝負應該已經很明顯了。

GLM-5.3 的版本完成度最高，多關卡、多技能、劇情還原度強，可玩性遠超其他兩個。

DeepSeek V4 Pro 實現了基本玩法，但是節奏偏慢、細節粗糙。

Kimi K3 雖然場景畫面還行，但遊戲機制太單一，還有卡頓問題。

綜合來看：

- 前端效果 GLM ≈ Kimi > DeepSeek
- 可玩性是 GLM > DeepSeek > Kimi
- 畫面抽象程度是 GLM > DeepSeek > Kimi

整體遊戲完成度上，GLM 5.3 遙遙領先。



## 實戰 2、AI 繪圖工具

上一個任務是前端遊戲，第二個任務當然要換個方向，測試模型的全棧工程能力。

我讓 3 個模型開發一個《AI 繪圖工具》，使用者輸入自然語言描述需求，後端呼叫大模型生成 draw.io 格式的圖表，前端嵌入 draw.io 開源編輯器，使用者可以直接線上編輯和修改生成的圖表。

這個任務同時考驗對 draw.io 開原始碼的理解、後端 AI 呼叫鏈路的設計、前端複雜元件的整合、以及整體產品設計的合理性。

為了方便測試，我直接在提示詞裡把 API Key 提供給了 AI，省去手動配置環境變數的步驟。

![](https://pic.yupi.icu/1/1786935817947-28512ebd-63a7-45bf-9282-89bb4807bfbf.png)



### GLM-5.3 成品效果

先看看 GLM-5.3 的效果。

整個頁面很有科技感，左側是 AI 對話方塊，右側是畫布編輯器。

產品引導做得也很到位，告訴你可以用一句話畫出專業圖表，還給了幾個示例型別。

![](https://pic.yupi.icu/1/1786947000691-52c43b54-e03d-41bc-a419-2f9e0b150548.png)

我讓 AI 幫我畫出 DeepSeek Harness 的架構圖。可以實時看到 AI 深度思考和生成 XML 程式碼的過程，右側顯示了一個炫酷的 Loading 動畫。

![](https://pic.yupi.icu/1/1786946651555-aa4f9a37-59c0-4f66-b691-dfae0ba85280.png)

生成完成後，右側立刻渲染出了完整的架構圖，分層很清晰，而且保留了 draw.io 原本的元素編輯能力，可以直接拖拽和修改。

![](https://pic.yupi.icu/1/1786946757859-0ff24615-3e22-4fe9-8ebb-0d3a35f74d72.png)

更強的是，它支援連續對話修改。比如我說「幫我把 DeepSeek Harness Core 這裡變成紅色」，AI 就能精準定位到對應的元素並修改樣式，右側畫布實時更新。

![](https://pic.yupi.icu/1/1786946921119-ae9fcde6-f3bb-4da2-8244-70652b4a71c7.png)

整體效果非常不錯，圖片匯出功能也能正常使用。

而且你會發現 GLM-5.3 把 draw.io 的編輯能力深度融合進了自己設計的介面中，看起來就像一個完整的產品，而不是生硬地嵌入了一個第三方元件。

### Kimi K3 成品效果

最後看 Kimi K3。

Kimi K3 這次生成的介面佈局跟 GLM 類似，也把 draw.io 自然融合到了專案中，整體介面風格非常 nice。

![](https://pic.yupi.icu/1/1786947935320-b6974f42-7680-490d-9c86-c938007a0c42.png)

![](https://pic.yupi.icu/1/1786948128170-e63bfe84-3e37-48be-ad72-2c16099debce.png)

### 實戰 2 對比

這個任務 GLM-5.3 的綜合表現最好，介面設計、AI 深度思考實時展示、連續對話修改、draw.io 深度融合，每一環都做到位了。

Kimi K3 的前端設計能力很強，但是後端偶爾會翻車。

DeepSeek V4 Pro 雖然也正常實現了核心功能，但是介面粗糙，整合方式生硬，表現最差。



## 我的感受

兩個專案全部跑完了，聊聊我的真實感受。

顯然，即使是在 DeepSeek Harness 這個 DeepSeek 的「角色專武」環境下，GLM-5.3 的表現依然很出色。

我選的這兩個任務覆蓋了純前端 3D 遊戲和全棧 AI 應用兩個完全不同的方向，可以看出 GLM-5.3 在任務理解、程式碼生成質量、產品設計意識這幾個維度上都明顯領先。

然後聊聊大家非常關心的成本問題，猜猜我花了多少 money 呢？

由於 GLM-5.3 我使用的是編碼套餐，不太好直接統計實際消耗金額，我只能拿積分來算了。

兩個專案累計消耗了 1151 積分，由於我訂的是 Pro 套餐（538 元/月），每週額度是 6 萬積分，算下來這次的消耗只佔了周額度不到 2%，折算成錢連 3 塊都不到。

![](https://pic.yupi.icu/1/image-20260817154109537.png)

由於我的 Kimi K3 套餐過期了，新的搶不到，所以是直接用 API Key 接入的，總共消耗了 31.07 元；漲價之後的 DeepSeek V4 Pro 消耗了 13.99 元。

單從我的實際花銷來看，GLM-5.3 按照套餐來算，價效比是最高的。一週 6 萬積分隨便你跑，根據我這次測試的這種任務來看，做幾十個小專案不成問題。

而且 GLM-5.3 會在釋出兩週後開源權重。

**在開源世界裡，GLM-5.3 目前可以說是程式設計能力的天花板。**

![](https://pic.yupi.icu/1/%25E6%25BB%2591%25E5%258A%25A8%25E5%258F%2598%25E5%2594%2590%25E5%2599%25A8%25E4%25B8%25AD.jpeg)

而且智譜在釋出文章中提到，Hugging Face 之前遭遇安全攻擊的時候，Anthropic 的 Mythos 模型只面向約 150 家大型機構提供服務，更多的中小企業和開源專案在最需要幫助的時候，反而用不上最強的防禦工具。

當攻擊能力在擴散，防禦能力就不能只掌握在少數人手中。GLM-5.3 的開源給所有人提供了一把防禦的盾牌，這件事本身的意義可能比跑分更重要。



## 寫在最後

這次橫評讓我對國產模型的程式設計能力更有信心了。GLM-5.3、Kimi K3、DeepSeek V4 Pro 這幾家打得不可開交，對我們使用者來說是好事兒，起碼有了更多的選擇。

不過模型發展太快了，今天還是第一名，下週可能就被新模型超越。與其糾結該選哪個模型，不如多動手實際測試，找到最適合自己場景的那個。

如果你想了解更多 AI 程式設計模型的實測對比，可以閱讀本教程模型動態板塊中的其他文章，或者閱讀程式設計工具板塊中的《AI 模型選擇指南》。
