## 一、AI 應用開發基礎

在開始做專案之前，我們先了解一下 AI 應用開發的基礎知識。

AI 應用就是利用 AI 能力（比如文字生成、圖片生成、語音識別等）來解決實際問題的應用程式。你不需要訓練 AI 模型，只需要呼叫現成的 AI API 就可以了。這就像你不需要知道汽車引擎怎麼工作，只需要會開車就行。

目前主流的 AI API 服務有很多。文字生成方面，有 OpenAI 的 GPT-4、Anthropic 的 Claude、Google 的 Gemini，還有國產大模型比如通義千問、文心一言、智譜 AI 等。圖片生成方面，有 DALL-E 3、Midjourney、Stable Diffusion，還有國產的文心一格等。語音識別方面，有 OpenAI 的 Whisper、Google Speech-to-Text、訊飛語音識別等。

AI 應用的開發流程和普通應用類似，只是多了一個呼叫 AI API 的步驟。整個流程是：使用者輸入 → 處理輸入 → 呼叫 AI API → 處理 AI 響應 → 展示結果。

聽起來很簡單對吧？確實，AI 應用開發的門檻已經非常低了。

![](https://pic.yupi.icu/1/aiapp-workflow%E5%A4%A7.jpeg)

在開發 AI 應用時，有幾個注意事項。

首先是 API Key 安全，不要把 API Key 暴露在前端程式碼中，否則別人可以盜用你的 Key。其次是成本控制，AI API 按使用量收費，要控制好成本，避免浪費。第三是錯誤處理，API 呼叫可能失敗，要做好錯誤處理，給使用者友好的提示。最後是使用者體驗，AI 響應可能需要幾秒鐘，要有載入提示，讓使用者知道正在處理。



## 二、專案實戰 - AI 聊天助手

AI 聊天助手是最基礎也是最實用的 AI 應用。透過這個專案，你可以學習如何用 Vibe Coding 的方式快速開發一個完整的 AI 對話應用。

這個專案要實現一個完整的聊天介面，使用者可以輸入問題，AI 給出回答。要支援多輪對話，AI 能記住之前說過的內容，這樣對話才連貫。為了更好的體驗，AI 的回答要逐字顯示，而不是一次性全部出現，這叫流式輸出。對話記錄要儲存在本地，重新整理頁面也不會丟失。另外，還需要一個清空對話的功能，方便開始新的話題。

![](https://pic.yupi.icu/1/demoweb6.png)

技術選型上，我們使用 React + TypeScript + Vite 作為前端框架，Tailwind CSS 來寫樣式。AI 能力透過呼叫大模型 API 實現，對話歷史用 LocalStorage 儲存，AI 的回答用 react-markdown 來渲染，這樣可以支援程式碼高亮等格式。



### 開發步驟

1）準備工作

開發的第一步是準備工作。你需要獲取 API Key 來呼叫 AI 模型。訪問 [智譜 AI 開放平臺](https://bigmodel.cn)，進入使用者控制檯，點選 API Key 就可以獲取。智譜 AI 提供的 GLM 模型效果不錯，而且有免費額度，適合學習使用。

2）寫需求文件

有了 API Key，就可以開始寫需求文件了。建立 `PRD.md` 檔案，明確你要做什麼：

```markdown
# AI 聊天助手 PRD

## 核心功能
1. 使用者可以輸入問題，AI 給出回答
2. 支援多輪對話，AI 能記住之前的對話內容
3. AI 回答要逐字顯示，不要一次性全部出現
4. 對話記錄要儲存在本地，重新整理頁面不會丟失
5. 可以清空對話，開始新的話題
6. AI 的回答支援 Markdown 格式，包括程式碼高亮

## 介面要求
- 類似微信的聊天介面
- 使用者訊息在右邊，AI 訊息在左邊
- 底部有輸入框和傳送按鈕
- 簡潔現代的設計風格
```

這個文件清楚地說明了要實現什麼功能，介面是什麼樣的。

3）寫技術設計文件

然後寫技術設計文件 `TECH_DESIGN.md`：

```markdown
# 技術設計

## 技術棧
- React + TypeScript + Vite
- Tailwind CSS
- 智譜 AI API
- LocalStorage 儲存對話歷史
- react-markdown 渲染 Markdown

## 資料結構
- Message: role（user 或 assistant）、content（內容）、timestamp（時間戳）
- 對話歷史儲存在 LocalStorage 中

## API 呼叫
- 使用智譜 AI Chat Completions API
- 啟用 stream 模式實現流式輸出
- API Key 儲存在環境變數中
```

這個文件說明了用什麼技術，資料結構是什麼樣的，API 怎麼呼叫。

4）寫 AGENTS.md 檔案

接著建立 `AGENTS.md` 檔案，告訴 AI 開發規範：

```markdown
# AI 聊天助手開發指令

## 專案概述
使用 React + TypeScript 開發的 AI 聊天助手，呼叫智譜 AI API 實現對話功能。

## 開發規範
- 使用 TypeScript，確保型別安全
- 使用 Tailwind CSS 編寫樣式
- API Key 從環境變數讀取，不要硬編碼
- 錯誤要有友好的提示

## 功能要求
- 實現流式輸出，AI 回答要逐字顯示
- 支援多輪對話，要把歷史訊息傳送給 API
- 對話歷史要儲存在 LocalStorage
- 支援 Markdown 渲染和程式碼高亮

## 注意事項
- 要處理 API 呼叫失敗的情況
- 載入時要有明確的提示
- 輸入框在傳送時要禁用，避免重複傳送
```

這個檔案是給 AI 的開發規範，讓它知道程式碼要怎麼寫。

5）和 AI 對話開發

有了這三個文件，就可以開始和 AI 對話開發了。開啟 Cursor，把這 3 個文件放在專案根目錄。

第一步是初始化專案：

```
請根據 PRD.md、TECH_DESIGN.md 和 AGENTS.md 的要求，初始化一個 React + TypeScript + Vite 專案，並安裝必要的依賴：Tailwind CSS、react-markdown、react-syntax-highlighter。
```

這個提示詞告訴 AI 要建立什麼專案，安裝哪些依賴。AI 會讀取這三個文件，然後按照要求建立專案結構，安裝依賴，配置 Tailwind CSS。

第二步是建立資料型別和 API 封裝：

```
建立 types.ts 檔案，定義 Message 型別。然後建立 api.ts 檔案，封裝智譜 AI API 呼叫，要支援流式輸出，引數從環境變數讀取。
```

這一步是為後續開發打基礎，把資料結構和 API 呼叫都封裝好，後面用起來就很方便。

第三步是實現聊天介面：

```
建立 ChatInterface 元件，實現聊天介面。要求：
1. 訊息列表顯示在上方，使用者訊息在右邊，AI 訊息在左邊
2. 底部有輸入框和傳送按鈕
3. 使用 Tailwind CSS 實現類似微信的聊天介面樣式
4. 訊息要支援 Markdown 渲染
```

這個提示詞說明了介面的佈局和樣式要求。AI 會建立完整的聊天介面元件。

第四步是實現對話功能：

```
實現傳送訊息的功能：
1. 使用者輸入訊息後，新增到訊息列表
2. 呼叫 API 獲取 AI 回答
3. 使用流式輸出，逐字顯示 AI 的回答
4. 要把歷史訊息也傳送給 API，實現多輪對話
5. 載入時禁用輸入框，顯示"思考中..."
```

這個提示詞包含了對話功能的所有要求。流式輸出是關鍵，它讓 AI 的回答像打字一樣逐字出現，使用者體驗會好很多。多輪對話也很重要，要把之前的對話歷史一起傳送給 API，這樣 AI 才能記住之前說過的內容。

第五步是新增資料持久化：

```
使用 LocalStorage 儲存對話歷史：
1. 每次對話更新後自動儲存
2. 頁面載入時讀取歷史記錄
3. 新增"清空對話"按鈕，清除歷史記錄
```

這樣使用者重新整理頁面後，之前的對話還在，不會丟失。

第六步是最佳化使用者體驗：

```
最佳化使用者體驗：
1. 新訊息出現時，自動滾動到底部
2. 新增複製按鈕，方便複製 AI 的回答
3. 程式碼塊要有語法高亮
4. API 呼叫失敗時，顯示友好的錯誤提示
```

這些細節雖然小，但能大幅提升使用者體驗。



### 開發技巧

在開發過程中，有幾個技巧可以讓你更高效。首先，不要一次性讓 AI 實現所有功能，而是分成多個小步驟，每完成一步就測試一下。這樣即使出問題，也容易定位和修復。

其次，在對話時要給 AI 提供足夠的上下文。明確告訴它要實現什麼功能、有什麼具體要求、要遵循什麼規範。上下文越清晰，AI 生成的程式碼質量就越高。

如果程式碼出現問題，記得把完整的錯誤資訊發給 AI，讓它幫你分析和修復。不要只說 “程式碼報錯了”，而是要把具體的錯誤資訊貼上給它。



### 擴充套件思路

基礎版完成後，你可以繼續擴充套件功能。

比如新增系統提示詞設定，讓 AI 扮演不同角色（比如程式設計助手、寫作助手、心理諮詢師等）；支援多個對話會話管理，可以同時進行多個話題的對話；新增語音輸入功能，用語音和 AI 對話；整合圖片識別功能，讓 AI 可以看圖回答問題；支援匯出對話記錄，儲存重要的對話內容。



## 三、專案實戰 - 智慧寫作助手

掌握了 AI 對話的基本流程後，讓我們來做一個更專業的應用 —— 智慧寫作助手。寫作助手是 AI 最實用的應用場景之一，透過這個專案，你可以學習如何用提示詞工程讓 AI 完成不同的寫作任務。

這個專案要支援多種寫作模式，比如文章續寫、內容改寫、文案生成、郵件撰寫等。使用者可以調整創意度和輸出長度等引數，控制 AI 的生成效果。還可以一鍵最佳化文字的語法和表達，讓文字更專業。為了方便選擇，可以一次生成多個版本，使用者挑選最滿意的。生成的內容要儲存到歷史記錄中，方便檢視和管理。

![](https://pic.yupi.icu/1/demoweb7.png)

技術棧和聊天助手類似，使用 React + TypeScript + Vite，配合 Tailwind CSS。核心還是呼叫智譜 AI API，資料用 LocalStorage 儲存。



### 開發步驟

1）設計提示詞模板

開發的第一步是設計提示詞模板。在開始寫程式碼之前，先設計好不同寫作任務的提示詞。建立一個 `prompts.md` 檔案，定義各種寫作模式的提示詞：

```markdown
# 寫作助手提示詞模板

## 文章續寫
請繼續寫下面的文章，保持風格一致，內容連貫：
[使用者輸入的內容]

## 內容改寫
請改寫下面的內容，使其更加流暢、專業：
[使用者輸入的內容]

## 內容擴充套件
請擴充套件下面的內容，增加更多細節和例子：
[使用者輸入的內容]

## 內容總結
請總結下面的內容，提取核心要點：
[使用者輸入的內容]

## 郵件撰寫
請寫一封[正式/友好]的郵件，主題是：[主題]

## 文案生成
請為[產品名稱]寫一段[風格]風格的營銷文案
```

提示詞是 AI 應用的核心，好的提示詞能讓 AI 生成更好的結果。一個好的提示詞通常包含 3 個要素：明確的任務描述、充足的上下文資訊、清晰的輸出格式要求。

![](https://pic.yupi.icu/1/promptcompare%E5%A4%A7.jpeg)

舉個例子，如果你想讓 AI 寫一篇文章，不要只說 “幫我寫一篇文章”，而要說清楚主題、讀者物件、字數要求、包含哪些內容。比如：

```markdown
請寫一篇關於 AI 程式設計的科普文章，面向零基礎讀者，通俗易懂，多舉例子，字數 800-1000 字，要包含什麼是 AI 程式設計、為什麼要學、如何入門。 
```

這樣 AI 才知道應該怎麼寫。

如果是改寫內容，要告訴 AI 這段內容的背景。比如：

```markdown
這是一篇技術部落格的開頭段落，請改寫得更吸引人，同時保持專業性。
```

這樣 AI 才知道應該往什麼方向改。

指定輸出格式也很重要。如果你想讓 AI 總結文章，可以明確要求：

```markdown
請總結這篇文章，輸出格式：
1. 核心觀點（3-5 條）
2. 關鍵資料（如果有）
3. 結論（一句話）
```

這樣生成的結果更規範，更符合你的需求。

有時候，給 AI 一些示例效果會更好。比如讓 AI 寫營銷文案，你可以先給幾個示例，讓它參考風格。這種方法叫 Few-shot Learning，在很多場景下都很有效。

2）寫需求文件

設計好提示詞模板後，就可以寫需求文件了。建立 `PRD.md` 檔案：

```markdown
# 智慧寫作助手 PRD

## 核心功能
1. 左右分欄佈局，左側輸入，右側顯示生成結果
2. 支援 6 種寫作模式：續寫、改寫、擴充套件、總結、郵件、文案
3. 可以調整創意度（temperature）和輸出長度
4. 生成的內容要流式顯示
5. 有"最佳化提示詞"按鈕，AI 幫使用者最佳化描述
6. 儲存生成歷史

## 介面要求
- 頂部：大標題
- 輸入區：大文字框（多行）
- 引數區：尺寸選擇、風格選擇
- 按鈕區：最佳化提示詞、生成內容
- 展示區：顯示生成的內容 + 複製按鈕
- 側邊欄：歷史記錄
```

3）和 AI 對話開發

有了文件，就可以和 AI 對話開發了。

第一步，建立基礎介面：

```
請根據 PRD.md 建立智慧寫作助手的介面：
1. 左右分欄佈局
2. 左側：模式選擇下拉框 + 輸入文字框 + 生成按鈕
3. 右側：顯示生成的內容
4. 使用 Tailwind CSS，介面要美觀
```

第二步，實現提示詞模板：

```
建立 promptTemplates.ts 檔案，根據 prompts.md 中的模板，實現 6 種寫作模式的提示詞函式。每個函式接收使用者輸入，返回完整的提示詞。
```

這樣就把提示詞邏輯封裝好了，不同的寫作模式用不同的提示詞。

第三步，實現生成功能：

```
實現內容生成功能：
1. 使用者選擇模式，輸入內容，點選生成
2. 根據選擇的模式，生成對應的提示詞
3. 呼叫智譜 AI API，使用流式輸出
4. 在右側實時顯示生成的內容
5. 支援 Markdown 渲染
```

第四步，新增引數調整：

```
新增高階設定面板：
1. 創意度滑塊（temperature: 0-1）
2. 輸出長度滑塊（max_tokens: 100-2000）
3. 這些引數要傳遞給 API 呼叫
4. 可以摺疊/展開高階設定
```

temperature 值會影響輸出的創意程度。

- 0-0.3 比較保守，適合事實性內容
- 0.4-0.7 比較平衡，適合大多數場景
- 0.8-1.0 很有創意，適合創意寫作。

第五步，新增歷史記錄：

```
實現歷史記錄功能：
1. 每次生成後，儲存到 LocalStorage
2. 儲存內容：提示詞、生成結果、生成時間
3. 左側顯示歷史記錄列表
4. 點選歷史記錄可以檢視之前的內容
5. 支援刪除歷史記錄
```



### 提示詞最佳化技巧

如果你不確定提示詞是否夠好，可以讓 AI 幫你最佳化。比如你可以這樣問：

```
我想讓 AI 幫我改寫文章，讓文章更專業。我現在的提示詞是："請改寫這段話"。請幫我最佳化這個提示詞，讓 AI 生成更好的結果。
```

AI 會給你一個更詳細、更有效的提示詞，比如：

```markdown
這是一篇技術部落格的開頭段落，請改寫得更吸引人，同時保持專業性。要求：
1. 用更生動的語言
2. 保持技術準確性
3. 字數控制在 200 字左右
```



### 擴充套件思路

基礎版完成後，可以繼續擴充套件功能。比如新增更多寫作模板，支援論文、報告、小說等不同型別的寫作；支援自定義提示詞模板，讓使用者可以建立自己的模板；新增多語言翻譯功能，一鍵翻譯成其他語言；實現批次生成，一次生成多個版本供選擇；新增文字對比功能，對比不同版本的差異。



## 四、專案實戰 - AI 圖片生成器

從文字生成到圖片生成，讓我們來做一個更酷的 AI 應用。AI 圖片生成是最酷的 AI 應用之一，透過簡單的文字描述，就能生成精美的圖片。這個專案可以讓你學習如何呼叫圖片生成 API。

這個專案的核心是文字生成圖片。使用者輸入描述，選擇尺寸和風格，點選生成就能得到圖片。為了幫助使用者寫出更好的提示詞，可以新增一個 “最佳化提示詞” 功能，讓 AI 幫使用者把簡單的描述擴充套件成詳細的提示詞。生成的圖片要儲存到歷史記錄，並且支援下載。

![](https://pic.yupi.icu/1/demoweb8.png)

技術棧和前面的專案類似，主要是呼叫圖片生成 API。智譜 AI 也提供了圖片生成能力，你可以使用同一個 API Key，[訪問官方獲取](https://bigmodel.cn)。



### 開發步驟

1）瞭解圖片生成 API

開發的第一步是瞭解圖片生成 API。圖片生成 API 的主要引數包括：

- prompt：圖片描述（最重要）
- size：圖片尺寸（比如 1024x1024）
- quality：質量（標準或高畫質）
- style：風格（寫實或藝術）

不同的引數組合會生成不同效果的圖片。

2）寫需求文件

然後寫需求文件 `PRD.md`：

```markdown
# AI 圖片生成器 PRD

## 核心功能
1. 使用者輸入圖片描述，點選生成
2. 可以選擇圖片尺寸和風格
3. 生成過程顯示載入動畫（通常需要 10-30 秒）
4. 生成後顯示圖片，可以下載
5. 有"最佳化提示詞"按鈕，AI 幫使用者最佳化描述
6. 儲存生成歷史

## 介面要求
- 頂部：大標題
- 輸入區：大文字框（多行）
- 引數區：尺寸選擇、風格選擇
- 按鈕區：最佳化提示詞、生成圖片
- 展示區：顯示生成的圖片 + 下載按鈕
- 側邊欄：歷史記錄
```

3）與 AI 對話開發

有了文件，就可以和 AI 對話開發了。

第一步，建立基礎介面：

```
請根據 PRD.md 建立 AI 圖片生成器的介面：
1. 輸入框：使用者輸入圖片描述
2. 引數選擇：尺寸（3 個選項）、風格（2 個選項）
3. 兩個按鈕：最佳化提示詞、生成圖片
4. 圖片展示區
使用 Tailwind CSS，介面要美觀。
```

第二步，實現圖片生成功能：

```
實現圖片生成功能：
1. 呼叫智譜 AI 圖片生成 API
2. 傳送 prompt、size、style 引數
3. 生成過程顯示載入動畫和提示文字
4. 生成成功後顯示圖片
5. 錯誤時顯示友好提示
```

圖片生成通常需要 10 ~ 30 秒，所以載入提示很重要，要讓使用者知道正在生成，不是卡住了。

第三步，實現提示詞最佳化功能：

```
實現提示詞最佳化功能：
當使用者點選"最佳化提示詞"按鈕時：
1. 把使用者輸入的簡單描述傳送給 AI
2. 讓 AI 擴充套件成詳細的圖片生成提示詞
3. 提示詞要包含：主體、風格、光線、色彩、構圖等細節
4. 把最佳化後的提示詞填回輸入框
```

這個功能很實用，可以幫助不會寫提示詞的使用者生成更好的圖片。

第四步，新增歷史記錄：

```
實現歷史記錄功能：
1. 每次生成成功後，儲存到 LocalStorage
2. 儲存內容：提示詞、圖片 URL、生成時間
3. 左側顯示歷史記錄列表（縮圖 + 提示詞）
4. 點選歷史記錄可以檢視大圖
5. 支援刪除歷史記錄
```

第五步，新增下載功能：

```
實現圖片下載功能：
點選下載按鈕時，下載當前顯示的圖片。
檔名格式：ai-image-[時間戳].png
```



### 圖片生成提示詞技巧

圖片生成的質量很大程度上取決於提示詞。一個好的提示詞通常包含這些元素：主體（畫什麼）、動作或狀態（在做什麼）、環境背景（在哪裡）、風格（什麼風格）、光線（什麼光線）、色彩（什麼色調）、質量詞（高畫質 / 4K 等）。

比如，如果你想生成一隻貓的圖片，可以這樣描述：

```markdown
一隻可愛的橘貓，坐在窗臺上看著外面的雨，溫暖的室內光線，柔和的色調，細膩的毛髮質感，景深效果，高畫質畫質，4K。
```

這樣的描述包含了所有關鍵要素，生成的圖片質量會更好。

關於風格，你可以用一些關鍵詞來指定。寫實風格用 photorealistic、realistic、detailed；卡通風格用 cartoon style、anime style、cute；油畫風格用 oil painting、artistic、impressionist；水彩風格用 watercolor、soft colors；賽博朋克風格用 cyberpunk、neon lights、futuristic。

質量詞也很重要，比如 high quality、detailed、4K、8K、professional、masterpiece 等，這些詞能讓 AI 生成更精細的圖片。

如果你不確定怎麼寫提示詞，可以讓 AI 幫你。比如你想生成一張圖片，內容是一個程式設計師在咖啡廳寫程式碼。你可以告訴 AI：

```
我想生成一張圖片，內容是：一個程式設計師在咖啡廳寫程式碼。請幫我把這個描述擴充套件成詳細的圖片生成提示詞。
```

AI 會給你一個詳細的描述，包含場景、光線、色調、構圖等各個方面。比如：

```markdown
一位年輕的程式設計師坐在溫馨的咖啡廳靠窗位置，專注地在膝上型電腦上寫程式碼，桌上放著一杯熱氣騰騰的拿鐵咖啡，溫暖的下午陽光透過窗戶灑在桌面上，背景是模糊的咖啡廳環境，柔和的光線，溫暖的色調，電影感構圖，景深效果，高畫質畫質，專業攝影。
```

💡 如果用的是國外的 AI 繪圖模型，英文提示詞的效果可能會更好哦。



### 成本控制建議

需要注意的是，圖片生成比文字生成貴很多，要注意控制成本。開發測試時用標準質量就夠了，不需要用高畫質質量。最佳化好提示詞再生成，避免反覆嘗試浪費額度。如果預算有限，可以考慮使用更便宜的替代方案。



### 擴充套件思路

基礎版完成後，可以繼續擴充套件功能。比如新增圖片編輯功能，基於現有圖片修改；支援批次生成，一次生成多張圖片；新增風格預設，一鍵選擇常用風格；實現圖片放大功能，檢視細節；甚至可以新增社群分享功能，讓使用者分享自己生成的圖片。



## 五、專案實戰 - 語音識別應用

最後，讓我們來做一個涉及音訊處理的 AI 應用。語音識別可以讓你的應用支援語音輸入，大大提升使用者體驗。這個專案可以讓你學習如何處理音訊資料，呼叫語音識別 API。

這個專案要實現語音錄製和識別功能。使用者點選按鈕開始錄音，再點選停止，然後將語音轉換為文字。要支援多種語言，識別結果可以編輯，並儲存到歷史記錄中。

![](https://pic.yupi.icu/1/demoweb9.png)

錄音功能使用瀏覽器自帶的 MediaRecorder API，不需要額外的庫。語音識別呼叫智譜 AI 的語音識別能力，[訪問官方獲取 API Key](https://bigmodel.cn/)。其他技術棧和前面的專案類似。



### 開發步驟

1）瞭解語音識別 API

開發的第一步是瞭解語音識別 API。語音識別 API 的呼叫很簡單：上傳音訊檔案，指定語言（可選），返回識別的文字。

2）寫需求文件

然後寫需求文件 `PRD.md`：

```markdown
# 語音識別應用 PRD

## 核心功能
1. 大大的錄音按鈕，點選開始錄音，再點選停止
2. 錄音時按鈕變紅色，有動畫效果
3. 停止後顯示"開始識別"按鈕
4. 識別過程顯示載入提示
5. 識別結果顯示在下方，可以編輯
6. 儲存識別歷史

## 介面要求
- 簡潔的單頁面
- 中央大圓形錄音按鈕
- 識別結果區域
- 底部歷史記錄列表
```

3）與 AI 對話開發

有了文件，就可以和 AI 對話開發了。

第一步，實現錄音功能：

```
請實現瀏覽器錄音功能：
1. 使用 MediaRecorder API 錄製音訊
2. 需要請求麥克風許可權
3. 點選按鈕開始錄音，再點選停止
4. 錄音時按鈕變紅色，有脈衝動畫
5. 停止後儲存音訊資料（Blob 格式）
```

這個提示詞說明了要用什麼技術，實現什麼功能。MediaRecorder API 是瀏覽器提供的錄音介面，不需要額外安裝庫，非常方便。

第二步，實現語音識別：

```
實現語音識別功能：
1. 呼叫智譜 AI 語音識別 API
2. 上傳錄音的音訊檔案
3. 指定語言為中文
4. 顯示識別結果
5. 錯誤時顯示友好提示
```

第三步，最佳化介面和體驗：

```
最佳化介面和使用者體驗：
1. 錄音按鈕要大且醒目（直徑 120px）
2. 識別結果區域要支援編輯
3. 新增複製按鈕，方便複製識別結果
4. 識別過程顯示載入動畫和提示文字
5. 整體使用簡潔現代的設計
```

第四步，新增歷史記錄：

```
實現歷史記錄功能：
1. 每次識別成功後儲存到 LocalStorage
2. 儲存內容：識別文字、時間戳
3. 底部顯示歷史記錄列表
4. 點選歷史記錄可以檢視詳情
5. 支援刪除歷史記錄
```



### 開發技巧

在開發過程中，有幾個技巧需要注意。首先是處理麥克風許可權，第一次使用時瀏覽器會詢問使用者是否允許訪問麥克風。如果使用者拒絕，要給出友好提示：“需要麥克風許可權才能錄音，請在瀏覽器設定中允許訪問麥克風”，並提供重新請求許可權的按鈕。

其次是音訊格式處理。MediaRecorder 錄製的音訊格式可能是 webm，大部分語音識別 API 都支援這個格式，如果不支援可以讓 AI 幫你轉換格式。

第三是錄音時長限制。為了避免檔案太大和識別時間太長，可以限制錄音時長，比如最長錄音 60 秒。錄音時顯示倒計時，到達時間自動停止。還可以實時顯示錄音時長，讓使用者知道錄了多久。



### 擴充套件思路

基礎版完成後，可以繼續擴充套件功能。比如新增語音翻譯功能，識別後自動翻譯成其他語言；支援實時識別，邊說邊識別；新增關鍵詞提取功能，自動提取重要資訊；支援多人對話識別，區分不同說話人；新增字幕生成功能，給影片生成字幕；甚至可以整合到其他應用，比如聊天助手，讓聊天助手支援語音輸入。
