## 一、小程式開發基礎

在開始做專案之前，先了解一下小程式開發的基礎知識。

小程式是一種輕量級的應用，不需要下載安裝，用完即走。微信小程式是最流行的小程式平臺，還有支付寶小程式、抖音小程式等。小程式的優勢在於：開發成本低（相比原生 APP）、使用者觸達容易（微信使用者基數大）、稽核相對寬鬆、可以快速迭代。

小程式和 Web 應用有什麼區別？

簡單來說，小程式執行在微信環境中，有一些特殊的 API 和限制。比如小程式可以呼叫微信的支付、分享、掃碼等功能，但不能直接訪問外部連結。從開發角度看，小程式使用的是類似 Vue 的語法，有自己的元件系統和生命週期。**如果你會 Web 開發，學習小程式會很快。**

微信小程式使用的技術棧包括：WXML（類似 HTML）、WXSS（類似 CSS）、JavaScript。可以使用原生開發，也可以使用框架（如 Taro、uni-app）來開發跨平臺小程式。對於 Vibe Coding 來說，我推薦使用原生開發，因為 AI 對原生語法的支援更好，生成的程式碼質量更高。

開發小程式需要準備幾樣東西：

- 微信開發者賬號（免費註冊）
- 微信開發者工具（官方提供的 IDE）
- 一個專案創意

![微信開發者工具](https://pic.yupi.icu/1/image-20260112150540207.png)

註冊賬號很簡單，去微信公眾平臺註冊一個小程式賬號，選擇個人型別即可。下載開發者工具也很簡單，去官網下載對應系統的版本。

用 Vibe Coding 開發小程式和開發 Web 應用類似，只是語法稍有不同。你需要告訴 AI 你在開發微信小程式，它會生成符合小程式規範的程式碼。比如，你可以說：“請用微信小程式原生語法建立一個記賬頁面，包含金額輸入、分類選擇、備註輸入。” AI 會生成 WXML、WXSS 和 JS 檔案。

💡 如果你想系統學習小程式開發，可以閱讀魚皮在程式設計導航上 [免費的保姆級小程式學習路線](https://www.codefather.cn/course/1789189862986850306/section/1789190355448471554)。



## 二、專案實戰 - 記賬小程式

記賬是一個很實用的功能，很多人都有記賬的需求。做一個記賬小程式，可以學習小程式的基本開發流程，包括資料儲存、頁面跳轉、元件使用等。

這個記賬小程式要實現基本的記賬功能。使用者可以新增收支記錄，包括金額、型別（收入/支出）、分類（餐飲、交通、工資等）、備註、日期。首頁顯示記錄列表和統計資料（本月收入、支出、結餘）。支援按日期篩選記錄。資料儲存在本地，使用微信的本地儲存 API。

![](https://pic.yupi.icu/1/demoweb13.png)

使用微信小程式原生開發，不使用任何框架。資料儲存使用 `wx.setStorageSync` 和 `wx.getStorageSync`。



### 開發步驟

1）第一步是註冊小程式賬號。去 [微信公眾平臺](https://mp.weixin.qq.com/) 註冊一個小程式賬號。選擇個人型別，填寫基本資訊，完成註冊。註冊後會得到一個 AppID，開發時需要用到。

2）第二步是下載開發者工具。去 [微信開放文件](https://developers.weixin.qq.com/miniprogram/dev/devtools/download.html) 下載微信開發者工具，安裝後用微信掃碼登入。

3）第三步是建立專案。開啟開發者工具，點選新建專案，填寫專案名稱，選擇專案目錄，填入 AppID，選擇不使用雲服務。點選確定，會自動生成一個小程式專案模板。

4）第四步是瞭解專案結構。小程式專案的基本結構包括：

- pages 目錄：存放頁面，每個頁面有 wxml（頁面結構）、wxss（頁面樣式）、js（頁面邏輯）、json（頁面配置）四個檔案
- utils 目錄：存放工具函式
- app.js：小程式邏輯
- app.json：小程式配置
- app.wxss：全域性樣式

5）現在可以用 Cursor 開啟專案目錄，開始和 AI 對話開發。

首先設計資料結構：

```
我要開發一個記賬小程式，請幫我設計資料結構。

需要儲存的資訊：
- 金額
- 型別（收入/支出）
- 分類（餐飲、交通、購物、工資等）
- 備註
- 日期

請給出 JavaScript 物件的結構。
```

AI 會幫你設計合理的資料結構，包括每個欄位的型別和說明。

然後建立首頁：

```
請用微信小程式原生語法建立首頁（pages/index/index）：

頂部顯示統計卡片：
- 本月收入（綠色）
- 本月支出（紅色）
- 本月結餘（藍色）

中間顯示記錄列表：
- 按日期分組顯示
- 每條記錄顯示：分類圖示、分類名稱、備註、金額
- 收入顯示綠色，支出顯示紅色

底部有一個大的"+"按鈕，點選跳轉到新增頁面。

使用 Flex 佈局，介面要美觀。
```

這個提示詞詳細說明了首頁的佈局和樣式。AI 會生成完整的 WXML、WXSS 和 JS 程式碼。

接著實現資料儲存：

```
建立 utils/storage.js 工具檔案，封裝資料儲存操作：

1. saveRecord(record)：儲存一條記錄
2. getRecords()：獲取所有記錄
3. deleteRecord(id)：刪除一條記錄
4. getMonthRecords(year, month)：獲取指定月份的記錄

使用 wx.setStorageSync 和 wx.getStorageSync 儲存資料。
記錄要有唯一 ID（可以用時間戳）。
```

這樣就把資料儲存邏輯封裝好了，後面用起來很方便。

然後建立新增頁面：

```
建立新增記錄頁面（pages/add/add）：

頂部有兩個 Tab：收入、支出

金額輸入區：
- 大號的金額輸入框
- 顯示"¥"符號

分類選擇區：
- 宮格佈局顯示分類圖示
- 收入分類：工資、獎金、理財、其他
- 支出分類：餐飲、交通、購物、娛樂、醫療、其他
- 選中的分類高亮顯示

備註輸入：
- 單行文字輸入框

日期選擇：
- 預設今天
- 點選可以選擇日期

底部儲存按鈕：
- 點選儲存記錄並返回首頁
```

接著實現統計功能：

```
在首頁實現統計功能：

1. 計算本月總收入：篩選本月的收入記錄，求和
2. 計算本月總支出：篩選本月的支出記錄，求和
3. 計算本月結餘：收入 - 支出

在頁面載入時和返回時重新整理統計資料。
```

最後實現記錄列表：

```
在首頁實現記錄列表：

1. 獲取所有記錄，按日期倒序排列
2. 按日期分組顯示（今天、昨天、更早）
3. 每條記錄顯示分類圖示、名稱、備註、金額
4. 長按記錄可以刪除

實現下拉重新整理功能。
```



### 開發技巧

在開發小程式時，有幾個技巧可以提高效率。首先，要利用好微信開發者工具的除錯功能。可以在模擬器中預覽效果，也可以在真機上預覽。真機預覽需要用微信掃碼，可以看到真實的執行效果。

其次，小程式的資料儲存是同步的，使用 `wx.setStorageSync` 和 `wx.getStorageSync`。如果資料量大，建議使用非同步版本 `wx.setStorage` 和 `wx.getStorage`，避免阻塞主執行緒。

另外，小程式的頁面跳轉有幾種方式：`wx.navigateTo`（保留當前頁面，可以返回）、`wx.redirectTo`（關閉當前頁面，不能返回）、`wx.switchTab`（跳轉到 tabBar 頁面）、`wx.navigateBack`（返回上一頁）。要根據場景選擇合適的方式。

最後，小程式有一些限制，比如包大小不能超過 2MB（分包後每個包不超過 2MB），要注意控制圖片大小和程式碼體積。可以使用圖片壓縮工具壓縮圖片，使用程式碼分包功能拆分程式碼。



### 擴充套件思路

基礎版完成後，可以繼續擴充套件功能。比如新增預算設定，設定每月預算，超支時提醒；新增圖表展示，用圖表顯示收支趨勢；支援分類管理，使用者可以自定義分類；新增賬單匯出，匯出為 Excel 檔案；支援多賬本，可以建立工作賬本、生活賬本等；整合雲同步，使用微信雲開發實現多裝置同步。



## 三、專案實戰 - 打卡小程式

完成了記賬小程式後，讓我們來做一個涉及日曆和資料視覺化的專案。打卡是一個很好的習慣養成工具，很多人用打卡來堅持學習、運動、早起等。做一個打卡小程式，可以學習小程式的日曆元件、資料視覺化等功能。

這個打卡小程式要實現習慣打卡功能。使用者可以建立打卡專案（比如每天學習、每天運動），設定打卡目標（連續打卡天數）。每天可以打卡一次，打卡後顯示打卡成功。首頁顯示所有打卡專案和打卡狀態。日曆檢視顯示打卡歷史，打卡的日期標記為綠色。統計資料顯示總打卡天數、連續打卡天數、完成率等。

![](https://pic.yupi.icu/1/demoweb14.png)

使用微信小程式原生開發，資料儲存使用本地儲存。日曆元件可以使用第三方元件庫（如 Vant Weapp）或自己實現。



### 開發步驟

1）開發的第一步是設計資料結構。告訴 AI：

```
我要開發一個打卡小程式，請幫我設計資料結構。

打卡專案：
- id
- name（專案名稱，如"每天學習"）
- target（目標天數）
- created_at（建立時間）

打卡記錄：
- id
- project_id（關聯的專案）
- date（打卡日期，格式 YYYY-MM-DD）
- note（打卡備註，可選）
- created_at（打卡時間）

請給出資料結構和儲存方案。
```

AI 會幫你設計合理的資料結構，並說明如何儲存在本地。

2）建立專案列表頁

告訴 AI：

```
建立首頁（pages/index/index），顯示打卡專案列表：

每個專案卡片顯示：
- 專案名稱
- 今日是否已打卡（已打卡顯示綠色勾，未打卡顯示灰色圓圈）
- 連續打卡天數
- 總打卡天數
- 進度條（已打卡天數/目標天數）

底部有"新增專案"按鈕。

點選專案卡片進入專案詳情頁。
點選打卡按鈕進行打卡。
```

這個提示詞說明了首頁的佈局和互動。AI 會生成完整的頁面程式碼。

3）實現打卡功能

告訴 AI：

```
實現打卡功能：

1. 檢查今天是否已打卡
2. 如果未打卡，建立打卡記錄
3. 儲存到本地儲存
4. 顯示打卡成功提示
5. 重新整理頁面資料

打卡時可以新增備註（可選）。
```

打卡功能要防止重複打卡，所以要先檢查今天是否已打卡。

4）建立專案詳情頁

告訴 AI：

```
建立專案詳情頁（pages/detail/detail）：

頂部顯示專案資訊：
- 專案名稱
- 目標天數
- 已打卡天數
- 連續打卡天數

中間顯示日曆：
- 顯示當前月份
- 打卡的日期標記為綠色
- 今天標記為藍色邊框
- 可以切換月份

底部顯示打卡記錄列表：
- 按日期倒序顯示
- 顯示日期、備註

右上角有刪除專案按鈕。
```

5）實現統計功能

告訴 AI：

```
實現統計功能：

1. 總打卡天數：該專案的所有打卡記錄數
2. 連續打卡天數：從今天往前數，連續打卡的天數
3. 完成率：已打卡天數 / 目標天數
4. 最長連續打卡：歷史上最長的連續打卡天數

在專案詳情頁顯示這些統計資料。
```

連續打卡天數的計算比較複雜，要從今天往前遍歷，檢查每一天是否有打卡記錄，直到遇到沒有打卡的日期。AI 會幫你實現這個演算法。

6）實現日曆元件

告訴 AI：

```
實現日曆元件：

1. 顯示當前月份的所有日期
2. 打卡的日期標記為綠色背景
3. 今天標記為藍色邊框
4. 可以切換上個月/下個月
5. 點選日期可以檢視當天的打卡備註

使用 Grid 佈局，每行 7 個日期（週日到週六）。
```

日曆元件的實現比較複雜，但 AI 可以幫你搞定。如果覺得自己實現太麻煩，也可以使用第三方元件庫，比如 Vant Weapp。



### 開發技巧

在開發打卡小程式時，有幾個技巧需要注意。首先是日期處理，JavaScript 的日期處理比較複雜，可以讓 AI 幫你封裝一些工具函式，比如獲取當月天數、判斷是否是今天、計算兩個日期的天數差等。

其次是連續打卡天數的計算。要從今天往前遍歷，檢查每一天是否有打卡記錄，直到遇到沒有打卡的日期。可以讓 AI 幫你實現這個演算法，它會考慮各種邊界情況。

另外，日曆元件的實現比較複雜，如果覺得自己實現太麻煩，可以使用第三方元件庫。Vant Weapp 是一個很好的小程式 UI 元件庫，提供了日曆元件。可以讓 AI 幫你整合 Vant Weapp，使用它提供的日曆元件。

最後，打卡資料可能會越來越多，要注意效能最佳化。可以只載入最近 3 個月的資料，更早的資料按需載入，避免一次性載入太多資料導致頁面卡頓。



### 擴充套件思路

基礎版完成後，可以繼續擴充套件功能。比如新增打卡提醒，每天定時提醒使用者打卡；實現打卡分享，生成打卡海報分享到朋友圈；新增打卡排行榜，和好友比拼誰堅持得更久；實現打卡獎勵，連續打卡獲得勳章；支援資料匯出，匯出打卡記錄；整合雲同步，使用微信雲開發實現多裝置同步。



## 四、小程式上線全流程

開發完成後，如何讓小程式上線呢？這裡詳細講解小程式的上線流程。

1）完善小程式資訊

在微信公眾平臺，完善小程式的基本資訊：小程式名稱、簡介、頭像、類目（選擇合適的類目）。個人型別的小程式有一些限制，比如不能使用支付功能、不能使用某些類目。如果需要這些功能，需要註冊企業型別。

2）配置伺服器域名

如果小程式需要呼叫後端 API，需要在微信公眾平臺配置伺服器域名。只有配置了的域名才能在小程式中訪問。注意，域名必須是 HTTPS 的，需要有 SSL 證書。如果是本地開發，可以在開發者工具中勾選"不校驗合法域名"。

3）上傳程式碼

在微信開發者工具中，點選右上角的 “上傳” 按鈕，填寫版本號和專案備註，點選上傳。上傳後，程式碼會提交到微信伺服器。

4）提交稽核

在微信公眾平臺，進入 “版本管理”，可以看到剛才上傳的版本。點選"提交稽核"，填寫稽核資訊。稽核資訊包括：測試賬號（如果需要登入）、測試說明（告訴稽核人員如何測試）、隱私相關說明等。提交後，等待稽核。稽核時間說是 1 ~ 7 天，一般 1 ~ 2 天就能稽核透過。

5）釋出上線

稽核透過後，會收到通知。在微信公眾平臺，點選 “釋出” 按鈕，小程式就正式上線了。上線後，使用者可以透過搜尋、掃碼、分享等方式訪問你的小程式。

6）版本更新

如果要更新小程式，重複上面的流程：上傳程式碼 → 提交稽核 → 釋出上線。可以使用 “分階段釋出” 功能，先發布給部分使用者，測試沒問題後再全量釋出。

### 常見稽核問題

小程式稽核可能會遇到一些問題，這裡列舉幾個常見的。

1）功能不完整。稽核人員發現功能無法正常使用，比如點選按鈕沒反應、頁面顯示錯誤等。要確保所有功能都能正常使用，提交前自己先完整測試一遍。

第二個是類目不符。小程式的功能和選擇的類目不符。比如你做的是工具類小程式，但選擇了社交類目。要選擇合適的類目，如果不確定，可以諮詢微信客服。

缺少必要說明。比如小程式需要獲取使用者位置，但沒有說明用途。要在隱私政策中說明清楚，為什麼需要這些許可權，如何使用這些資料。

4）內容違規。小程式的內容違反了微信的規範，比如包含不當內容。要仔細閱讀微信小程式運營規範，確保內容合規。

如果稽核不透過，會收到拒絕原因。根據原因修改後，重新提交稽核即可。

**不要灰心，很多小程式第一次都會被拒絕，這是正常的。**



## 五、我上線《學習英雄》小程式的經歷

《學習英雄》是一個 AI 問答引導式學習小程式，使用者可以輸入想學習的主題，AI 自動生成相關的知識問答卡片，透過闖關答題的形式引導使用者更輕鬆愉快地掌握知識。

換到以前，我自己都不敢相信，記得大學的時候上線個小程式很快的，看來真的是時代變了。



### 完整的上線流程

1）小程式備案

以前壓根兒是沒有這一步的，但是自 2023 年 9 月 1 日起，所有新開發的微信小程式必須完成備案後才能上架。

備案操作是免費的，主要就是在後臺填寫一些個人/企業資訊。但是稽核週期大約 2 ~ 22 個工作日（含工信部稽核）。我是在國慶節前提了備案，過了 12 天后才透過；如果不是假期，可能會快點吧。

2）小程式類目申請

由於我的小程式用到了 AI 大模型來做問答功能，需要新增 “深度合成-AI 問答類目”，否則無法透過程式碼釋出稽核。

![](https://pic.yupi.icu/1/image-20251203212944981.png)

那我就按照修改指引新增類目唄，結果新增 AI 相關的類目是需要資質檔案的！因為我用的是別人的大模型，需要有技術主體的《網際網路資訊服務演算法備案》和《小程式主體與技術主體的合作協議》。

![](https://pic.yupi.icu/1/5b7bf1460d71ff74477082606e6e7cf8.png)

什麼？還要合作協議？！到這一步我估計會勸退一大波萌新，我剛看到的時候也頭疼了。

![](https://pic.yupi.icu/1/image-20251203215116730.png)

不過別慌，你用哪家的 AI 大模型服務，就直接去找對應的工作人員要就好了。比如我用的是阿里雲大模型，直接去官網聯絡客服，他們的技術支援響應很快，也很熱心。你只需要做到把自己的需求描述清楚，對方會幫你處理的。

![](https://pic.yupi.icu/1/image-20251203195218556.png)

大概花費了 10 天左右，我順利拿到了申請類目的材料，提交申請就好。

3）程式碼釋出稽核

感覺現在小程式的稽核越來越嚴格了，尤其是剛開始做的小程式，很容易因為一些意想不到的原因被打回來。

### 經驗總結

雖然我這次小程式上線花了近 2 個月，但其實中間有些空餘的時間是我自己沒來得及看到通知。不過就算只考慮必須的流程，差不多也要 1 個月了。

如果你只是想做個簡單的工具小程式，不涉及 AI 功能和需要報備的類目（比如社交、金融、醫療等），應該能省不少時間。

![](https://pic.yupi.icu/1/0.png)

不過我估計現在很多同學都有用 AI 做個《有 AI 功能的小程式》的想法，所以還是建議大家：

1. 提前申請小程式的類目：如果涉及 AI 功能，儘早準備資質材料
2. 先搞出最小可用版本：做一個 Demo 拿來過審、走完一次上線釋出的流程
3. 統籌安排時間：開發可能只要幾天，但上線流程可能要幾周甚至幾個月
4. 稽核前充分測試：確保所有功能正常，避免因為小問題被打回
5. 詳細說明測試流程：提供測試賬號和詳細的測試說明
