# AI 創意應用 - 蒸餾自己成 Skill 專案

本專案是一個有趣的 AI 創意應用，把自己的知識、經驗、思維模式「蒸餾」成一個 AI 技能包（Skill），讓 AI 以你的風格思考和回答問題。全程不需要寫程式碼，有手就能做。

本文不涉及複雜開發過程，僅給大家分享一個典型的 AI 創意應用案例，幫大家開拓思路。

專案程式碼免費開源：https://github.com/liyupi/yupi-skill

下面帶大家看看我是怎麼一步步把自己蒸餾成 Skill 的，你也可以照著這個流程蒸餾自己或者身邊的人（要合法哦），整個過程不需要寫程式碼，有手就行。

> Skills 簡單來說就是一種 AI 的「技能包」，它是一個包含 SKILL.md 檔案的目錄，用 Markdown 指令定義了 AI 在特定場景下的行為模式。裝上之後，AI 就能按照技能包裡的規則來思考和回答問題。目前 Claude Code、Cursor、Codex 等主流 AI 程式設計工具都支援。



## 準備工作

先新建一個 `yupi-skill` 目錄，用 AI 程式設計工具開啟。後面我們所有的蒸餾操作都在這個目錄裡完成。

建議用能力最強、上下文較長的大模型，蒸餾效果會更好。我這裡用的是 Claude Opus。

![](https://pic.yupi.icu/1/image-20260409142017010.png)



## 第一步：收集原料

AI 不瞭解你，它需要「原料」才能提煉出你的思維方式、表達風格和專業判斷。

這一步是整個流程的地基。原料越真實、越豐富，蒸餾出來的「你」就越像你。

你可以提供這些型別的素材：

| 素材型別 | 舉例 | 它能蒸餾出什麼 |
|---------|------|-------------|
| 自我介紹 / 簡歷 | 我叫 XXX，做了 X 年 XXX，MBTI 是 ISTJ… | 你的身份定位和性格特徵 |
| 個人經歷 | 求學、工作、轉行的關鍵故事 | 你的價值觀和成長路徑 |
| 聊天記錄 | 微信 / 飛書 / 釘釘的對話匯出 | 你的真實說話方式、口頭禪 |
| 工作文件 | 週報、方案、程式碼評審意見 | 你的專業判斷和做事方式 |
| 創作內容 | 部落格、影片指令碼、朋友圈、社交媒體 | 你的觀點和表達風格 |
| 別人對你的評價 | 同事反饋、朋友評價 | 你的盲區（自己看不到的特點）|

以我自己為例，我丟進去的原料包括：個人簡歷和自我介紹、寫過的爆款文章（用來蒸餾創作風格）、個人經歷文件、工作文件，還有和學員的聊天記錄等。

把這些素材檔案丟進專案的 `references/` 資料夾就行，什麼格式都行，比如文章、截圖、PDF、聊天記錄匯出、備忘錄…… 不用分類，先全丟進去。

![](https://pic.yupi.icu/1/image-20260409144409055.png)


### 聯網採集公開素材

如果你在網上有公開內容（部落格、影片、社交媒體等），還可以讓 AI 幫你聯網蒐集，省得自己一個個找。

前提是你的 AI 工具支援聯網搜尋，可以利用自帶的聯網功能、網頁抓取工具、Firecrawl MCP 等等。

下面這段是素材收集提示詞模板：

```
我想把自己蒸餾成一個 Agent Skill，現在需要先收集關於我的素材。

我已經在 references/ 資料夾裡放了一些本地素材，請先閱讀這些檔案，再結合聯網搜尋補充更多資訊。

我的基本資訊：
- 名字：[你的名字]
- 身份：[比如程式設計師、產品經理、獨立開發者]

我的公開內容渠道（請逐一訪問並整理關鍵內容）：
- [平臺1]：[連結]
- [平臺2]：[連結]
- ...

同時請聯網搜尋更多關於我的公開資訊（文章、採訪、產品、他人評價、大事件等）。

要求：
1. 只整理，不分析。記錄原始資訊，不要提煉觀點或下結論
2. 按來源型別分成幾個檔案存到 references/ 目錄下（如個人內容、他人評價、產品與專案、經歷與事件等，可根據內容量靈活調整）
3. 每條資訊標註來源連結和資訊型別（本人原話/本人文章/他人評價/媒體報道）
4. 整理完後告訴我：收集了多少條資訊、覆蓋了哪些方面、哪些方面資訊不足
```

把模板裡的內容替換成自己的資訊就行。比如我實際傳送的提示詞：

```markdown
我的基本資訊：
- 名字：程式設計師魚皮
- 身份：AI + 程式設計知識博主、教育創業者、全棧開發者

我的公開內容渠道：
- B 站主頁：https://space.bilibili.com/12890453
- 公眾號：程式設計師魚皮（搜尋相關文章）
- 掘金部落格：https://juejin.cn/user/2444938365386621
- GitHub 主頁：https://github.com/liyupi
- 公司主頁：https://yuyuanweb.com
- 個人產品大全：https://dogyupi.com
- 個人經歷和程式設計學習路線：https://github.com/liyupi/codefather
```

![](https://pic.yupi.icu/1/image-20260409153025082.png)

AI 完成了素材收集，並且分類建立了多個檔案：

![](https://pic.yupi.icu/1/image-20260409160036931.png)

如果 AI 說缺少哪方面的素材，你可以再手動補充。



## 第二步：分析素材，生成畫像

素材整理完了，但這時候它們還只是一堆散亂的原料。

這一步要讓 AI 通讀所有素材，提煉出一份結構化的《人物分析報告》，包括你的核心觀點、表達風格、做事方式、關鍵經歷，全都濃縮在一份文件裡。

這份報告是後續所有步驟的基礎。

給 AI 傳送提示詞：

```
references/ 裡的素材已經整理好了。

現在請你通讀所有素材，對我進行全面分析，生成一份「人物分析報告」，
儲存為 references/人物分析報告.md，包含以下維度：

1. 身份概要：我是誰、做什麼的、關鍵背景
2. 核心觀點和方法論：我反覆在說的、真正相信的東西
3. 表達風格：句式偏好、口頭禪、幽默方式、說話節奏
4. 做事方式：我怎麼做決策、推薦什麼、反對什麼
5. 關鍵經歷時間線：按時間排列的重大節點
6. 他人評價：別人怎麼看我

每個結論標註依據來源（來自哪個檔案/連結），資訊不足的維度直接說明。
```

![](https://pic.yupi.icu/1/image-20260409160843491.png)

AI 給出了詳細的人物分析報告。比如分析出了我的表達風格：結論先行 → 分點展開 → 一句話總結；自黑式幽默；短段落 + 大量留白；諮詢時直言不諱但收尾溫暖。

![](https://pic.yupi.icu/1/image-20260409161228612.png)

如果你想讓蒸餾效果更好，可以看看 AI 給出的建議。比如 AI 讓我補充 B 站影片口語風格轉錄和學員評價原文，於是我又給它餵了一些影片稿。

AI 給人物分析報告補充了更多我的表達風格：

![](https://pic.yupi.icu/1/image-20260409162017577.png)



## 第三步：AI 追問，挖掘深層思維

前面收集的素材能體現你「說過什麼、做過什麼」，但一個好的 Skill 需要更深層的東西，比如你怎麼思考、憑什麼做判斷、什麼情況下會改主意。

這一步的目標是透過 AI 追問，挖出你的心智模型、決策邏輯和內在矛盾，讓最終的 Skill 不只是「說話像你」，而是「思考像你」。

跟 AI 說：

```markdown
基於你剛才的人物分析報告，現在我需要你更深入地瞭解我，
目標是提煉出我的「思維作業系統」，包括我看問題的方式、做判斷的邏輯、表達的習慣。

請你先告訴我你初步提煉出的：我的核心心智模型、決策規則、表達特徵。
然後追問我 10 ~ 15 個問題，重點挖掘：
- 我反覆強調的觀點，背後更深的原因和適用邊界
- 我做判斷的具體標準，以及做錯過的決策
- 我說的和做的不一致的地方
- 我絕對不會做的事

問題要根據分析報告中的具體內容來問，不要問通用問題，用聊天的語氣。
```

AI 給出了我的核心心智模型，黑話直接拉滿，我差點兒沒看懂：

![](https://pic.yupi.icu/1/image-20260409163556431.png)

然後 AI 給了我 12 個追問。這些問題不是通用模板，而是根據我提供的素材定製的，每個問題都很犀利：

![](https://pic.yupi.icu/1/image-20260409163641942.png)

用自己平時說話的方式簡單回答就行。比如第一題：

> 你說「堅持下去一定會成功」，但你也說魚聰明 AI 一個月就止損了，劇本殺店也關了。你怎麼區分「應該堅持下去」和「應該馬上止損」？有沒有一個具體的判斷標準，比如時間、金額、還是某種感覺？

我的回答：堅持下去不是說一條路走到黑，而是把自己認為在當前情況下最值得做的事情做到最好。先根據時局判斷方向，然後在你認為正確的方向上傾盡全力。

最好把問題和回答儲存到一個單獨的文件中防止丟失。全部回答完成後，把你的答案發給 AI，讓它合併到分析報告中：

```markdown
請你把我的回答整合到分析報告中，更新心智模型和決策邏輯的提煉。
@你的回答
```

![](https://pic.yupi.icu/1/image-20260409165326778.png)

AI 透過我的回答，更瞭解我了。心智模型做了 6 處關鍵修正和深化：

![](https://pic.yupi.icu/1/image-20260409165739285.png)



## 第四步：補充能力（可選）

到這裡，AI 已經很瞭解你了。但一個好的 Skill 不只是「說話像你」，還需要做事也像你。遇到具體問題時，能像人一樣先查資料再給建議。

這一步讓 Skill 從「鸚鵡學舌」升級到「真正能幫人」。

你可以告訴 AI，你的 Skill 需要哪些特殊能力。

以我為例，因為我有大量學程式設計、求職找工作、學 AI 的資源分佈在不同網站上，所以我希望 Skill 在回答相關問題時能自動去這些網站獲取最新資訊。

給 AI 準備的提示詞：

```markdown
之後生成最終 Skill 時，請加入以下能力：

1）聯網搜尋：遇到需要具體資訊的問題時（比如最新技術趨勢、某個工具的用法），先用聯網搜尋工具查資料，再用我的風格和判斷框架回答。

2）指定資訊源：回答跟我相關的問題時，優先去這些地方獲取最新資訊：
- https://dogyupi.com ：使用者問"魚皮有什麼產品"或想了解我的整體業務時，去這裡查產品大全
- https://www.codefather.cn ：使用者問程式設計學習路線、專案教程、技術知識時，去這裡查最新教程
- https://ai.codefather.cn ：使用者問 AI 相關的工具、教程、資訊時，去這裡查 AI 導航和知識庫
- https://mianshiya.com ：使用者問面試題、刷題、求職準備時，去這裡查面試題庫
- https://laoyujianli.com ：使用者問怎麼寫簡歷、改簡歷時，推薦這個工具
- https://github.com/liyupi ：使用者問我的開源專案或想看原始碼時，去這裡查

3）持續進化：支援透過補充新素材來持續更新和最佳化 Skill
```

你還可以新增 `scripts` 指令碼目錄，放一些 Python 指令碼實現自動化操作，甚至可以對接 API 從你的產品中獲取資料。

不過因為現在很多 AI 程式設計工具都自帶聯網搜尋和網頁抓取功能，這裡就不寫額外的指令碼了。

傳送提示詞給 AI 後，AI 確認理解了任務：

## 第五步：開始蒸餾

前面四步已經收集了所有資訊，這一步讓 AI 把它們組裝成一個標準的 `SKILL.md` 檔案。

先安裝 Anthropic 官方提供的 `skill-creator` 技能。它是一個「造技能的技能」，能引導 AI 自動生成符合規範的 Skill 結構。

輸入一行命令就能安裝了：

```bash
npx skills add https://github.com/anthropics/skills --skill skill-creator
```

![](https://pic.yupi.icu/1/image-20260409180936318.png)

安裝好之後，在提示詞中宣告使用 skill-creator（或者直接用斜槓命令 `/skill-creator`）：

```markdown
現在你已經透過素材整理、分析報告、追問訪談全面瞭解了我。
請使用 skill-creator 為我建立一個完整的 Skill。
要求：
1. 以我的身份和口吻說話，像我本人在回答一樣
2. 提煉出我看問題的方式、做判斷的規則、說話的習慣
3. 如果上一步配置了聯網搜尋和資訊源，也寫進 Skill 裡
4. 寫明這個 Skill 做不到什麼、以及怎麼用新素材更新它
生成完成後，自己想 3 個使用者最可能問的問題，用 Skill 回答並評估是否像我。
```

![](https://pic.yupi.icu/1/image-20260409171938570.png)

AI 完成了整個 Skill 的開發和測試。生成的 `yupi-skill` 目錄就是可以直接使用的技能包：

![](https://pic.yupi.icu/1/image-20260409172607113.png)

大功告成！

## 開源釋出

測試沒問題後，就可以把整個 `yupi-skill` 目錄開源了。

注意，製作技能過程中的所有素材檔案（比如聊天記錄、個人經歷文件、人物分析報告等）最好不要一起開源。尤其是你要蒸餾自己或者身邊的人，這些素材可能會洩露隱私。

但保險起見，還是要確認一下生成的 Skill 不依賴製作過程中的文件。當然，在不涉及隱私暴露的前提下，如果為了效果更好、回答更準確，你可以按需保留一部分參考檔案。

![](https://pic.yupi.icu/1/image-20260409172930076.png)

然後讓 AI 幫你生成一份有吸引力的 README.md 專案介紹文件：

```markdown
參考 GitHub 上知名的 Skill 倉庫：https://github.com/titanwings/colleague-skill/

幫我給 @yupi-skill 生成完備的、有吸引力的 README.md 文件。

然後把這個目錄開源到 https://github.com/liyupi/yupi-skill
```

![](https://pic.yupi.icu/1/image-20260409174544926.png)

## 寫在最後

整個蒸餾過程並不複雜，總結下來就五步：收集原料 → 生成畫像 → AI 追問 → 補充能力 → 開始蒸餾。

全程不需要寫程式碼，有手就能做。
