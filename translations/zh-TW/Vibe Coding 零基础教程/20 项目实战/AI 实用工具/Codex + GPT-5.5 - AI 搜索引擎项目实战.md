# Codex + GPT-5.5 實戰：手把手開發一個 AI 搜尋引擎

想必你已經發現了，如今的搜尋引擎已經全面進化了。

以前搜東西，就是輸入關鍵詞，然後在一堆藍色連結裡挑著看。

現在呢，直接輸入一個問題，AI 會幫你聯網搜尋、彙總分析，給出一份帶引用來源的完整回答。

比如主打 AI 搜尋的 Perplexity，據說月活使用者已經突破 1 億了；Google、百度、必應也都在搜尋結果里加了 AI 智慧摘要。

搜尋這件事，正在從「人找資訊」變成「AI 幫你找資訊」。

那這種 AI 搜尋引擎到底是怎麼實現的？

## 需求分析

這次要做的專案叫 yupi-ai-search AI 搜尋引擎，對標 Perplexity。

要注意，AI 搜尋引擎跟普通的 AI 對話應用不一樣。如果你只讓 AI 回答問題，它用的是訓練資料裡的舊知識，回答可能是過時的。AI 搜尋引擎的關鍵在於 **聯網搜尋** 能力，讓 AI 先去網上搜最新的資訊，再基於這些資訊來回答，這樣才能確保答案是準確、及時的。

具體的需求是：使用者輸入一個問題，系統自動聯網搜尋最新資訊，再交給 AI 大模型綜合分析，生成一份帶引用來源的智慧回答，同時還能像傳統搜尋引擎一樣檢視完整的搜尋結果列表。使用者還可以透過相關問題推薦繼續追問，不斷深挖感興趣的內容。

![](https://pic.yupi.icu/1/image-20260512142357593.png)



## 方案設計

這個專案採用前後端分離架構，前端用 Vue 3，後端用 Python FastAPI + LangChain。

不過傳統的前後端技術不是重點，實現 AI 搜尋引擎的關鍵在於兩樣東西：一個是搜尋服務，負責聯網獲取最新資訊；一個是 AI 大模型，負責理解搜尋結果並生成綜合回答。

AI 大模型我就選擇 DeepSeek V4，試試它在真實業務場景中的效果。

這個專案真正的核心是，搜尋服務要怎麼實現？



### 搜尋服務

先簡單聊聊搜尋引擎的原理。

傳統搜尋引擎乾的事情其實就 3 步：

1. 抓取網頁，派爬蟲到處爬
2. 建立索引，把網頁內容整理成資料庫
3. 排名展示，根據相關性給結果排序

Google、百度這些搜尋引擎，背後都是幾十萬臺伺服器在跑這套系統。

![](https://pic.yupi.icu/1/01_%25E6%2590%259C%25E7%25B4%25A2%25E5%25BC%2595%25E6%2593%258E%25E5%258E%259F%25E7%2590%2586%25E7%25A4%25BA%25E6%2584%258F%25E5%259B%25BE_compressed_v1.png)

如果擱以前，讓你自己開發一個搜尋引擎，簡直想都不敢想，光是抓取全網頁面這一步就能把人勸退。

但現在不一樣了，有了 AI 程式設計工具，加上現成的搜尋引擎 API 服務，你不需要自己爬網頁、建索引，直接調 API 就能拿到搜尋結果，然後交給 AI 總結就完事了。

目前專門為 AI 應用設計的搜尋服務已經有不少了，比如 Tavily Search、Firecrawl、Brave Search API 等等，它們都能透過 API 呼叫拿到結構化的搜尋結果，直接給 AI 使用。

![](https://pic.yupi.icu/1/image-20260512152607731.png)

下面重點介紹一下本專案選用的 Tavily Search。



### Tavily Search

Tavily Search 是目前 AI 應用開發領域最主流的搜尋 API 之一，知名的 AI 應用開發框架 LangChain 官方首推的搜尋工具就是它。

它有幾個優勢：

1. 返回的是結構化的搜尋結果（標題、URL、內容摘要），不是原始 HTML，直接塞給 AI 就能用，省 tokens
2. 搜尋速度快，一般 3 秒左右就能出結果
3. LangChain 有官方整合包 `langchain-tavily`，幾行程式碼就能接入
4. 支援中文搜尋，可以透過 `country` 引數設定為中國，最佳化中文搜尋結果

價格方面，免費版每月 1000 次 API 呼叫，不需要綁信用卡，對於個人專案和 MVP 驗證完全夠了。按需付費是每次 0.008 美元（約 6 分錢），Growth 套餐 10 萬次/月 500 美元，所以實際上線還是要注意成本的。

下面我帶大家簡單體驗一下。

進入 [Tavily 官網](https://www.tavily.com)，可以看到它提供 4 方面的能力，包括聯網搜尋、提取網頁內容、爬蟲和深度研究。

![](https://pic.yupi.icu/1/1776256669936-290f2a07-4b99-4f2e-8917-5a8f5c8ee120.png)

登入後進入管理後臺，獲取 API Key：

比如我搜尋一下 “程式設計師魚皮”，可以看到返回了 JSON 格式的結構化結果，每條都包含標題、URL 和內容摘要，搜到了我的部落格、GitHub 主頁等資訊，還挺全面的。

### LangChain 整合 Tavily

這個專案中，我們使用主流的 AI 應用開發框架 LangChain 來整合 Tavily。

LangChain 有現成的官方整合包 `langchain-tavily`，用起來非常方便。只需要在程式碼裡給 Agent 繫結 TavilySearch 工具，然後建立 Agent 就能直接對話了：

```python
from langchain_tavily import TavilySearch
from langchain.agents import create_tool_calling_agent

tavily_search_tool = TavilySearch(
    max_results=5,
    topic="general",
)

# 建立 Agent，繫結搜尋工具
agent = create_tool_calling_agent(model, [tavily_search_tool])
# 使用者提問，Agent 自動判斷是否需要搜尋
response = agent.invoke({"messages": "最近有什麼 AI 新聞？"})
```

除了搜尋，還有 TavilyExtract 工具，可以根據網址提取乾淨的網頁內容：

![](https://pic.yupi.icu/1/1776257649471-db04269f-1efd-4a96-b485-c762dc2d0b59.png)

看不懂程式碼沒關係，之後我們把這些需求寫進提示詞，讓 AI 自己去查文件、寫程式碼就行。



### Firecrawl 搜尋服務

除了 Tavily，Firecrawl 也是一個不錯的選擇。Firecrawl 更擅長網頁抓取和全站爬取，它本身也提供了搜尋功能。

兩者的定位有一點兒差異，我用表格簡單對比一下：

| 維度           | Tavily Search                        | Firecrawl                            |
| -------------- | ------------------------------------ | ------------------------------------ |
| 定位           | AI 原生搜尋 API，專為 RAG/Agent 設計 | Web 資料 API，主打網頁抓取和內容提取 |
| 搜尋速度       | 1 ~ 3 秒                             | ~7 秒（含頁面抓取）                  |
| 返回格式       | 結構化摘要，節省 Tokens              | Markdown/HTML/JSON，內容更完整       |
| LangChain 整合 | 官方首推，有專用包                   | 有 Python SDK，需自行封裝            |
| 開源           | 否                                   | 是（AGPL-3.0，可自部署）             |
| 免費額度       | 1000 次/月                           | 1000 credits/月                      |
| 100K 量級月費  | $500                                 | $83                                  |
| 最適合場景     | AI Agent 聯網搜尋                    | 全站爬取、資料提取                   |

對於我們這個 AI 搜尋引擎專案，Tavily 的搜尋速度和結構化返回更合適，所以選它作為主力。

在後面的環境準備部分，我也會帶大家安裝 Firecrawl，不過它的作用是幫 AI 程式設計工具聯網搜尋技術文件，跟專案本身的搜尋功能不是一回事兒。



### 核心業務流程

最後梳理一下整個 AI 搜尋引擎的核心流程：

1. 使用者在前端輸入問題
2. 後端接收請求，呼叫 Tavily Search API 聯網搜尋，拿到結構化的搜尋結果
3. 把搜尋結果作為上下文注入 Prompt，交給 DeepSeek V4 大模型
4. AI 基於搜尋結果生成帶引用編號的綜合回答，透過 SSE 流式返回給前端
5. 前端同時展示 AI 綜合回答和完整的搜尋結果列表
6. AI 回答完成後，自動生成相關問題推薦，方便使用者繼續探索

## 開發編碼

新建一個 `yupi-ai-search` 專案資料夾，在 Codex 中開啟：

![](https://pic.yupi.icu/1/1778555023028-80d1f617-111e-4e19-815c-7f455101674a.png)

然後輸入提示詞。這裡分享一下我實際用的提示詞，給大家參考：

```markdown
## 角色

你是一個全棧工程師，擅長 Python + FastAPI + LangChain + Vue 開發。

## 任務

開發一個叫 yupi-ai-search 的 AI 搜尋引擎網站。使用者輸入自然語言問題，系統自動聯網搜尋最新資訊，再將搜尋結果交給 DeepSeek V4 大模型綜合分析，生成一份帶引用來源的智慧回答，同時展示完整的搜尋結果列表。

核心功能：
1. 搜尋主頁：簡潔的搜尋框，輸入問題後發起 AI 搜尋
2. AI 聯網搜尋：呼叫 Tavily Search API 獲取最新網頁資訊，將搜尋結果作為上下文注入 Prompt，讓 AI 生成綜合回答
3. 引用來源展示：AI 回答中引用的資訊必須標註來源編號，底部列出所有引用來源的標題和連結，使用者可點選跳轉原文
4. 搜尋結果列表：除了 AI 綜合回答外，還要像傳統搜尋引擎一樣展示完整的搜尋結果列表，包括 AI 未直接引用到的結果
5. 流式輸出：AI 回答支援 SSE 流式輸出，打字機效果實時顯示
6. 搜尋歷史：本地儲存搜尋歷史記錄，支援快速重新搜尋
7. 相關問題推薦：AI 回答完成後，自動生成 3-5 個相關問題供使用者繼續探索

## 技術棧

- 後端：Python FastAPI + LangChain
- 前端：Vue 3 前後端分離，支援 Markdown 渲染和程式碼高亮
- AI 模型：對接 DeepSeek V4（相容 OpenAI SDK 格式，透過環境變數配置）
- 搜尋：Tavily Search API（透過 langchain-tavily 整合）

## 要求

1. 頁面參考 Perplexity 的簡潔風格，搜尋頁面居中大搜尋框，結果頁面資訊密度高，使用 UI UX Pro Max 技能美化
2. 開發前，先透過 Firecrawl 聯網搜尋相關資訊，透過 Context7 查詢 LangChain、FastAPI、Tavily Search、DeepSeek API 的最新文件
3. 必須生成完整可執行的程式碼，每步完成後必須自主測試驗證
```

雖然看著又臭又長，但其實是藉助 AI 生成的，我簡單解讀一下這段提示詞的幾個要點：

- **角色定義** 放在最前面，讓 AI 進入全棧工程師的狀態
- **任務描述** 用自然語言把需求講清楚
- **技術棧** 只列關鍵選型，比如 LangChain + Tavily Search 的組合，讓 AI 自己決定具體的實現方案

## 擴充套件思路

雖然我們很快就開發出了一個能用的 AI 搜尋引擎，但要知道，開發完成只是第一步。一個成熟的搜尋引擎產品，要考慮的事情還有很多，這也是跟其他同學拉開差距的地方。

我這裡藉助 AI 給大家提供一些思路：

1. 搜尋結果快取：同樣的問題短時間內被多個使用者搜尋，沒必要每次都調 Tavily 的 API，快取下來能省不少成本
2. 搜尋結果排序最佳化：可以根據來源的權威性、內容的時效性來重新排序，而不是直接用 Tavily 返回的順序
3. 多模態搜尋：支援搜圖片、搜影片、搜檔案，不只是文字
4. 可觀測性：加上日誌、監控和鏈路追蹤，知道每一次搜尋請求經歷了哪些步驟、各花了多少時間、哪裡容易出問題
5. 成本控制：搜尋 API 和大模型 API 都是按量計費的，要做好限流、配額管理，防止被惡意刷介面，一不小心就是一筆大開支
6. 安全防護：防止 Prompt 注入攻擊、過濾違規內容，這些上線前必須考慮

我們要學會站在巨人的肩膀上，用現成的工具快速搭建原型，但同時也要能看到原型背後缺少的東西，這才是真正的工程能力。



## 我的感受

最後聊聊我用 Codex、GPT-5.5 和 DeepSeek V4 的真實感受。

先說 Codex，Codex 的介面主打一個簡潔，第一眼看上去甚至不像 AI 程式設計工具，更像個 AI 聊天助手。但功能其實比較完整，比如 MCP 和 Skills 擴充套件、外掛市場、自動化、Git 整合、Browser Use、Computer Use，AI 程式設計所需的工程能力基本都具備了。

而且最近的更新速度嘎嘎快，還有工夫整個 AI 桌面寵物給我們加點兒情緒價值……（雖然有些 UI 調整我覺得不如之前的好看）

![](https://pic.yupi.icu/1/image-20260505182943304-20260512154052050.png)

不過缺點也很明顯。預設可用的模型有限，不像 Cursor 和 Copilot 原生就整合了 Claude、GPT、Gemini 各種模型隨便切。易用性也差了一些，從 MCP 配置那裡大家應該已經感受到了。Copilot 可以直接在擴充套件市場一鍵搜尋安裝 MCP，Cursor 也支援視覺化編輯 JSON 配置，Codex 這邊還得自己折騰命令列或者手寫 TOML。

![](https://pic.yupi.icu/1/1777266857576-e240c700-e113-4d3d-8f4d-44512175986f-20260512145745548-20260512154052085.png)

再說說 GPT-5.5 模型。我除了這個專案之外，之前的教程以及自己的專案中也多次用到了 GPT-5.5，整體感覺不如 Claude Opus 4.6。但能力還是很強的，只要提示詞到位，基本都能一把梭全棧專案的前端和後端，而且核心業務流程大機率一次性跑通。

我感覺 GPT-5.5 的特點是 **很聽提示詞的話**，前端表現中規中矩，不會給你特別大的驚喜。所以想要利用好能力強的大模型，提示詞還是得認真寫、功能點列清楚、給一點方案和開發流程的引導，AI 才能給你滿意的結果。

再看看 GPT-5.5 的成本。這次開發消耗了 13.4 萬 tokens，上下文用了 52%。Codex 桌面端的上下文容量是 258K，開發這種全棧專案基本夠用了：

![](https://pic.yupi.icu/1/1778562964683-a8df5a46-5762-48f5-9593-4e89d21b739f.png)

我目前開的是 GPT Plus 會員，一個月 20 刀（150 元左右），每 5 小時和每週有限額。做完這個專案後，5 小時的額度用了差不多一半，不算擴充套件功能的話，1 周差不多能做 10 個完整專案。

![](https://pic.yupi.icu/1/1778563016906-8653e48f-c417-44c6-8157-99f4e82b7a86.png)

最後說說 DeepSeek V4 吧。這次專案用的是 V4-Flash 模型作為搜尋引擎的大腦，生成速度還是挺快的，效果也不錯，作為搜尋結果的整理完全夠用了，不需要上 Pro。

Flash 模型的價格很便宜，我測試時用了 24 次請求才花了 9 分錢。按正常上線給使用者訪問的量來算，1 天 1000 次請求大約消耗 3.75 元，價效比很高，我們團隊的一些業務也會對接 DeepSeek API。

![](https://pic.yupi.icu/1/1778561258409-d0081f49-c868-49a8-80e5-f1342e83bde7.png)

總的來說，AI 應用開發的門檻已經非常低了。以前做一個搜尋引擎是大廠才能乾的事情，現在一段提示詞就能搞出來一個能用的原型。

但畢竟「能做出來」和「做得好」之間還有很大的距離，前面提到的快取、安全、成本控制這些工程化的東西，才是真正考驗功底的地方。
