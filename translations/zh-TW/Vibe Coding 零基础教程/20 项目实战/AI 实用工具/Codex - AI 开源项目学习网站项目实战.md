# Codex - AI 開源專案學習網站專案實戰

本專案是一個 AI 驅動的開源專案學習助手，使用者輸入 GitHub 倉庫地址，系統自動分析原始碼並生成通俗易懂的分析報告，還支援針對原始碼的互動式問答。全程使用 Codex + GPT-5.5 開發，後端對接 DeepSeek V4 API。

大家好，我是程式設計師魚皮。

最近 AI 圈兒也太鬧騰了，4 月 23 號 OpenAI 釋出了 GPT-5.5，緊接著第二天 DeepSeek 就放出了 V4，兩個重磅模型前後腳上線。

![](https://pic.yupi.icu/1/image-20260428152723505.png)

光看跑分沒什麼意思，模型好不好用，還得拿真實專案來檢驗。

正好 OpenAI 的 Codex 桌面端這段時間更新很猛，已經從一個純 AI 程式設計工具進化成了支援 Computer Use、外掛市場、內建瀏覽器的「超級 App」。

所以這篇文章，我全程用 Codex + GPT-5.5 來開發一個完整的全棧專案，後端對接 DeepSeek V4 的 API 實現 AI 能力。

看完這期，你能學會 Codex 的使用方法、感受新模型的實際能力、掌握 AI 程式設計的實用技巧，可謂一舉三得。

點個收藏，咱們開始~



## 需求分析

這次要做的專案叫「專案學習助手」（project-helper），核心需求很簡單：

使用者輸入一個 GitHub 倉庫地址，系統自動克隆專案並分析原始碼，生成一份通俗易懂的完整分析報告。報告涵蓋專案概述、技術棧、目錄結構、核心模組、資料流、設計模式、閱讀建議等，真正做到「傻子也能懂」。分析過程實時推送進度，已經分析過的專案自動快取，不用重複分析。

![](https://pic.yupi.icu/1/image-20260427152036161.png)

另外，使用者還可以針對原始碼進行互動式問答，AI 會自主搜尋程式碼、讀取檔案來回答問題，支援流式輸出。

這樣一來，你可以快速學會任何開源專案，哪怕面對幾萬行程式碼的倉庫，也完全不虛。



## 方案設計

如果你完全沒有任何技術基礎，可以讓 AI 幫你完成方案設計。

但這裡為了節省時間和 tokens，我直接告訴 AI 怎麼做。

專案採用前後端分離架構：

- 後端用 Python FastAPI + LangChain + SQLite
- 前端用 Vue 框架
- AI 能力對接 DeepSeek V4 的 API

AI 分析和 AI 問答能力的實現還是有點小技巧的，如果一個程式碼倉庫有幾萬行，難道要全部扔給 AI 自己去分析麼？

我的思路是， 採用 AI 工具呼叫（Tool Use）的方式，給 AI 提供讀取檔案、搜尋程式碼、獲取倉庫結構等工具，剩下的交給 AI 自己判斷該看哪些檔案、該怎麼組織答案。這也是 DeepSeek V4 專門最佳化過的 Agentic 場景。

![](https://pic.yupi.icu/1/image-20260427143741108.png)

## 開發

新建一個 `project-helper` 專案資料夾，在 Codex 中開啟：

![](https://pic.yupi.icu/1/1777259374913-7c4ecded-191b-4010-820a-fe8c31ab3da9.png)

然後輸入提示詞。這裡分享一下我實際用的提示詞，給大家參考：

```markdown
## 角色

你是一個全棧工程師，擅長 Python + FastAPI + LangChain 開發。

## 任務

開發一個叫 project-helper（專案學習助手）的 Web 應用，幫助使用者快速讀懂任意開源專案的原始碼，傻子也能懂。

使用者輸入一個 GitHub 倉庫地址，系統自動克隆專案並分析原始碼，生成一份通俗易懂的完整分析報告，涵蓋專案概述、技術棧、目錄結構、核心模組、資料流、設計模式、閱讀建議等。分析過程實時推送進度，已分析過的專案自動快取，無需重複分析。

使用者還可以針對原始碼進行互動式問答，給 Agent 提供讀取檔案、搜尋程式碼等工具，讓 AI 自主查詢程式碼來回答問題，支援流式輸出。

## 技術棧

- 後端：Python FastAPI + LangChain + SQLite + 對接 DeepSeek V4 模型
- 前端：Vue，前後端分離

## 要求

1. 頁面需要閱讀舒適，具有科技感，程式碼塊有語法高亮，使用 UI UX Pro Max 技能美化頁面
2. 開發前，先透過 Firecrawl 聯網搜尋資訊，透過 Context7 查詢最新技術文件和用法
3. 必須生成完整可執行的程式碼，每步完成後必須自主測試驗證
```

簡單解讀一下這段提示詞的幾個要點：

- **角色定義** 放在最前面，讓 AI 進入全棧工程師的狀態
- **任務描述** 用自然語言把需求講清楚
- **技術棧** 只列關鍵選型，讓 AI 自己決定具體實現方案
- 最後兩條要求是關鍵，讓 AI 先查文件再寫程式碼，避免瞎編寫法；讓 AI 開發完後自主測試，減少翻車

模型我選擇 GPT-5.5，智慧程度選「高」，許可權給完全訪問（主要圖個省事兒）：

![](https://pic.yupi.icu/1/1777259547435-755d715a-4233-4779-a198-a2d38d94c92c.png)

注意，如果你想讓 AI 測試得更完整，可以先獲取好 DeepSeek 的 API Key 並直接寫在提示詞裡。否則沒有 API Key，AI 是沒法完成大模型呼叫測試的。

## 測試驗證

接下來需要獲取 DeepSeek 的 API Key，進入 [DeepSeek 開放平臺](https://platform.deepseek.com)，建立 API Key，記得不要洩露哦！

![](https://pic.yupi.icu/1/1777261129697-2ad16c21-6d70-4e87-879c-df2dd7e888b2.png)

大家在使用某個 AI 大模型時，記得要關注一下價格。比如目前 DeepSeek 的 V4-Flash 百萬 tokens 輸入只要 1 元、輸出 2 元；V4-Pro 輸入 3 元、輸出 6 元（限時 2.5 折優惠到 5 月 5 號）。快取命中的話更便宜，V4-Flash 輸入低至 0.02 元/百萬 tokens。

![](https://pic.yupi.icu/1/1777261160054-a4d31930-44d6-4bcb-a3d0-72b533793cb7.png)

但是 DeepSeek 目前還沒有 Coding Plan，不太建議拿它來 AI 程式設計，估計消耗的 tokens 會讓很多同學吃不消。但是用它來做 AI 應用的大腦非常合適，價效比很高。

根據 AI 給出的指引，在 Codex 中開啟終端，設定環境變數，把 API Key 改為你自己的：

```bash
export DEEPSEEK_API_KEY=你的_key
export DEEPSEEK_MODEL=deepseek-v4-pro
```

![](https://pic.yupi.icu/1/1777261353853-35e38b40-6f56-4d02-b2f1-90bfed1755be.png)

不過這種 `export` 方式是臨時的，終端一關就沒了。

更好的做法是讓 AI 搞一個環境變數配置檔案，我們手動填寫就行。

![](https://pic.yupi.icu/1/1777261704240-13861afc-d888-46cb-b2ff-594d3acd3dd7.png)

注意，如果你的專案要開源，一定記得在 `.gitignore` 中忽略 `.env` 檔案，防止 API Key 洩露到 GitHub 上。

然後直接在編輯器中開啟 `.env` 檔案，把 API Key 填進去：

![](https://pic.yupi.icu/1/1777261752700-19c79ce9-9589-476d-a728-369353e279ff.png)

## 我的感受

最後聊聊我用 Codex、GPT-5.5 和 DeepSeek V4 的真實感受。

先說 Codex，Codex 的介面主打一個簡潔，第一眼看上去甚至不像 AI 程式設計工具，更像個 AI 聊天助手。但功能其實比較完整，比如 MCP 和 Skills 擴充套件、外掛市場、自動化、Git 整合、Browser Use、Computer Use，AI 程式設計所需的工程能力基本都具備了。

不過缺點也很明顯。預設可用的模型有限，不像 Cursor 和 Copilot 原生就整合了 Claude、GPT、Gemini 各種模型隨便切。易用性也差了一些，從 MCP 配置那裡大家應該已經感受到了。Copilot 可以直接在擴充套件市場一鍵搜尋安裝 MCP，Cursor 也支援視覺化編輯 JSON 配置，Codex 這邊還得自己折騰命令列或者手寫 TOML。

![](https://pic.yupi.icu/1/1777266857576-e240c700-e113-4d3d-8f4d-44512175986f.png)

再說說 GPT-5.5 模型。有一說一，我測了幾個全棧專案，並沒有明顯感受到 GPT-5.5 和 Claude Opus 模型的差距。只要提示詞到位，基本都能一把梭全棧專案的前端和後端，而且核心業務流程大機率一次性跑通。前端表現嘛，中規中矩，雖然實現了響應式，但 UI 沒有特別驚豔的地方。。。

![](https://pic.yupi.icu/1/1777267657382-9f026e06-9984-42f6-b371-c998a41d2af9.png)

再看看 GPT-5.5 的成本。以開發前面這個專案為例，共消耗了 13 萬 tokens，上下文用了 50%。Codex 桌面端目前上下文容量是 258K，開發簡單的全棧專案沒問題，但複雜工程專案可能會有壓力。

![](https://pic.yupi.icu/1/1777268009237-7136c440-d7f9-4fec-8949-9c7fbc3deeb9.png)

我目前開的是 GPT Plus 會員，一個月 20 刀（150 元左右），每 5 小時和每週有限額。做完這個專案，5 小時的額度基本就用完了，不算擴充套件功能的話，1 周差不多能做 5 個完整專案。

![](https://pic.yupi.icu/1/1777266442906-7ccad38c-40d0-488e-a891-27dafc3876ef.png)

最後說說 DeepSeek V4。

我們團隊之前的業務有接入 DeepSeek V3，也在帶大家做的專案中用過 V3。這次把 V4 接到業務裡，生成速度還是挺快的，效果比 V3 提升明顯，尤其是對程式碼的理解和分析能力。而且有了 100 萬 tokens 的超長上下文支援，讓我們可以做更重的 AI 應用，比如深度研究、複雜專案原始碼的全域性分析等等。

看一下實際的 API 消耗，測試過程中用了 27 次請求，消耗了 5 萬多 tokens，花費 0.15 元。按正常使用者使用量算，一天 1000 次請求大約消耗 5.5 元，價效比很高。

![](https://pic.yupi.icu/1/1777266027113-1126052d-a9a6-4049-ab3a-b75291612a87.png)

總的來說，後續我不太會繼續用 Codex 來做日常 AI 程式設計，做複雜專案時會選擇 GPT-5.5 或 Claude Opus 模型，但開發 AI 應用時會優先對接 DeepSeek V4 的 API，便宜好用。



## 寫在最後

這個專案從需求到上線，全程用 Codex + GPT-5.5 完成開發，後端對接 DeepSeek V4 的 API，整個過程不到 20 分鐘。

雖然 Codex 在 MCP 配置體驗上還不如 Cursor 和 Copilot 方便，但功能完整度已經很不錯了。更重要的是，這個專案讓我們看到了用不同 AI 程式設計工具開發全棧專案的可能性。如果你想了解更多 AI 程式設計工具的使用方法和對比，可以閱讀本教程程式設計工具板塊的相關文章。
