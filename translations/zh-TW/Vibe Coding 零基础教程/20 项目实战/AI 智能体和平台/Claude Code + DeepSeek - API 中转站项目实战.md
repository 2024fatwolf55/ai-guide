## 什麼是 API 中轉站？

打個比方，你想買個國外的包，但自己不方便直接去海外專櫃，於是找了個代購。你把錢給代購，代購幫你去各大品牌店買好寄給你，順便賺個差價和服務費。

API 中轉站乾的就是代購的活。

你平時用 AI 聊天、寫程式碼、做應用，不直接對接 AI 模型廠商（比如 OpenAI、DeepSeek、智譜等），而是透過中轉站這個「中間商」來呼叫。中轉站把各家 AI 模型的 API 聚合到一個平臺上，你註冊一箇中轉站的賬號就能呼叫所有模型，不用到處註冊，能方便不少。

![](https://pic.yupi.icu/1/Gemini_Generated_Image_w1vnohw1vnohw1vn-20260509174715470.jpg)

為什麼中轉站那麼火呢？得看它解決了什麼問題。

對於國內開發者來說，想用 Claude、GPT 這類國外模型，支付和網路都是門檻。中轉站幫你解決了這些麻煩，支援國內常用的付款方式，國內網路直連，不用折騰。就算你只用國產模型，每家註冊一個賬號、各管理一套 API Key 也挺麻煩的，中轉站可以幫你統一管理。

目前最知名的中轉站應該是 **OpenRouter**，聚合了幾百個大模型，據說年流水已經過億美元了。

![](https://pic.yupi.icu/1/image-20260509161936710.png)

一箇中轉站就能賺這麼多錢，難怪連懂王都來分一杯羹了。

順便提一下，程式設計師朋友們可能聽說過一個概念叫「AI 閘道器」，其實它跟 API 中轉站是有點區別的。中轉站更偏向「幫你代買 API」的二道販子角色，AI 閘道器更偏向企業內部統一管理多個模型的基礎設施。不過核心技術是相通的。



## 中轉站的原理

我知道很多同學在用或者考慮用中轉站，但市面上的中轉站魚龍混雜，很容易踩雷。

想少踩坑，最好的辦法就是了解中轉站的原理，知道它背後到底在幹什麼。

中轉站的核心其實就兩個字：**代理**。

你的請求不直接發給 AI 模型，而是先發到中轉站的伺服器，中轉站幫你轉發到對應的模型廠商，拿到結果後再返回給你。

而且大多數中轉站都有一個共同的設計，就是對外 “偽裝” 成 OpenAI 的介面格式。幾乎所有 AI 工具（Claude Code、Cursor、各種 SDK）都支援 OpenAI 格式，所以使用者只需要改 2 個引數就能接入中轉站，一行業務程式碼都不用動：

```python
client = OpenAI(
    api_key="sk-relay-xxx",       # 改成中轉站的 Key
    base_url="http://你的中轉站/v1" # 改成中轉站的地址
)
```

中轉站的伺服器收到請求後，會根據你指定的模型名稱，把請求路由到對應的 AI 廠商。如果配置了多個 API Key，還會自動輪換，避免單個 Key 被限流。同時記錄每次呼叫的 Token 消耗，用於計費。

![](https://pic.yupi.icu/1/Gemini_Generated_Image_vjaih0vjaih0vjai-20260509174715559.jpg)

但有個問題，你的所有請求都要經過中轉站的伺服器，這一層對使用者來說完全是個「黑盒」。中轉站那邊具體做了什麼，你根本不知道！

而很多不靠譜的中轉站，正是在這個黑盒裡動了手腳。

最近 CISPA 亥姆霍茲資訊保安中心發了一篇論文，揭露了一個觸目驚心的事實：**近一半的第三方 API 中轉站在進行系統性欺詐**！

![](https://pic.yupi.icu/1/image-20260509133411306.png)

常見的黑心操作有這麼幾種：

1）模型掉包

你付 GPT-5 的錢，實際跑的是某個廉價開源小模型。論文測了 28 箇中轉站，竟然高達 45.83% 的 API 端點存在模型身份不匹配，醫療場景下效能差距高達 47%！

2）虛報 Token 消耗

你實際用了 100 Token，賬單上給你寫 150。使用者付了 14.84 美元，實際只獲得 5.7 到 7.7 美元價值的服務。

3）快取套利

AI 模型廠商對重複出現的內容（比如相同的 System Prompt）會給快取優惠價，但中轉站按原價收你的錢，把這部分差價默默吃掉了。

4）資料收割

更可惡的是，有些中轉站收集並販賣使用者的程式碼和敏感資料！

調研發現，17 家頭部中轉站中有 15 家是個人運營，無企業註冊、無 ICP 備案。使用者充值金額積累到一定程度後，說不定就直接刪庫跑路了。。。

所以建議大家有條件的話，還是用官方 API 吧。實在要用中轉站，也要選有企業資質和備案的大平臺。

如果你想更深入地瞭解中轉站，GitHub 上有不少開源專案可以參考。看完這些專案，再自己動手做一個，中轉站對你來說就再也沒有秘密了。



## 開源中轉站專案

GitHub 上中轉站相關的開源專案非常多，可以說是無奇不有。我挑幾個有代表性的給大家看看。

1）[one-api](https://github.com/songquanpeng/one-api)

元祖級專案，GitHub 上幾萬 Star。它用 Go 語言開發，把所有主流大模型的 API 統一成 OpenAI 格式，支援幾十種模型，而且只需要一個檔案就能跑起來，還支援 Docker 部署。

![](https://pic.yupi.icu/1/image-20260509160501101.png)

不誇張地說，市面上 80% 以上的商業中轉站底層都是 one-api 或者它的衍生版本，只是套了個殼。

2）[new-api](https://github.com/QuantumNous/new-api)

在 one-api 基礎上二次開發，新增了 Prometheus 監控、OpenTelemetry 可觀測性等企業級特性，也是很多商業中轉站的底層框架。

![](https://pic.yupi.icu/1/new-api-dashboard.jpeg)

順便提一嘴，傅盛的 EasyRouter 就被 new-api 原作者扒出來是套殼的，前端程式碼中有 98 處指向 new-api 的關鍵詞匹配，而且移除了版權資訊，涉嫌違反 AGPL v3 開源協議。

3）[sub2api](https://github.com/Wei-Shaw/sub2api)

這個專案厲害了，能把 Claude、OpenAI 的網頁版訂閱賬號逆向轉化成標準的 API 介面，相當於多個人拼車共享一個 Plus 會員，一個賬號的額度分給好幾個人用。

![](https://pic.yupi.icu/1/image-20260509161048654.png)

4）[metapi](https://github.com/cita-777/metapi)

號稱「中轉站的中轉站」，把你在多個 one-api / new-api / sub2api 上註冊的賬號聚合成一個統一閘道器，基於成本、餘額、使用率三維加權來分配流量。

![](https://pic.yupi.icu/1/dashboard-20260509174717717.png)

5）[all-api-hub](https://github.com/qixing-jk/all-api-hub)

這是一個瀏覽器擴充套件，專門用來管理你在各個中轉站上的賬號。裝上之後，可以在一個面板裡看到所有中轉站的餘額和用量，還支援自動簽到、價格橫向對比，對於同時用好幾個中轉站的人來說挺方便的。

![](https://pic.yupi.icu/1/model-list-20260509174717782.png)

除了這些中轉站專案，企業級場景下還有像 [LiteLLM](https://github.com/BerriAI/litellm)、[Higress AI](https://higress.ai/)、[Kong AI Gateway](https://konghq.com/products/kong-ai-gateway) 這些更正經的開源 AI 閘道器。不過這類專案有一定的技術門檻，非程式設計師朋友不用深入瞭解。

![](https://pic.yupi.icu/1/image-20251019163817976-20251028181254777.png)

## 需求分析

我們要做的這個中轉站可以說是「麻雀雖小，五臟俱全」。核心功能包括：

1）對外暴露相容 OpenAI 格式的介面，支援流式和非流式響應，使用者改個 base_url 和 api_key 就能接入。

2）接入 DeepSeek V4、智譜 GLM-5、通義千問 Qwen-Plus 三個國產大模型，支援使用者指定模型，也支援 auto 模式自動路由。

3）中轉站自有 API Key 管理體系，管理員可以建立、禁用、刪除 Key，給每個 Key 設定餘額上限。

4）記錄每次呼叫的 Token 消耗，不同模型設定不同計費倍率，後臺可檢視呼叫日誌和用量統計圖表。

5）定期檢測各模型渠道的可用性，請求失敗自動重試到其他渠道，管理面板顯示健康狀態。

6）管理面板包含儀表盤、渠道管理、Key 管理、呼叫日誌，支援管理員密碼登入。

## 方案設計

如果你完全沒有技術基礎，可以讓 AI 幫你完成方案設計。

但這裡為了節省時間和 tokens，我直接告訴 AI 怎麼做。

為了儘快跑通核心功能，我們的中轉站不需要使用者註冊登入，也不需要對接支付系統。管理員在後臺建立 API Key，透過其他方式收完錢後，把 Key 發給使用者、手動調整餘額就行了。

你還別覺得這種方式 low，市面上大多數小中轉站就是這麼運作的！搭個 one-api / new-api 之類的開源專案，後臺建立 Key，透過髮卡工具或者群聊賣 Key 就能開張了。。。

如果想學完整的帶使用者註冊、線上支付、監控告警的企業級 AI 閘道器，可以看看我們團隊之前出過的 [保姆級的 AI 閘道器專案實戰教程](https://www.codefather.cn/course/2029830328322994177)，基於 Spring Boot 3 + Spring AI + Vue 3 從零搭建，感興趣的同學可以到 [程式設計導航](https://www.codefather.cn) 學習。

### 安裝 Claude Code

先簡單介紹一下 Claude Code。它是 Anthropic 推出的 AI 程式設計工具，直接在終端裡執行，你跟它聊天描述需求，它就能自主分析專案、寫程式碼、跑命令、修 Bug，全程自主執行。

除了基礎的程式碼生成，還能使用工具和 Skills 技能包、連線 MCP 外部服務、用 Plugins 外掛擴充套件能力，甚至搞多智慧體協作，擴充套件性很強。

![](https://pic.yupi.icu/1/image-20260429110454017-20260509174718125.png)

安裝 Claude Code 很簡單。

首先確保你的電腦有 Node.js 環境和 npm 軟體依賴安裝工具，沒有的話，直接到 [Node 官網](https://nodejs.org/en/download) 下載傻瓜式安裝包就好：

### 安裝擴充套件

Claude Code 預設就有讀寫檔案、跑終端命令、搜尋程式碼這些基礎能力，但要做好一個完整專案，光靠這些還不夠。

我們需要下面 3 個擴充套件：

1. Frontend Design：前端美化技能，讓生成的頁面更有設計感
2. Firecrawl：聯網搜尋和網頁抓取，讓 AI 能獲取最新的技術資訊
3. Context7：查詢最新的技術文件和 API 用法，減少 AI 瞎編的情況

下面來依次安裝。



#### 1、安裝 Frontend Design

Frontend Design 是 Anthropic 官方的前端美化技能，可以讓 AI 生成的頁面更有設計感。

在 Claude Code 中，先透過 `/plugin` 命令新增官方技能市場，相當於裝了個技能商店：

```bash
/plugin marketplace add anthropics/skills
```

![](https://pic.yupi.icu/1/1777344066799-72c95f99-82bc-46ff-92f5-02cf6d21b1b9-20260429113524910-20260509174718645.png)

## DeepSeek + Claude Code 開發

新建一個 `yupi-ai-relay` 專案資料夾，開啟終端並輸入 `cd` 命令進入目錄，然後輸入 `claude` 開啟 Claude Code：

接下來輸入提示詞。這段提示詞也是我利用 AI 程式設計工具，根據我的需求描述生成的，給大家參考：

```markdown
## 角色
你是一個全棧工程師，擅長 Node.js + Next.js + TypeScript 開發。

## 任務
開發一個叫 yupi-ai-relay 的網站，實現一個簡易但完整的 AI 大模型 API 中轉站，相容 OpenAI API 格式，支援多模型路由。

## 核心功能
1. 對外暴露 `/v1/chat/completions` 介面，完全相容 OpenAI Chat Completions API 格式，支援流式（SSE）和非流式響應，使用者只需修改 base_url 和 api_key 即可接入
2. 接入 3 個國產大模型：DeepSeek V4、智譜 GLM-5、通義千問 qwen-plus。支援使用者指定 model 引數選擇模型，也支援 auto 模式隨機負載均衡
3. 中轉站自有 API Key 體系（sk-relay-xxx 格式），管理後臺可建立/禁用/刪除 Key，每個 Key 可設定餘額上限
4. 記錄每次請求的 Token 消耗（prompt_tokens + completion_tokens），不同模型設定不同計費倍率，管理後臺可檢視呼叫日誌和用量統計圖表
5. 定期檢測各模型渠道可用性，請求失敗自動重試到其他可用渠道，管理面板顯示各渠道健康狀態
6. 管理面板包含儀表盤概覽、渠道管理、Key 管理、呼叫日誌，支援管理員密碼登入

## 技術棧
- 框架：Next.js + TypeScript
- 資料庫：SQLite（透過 better-sqlite3，零配置）
- 樣式：使用 Shadcn UI 元件庫
- 圖表：Recharts

## 要求
1. 頁面參考 OpenRouter 官網風格，淺色主題，簡潔大方接地氣，使用 frontend-design 技能美化頁面
2. 開發前，先透過 Firecrawl 聯網搜尋確認 DeepSeek、智譜、通義千問最新的 API 格式，透過 Context7 查詢 Next.js 最新文件
3. 必須生成完整可執行的程式碼，每步完成後透過 webapp-testing 自主測試驗證
4. 環境變數透過 .env.local 配置各模型的 API Key
```

總結一下，Cursor + GPT-5.5 的開發速度確實快了很多，但最終效果並沒有像我想象中那樣甩開 DeepSeek 一大截，甚至在前端的表現上，我覺得 DeepSeek 更勝一籌。

而且國外模型的價格普遍比國內貴。所以還是要根據自己的需求選擇模型，如果你還不太會 AI 程式設計，建議先用比較便宜的國產模型練手，不然可能一頓操作花了幾十塊，結果什麼都沒搞出來。



## 最後嗶嗶

做完這個中轉站，相信你已經完全理解了它的原理。

我還很貼心地給大家準備了「黑心版」中轉站的提示詞，僅供整活娛樂和教學目的，實際千萬不要這麼幹！

```markdown
## ⚠️ 黑心中轉站 DLC（僅供娛樂，不是魚皮教的）

在管理面板中增加一個「高階設定（請勿開啟）」摺疊面板，標題旁加 💀 圖示，預設關閉，包含以下功能：

1. Token 暗稅滑塊（1.0x - 3.0x）：實際消耗 100 Token，賬單上乘以倍率顯示 150，使用者看到的 usage 欄位是虛報後的數字
2. 偷樑換柱開關：使用者請求模型 A 實際轉發到便宜的模型 B，返回的 model 欄位仍顯示使用者請求的原始模型名
3. Prompt 快取吸血：對話中重複的 prompt 快取命中後，仍按完整 Token 數向使用者收費
```

看到這裡，再回過頭看那些中轉站的坑，什麼模型掉包、虛報 Token、快取套利，你應該能明白它們是怎麼實現的了。

所以我再次建議，有條件儘量用官方 API 吧！別為了省一點錢，把自己的程式碼和資料送了出去。
