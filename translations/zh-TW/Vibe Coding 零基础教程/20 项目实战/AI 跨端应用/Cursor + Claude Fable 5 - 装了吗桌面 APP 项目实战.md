## 一、提示詞設計

先簡單說一下「裝了嗎」是幹嘛的。

使用者輸入想安裝的軟體名稱（比如 MySQL、Node.js），系統透過 AI 大模型自動生成一份完整的安裝指令碼和方案，支援一鍵執行安裝，幫學程式設計的小白徹底解決裝環境的痛苦。



### 先讓 AI 幫我寫提示詞

我的需求比較零散，如果不把提示詞整理清楚，直接丟給 Claude Fable 5 基本就是浪費 tokens。

所以我先透過一個 AI 對話，把零散的想法和草稿素材餵給 Claude Opus 4.6，讓它幫我梳理成一段完整的提示詞。

```markdown
我想透過一條提示詞，讓 Claude Fable 5 + Cursor 幫我自主開發一個「裝了嗎」桌面 APP，相容 Mac 和 Windows 系統。同時我要求它透過聯網搜尋調研 Loop Engineering 的最新理念，在提示詞中體現出迴圈自主的感覺，確保 AI 能自主完成任務。

@需求描述
```

![](https://pic.yupi.icu/1/1781162074833-0d4935e4-fc59-4aee-b226-81220132a1ef.png)

為了讓 AI 開發時能夠自主測試 AI 相關的功能，我還需要提前把大模型的 API Key 提供給它。但我不想直接把 Key 寫在提示詞裡，萬一洩露就麻煩了。

更好的做法是讓 AI 讀取本地已有的配置檔案，比如我讓它讀取我 Claude Code 的配置 `~/.claude/settings.json`，從裡面拿到 API Key 和 Base URL。



### 提示詞講解

經過幾輪對話，AI 幫我生成了一段完整的提示詞，結構非常清晰：

![](https://pic.yupi.icu/1/image-20260611162938865.png)

下面簡單講解一下這段提示詞的結構。

1）角色定義：全棧工程師，擅長 Python + Electron + React 開發。

2）任務描述：開發一個叫「裝了嗎」的完整系統，幫學程式設計的同學一鍵安裝軟體。

包含三個部分：

- Electron 桌面 APP：使用者輸入想裝的軟體，選版本和平臺，AI 生成安裝方案，支援一鍵安裝
- Python 服務端：統一呼叫 AI 生成方案、儲存資料、提供 API
- Web 管理後臺：給管理員管理所有方案和使用者反饋

3）技術選型上，桌面端用 **Electron** 框架。Electron 是用 JavaScript、HTML、CSS 構建跨平臺桌面應用的框架，一套程式碼同時打包 Mac 和 Windows，QQ、VS Code、Notion 這些大家熟悉的 APP 都是用它做的。

4）核心亮點是最後的「自主開發迴圈」，這裡就體現了 Loop Engineering 的思想：

1. AI 在專案根目錄維護 PROGRESS.md，記錄當前階段、已完成事項、進行中事項
2. 每完成一個模組，立即編譯執行驗證，有報錯就修復，透過後再推進下一個
3. 全部功能完成後，以使用者視角做一次完整的端到端測試
4. 同一個問題修復超過 5 次仍未解決就跳過，避免死迴圈

這樣 AI 就不會寫完程式碼就停下來等我人工驗證，而是會自己跑起來不斷迴圈驗證，遇到問題自己修復，直到整個系統能用為止。

💡 完整的提示詞和更多實戰教程都收錄在我免費開源的 [《AI 程式設計零基礎入門教程》](https://ai.codefather.cn/vibe) 裡，上千張圖、幾十萬字，帶你從 0 開始學會 AI 程式設計。

## 三、AI 自主開發

執行之後，AI 就開始了它的自主迴圈。

它先讀取了我本地的 Claude Code 配置檔案，拿到 API Key 和 Base URL，寫進了服務端的 `.env` 檔案。

![](https://pic.yupi.icu/1/image-20260611155938897.png)

然後開始按順序開發服務端、桌面端、管理後臺。

整個過程我基本沒有干預，AI 自己維護著 PROGRESS.md 記錄進度，開發完一個模組就自動跑測試，遇到報錯就自己修，修完繼續推進。它甚至自己開啟了桌面 APP 和瀏覽器，模擬使用者操作來做端到端驗證。

![](https://pic.yupi.icu/1/image-20260611160046322.png)

## 五、迭代最佳化

雖然核心功能是正常的，但是執行過程中，你們有沒有發現問題？

我發現了 2 個問題：

1）版本號資訊搜尋能力不夠。比如我要裝個 Scala，給出來的版本號列表是錯誤的。

2）Mac 系統過度依賴 homebrew 這個軟體包管理工具。homebrew 源的版本不一定全面，比如 Scala 確實有 3.4.2 版本，但透過 homebrew 來安裝會失敗。

![](https://pic.yupi.icu/1/1781160489542-c6aafe61-8aa7-4f35-8744-d775009ebe48.png)

於是我給 AI 下了一條修復指令，讓它自主修復這兩個問題並進行測試驗證。

```markdown
自主修復 2 個問題，並進行測試驗證。
1）安裝軟體時，版本號列表獲取錯誤。必須最佳化資訊搜尋能力，優先從官方資訊源獲取版本號列表和安裝方式，如果沒有官方資訊源，才降級為透過聯網搜尋獲取版本號資訊，最後才是完全交給 AI 推斷版本號。
2）Mac 系統預設使用 homebrew 來安裝，但是 homebrew 的版本不一定全面，有時可能會安裝失敗，你需要優先透過官方獲取安裝方式，homebrew 作為一種備選方案，且要為 homebrew 安裝失敗時考慮降級方案。
```

大概 20 分鐘後，AI 完成了修復任務。

## 最後嗶嗶

回過頭來看，為什麼 Claude Fable 5 能做到一次性完成可用、兩次互動就達到滿意效果？

除了模型本身能力確實強之外，還有兩個關鍵因素：

1. 配套的 **Harness 駕馭工程**，包括我們提前準備的 MCP 工具、前端技能包、API Key 的配置方式，再加上 Cursor 本身自帶的 Browser Use 瀏覽器操作等能力，這些都是在幫 AI 搭好腳手架。
2. 採用了 **Loop Engineering** 的思想，在提示詞裡設計了自主開發迴圈，讓 AI 不停下來等我，而是自己跑起來、自己驗證、自己修。

我現在理解為什麼 Claude Code 之父和 OpenClaw 之父都在力挺 Loop Engineering 了，這種體驗真的爽。

想深入掌握 Loop Engineering 的完整玩法，可以閱讀本教程經驗技巧板塊中的《Loop Engineering 保姆級教程》。

但話說回來，要是隨便一兩句提示詞丟給 AI，很有可能就是純浪費錢。模型越強，對提示詞和工程配套的要求就越高。這也是為什麼 Claude Fable 5 出來之後，不少同學跟我說感覺自己駕馭不了這個模型，還是 AI 程式設計的經驗和方法沒到位。

至少我現在已經用 Claude Fable 5 跑了好幾個專案了，感覺真心強得沒邊兒了，長程複雜任務的交付確定性是目前最好的，就是別偷偷給我降級成 Opus 4.8（
