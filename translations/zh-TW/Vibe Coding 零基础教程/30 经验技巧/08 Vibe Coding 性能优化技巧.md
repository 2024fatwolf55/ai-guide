# Vibe Coding 效能最佳化技巧

> 讓你的應用跑得更快



你好，我是魚皮。

在 Vibe Coding 中，你可能遇到過這樣的情況：用 AI 做出來的應用，功能都正常，但就是有點慢。比如頁面載入要等好幾秒、點選按鈕半天沒反應、滾動列表卡卡的。不僅使用者體驗不好，自己用著也不爽。

這就是效能問題，AI 生成程式碼的常見問題之一。因為 AI 更關注 “能不能跑”，而選擇性忽略 “跑得快不快”。在 Vibe Coding 中，我們追求的是快速實現功能，但不代表要犧牲效能。還好，效能最佳化同樣可以藉助 AI 來完成。

下面，我就來教你如何在 Vibe Coding 中識別效能瓶頸，以及如何讓 AI 幫你最佳化效能。即使你不懂技術原理，也能讓應用跑得更快。



## 一、識別效能問題

最佳化之前，先要知道問題在哪裡。

首先要知道，效能不是一個抽象的概念，而是使用者的真實感受。使用者關心的是：頁面開啟快不快？點選按鈕響應快不快？滾動流暢不流暢？

如今，使用者對效能的要求越來越高。如果你的頁面載入超過 3 秒，使用者可能就會離開。如果點選按鈕後沒有立即反饋，使用者會以為頁面卡住了。

所以，最佳化效能的第一步是站在使用者的角度，感受應用的速度。



### 使用效能測試工具

除了主觀感受，還要用工具來客觀測量。不用擔心，這些工具都很簡單，不需要程式設計基礎。

1）瀏覽器開發者工具

按 F12 開啟開發者工具，切換到 Performance 效能標籤，點選錄製按鈕，然後操作你的應用，最後停止錄製。你會看到一個詳細的效能報告，包括每個操作花了多少時間，哪些函式最慢，有沒有卡頓等。

![](https://pic.yupi.icu/1/image-20260105150358449.png)

如果你看不懂這些資料，沒關係，可以截圖給 AI，讓它幫你分析：

```markdown
這是我的效能報告截圖，請幫我找出效能瓶頸在哪裡。
```



2）Lighthouse

Chrome 自帶的效能測試工具。在開發者工具的 Lighthouse 標籤，點選 "分析網站載入情況"，它會給你的頁面打分，並提供最佳化建議。

![](https://pic.yupi.icu/1/image-20260105150513178.png)

重點關注這幾個指標：

- LCP（Largest Contentful Paint）：最大內容繪製時間，應該在 2.5 秒內
- FID（First Input Delay）：首次輸入延遲，應該在 100 毫秒內
- CLS（Cumulative Layout Shift）：累積佈局偏移，應該小於 0.1

![](https://pic.yupi.icu/1/image-20260105150756392.png)



3）其他線上工具

還可以用 PageSpeed Insights、GTmetrix 等線上工具測試你的網站，它們會從真實使用者的角度測試效能。



### 找到效能瓶頸

測試後，你會發現一些慢的地方。不要急著最佳化所有問題，先找到最嚴重的瓶頸。

一般來說，AI 生成的程式碼效能瓶頸在這幾個地方：

- JavaScript 檔案太大，載入慢
- API 請求太慢，或者請求太多
- 渲染邏輯複雜，導致頁面卡頓
- 資料庫查詢慢，或者查詢太多
- 引用的資源太大，沒有壓縮和最佳化

找到瓶頸後，優先最佳化影響最大的那個。你可以直接把測試結果和程式碼一起發給 AI，讓它幫你定位問題：

```markdown
我的應用載入很慢，這是效能測試結果【貼測試結果】，這是相關程式碼【貼程式碼】，請幫我找出問題並給出最佳化方案。
```




## 二、常見效能瓶頸

基於我的經驗，這裡總結了一些 AI 生成程式碼時容易出現的效能瓶頸。瞭解這些問題，能幫你更好地引導 AI 生成高效能的程式碼。



### 不必要的重新渲染

在前端開發框架（比如 React）中，元件會因為各種原因重新渲染。如果渲染太頻繁，頁面就會卡。

AI 生成的程式碼可能會忽略這個問題，因為它更關注功能實現。常見的原因是：父元件更新時，所有子元件都會重新渲染，即使它們的資料沒變。每次渲染都建立新的函式或物件，導致子元件認為資料變了。狀態更新太頻繁，比如在輸入框的每次輸入都觸發複雜計算。

如何讓 AI 幫你最佳化？

你可以這樣告訴 AI：

```markdown
這個元件渲染太頻繁，頁面很卡。請幫我最佳化，使用 React.memo、useMemo 和 useCallback 來減少不必要的渲染。
```

即使你不懂這些技術名詞，直接跟 AI 說 “這個頁面很卡”，AI 也會幫你做好最佳化。



### 大量資料的渲染

如果要渲染一個很長的列表，比如 1000 條資料，AI 可能會直接把所有資料一次性渲染出來，導致頁面很慢。

如何讓 AI 幫你最佳化？

告訴 AI 你的具體需求：

```markdown
我有一個 1000 條資料的列表，全部渲染太慢了。請幫我實現虛擬滾動，只渲染可見的部分。
```

或者：

```markdown
請幫我實現分頁功能，一次只顯示 20 條資料。
```

AI 會給你完整的實現方案，包括相關的庫推薦（比如 react-window）和程式碼示例。



### 圖片未最佳化

圖片一般是頁面最大的資源。AI 在生成程式碼時，往往會直接使用原始圖片，不會主動最佳化。

你可以讓 AI 幫你實現圖片最佳化：

```markdown
請幫我實現圖片懶載入功能，只有圖片進入視口時才載入
```

或者：

```markdown
請幫我把圖片改成 WebP 格式，並新增壓縮處理
```

對於圖片壓縮，你可以使用線上工具（比如 [TinyPNG](https://tinypng.com/)），或者讓 AI 幫你寫個程式，來實現自動化的圖片處理流程。



### 同步的 API 請求

AI 生成完整的前後端程式碼時，一般會按照最直觀的方式實現，也就是前端一個請求接一個請求呼叫後端。這樣一來，請求總時間就是所有請求時間的總和，會比較慢。

比如下面這段程式碼：

```typescript
// AI 最初可能生成的：序列請求（慢）
const user = await fetchUser();
const posts = await fetchPosts();
const comments = await fetchComments();
// 總時間 = t1 + t2 + t3
```

如果你發現了這個問題，可以告訴 AI：

```markdown
這幾個 API 請求是獨立的，請幫我改成並行請求，減少總等待時間。
```

AI 會幫你改成這樣：

```typescript
// 最佳化後：並行請求（快）
const [user, posts, comments] = await Promise.all([
  fetchUser(),
  fetchPosts(),
  fetchComments()
]);
// 總時間 = max(t1, t2, t3)
```

就是這樣一個小最佳化，說不定能讓頁面的載入速度提升 2 ~ 3 倍。



### 缺少快取

快取就像是把常用的東西放在手邊，下次用的時候不用再去遠處拿。比如你第一次查詢使用者資訊需要 1 秒，如果把結果快取起來，下次再查詢同一個使用者，0.01 秒就能拿到結果。

![](https://pic.yupi.icu/1/cacheusage%E5%A4%A7.jpeg)

AI 生成的程式碼一般不會主動新增快取機制，導致每次都要重新獲取相同的資料，浪費時間。

你可以這樣告訴 AI：

```markdown
這個資料每次都要重新獲取，太慢了。請幫我新增快取，把資料快取 5 分鐘。
```

或者

```markdown
請幫我實現一個簡單的記憶體快取，避免重複請求相同的資料。
```

AI 會根據你的場景選擇合適的快取方案，比如瀏覽器快取、記憶體快取或者 CDN。



## 三、前端效能最佳化

前端效能直接影響使用者體驗，我們重點講一下。這部分內容對於有程式設計基礎的朋友會更有幫助，如果你是零基礎，可以把這些最佳化需求直接告訴 AI，讓它幫你實現。




### 程式碼分割

AI 生成的程式碼可能會把所有功能打包成一個大檔案，使用者開啟頁面時要下載整個檔案，很慢。

你可以告訴 AI：

```markdown
我的 JavaScript 檔案太大了，請幫我實現程式碼分割，把管理面板的程式碼獨立出來，只有使用者訪問時才載入。
```

AI 會幫你改成這樣：

```typescript
// AI 最初可能生成的：一次性匯入
import AdminPanel from './AdminPanel';

// 最佳化後：懶載入
const AdminPanel = lazy(() => import('./AdminPanel'));

function App() {
  return (
    <Suspense fallback={<Loading />}>
      <AdminPanel />
    </Suspense>
  );
}
```

這樣，只有使用者訪問管理面板時，才會載入相關程式碼，首頁載入速度可能提升 50% 以上。



### 最佳化渲染效能

如果 AI 生成的程式碼使用了 React 框架，那麼 “渲染” 可能會成為瓶頸。

最佳化方法包括：

1）使用 `React.memo` 避免不必要的渲染。比如一個展示使用者資訊的元件，如果使用者資訊沒變，就不需要重新渲染：

```typescript
const UserCard = React.memo(({ user }) => {
  return (
    <div>
      <h2>{user.name}</h2>
      <p>{user.email}</p>
    </div>
  );
});
```

2）使用 `useMemo` 快取計算結果。如果有複雜的計算，不要每次渲染都重新計算：

```typescript
function TodoList({ todos }) {
  // 不好：每次渲染都重新計算
  const completedCount = todos.filter(t => t.completed).length;
  
  // 好：只在 todos 變化時重新計算
  const completedCount = useMemo(
    () => todos.filter(t => t.completed).length,
    [todos]
  );
  
  return <div>已完成：{completedCount}</div>;
}
```

3）使用 `useCallback` 快取函式。避免每次渲染都建立新函式：

```typescript
function TodoList({ todos, onDelete }) {
  // 不好：每次渲染都建立新函式
  const handleDelete = (id) => {
    onDelete(id);
  };
  
  // 好：快取函式
  const handleDelete = useCallback((id) => {
    onDelete(id);
  }, [onDelete]);
  
  return <div>{/* ... */}</div>;
}
```



### 最佳化資源載入

減少首次載入的資源大小和數量。

1）壓縮資源：使用 Gzip 或 Brotli 壓縮 JavaScript、CSS 等文字檔案。現代的構建工具（如 Vite、Next.js）一般會自動做這個。

2）Tree Shaking：移除未使用的程式碼。確保你的構建工具開啟了 Tree Shaking，只打包實際用到的程式碼。

3）預載入關鍵資源：對於首屏需要的資源，可以預載入：

```html
<link rel="preload" href="/fonts/main.woff2" as="font" type="font/woff2" crossorigin>
```

4）延遲載入非關鍵資源：對於不是立即需要的資源，可以延遲載入：

```html
<script src="/analytics.js" defer></script>
```



### 最佳化 CSS

CSS 也會影響效能，這是比較容易被忽略的點。

1）避免複雜的選擇器：複雜的 CSS 選擇器會讓瀏覽器花更多時間匹配元素。儘量用簡單的類名。

2）減少重排和重繪：修改 DOM 會觸發重排（reflow）和重繪（repaint），很消耗效能。儘量批次修改 DOM，而不是一個一個改。

3）使用 CSS 動畫而不是 JavaScript：CSS 動畫由瀏覽器最佳化，比 JavaScript 動畫更流暢。

## 四、後端效能最佳化

後端效能決定了 API 的響應速度。同樣，這些最佳化都可以透過 AI 來實現，你只需要描述清楚需求就好。




### 資料庫查詢最佳化

資料庫查詢往往是後端最慢的部分。AI 生成的資料庫查詢程式碼通常比較簡單直接，可能會有效能問題。

如何讓 AI 幫你最佳化呢？提供幾個思路：

1）讓 AI 新增索引

```markdown
使用者表的 email 欄位查詢很慢，請幫我新增索引。
```

AI 會給你具體的 SQL 語句或 ORM 配置。



2）避免 N+1 查詢

這是 AI 生成程式碼時最容易出現的效能陷阱。比如你要獲取 10 篇文章和它們的作者資訊，AI 可能會生成這樣的程式碼：

```typescript
// AI 可能生成的：N+1 查詢（慢）
const posts = await db.posts.findMany(); // 1 次查詢
for (const post of posts) {
  post.author = await db.users.findOne({ id: post.authorId }); // N 次查詢
}
// 10 篇文章 = 11 次查詢
```

你可以告訴 AI：這段程式碼查詢太多次了，請最佳化成一次查詢。

AI 會幫你改成：

```typescript
// 最佳化後：一次查詢（快）
const posts = await db.posts.findMany({
  include: { author: true }
});
// 10 篇文章 = 1 次查詢
```

這個最佳化能讓介面響應速度提升 10 倍以上。



3）只查詢需要的欄位

告訴 AI：

```markdown
請只查詢需要的欄位，不要用 SELECT *，減少資料傳輸量。
```

AI 會幫你最佳化查詢語句。



### 使用快取

使用快取能大大提高響應速度。

1）記憶體快取：把常用的資料快取在記憶體裡，比如使用者資訊、配置資料等。可以用 Redis 記憶體儲存或者簡單的 Map。

2）HTTP 快取：設定合適的 Cache-Control 響應頭（HTTP 頭是伺服器告訴瀏覽器如何處理資源的指令），讓瀏覽器快取靜態資源

```typescript
// 靜態資源：快取一年
res.setHeader('Cache-Control', 'public, max-age=31536000, immutable');

// API 資料：快取 5 分鐘
res.setHeader('Cache-Control', 'public, max-age=300');
```

3）CDN 快取：CDN（內容分發網路）就像在全國各地開了很多倉庫，使用者訪問時從最近的倉庫拿資源，比從總部拿要快得多。使用 CDN 來快取和加速靜態資源的分發，能大幅提升全球使用者的訪問速度。

![](https://pic.yupi.icu/1/image-20260105153947917.png)




### 非同步處理

不要讓使用者等待耗時的操作。

舉個例子，使用者上傳了一張圖片，需要生成縮圖。不要讓使用者等待生成完成，而是：

1. 立即返回成功響應
2. 在後臺非同步生成縮圖
3. 生成完成後更新資料庫

這樣使用者體驗會好很多。




### API 設計最佳化

好的 API 設計也能提高效能。

1）批次操作：如果要刪除多個專案，不要傳送多個請求，而是一次性傳送：

```typescript
// 不好：多次請求
for (const id of ids) {
  await deleteItem(id);
}

// 好：批次請求
await deleteItems(ids);
```

2）分頁和遊標：大量資料不要一次性返回，而是使用分頁或遊標分批返回。

分頁就像翻書，一頁一頁看；遊標就像書籤，記住你看到哪裡了，下次從那裡繼續。你可以透過 [這篇文章](https://www.codefather.cn/post/1823563686797688834) 進一步瞭解遊標機制。

3）GraphQL：GraphQL 是一種查詢語言，讓客戶端可以精確地指定需要哪些資料，而不是伺服器返回一堆用不到的資料。就像點菜時可以自己選配菜，而不是隻能點套餐。




## 五、Vibe Coding 效能最佳化實戰

讓我用幾個真實的案例，展示如何在 Vibe Coding 中透過 AI 來最佳化效能。這些案例都是我在實際專案中遇到的問題。



### 案例一、慢速列表

問題：我用 AI 做了一個文章列表頁面，載入 100 篇文章時很慢，頁面卡頓。

我的做法：

1）先用 Performance 工具測試，發現渲染 100 個文章卡片元件花了 2 秒

2）截圖測試結果，連同程式碼一起發給 AI：

```markdown
這個列表頁面很卡，這是效能測試結果【截圖】，這是程式碼【程式碼】，請幫我最佳化。
```

3）AI 給出了最佳化方案：使用虛擬滾動、React.memo、圖片懶載入

4）我讓 AI 直接實現這些最佳化：

```markdown
請幫我實現虛擬滾動，使用 react-window 庫。
```

5）測試最佳化效果，確認沒問題

最後，頁面載入時間從 3 秒降到 0.5 秒，滾動變得流暢，整個最佳化過程不到 10 分鐘。



### 案例二、慢速搜尋

問題：我用 AI 實現了搜尋功能，但搜尋很慢，使用者每輸入一個字元，都要等半秒才能看到結果。

我的做法：

1）透過瀏覽器的開發者工具觀察發現，每次輸入都觸發了 API 請求

2）我告訴 AI：

```markdown
搜尋太慢了，每次輸入都發請求。請幫我最佳化，使用者停止輸入 300ms 後再傳送請求，並且取消之前的請求。
```

3）AI 實現了 debounce 防抖（等使用者停止輸入後再發請求）和 AbortController（取消之前的請求，避免浪費資源）

4）我又讓 AI 新增快取：

```markdown
請新增搜尋結果快取，相同的搜尋詞不要重複請求。
```

最後，搜尋變得流暢，不再卡頓，API 請求減少了 80%，節省了後端資源。



### 案例三、慢速首頁

問題：我用 AI 做的網站首頁載入很慢，要等 5 秒才能看到內容。

我的做法：

1）用 Lighthouse 測試，發現 JavaScript 檔案太大（2MB），而且圖片沒有最佳化

2）把 Lighthouse 報告截圖發給 AI：

```markdown
這是我的效能測試報告【截圖】，請幫我最佳化。
```

3）AI 給出了一系列最佳化建議，我逐個讓它實現：

- 請實現程式碼分割，把不必要的程式碼延遲載入
- 請幫我壓縮圖片，使用 WebP 格式
- 請配置 CDN 加速靜態資源
- 請啟用 Gzip 壓縮

4）每次最佳化後都測試效果，確保有改善

最後，首頁載入時間從 5 秒降到 1.2 秒，Lighthouse 評分從 45 提升到 90+，使用者明顯感覺快了很多。



## 六、Vibe Coding 效能最佳化的原則

在 Vibe Coding 中最佳化效能時，要遵循一些基本原則。這些原則能幫你更高效地利用 AI。



### 先測量，再最佳化

不要憑感覺最佳化，要用工具測量。很多時候，你以為慢的地方其實不慢，真正的瓶頸在別處。

在 Vibe Coding 中，測量尤其重要。因為 AI 可能會給你很多最佳化建議，但不是所有建議都值得實施。先測量，找到真正的瓶頸，然後讓 AI 針對性地最佳化，這樣效率最高。



### 最佳化關鍵路徑

不是所有地方都需要最佳化。優先最佳化使用者最常用的功能，以及對效能影響最大的地方。比如首頁載入、核心功能的響應速度等。



### 平衡效能和可讀性

效能最佳化有時會讓程式碼變複雜。你要在效能和可讀性之間找到平衡。如果一個最佳化只能提升 10ms，但讓程式碼難以理解，那可能不值得。



### 不要過早最佳化

在專案早期，不要花太多時間最佳化效能。先把功能做出來，等有了真實使用者和資料，再根據實際情況最佳化。過早最佳化可能會浪費時間，因為你不知道真正的瓶頸在哪裡。

這一點在 Vibe Coding 中尤其重要。因為 AI 能快速實現功能，你可能會忍不住想把所有細節都最佳化到完美。但記住，先讓應用跑起來，有使用者用了，再最佳化。MVP 思維同樣適用於效能最佳化。



### 持續監控

效能不是最佳化一次就夠了。隨著功能增加，新的效能問題會出現。建議使用效能監控工具（比如 Sentry、LogRocket），持續監控應用的效能，及時發現和解決問題。



## 七、如何讓 AI 幫你最佳化效能？

如果前面的很多技術你都沒有接觸過、也聽不懂，那麼可以完全透過 Vibe Coding 來最佳化效能。完整流程是這樣的：




### 1、讓 AI 分析效能問題

把程式碼和測試結果一起發給 AI，讓它幫你分析：

```markdown
我的應用效能有問題，這是 Performance 測試結果【截圖】，這是相關程式碼：

【貼上你的程式碼】

請幫我分析效能瓶頸，重點關注：
1. 有沒有不必要的重新渲染？
2. 有沒有重複的計算？
3. 資料結構選擇是否合理？
4. 有沒有可以並行的操作？
```

AI 會給你詳細的分析和建議。



### 2、讓 AI 提供最佳化方案

找到問題後，讓 AI 給你具體的最佳化方案：

```markdown
這段程式碼在資料量大時很慢。請給我一個最佳化方案，要求：
1. 使用虛擬滾動
2. 保持程式碼可讀性
3. 不改變現有的 API
4. 給出完整的實現程式碼
```

AI 會給你具體的最佳化程式碼，你可以直接使用。



### 3、分步驟最佳化

不要一次性實施所有最佳化。每次只最佳化一個地方，測試效果，確認有改善再繼續。

比如：
1. 先最佳化最慢的部分（比如資料庫查詢）
2. 測試效果，確認有改善
3. 再最佳化第二慢的部分（比如圖片載入）
4. 繼續測試，確認有改善

這樣即使某個最佳化出了問題，也容易回退。



### 4、驗證最佳化效果

每次最佳化後，一定要驗證效果。可以用 Performance 工具測量最佳化前後的效能，確保最佳化真的有效。

如果最佳化效果不明顯，可以把測試結果反饋給 AI：

```markdown
我按你的方案最佳化了，但效果不明顯，這是新的測試結果【截圖】，還有其他最佳化方法嗎？
```

AI 會根據新的資料給你更好的建議。



## 寫在最後

效能最佳化是一個持續的過程，不是一次性的任務。隨著專案發展，新的效能問題會不斷出現，你需要持續關注和最佳化。

在 Vibe Coding 中，效能最佳化的核心是：**發現問題 → 描述需求 → 讓 AI 實現 → 驗證效果**。你不需要成為效能最佳化專家，只需要知道如何引導 AI 幫你解決問題。

讓我總結一下本文的要點：

1. 先識別問題：用工具測量，找到真正的瓶頸，不要憑感覺。把測試結果給 AI 看，讓它幫你分析。
2. 瞭解常見問題：AI 生成的程式碼容易出現這些效能問題 —— 不必要的渲染、大量資料一次性載入、圖片未最佳化、序列請求、缺少快取。知道這些問題，你就能更好地引導 AI。
3. 善用 AI：把效能問題描述清楚，讓 AI 給你最佳化方案。分步驟實施，每次最佳化後都要驗證效果。
4. 遵循原則：先測量再最佳化，優先最佳化影響最大的地方，不要過早最佳化，保持 MVP 思維。

記住，效能最佳化的目標不是追求極致的速度，而是給使用者良好的體驗。只要使用者感覺快，就夠了。
