# 我的 GitHub 漲星漲粉技巧

> 讓更多人發現你的開源專案



你好，我是程式設計師魚皮。

在前面的內容中，我們已經學習瞭如何用 Vibe Coding 做出自己的產品。但很多同學做完專案後就放在那了，沒人知道、也沒人用，怪可惜的。

其實 GitHub 是一個非常好的產品推廣渠道，尤其是開源專案。我自己的 **GitHub 關注者已經突破 2w**，在中國區關注者排行榜中排到前 7。

![](https://pic.yupi.icu/1/image-20260216150445005.png)

如今有了 AI 的加持，想做個開源專案比以前容易太多了，但很多同學發完之後 Star 寥寥無幾，漲關注就更難了。

所以這篇文章我把自己這些年實踐過的「GitHub 漲星漲粉技巧」全公開，希望能幫大家把自己的開源專案推出去。



## 魚皮的 GitHub 漲星漲粉技巧

漲 Star 和漲關注其實是一回事，核心是 **持續提供價值 + 讓更多人看到**。

1）先有一個主打專案：與其分散精力做 10 個沒人知道的小專案，不如集中火力把一個做到位。

我的程式設計導航、面試鴨、AI 知識庫，每個都是持續迭代出來的，不是寫完就扔。我去年重點發力 AI 程式設計方向，熬夜肝了無數個大爺，打磨 [ai-guide](https://github.com/liyupi/ai-guide) 這個免費 AI 教程倉庫，從 0 做到了近 7k Star，靠的是持續輸出有價值的內容。

![](https://pic.yupi.icu/1/image-20260216151737267.png)

2）裝修你的 GitHub 主頁：在你的 GitHub 賬號下新建一個和使用者名稱同名的倉庫，裡面的 README 文件會直接展示在你的主頁上。

建議在文件裡寫好自我介紹、置頂最拿得出手的專案。你的主頁就是你在開源世界的臉面，別人一看你的主頁就知道 follow 你能獲得什麼，followers 自然越來越多。

![](https://pic.yupi.icu/1/image-20260216151341675.png)

3）用心寫好專案 README：很多人程式碼寫得不錯，但 README 就一句 "A project built with React"，誰敢用啊？

好的 README 要說清楚專案解決什麼問題，包括效果截圖/動圖、快速上手步驟、專案亮點等。你把 README 當成產品詳情頁用心寫，別人能感受到你的認真，自然更願意給你一顆星。

4）提供可體驗的地址：光有程式碼不夠，一定要部署一個線上 Demo 讓別人直接體驗。很多人看到一個專案，如果沒有可以直接訪問的地址，大機率就划走了，眼見為實嘛。

![](https://pic.yupi.icu/1/image-20260216151931295.png)

5）降低使用門檻：提供 Docker 一鍵部署、寫清楚環境要求、準備好示例資料。讓別人 clone 下來 2 分鐘就能跑起來，而不是折騰半天環境。門檻越低，願意試用和給 Star 的人越多。

![](https://pic.yupi.icu/1/image-20260216152025708.png)

6）重視倉庫 SEO：GitHub 本身就是個搜尋引擎，你的專案名稱、Description、Topics 標籤都是關鍵詞。

比如我的 ai-guide 專案，在 GitHub 上搜尋 "ai guide"、"AI程式設計教程" 的排名都很靠前，這些自然搜尋流量是免費的。你可以搜一下自己專案的核心關鍵詞，看看排第幾，然後針對性最佳化。

![](https://pic.yupi.icu/1/image-20260216152123748.png)

7）追熱點出爆款：熱門話題自帶流量，關鍵是要快狠準。當年「合成大西瓜」火遍全網的時候，我第一時間做了個魔改工具開源，一夜爆了；「羊了個羊」刷屏的時候，我馬上做了「魚了個魚」遊戲跟上，也迅速起量。

![](https://pic.yupi.icu/1/image-20260216152348389.png)

現在有了 AI，你可以用它幫你快速分析熱點背後的需求、生成完整專案，從發現熱點到上線開源可能就一個晚上的事。

8）社群分享：你的專案做好了，一定要主動去社群曝光，比如在程式設計導航、掘金、V2EX、Reddit、Twitter 上分享。

注意，分享時不是甩一個連結就完事了！而是要講清楚：我遇到了什麼問題 → 我怎麼解決的 → 你也可以直接用。讓人覺得「這對我有用」而不是「又來打廣告的」。

目前各大平臺對開源專案的推廣容忍度很高，平臺樂意推、使用者也天然信任開源的東西。像我的 [程式設計導航網站](https://www.codefather.cn/)，也經常有學程式設計的同學來分享自己的專案，我作為平臺方是很樂意幫忙推薦的，互相成就嘛。

![](https://pic.yupi.icu/1/1%20%E7%BC%96%E7%A8%8B%E5%AF%BC%E8%88%AA%E5%AD%A6%E4%B9%A0%E8%B7%AF%E7%BA%BF.png)

9）拓寬你的受眾：先想清楚你的專案是給誰用的。如果你的專案不是純中文場景，千萬不要只盯著國內使用者。可以用 AI 把 README 翻譯成英文，倉庫描述也用英文來寫，面向全球開發者。GitHub 上海外使用者是大頭，多了幾十倍的潛在受眾。我前段時間還專門開源了一個 [GitHub Global 工具](https://github.com/liyupi/github-global)，幫你一鍵把倉庫翻譯成多種語言，出海成本不要太低。

![](https://pic.yupi.icu/1/1769079083162-aa879560-6044-4ef7-a3a2-718b03070978.png)

10）長期走一個方向：我的 GitHub 從程式設計學習資源、專案實戰教程、面試刷題、到 AI 程式設計，一直圍繞「幫程式設計師成長」這條線。方向一致，別人才願意長期關注你，而不是看完一個專案就走了。而且隨著 AI 程式設計的普及，GitHub 的使用者群體已經遠不止傳統程式設計師了，很多產品經理、設計師、創業者也開始逛 GitHub 找工具，你的潛在受眾其實比以前大得多，堅持走下去回報會越來越大。

AI 時代，開源的門檻已經被磨到地板上了，但這也意味著競爭更激烈。與其做 10 個 AI 生成的 Demo，不如認真打磨一個能解決真實問題的專案，持續迭代、持續分享，Star 和 followers 都是水到渠成的事。



## 寫在最後

GitHub 不僅是存程式碼的地方，更是你展示自己的舞臺。用好它，你的產品能被全世界的開發者看到。

結合本板塊前面講到的 SEO 最佳化思路，再加上這些 GitHub 運營技巧，相信你的開源專案一定能獲得更多關注。
