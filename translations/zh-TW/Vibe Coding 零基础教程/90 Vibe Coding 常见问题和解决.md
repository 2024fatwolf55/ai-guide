## Vibe Coding 概念理解


### Vibe Coding 和傳統程式設計有什麼區別？

回答：傳統程式設計是你自己寫程式碼，Vibe Coding 是你用自然語言描述需求，讓 AI 幫你寫程式碼。傳統程式設計需要你掌握程式語言的語法和細節，Vibe Coding 更注重需求的表達和 AI 的引導。但本質上，它們都是在解決問題，只是方式不同。你可以把傳統程式設計理解成自己做飯，Vibe Coding 理解成點外賣 —— 最終都能吃上飯，但過程完全不一樣。



### Vibe Coding 適合所有人嗎？

回答：Vibe Coding 降低了程式設計的門檻，讓更多人能參與開發。但它不是萬能的，對於非常複雜的系統、對效能要求極高的專案、需要深度最佳化的場景，傳統程式設計可能更合適。Vibe Coding 最適合快速原型開發、個人專案、中小型應用、工具類軟體等場景。如果你是零基礎想學程式設計，或者想快速把想法變成產品，Vibe Coding 就很適合你。




### 學了 Vibe Coding 還需要學傳統程式設計嗎？

回答：需要，但不用急。Vibe Coding 能幫你快速實現功能，但要真正理解程式碼、除錯複雜問題、最佳化效能，還是需要程式設計基礎。建議邊用 Vibe Coding 做專案，邊學習程式設計知識。這樣學習效率更高，也更有動力。你可以先用 AI 做出幾個專案，有了成就感後再系統學習程式設計，會比一開始就啃書本有意思得多。




### AI 生成的程式碼靠譜嗎？

回答：AI 生成的程式碼能用，但不一定完美。它可能有 bug、效能問題、安全隱患。所以你需要測試功能、審查程式碼、持續最佳化。不要盲目相信 AI，要保持批判性思維。就像你點外賣也要檢查一下菜品是否新鮮一樣，AI 生成的程式碼也需要你把關。不過隨著 AI 模型的進步，程式碼質量已經越來越高了。




### Vibe Coding 會取代程式設計師嗎？

回答：不會完全取代，但會改變程式設計師的工作方式。就像計算器沒有取代數學家，搜尋引擎沒有取代圖書館員一樣，AI 程式設計工具會成為程式設計師的助手，而不是替代品。未來的程式設計師需要更強的產品思維、架構能力和問題解決能力，而不只是寫程式碼的能力。會用 AI 的程式設計師會比不會用的更有競爭力。




### 什麼是 AI 幻覺？

回答：AI 幻覺是指 AI 編造了不存在的內容，比如虛構了一個不存在的 API、錯誤的函式用法、或者根本不存在的庫。這是 AI 模型的固有問題，因為它是基於機率生成內容的。遇到幻覺時，不要慌，要求 AI 提供文件連結驗證，或者自己查官方文件確認。如果 AI 堅持錯誤，可以換個模型試試，或者開新對話重新描述問題。




### MVP 是什麼意思？

回答：MVP 是 Minimum Viable Product 的縮寫，意思是最小可行產品。簡單來說就是先做一個最簡單但能用的版本，然後再慢慢完善。比如做記賬應用，MVP 版本可能只有記錄支出、檢視列表、計算總額這三個功能，其他的分類、圖表、匯出等功能以後再加。這樣做的好處是能快速驗證想法，避免一開始就陷入細節，保持開發動力。




### 什麼是上下文視窗？

回答：上下文視窗是指 AI 模型一次能 “記住” 的內容量，一般用 Token 來衡量。比如 Claude Sonnet 的上下文視窗是 200K Token，大約相當於 15 萬個中文字。上下文視窗越大，AI 能處理的程式碼量就越多，能記住的對話歷史就越長。如果你的專案程式碼很多，選擇上下文視窗大的模型會更合適，比如 Gemini 3 Pro、Claude Opus 4.8 和 DeepSeek-V4-Pro 都支援 1M Token。




## Vibe Coding 工具選擇


### Cursor 和 Windsurf 哪個更好？

回答：兩個都很好，各有特點。Cursor 生態更成熟，社群更大，外掛更多，文件更完善。Windsurf 有一些創新功能比如 Cascade 模式，介面也更現代。

如果你是新手，建議從 Cursor 開始，因為遇到問題更容易找到解決方案。如果你喜歡嚐鮮，可以試試 Windsurf。當然最好的辦法是 “我全都要”，兩個都試試，看哪個更適合你的工作方式。




### 免費版夠用嗎？

回答：對於學習和小專案，免費版夠用。Cursor 免費版每月有一些特定模型的額度。但如果是日常工作或大專案，建議用付費版。付費版的額度更多，模型更強，體驗更好，本質是拿金錢換時間。

可以先用免費版試試，覺得好用再升級。學生黨可以充分利用各種免費資源，完全夠學習使用了。




### 如何選擇 AI 模型？

回答：根據任務複雜度和預算選擇。

- 對於簡單任務，比如只是開發個單頁面應用或者演示網站，用便宜的模型（Gemini Flash、DeepSeek）
- 對於複雜任務，比如開發包含完整前後端的全棧專案或系統，用強大的模型（Claude Opus、GPT-5.5）
- 如果做前端 UI，Gemini 3 Pro 的表現很不錯
- 如果預算有限，國產模型（DeepSeek、通義千問、智譜 GLM-5）價效比很高

如果不確定用什麼模型，可以用 Auto 模式讓工具自動選擇，或者先用便宜的模型試試，不行再換更強的模型。




### Bolt.new 和 v0.dev 有什麼區別？

回答：Bolt.new 更適合做全棧應用，能生成完整的前後端程式碼，還能直接在瀏覽器裡執行和除錯。v0.dev 更專注於前端 UI 元件，特別擅長生成漂亮的介面。如果你想快速做一個完整的應用，用 Bolt.new。如果你只是想生成一些 UI 元件，用 v0.dev。兩個都是零程式碼平臺，不需要安裝軟體，開啟瀏覽器就能用，特別適合新手。




### API Key 在哪裡獲取？

回答：去對應服務的官網註冊賬號，然後在設定或 API 頁面生成 Key。比如 OpenAI 的 Key 在 platform.openai.com 獲取，Anthropic 的 Claude Key 在 console.anthropic.com 獲取，Supabase 的 Key 在專案設定裡。

生成 API Key 後記得妥善保管，不要洩露，也不要提交到 GitHub 等公開倉庫。建議用環境變數或配置檔案來管理 API Key，避免硬編碼在程式碼裡。




### 如何在國內訪問 Cursor 和 Claude？

回答：Cursor 可以直接訪問，但 Claude 官網在國內訪問可能有困難。可以使用國產模型替代，比如 DeepSeek、通義千問、智譜 GLM 在程式設計能力上已經很接近國際模型了，而且訪問速度更快，價格更便宜。如果一定要用 Claude，可以考慮使用 API 方式，或者透過 OpenRouter 等中轉服務。




### Cursor 有哪些 AI 模式？

回答：Cursor 2.0 主要提供了 2 大 AI 互動模式

1. Chat 模式：對話模式，適合問問題、解釋程式碼、小範圍修改。
2. Agent 模式：最強大的模式，可以自主規劃和執行復雜任務，能同時修改多個檔案，支援並行執行多個代理。

如果你只是想問問題或改一個函式，用 Chat 就夠了。如果要新增新功能、涉及多個檔案的修改，用 Agent 更合適。Agent 模式還支援 Plan Mode，會先生成計劃讓你確認，再執行修改。




### 選擇零程式碼平臺還是程式碼編輯器？

回答：如果你是完全零基礎，或者只是想快速做個原型，用零程式碼平臺（Bolt.new、v0.dev）。如果你想做複雜專案，需要更多控制權，或者想學習程式設計，用程式碼編輯器（Cursor、Claude Code 等）。

零程式碼平臺簡單快速，但靈活性有限。程式碼編輯器功能強大，但學習難度更大。建議先用零程式碼平臺體驗一下，有了感覺再學程式碼編輯器。




## Vibe Coding 使用技巧


### AI 生成的程式碼報錯怎麼辦？

回答：把完整的錯誤資訊和相關程式碼複製給 AI，讓它分析和修復。注意要包含完整的錯誤堆疊，不要只複製一句話。如果 AI 修復不了，可以切換到更強的模型試試，或者開新對話重新描述問題。也可以自己查文件或搜尋解決方案，在社群或論壇求助。很多時候錯誤資訊本身就包含了解決線索，學會看錯誤資訊很重要。




### AI 總是用錯誤的技術棧怎麼辦？

回答：在每次對話開始時，明確說明你的技術棧。比如 “我用的是 React + TypeScript + Tailwind CSS，請用這些技術實現”。

或者在專案中配置 `.cursorrules` 規則檔案，讓 AI 自動知道你的技術棧。

如果 AI 還是用錯，及時中斷並糾正：“我用的是 React，不是 Vue，請用 React 重寫！”

多次強調後 AI 就會記住了。




### 如何讓 AI 生成的程式碼更符合專案風格？

回答：提供參考程式碼，讓 AI 模仿。比如：“請參考這個元件的風格來寫新元件”，然後貼上參考程式碼。

或者在上下文檔案中詳細說明程式碼風格，包括命名規則、元件結構、註釋格式等。

還可以提供一個程式碼規範文件，讓 AI 按照規範來寫。

最重要的是，提示詞越具體越好，不要只說 “寫得好看一點”，要說清楚什麼是好看。




### AI 生成的程式碼效能不好怎麼辦？

回答：先用 Chrome DevTools、Lighthouse 等工具找到效能瓶頸，然後讓 AI 針對性地最佳化。比如 “這個列表渲染很慢，請用虛擬滾動最佳化”，或者 “這個函式在大資料量時很慢，請最佳化演算法”。

不要一開始就追求完美效能，先讓功能跑起來，發現瓶頸再最佳化，大部分情況下 AI 生成的程式碼效能已經夠用了。




### 如何處理 AI 的幻覺？

回答：如果 AI 編造了不存在的 API，要求它提供文件連結。如果提供不了，說明是幻覺，讓它用正確的 API。

如果 AI 陷入死迴圈，切斷上下文，開新對話。

如果 AI 堅持錯誤方案，換個模型試試，或者自己查文件確認。

遇到不確定的內容，一定要驗證，不要盲目相信。建議養成查文件的習慣，這是程式設計師的基本功。




### 如何除錯 AI 生成的程式碼？

回答：使用斷點除錯，而不是隻用 console.log。

可以在瀏覽器或編輯器中設定斷點，單步執行程式碼，檢視變數值。這樣能更清楚地看到程式碼的執行過程。如果還是找不到問題，把錯誤資訊和程式碼給 AI，讓它幫你分析。也可以讓 AI 新增詳細的日誌，幫助你理解程式碼的執行流程。

除錯是程式設計師的必備技能，值得多花時間學習。




### 如何提高提示詞的質量？

回答：提示詞要具體、清晰、有結構。不要說 “做一個網站”，要說 “做一個記賬網站，包含新增支出、檢視列表、統計總額三個功能，介面用藍色調，簡潔現代風格”。

可以把提示詞分成幾個部分：功能需求、介面要求、技術要求。還可以提供參考案例，比如 “介面風格參考 Notion”。

記住，提示詞寫得越詳細，AI 生成的結果越符合預期。




### AI 生成的程式碼太冗長怎麼辦？

回答：讓 AI 重構程式碼，提取重複部分，簡化邏輯。比如 “這段程式碼太長了，請重構一下，提取公共函式，減少重複”。或者 “請用更簡潔的方式實現這個功能”。

AI 一般會優先讓程式碼能跑起來，而不是追求簡潔，所以需要你主動要求最佳化。不過也不要過度追求簡潔，可讀性更重要。




### 如何讓 AI 解釋程式碼？

回答：透過讓 AI 解釋程式碼，你能更快地理解和學習。可以直接問 AI “這段程式碼是做什麼的？請詳細解釋”，或者 “這個函式的邏輯是什麼？為什麼要這樣寫？”。AI 會用通俗易懂的語言給你解釋。

如果解釋太簡單，可以說 “請更詳細地解釋，包括每一步的作用”。如果解釋太複雜，可以說 “請用更簡單的語言解釋，我是新手”，甚至可以說 “我是傻子”，效果可能會出其不意~




### 如何處理 AI 生成的過時程式碼？

回答：AI 的訓練資料可能有滯後，所以有時會生成舊版本的程式碼。你需要明確告訴 AI 使用最新版本，比如 “請用 React 19 的最新寫法” 或者 “請用 Next.js 15 的 App Router”。並且一定要提供給 AI 最新的官方文件。




### 如何在提示詞中加入程式碼示例？

回答：直接把程式碼用三個反引號包裹起來，然後貼到提示詞裡。比如：

````markdown
請參考這段程式碼的風格：

```jsx
程式碼內容
```
````

如果程式碼比較長，可以只貼關鍵部分。也可以利用 AI 程式碼編輯器的 `@` 能力，讓 AI 讀取專案中的檔案，比如 “請參考 @src/components/Button.tsx 的風格”。提供程式碼示例能讓 AI 更準確地理解你的需求。




### AI 總是生成重複的程式碼怎麼辦？

回答：提醒 AI 提取公共函式或元件。比如 “這些程式碼有很多重複，請提取成公共函式” 或者 “請建立一個可複用的元件”。也可以在提示詞裡明確說 “避免重複程式碼，使用 DRY 原則”。如果 AI 還是生成重複程式碼，可以自己手動重構，或者換個模型試試。




### 如何處理 AI 生成的不安全程式碼？

回答：讓 AI 審查程式碼的安全性。比如 “請檢查這段程式碼是否有安全問題” 或者 “請新增輸入驗證，防止 XSS 攻擊”。也可以使用安全掃描工具，比如前端程式碼可以用 ESLint 的安全外掛。對於敏感操作（比如使用者認證、支付），一定要格外小心，最好請有經驗的開發者、或者多用幾個不同的高階 AI 模型來交叉驗證。




## Vibe Coding 專案開發


### 專案做到一半程式碼變得很亂怎麼辦？

回答：及時重構，不要等到完全亂套了再處理。每完成一個功能，花 10 ~ 15 分鐘整理一下程式碼。提取重複程式碼，拆分大函式，改進命名，新增註釋。

如果已經很亂了，可以讓 AI 幫你重構，但要小步進行，每一步都要測試。比如 “請幫我重構這個檔案，提取公共函式”，而不是 “重構整個專案”。小步快跑，逐步改進。

注意，重構前一定要先用 Git 提交當前程式碼！這樣即使重構出問題，也能隨時回退到之前的版本。養成頻繁提交的習慣，是保護程式碼的最好方式。




### 如何部署 AI 生成的專案？

回答：很多零程式碼平臺（比如 Bolt.new）支援一鍵部署，點個按鈕就能上線。

如果要手動部署，可以用 Vercel、Netlify 等平臺。把程式碼推送到 GitHub，然後在平臺上連線倉庫，它會自動構建和部署。

如果需要後端，可以用 Supabase 等 BaaS 服務。如果需要用自己的伺服器，可以利用 Docker 容器化部署。

總之，部署其實沒那麼難，跟著魚皮的部署教程一步步來就行。




### 專案上線後出了 bug 怎麼辦？

回答：首先，用監控工具（Sentry、LogRocket）收集錯誤資訊。然後，在本地復現問題，找到原因。

修復後，讓 AI 多寫測試，確保問題不再出現。最後儘快部署修復版本。

為了避免這種情況，上線前要充分測試，包括功能測試、邊界情況測試、不同裝置測試。可以讓朋友幫忙測試，往往能發現你一個人沒注意到的問題。




### 如何從玩具專案變成真正的產品？

回答：需要考慮到很多方面，比如

1. 完善錯誤處理，考慮各種異常情況
2. 新增測試，確保功能穩定
3. 最佳化效能，讓應用跑得更快
4. 加強安全，保護使用者資料
5. 改進 UI，讓應用更好用
6. 寫好文件，方便維護和擴充套件
7. 還要考慮 SEO、監控、日誌等

這是一個持續改進的過程，不要想著一步到位。每次改進一點，慢慢就能變成真正的產品。




### 如何評估專案的質量？

回答：不要只關注功能，質量同樣重要。一個功能完整但 bug 一堆的專案，不如一個功能簡單但穩定可靠的專案。

可以從這幾個方面評估：

- 功能完整性（是否實現了所有需求）
- 程式碼質量（是否清晰、可維護）
- 效能表現（載入速度、響應速度）
- 安全性（有沒有漏洞）
- 使用者體驗（是否好用）
- 測試覆蓋率（是否有足夠的測試）




### 遇到 AI 解決不了的問題怎麼辦？

回答：首先，一定不要對著一個 AI 死磕，可以換個 AI 模型試試，不同模型擅長的領域不一樣。

如果你有程式設計基礎，最好看看官方文件，文件是最權威的資料。

或者搜尋類似問題的解決方案，比如 GitHub Issues 區，因為很多問題別人已經遇到過了，照搬解決方案就好。

還可以在社群或論壇求助，比如在  [程式設計導航](https://codefather.cn/) 提問；或者請教有經驗的開發者，有時候一句話就能點醒你。

記住，AI 是工具，不是萬能的，人的智慧同樣重要。




### 如何管理專案的版本和程式碼？

回答：用 Git 做版本控制，把程式碼託管到 GitHub。

- 每完成一個功能就提交一次，寫清楚提交資訊
- 如果要嘗試新功能，建立新分支，測試沒問題再合併
- 定期備份程式碼，避免資料丟失
- 如果是團隊協作，制定好分支策略和程式碼規範

Git 是程式設計師的必備技能，絕對值得花時間學習。但是不用死記硬背 Git 的命令，因為 AI 就可以幫你搞定。




### 如何處理專案依賴和包管理？

回答：用 npm 或 pnpm 管理依賴，定期更新包版本。

還要注意下面幾點：

1. 注意檢查包的安全性，避免使用有漏洞的包。
2. 如果遇到依賴衝突，可以讓 AI 幫你解決
3. 不要安裝太多不必要的包，每個包都會增加專案體積和複雜度
4. 定期清理不用的依賴，保持專案整潔

如果不確定要用哪個包，可以讓 AI 推薦，它會給你幾個選擇和對比。




### 如何測試 AI 生成的程式碼？

回答：如果是重要專案，可以讓 AI 幫你寫自動化測試，比如單元測試、整合測試。

但是不要完全相信 AI，必須手動測試！把每個功能都點一遍，試試各種邊界情況。

測試不僅能發現 bug，還能讓你更瞭解程式碼的行為。不要覺得測試浪費時間，它能幫你省下更多除錯的時間。還可以讓朋友或邀請使用者幫忙測試，他們往往能發現你沒想到的問題。




### 如何最佳化 AI 生成的 UI 介面？

回答：可以讓 AI 參考優秀的設計，比如透過文字描述 “介面風格參考 Notion，簡潔現代”，或者找一些優秀網站的截圖貼給 AI 理解並參考。

如果你有一定的程式設計基礎，或者有自己喜歡的 UI 元件庫，可以直接推薦給 AI。比如 Ant Design、Material-UI、shadcn/ui，它們提供了現成的漂亮元件。

記住，好的 UI 不是花哨，而是清晰、一致、好用。




### 如何處理多人協作開發？

回答：使用 Git 分支管理，每個人在自己的分支上開發，完成後合併到主分支。

此外，還有幾個重要事項：

1. 制定程式碼規範，保持程式碼風格一致。可以讓 AI 幫你生成團隊協作文件，包括開發規範、Git 工作流等。
2. 使用 Pull Request 進行程式碼審查，互相學習
3. 定期同步程式碼，避免衝突
4. 使用專案管理工具（比如 Notion）分配任務
5. 保持溝通，遇到問題及時討論




### 如何給專案新增資料庫？

回答：最簡單的方法是用 BaaS 服務，比如 Supabase、Firebase。它們提供了資料庫、認證、儲存等功能，不需要自己搭建伺服器。

直接告訴 AI “請整合 Supabase 資料庫”，它會幫你生成程式碼。

對於小專案，BaaS 服務完全夠用，而且省心。

如果需要更多控制權，可以用 PostgreSQL、MongoDB 等資料庫，但需要自己部署和管理。




### 如何處理使用者認證和授權？

回答：不要自己從零實現認證系統，太容易出安全問題。建議使用現成的方案，比如 Supabase Auth、Firebase Auth、Auth0、NextAuth.js。這些方案提供了完整的認證流程，包括郵箱驗證、密碼重置、第三方登入等。

直接告訴 AI “請用 NextAuth.js 實現使用者登入註冊”，它會幫你整合。

如果是學習專案，可以簡單實現，但商業專案一定要用成熟方案。




## Vibe Coding 學習成長


### 零基礎能學 Vibe Coding 嗎？

回答：完全可以。Vibe Coding 降低了程式設計門檻，零基礎也能上手。建議從零程式碼平臺（Bolt.new）開始，先做出幾個小專案，建立信心。然後邊做邊學，瞭解一些基本的程式設計概念，比如變數、函式、條件判斷、迴圈等。不用一開始就學很深，能看懂 AI 生成的程式碼就行。慢慢地，你會發現自己能理解越來越多，甚至能自己修改程式碼了。




### 學習 Vibe Coding 需要多長時間？

回答：入門很快，不到 10 分鐘就能做出第一個專案。但要熟練掌握，需要日復一日的實踐。建議每天花 1 ~ 2 小時練習，先做一些小專案積累經驗、然後嘗試做商業級產品。

記住，學習是持續的過程，不要急於求成。重要的不是學多快，而是能不能堅持。每天進步一點點，幾個月後回頭看，你會驚訝於自己的成長。




### 有哪些學習資源推薦？

回答：

1. 官方文件是最好的資源，比如 Cursor 的文件、Claude 的文件。
2. [魚皮的AI 導航](https://ai.codefather.cn/) 收錄了大量 AI 工具和學習資源。
3. B 站、YouTube 上有很多 Vibe Coding 的影片教程，我在 “程式設計師魚皮” 這個賬號也經常做這方面的分享。
4. GitHub 上有 awesome-vibe-coding 這樣的資源合集
5. 還可以加入 [程式設計導航](https://www.codefather.cn/) 等開發者社群，和其他人交流學習。




### 如何提高 Vibe Coding 水平？

回答：多實踐是最重要的。

- 做各種型別的專案，從簡單到複雜
- 學習優秀的提示詞和對話技巧，看別人是怎麼用 AI 的。
- 理解 AI 生成的程式碼，不要只是複製貼上。
- 總結經驗教訓，記錄遇到的問題和解決方法。
- 保持學習，關注新工具和新技術。
- 可以嘗試重構之前的專案，用新學的技巧改進它
- 教別人也是很好的學習方式，能加深你的理解，輸出促進輸入




### 如何平衡 AI 輔助和自主學習？

回答：不要完全依賴 AI，也不要完全排斥 AI。可以先讓 AI 生成程式碼，然後自己理解和修改。遇到不懂的地方，先自己思考，再問 AI。

如果你還處於入門階段，可以定期做一些不用 AI 的練習，鞏固基礎。

**記住，AI 是工具、是加速器，但不能代替你的思考。**

就像計算器不能代替數學思維一樣，AI 不能代替程式設計思維。用 AI 提高效率，用思考提升能力。




### 如何保持學習動力？

回答：做自己感興趣的專案，而不是為了學習而學習。

你可以：

- 設定小目標，每完成一個就獎勵自己
- 和朋友一起學習，互相鼓勵
- 分享你的作品，獲得反饋和認可
- 記錄學習過程，看到自己的進步

學習是馬拉松，不是短跑，慢慢來，享受過程。最重要的是，記住你為什麼開始學習，想做什麼，想成為什麼樣的人。不要和別人比，而是和過去的自己比。




## Vibe Coding 成本和效率


### 如何控制 AI 使用成本？

回答：有非常多節省真金白銀的技巧

- 簡單任務用便宜的模型，複雜任務才用貴的模型
- 充分利用免費資源，比如 DeepSeek、通義千問的免費額度
- 最佳化提示詞，一次說清楚，減少反覆對話
- 避免讓 AI 生成大量不必要的程式碼
- 使用快取功能，減少重複計算

如果是學習階段，免費資源完全夠用。如果是商業專案，成本是值得的，因為 AI 能大大提高效率，節省的人力成本遠超 AI 成本。



### 如何提高開發效率？

回答：有很多提高效率的技巧：

- 使用快捷鍵，減少滑鼠操作
- 利用 Agent 模式，讓 AI 自動化工作，減少人工投入的時間
- 準備好提示詞模板，常用的需求直接套用
- 使用程式碼片段，快速插入常用程式碼
- 配置好開發環境，減少重複工作
- 學習一些基礎知識，能更快理解和修改 AI 生成的程式碼

最重要的是，做好規劃，想清楚再動手，避免返工。Vibe Coding 完整專案時，真正的效率不是快，而是少走彎路。



### 如何避免重複勞動？

回答：程式設計師的優點就是 “懶”，避免重複勞動的關鍵就是 **沉澱和複用**。

具體的幾種做法：

- 把常用的提示詞、配置、程式碼片段儲存起來，需要時直接複製，或者讓 AI 複用。
- 使用模板專案，新專案基於模板建立，而不是從 0 開始生成
- 把解決過的問題記錄下來，下次遇到直接查閱
- 建立自己的知識庫，積累經驗



### 如何選擇合適的訂閱計劃？

回答：如果是學習階段，先用免費版，不夠用再升級。如果是日常工作或者要做個商業專案，訂閱 Cursor Pro 的價效比最高。如果需要大量使用，可以考慮 API 按量付費。如果預算有限，國產模型的訂閱更便宜。

總之，不要一開始就訂閱最貴的，先試用，找到最適合自己的。也不要排斥付費，畢竟工具是為了提高效率，如果能幫你節省時間，成本就是值得的。
